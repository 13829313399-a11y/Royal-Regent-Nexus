### Notification Work Center

`/notifications` and the top-bar bell use `src/stores/workCenter.ts`, one application-level `WorkCenterHost`, and `/api/work-center`. The current-source adapters cover molding-sample approval/production/problems, internal-quote department work and version-specific batch review, registration/password-reset requests, supplier shipment receipt/correction, and identity information. Other modules are not included in these counts. A business task ends only through its original domain workflow; personal read/snooze/pin/follow/archive actions never approve, receive stock, or complete production. Supplier-only portal sessions do not start this internal center.

Canonical responsibility keys include source, stage and cycle. Source reads and current IAM remain authoritative even before projection backfill. Shared notification `read_at`/`handled` is historical evidence, not personal read state or proof of business completion. Personal states are isolated by user and employment epoch; observed-version reads are monotonic. Source changes update replayable projection/events inside the original transaction. Read snapshots use one transaction and bounded SQL pagination; failed source adapters expose partial health instead of a false zero. Partial health distinguishes unavailable sources, historical orphan notices and current business verification issues.

`/notifications?view=verification` lists only currently authorized unverified tasks (never orphan notices); it preserves original workflow state and exposes the source action and safe version explanation. Business verification prompts navigate to those tasks instead of suggesting that synchronization repairs them. Bell information loading/errors are separate from task synchronization; refreshing an open information tab reloads its list, and failed refreshes mark cached task snapshots stale. Legacy notification endpoints overlay personal reads and reject manual handling of active responsibilities.

Existing databases must explicitly apply additive migration `20260928_0126` after backup. Startup refuses an incomplete work-center schema. `backend/scripts/reconcile_work_center.py` requires an explicit database URL, defaults to dry-run, and preserves source rows and personal states; repeat apply is idempotent. Roll back the UI with `VITE_WORK_CENTER_ENABLED=false` while retaining the new tables and compatible backend. Migration downgrade refuses existing personal state/preferences. The `D:/RR/royal-regent-nexus` local SQLite includes the reconciled work-center migrations; its current head is defined in section 7. Startup then reconciled fixed-v33 catalog metadata and audit records, adding three fabric permissions and twelve grants to four fixed roles; accounts, sessions, user-role bindings and business records were unchanged.
