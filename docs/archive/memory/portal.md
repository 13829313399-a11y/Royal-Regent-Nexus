### Portal UI System (Jade Atlas)

The seven department homepages (`/modules/:department`, name `modules-department`) all render `ModuleCenterView.vue` and share one portal system. `src/components/portal/portalPresentation.ts` holds presentation-only per-department config (accent, accent soft surface, motif, permission note, todo empty text) and is computed from the route parameter, not read once on mount, because the same component instance is reused when the department changes. Motif artwork lives in `PortalMotif.vue` and the identity area in `PortalHero.vue`, which wraps the existing `PageHeader` so its `title` / `description` / `actions` contract and the factory title assertions in `moduleCenterFactoryScope.spec.ts` keep working.

`src/components/portal/styles/portal.css` and `portal-shell.css` retain the default Jade appearance and are imported by `AppShell.vue` and all their ordinary selectors are namespaced under `.rrn-portal[data-portal-ui="jade-v3"]` or `.app-shell[data-portal-shell="jade-v3"]`, never on `:root` or the shared component defaults.

`src/lib/portalRouteScope.ts` is the only switch for portal appearance. It matches by route name plus `isModuleDepartmentId`, and must not use path prefixes or `meta.fullPage`: `/modules/:department/:module` is the module detail page and keeps the default appearance. `AppShell.vue` puts `data-portal-shell="jade-v3"` on `.app-shell` only for `dashboard`, `modules-department` (valid department), `workbench`, `people-directory` and `shared-tool-center`; the two `fullPage` permission pages use their own local `data-portal-region` hooks. Navigation theming only targets the named hooks (`.topbar-surface`, `.topbar-search-slot`, `.topbar-factory-button`, `.sidebar-surface`, `.sidebar-group-label`, `.sidebar-nav-link`, `.sidebar-nav-icon`, `.sidebar-health`) and reads sidebar selection from `aria-current="page"`.

Shared components stay default-first and opt in explicitly: `PermissionMatrix` and `TodoQueue` take `appearance="portal"` (used by the department homepage) while `ModuleDetailView` keeps the default markup and styles, and `IamNavigation` takes `appearance="portal"` only from `IamRoleTemplatesView`. `MemberRow` / `MemberDirectoryList` portal styling is scoped by `[data-directory-variant="default"]` so the member drawer is unaffected. Department homepages do not use `reveal-grid`; V4 separates list movement, a temporary reveal wrapper and article hover, and disables the old article entrance animation.

`ModuleCard` keyboard activation only fires when the event target is the card itself, and the fixed strings `router.push(module.route)`, `:role="module.route ? 'link' : undefined"` and `@click.stop` are pinned by `productionModuleEntry.spec.ts`. Backend entry labels such as `共 128 条` and `在线服务 23 / 24` are hardcoded demonstrations; the portal only marks them as sample context and never presents them as live figures.

The dashboard and seven valid department homepages additionally opt into `data-home-experience="prism-v4"` through the strict `getHomeExperienceScope` helper. Existing Jade markers remain; business details, workbench, directory, tools, IAM and authentication pages do not opt in. `homePrismPresentation.ts` contains only the eight visual identities; `HomePrismArtwork.vue` contains finite decorative SVG motion. `home-prism.css`, `home-prism-motion.css` and `home-prism-shell.css` scope their content/shell overrides to that V4 marker. See `DESIGN.md` section 15.5 for this explicit exception to the quieter global design baseline.

`useHomePresentation` searches and resolves preview IDs exclusively against the existing final `visibleModules` pipeline; module data, supplier route remapping, factory rules and authorization still belong to their original sources. Search preserves order, supports IME and safe text highlighting, and provides separate no-result/no-module states. Preview supports route-only, internal href and external href actions; targetless placeholders remain inert. Hover waits 140ms; explicit preview pins the target. Account, raw factory context (including group), resolved factory or department changes clear query/pin state; revoked or filtered targets disappear immediately. Mobile uses one Reka dialog preview and restores trigger/search focus.

`useHomeAppearance` shares account-scoped density/motion preferences through AppShell, whose reduced-motion and visibility listeners remain active on business fullPage routes. Only schema version plus density/motion enums are persisted; guest choices stay in memory. System reduced motion and hidden documents override expressive motion. `src/features/route-motion` observes accepted navigation for both shell branches, preserving one business tree without out-in, global route keys or KeepAlive. Only the content opacity and an inert catalog-icon ghost animate; large workspaces never receive root transform/filter. Registered parent route identities keep query/hash and module-local navigation from replaying the entrance. New intent cancels old decoration; token-owned cleanup cannot cancel a newer navigation.

Identity, authorization and factory boundaries clear source/return snapshots. Home return restores a bounded in-memory source focus/scroll record within the same context. UV, 3D and homepage content entrances yield to the shared owner; their later local motion stays local.  Identity-keyed homepage SVG artwork keeps its finite layer/trace/scan motion independently of route ownership, still subject to motion preferences, reduced motion and document visibility. `VITE_ROUTE_MOTION_ENABLED=false` disables this shared visual layer at build time without delaying or changing navigation. Sidebar and department indicators measure DOM geometry and retain positioning transforms with animation off; V4 production uses only MAIN as the canonical current sidebar item while preserving the module-configuration alias.

TopBar measures its real height for sticky offsets and exposes a narrow-screen factory select through the unchanged switch logic. The department layout queries a distinct `home-page` ancestor (640px two cards; 1000px main plus 320px aside), while the dashboard retains its existing ancestor container queries. The homepage does not add backend APIs, business KPIs or business-editing flows.
