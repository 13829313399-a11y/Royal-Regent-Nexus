# 客户箱唛模板与本单备注

箱唛资料库 → 文档生成 PDF → 客户模板 → `4500227434 · 正侧唛通用模板`。

这套模板依据已提供的四页确认 PDF 建立，采用红框、左右正侧唛、窄体英文、ZURU 图案和向上标识。模板只保存版式与通用规则；历史订单号、货号、地址、数量和条码不进入通用模板。纸面上的品牌或收货人不用于识别系统业务客户，由使用者明确选择版式。

选择本单 Excel 和工作表，明确同意发送文字、备注和图片后，一次调用专用 DeepSeek Flash。请求包括可见原生单元格及位置、文字备注/批注、受支持的嵌入图片，以及移除历史业务数据的模板参考图。业务值仍由服务端按原生单元格引用取值；图像和模板不能提供本单 PO、货号、数量、重量或条码。旧客户端只有文字同意时，不启用图片外发；旧的订单关联单块生成路径保持原来的文字输入。

模型只返回有原稿备注/图片来源的本单修改。当前参数支持正文审阅字号、文字对齐、LOGO显示、向上/易碎/防潮标识及条码左右位置。复杂图形、指定字体、任意字段移动、实际尺寸要求等不能自动兑现时列为待确认；未被修改项覆盖的原稿备注独立保留。修改清单可以取消采用，更新预览和下载完整记录都不再次调用 API。人工修改图案优先于模型建议。

本单方案与原稿字节哈希、工作表范围、账号及授权范围、模板版本、连接和有效期一起签名。更换原稿或模板后必须重新读取。生成与取消修改只处理请求内副本，没有修改客户模板的写入接口。默认下载仅含箱面，完整记录另外保留备注、未选入字段、修改来源以及未采用的修改。生成不会自动入库、确认可用或通过 QC；现有权限与订单关联流程不变。

## 运行要求与边界

- 模板定义与素材位于 `backend/app/templates/carton_marks/zuru_front_side_v1.json`、`zuru_front_side_logo.png` 和 `zuru_front_side_reference.jpg`；素材按 SHA-256 校验。
- `CARTON_MARK_TEMPLATE_FONT_FILE` 指向私有部署的 Arial Narrow Bold 字体；Windows 默认使用 `C:/Windows/Fonts/ARIALNB.TTF`。中文在 Windows 优先嵌入黑体，其余环境保留已有 STSong 回退，须另验中文显示。
- 图片请求上限为12张、Base64合计8MB。客户模板参考图占一张；只处理选定可见工作表，图像最长边1400像素。旧 XLS 局部工作表、WMF和绘图形状仍有读取限制，超过范围或无法识别时保留提示。不会把整个 Excel 文件交给模型。
- 新客户模板每次明确读稿调用一次 API；后续预览与本单修改本地完成。已有 `4500222793` 厂商表格的严格匹配本地路径仍可不调用 API。
- A4/A3为审阅稿，不是1:1生产图。条码静区和原稿明确尺寸不为排版而缩小；放不下时拒绝生成并提示使用更大纸张或另行确认。实际LOGO分档规则、箱体尺寸和实打扫码需要生产核验。
- 未拿到 `4500227434` 对应 Excel，不能宣称这份真实原稿已自动转换验收。其他同客户“Excel原稿＋确认PDF”可用于补充匹配和业务验收。

已用合成订单、合成备注图片和空白模板完成一次真实云端读稿：返回侧唛居中与仅侧唛防潮标识，并生成PDF。这个结果不代表其他真实原稿已通过。Chrome DevTools MCP 未提供时，实际浏览器交互与视口仍待验证。
