# 人员与权限工作区：设计与验收

## 目标与范围

用户要求直接优化现有权限管理页面，保留功能并显著改善布局、信息层级和操作舒适度。本次以启用三个 IAM UI 开关后的 `/system/users` 为主，重构人员目录、待办队列、只读人员详情与岗位办理面板的呈现。`/system` 持久工作区的合并版顶栏同步采用深玉色。

实现沿用主项目 Vue 3、现有 Button、Reka Dialog、Lucide 图标、中文字体及全局主色/边框/文本 token。原有 API、路由守卫、授权范围、厂区隔离、资料来源、审计语义和审批写入流程由原模块继续负责。

主要源码：

- `src/components/iam/workspace/IamWorkspaceLayout.vue`
- `src/features/identity-management/PositionWorkbench.vue`
- `src/features/identity-management/PositionReviewPane.vue`
- `src/features/identity-management/workspace/PersonContext.vue`
- `src/features/identity-management/workspace/permission-studio.css`

## 设计依据与层级

设计依据为 `DESIGN.md`、现有 `iamx-*` / `iw-*` 结构及当前真实字段。初始浏览器停在登录页，重构前的视觉问题首先依据源码和布局样式分析：信息层级接近、筛选条缺少明确搜索分组、人员信息纵向占用较多、方案与权限影响缺少足够清晰的视觉分区。没有将登录页面截图当作权限页面的原始视觉证据。

参考图采用“深玉顶栏、浅瓷画布、左队列、右办理”的工作区。实际实现保留真实入口“权限方案”，搜索提示使用现有 `/` 快捷键；图中示例数量、姓名和账号不进入业务源码。

| 层级 | 呈现与操作 |
| --- | --- |
| 一级导航 | 合并版顶栏保留人员与权限、权限方案、操作记录；使用已有导航状态和账号菜单 |
| 页面任务 | 标题与说明、待办处理/全部人员分段切换 |
| 检索 | 姓名或账号搜索、组织/类型/状态筛选、查询、重置、刷新 |
| 主工作区 | 左侧队列强调人员、变化和状态；右侧详情与办理内容独立滚动 |
| 人员详情 | 姓名头像、只读标记、资料/例外/账号标签；资料分组；授权来源保留真实有效条件 |
| 岗位办理 | 前后岗位对比；方案选择与权限影响在空间允许时并排；底部保留预览和确认操作 |

列表数量及状态全部沿用接口返回值；未知统计继续表示为不可用。长文本保留原值并提供 title；列表使用必要截断，详情正文允许换行。手机使用原有列表/详情切换及返回焦点逻辑。

## 交互与状态

“重置”清除搜索、组织、类型并恢复“未结束”状态，通过原筛选逻辑重新查询。如果因未保存的岗位办理而取消离开，搜索与筛选会恢复原值，保持表单、URL 和列表一致。“查看首位人员”和“查看首条待办”只调用原选择方法，不创建岗位待办或更改账号状态。未选择记录时显示三步办理提示。

保留加载、空态、错误、部分来源不可读取、权限受限、只读、忙碌、成功、退回、高风险确认与未知结果恢复的原语义。读取期间使用骨架与刷新图标反馈。资料标签及高级入口在已有写入锁期间禁用，避免进行中的办理被打断。停用确认使用已有危险按钮变体，恢复保留主按钮语义。

桌面左栏占约 36–37%，其余空间用于详情；详情内部按容器宽度降为单列。900px 及以下采用列表/详情切换，详情展开时收起页面标题与筛选条，保留返回入口。600px 及以下进一步压缩装饰、扩大底部触控操作。桌面高度不超过 850px 时压缩人物摘要、岗位对比和方案间距，使 1366×768 也能看到首个方案与权限影响；极低高度窗口保留外层滚动能力。

动效使用现有工作区的导航指示器，新增短时进场、按钮按下、选中与加载反馈。没有常驻装饰循环；`prefers-reduced-motion` 关闭新增动画和过渡。

### 浏览器检查范围与证据

由于真实前端当前未登录，独立验收页在 5174 端口挂载实际 IamWorkspaceLayout、PositionWorkbench、PositionReviewPane、PersonContext 与 usePositionReview。账号、API 和示例人员数据在该验收页内替换为合成模块，页面明确显示“合成数据 · 独立 UI 验收”；业务源码没有加入演示人员或绕过登录。Fetch / XHR 被阻断，8000 端口也被 CSP 禁止连接。

| 视口 | 布局结果 |
| --- | --- |
| 320×820 | 手机详情单列；没有横向溢出，底部按钮在视口内 |
| 640×900 | 手机列表/详情模式；没有横向溢出 |
| 1024×768 | 桌面双栏，详情按容器收为单列；没有横向溢出 |
| 1280×800 | 桌面双栏；没有横向溢出 |
| 1366×768 | 双栏、岗位对比、首个方案及权限影响可同时查看；固定操作可见 |
| 1440×900 | 人员资料分组清晰；主区独立滚动，无横向溢出 |
| 1536×960 | 宽屏双栏与方案/影响分区正常；没有横向溢出 |

上述 7 组检查均为 DOM 几何测量与浏览器观察；页面宽高没有超过视口。1366×768 在最后一次低高度间距调整后再次截图检查。浏览器没有相关警告或错误。

已实际操作：

- 更换办理方式并选择工程部主管方案，实际 hook 自动预览显示新增 2、将停止 0、保持 3、来源变化 1；数值来自合成 API。
- 在办理存在改动时点击重置并取消离开，搜索文字、原方案和页面保留，焦点回到重置按钮。
- 合成办理确认成功并显示结果；仅改变验收页内存，没有向真实人员发送通知或写入真实权限。
- 空搜索显示无记录，重置后恢复示例人员列表。
- 使用键盘 Enter 打开首位人员，显示真实资料组件及 8 项资料、授权来源。
- 打开停用账号确认并按 Escape 取消，弹窗关闭后焦点回到停用账号，示例账号仍为在用。
- 320px 人员详情长邮箱换行，标签、返回入口和底部操作可见。

界面核验过程中修正了合并版品牌标题样式优先级、空队列布局优先级、方案卡片纵向排列、权限变化数字色彩，以及取消筛选重置时表单回滚的问题。
