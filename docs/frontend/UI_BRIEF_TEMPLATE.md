# UI 设计交付简报模板

新模块或重大 UI 重构必用，普通小修复直接记录范围与验收动作。项目规则见 [AGENTS.md](../../AGENTS.md)，设计基线见 [DESIGN.md](../../DESIGN.md)，执行流程见 [WORKFLOWS.md](WORKFLOWS.md)。简报以决策和证据为主，不重复全局规则。

## 目标与源码范围

- 模块、页面、路由、真实岗位、厂区/组织和高频操作：
- 业务字段、核心任务与当前问题（原始截图/DOM 证据；新模块可无基线）：
- 源码、package.json、路由、组件和样式入口：
- 允许修改的范围；不改变的字段、流程、权限、API 合同与相邻模块：

## 设计方向与构图

- DESIGN.md 场景（主/次）、密度、动效等级；相关局部例外：
- 视觉目标与参考（用户参考图、实际项目优质页面、Design Lab 或自主草图/局部原型；注明具体借鉴点、证据路径及适用范围）：
- 两种有意义的构图方向、最终选择及理由（避免形式化凑方案）：
- 首屏关键任务与信息层级、主要工作区、导航/筛选/操作区、数据展示和详情布局：
- 模块辨识度及关键视觉设计（配色、材质、排版、图标、必要业务可视化、交互亮点；不强制装饰数量）：
- 复用原语、必要的专属组件及局部 token；有意义的默认值偏离与理由：
- 必须保持的操作习惯；参考与业务约束的冲突处理：

## 页面状态与交互

- 默认、加载、空态、错误、权限受限、只读、禁用、成功及危险确认：
- 信息密度、长文本、数字、滚动、实际视口及降级策略：
- 键盘焦点、弹窗关闭/焦点返回、可访问名称、对比度：
- 关键微交互、反馈、状态变化、动画目的、token 或局部变体；减少动态/透明度与打断行为：

- 相关实际测试/构建命令、计划验证的视口/状态、截图与缺陷记录位置：

## 独立设计评审（必须独立于技术 QA）

按 DESIGN.md §17.2，使用真实页面截图及实际交互，对照本轮设计目标。评审者不得参与实施；无独立评审或真实浏览器证据则标 UNVERIFIED。设计缺陷即使不影响功能也可要求 REWORK。

- 评审者/会话、实际版本、路由、状态/视口、参考、截图和交互证据：
- 评审状态：PASS / REWORK / UNVERIFIED；不适用项须说明原因。
