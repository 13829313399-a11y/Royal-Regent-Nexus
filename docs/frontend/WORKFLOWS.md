# RR 前端工作流

本流程继承 [AGENTS.md](../../AGENTS.md) 的开发、验证和 Git 约定，以 [DESIGN.md](../../DESIGN.md) 为设计基线；设计事实仍需对照源码。规则和 Skill 是工作方法，不是新组件库，也不授权修改任务以外的页面或数据。

## 按任务选择流程

| 任务 | 设计准备 | 实施与验收 |
| --- | --- | --- |
| 明确的小修复或局部样式调整 | 定位相关源码和设计规范，写清预期行为 | 局部修改，检查受影响路由/状态/视口，运行相关检查 |
| 新模块或重大布局重构 | 使用 [UI 简报](UI_BRIEF_TEMPLATE.md)，必要时调用企业页面设计 Skill | 复用组件和 token，实现相关状态，再做浏览器验收 |
| 跨模块设计一致性问题 | 对照真实页面、共享组件和现有设计基线定位差异 | 只在授权范围内调整共享实现；检查受影响的代表性路由，长期设计事实变化时同步 DESIGN.md |
| 只读设计或视觉审查 | 根据请求检查源码、参考或运行页面 | 输出具体发现与证据；未授权实现时不修改页面 |
| 规则、Skill 或文档配置 | 核对已有规则与引用 | 校验技能格式、引用、文件差异和作用域；不启动业务页面或运行无关构建 |

## Skill 与工具分工

- [enterprise-ui-art-director](../../.agents/skills/enterprise-ui-art-director/SKILL.md)：新企业页面、重大布局调整或明确的 UI 设计审查。普通缺陷修复不必走完整设计流程。
- [visual-qa-loop](../../.agents/skills/visual-qa-loop/SKILL.md)：真实浏览器中的外观、相关交互与缺陷复查。纯文档或配置任务不触发。
- 现有前端构建、测试、Figma 等技能按实际任务选用。有明确设计稿时读取该参考；从零创建独立应用时才考虑完整应用搭建流程。
- 同一个阶段采用一套连贯流程；已有技能完成的检查可以共用证据，不重复整轮工作。两个自定义 Skill 不依赖额外插件或特定 MCP。
- 复用当前可用的浏览器主工具。只有任务确有能力缺口时才评估新增工具；配置本流程不会安装工具、改变账号权限或修改模型设置。
- 主应用与 `shinobu-web` 等子项目分别核对自己的依赖、脚本和入口，不把 React、Vue 或某组件库的要求套到整个仓库。

## 设计依据与变更边界

读取任务涉及的 DESIGN.md 章节、真实组件和模块样式，保留已记录的局部例外。普通业务页优先可读性和操作效率；品牌展示、打印或专用工作台按各自约定处理。不强制每页添加装饰性视觉特色，不复制模板中的默认动效时长覆盖项目规则。

简报中记录真实字段、主要操作、状态及验收动作。参考图与权限、厂区隔离、API 合同或工作流冲突时，保留业务要求并解释视觉偏差；缺少会影响正确性的业务决策时再澄清。已获授权的常规实现选择无需重复确认。

## 浏览器验收与结束条件

打开实际目标路由，确认运行源码、账号/厂区上下文及内容渲染。明显空白区域先检查 DOM。新建或重大重构的普通页面覆盖 DESIGN.md 第 17 节规定的断点矩阵，再补充 1366×768、1440×900 等实际业务桌面尺寸；宽工作区可补充 1920×1080。固定宽度工作区按声明的最低宽度和小屏降级策略验证。小修复检查受影响布局和相关断点；通用模板的视口示例不能替代项目规定。

操作相关主流程，检查真实可达状态、键盘焦点、长文本、溢出和必要的减少动态效果表现。发现问题后记录证据，在授权范围内修复并复查；验收条件达到即可结束，不设固定轮数。不具备验证条件时明确报告缺口，不通过改写生产数据制造验收状态。

截图沿用项目已有本地证据目录，报告实际路径；历史 QA 产物和业务数据保持原样。是否纳入 Git 由明确交付要求决定，不能为整理证据扩大提交范围。

## 交付

沿用项目的“改动文件、实现行为、验证命令、剩余风险”格式。UI 任务补充实际验证的路由、状态、视口、截图和未验证项。测试、浏览器观察、数据库验证及生产/设备验收分别陈述，不能互相替代。仅在长期事实改变时按原位维护规则更新项目记忆。
