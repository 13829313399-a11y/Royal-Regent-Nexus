AI-B7A Vision 私密传输兼容性 Spike
====================================

## 结论边界

此 Spike 只验证一个尚未由当前官方合同明确承诺的兼容性问题：
`qwen3.7-plus` 的 Responses API 是否能在同一请求中接受 PNG Base64 Data
URL、流式响应和自定义 Function Call，并保持 `store=false`。

在显式 Live 测试真正通过前，不能把 Data URL 路径标记为可用，不能实现正式附件
入口，也不能开启 `AI_CLOUD_VISION_ENABLED`。当前官方合同只承诺 public URL 时，
Live 结果才是本系统对 Data URL 兼容性的有效证据。

测试代码只在内存中生成一张 32 x 32、四个纯色象限的 PNG：

- 不读取或写入图片文件；
- 不使用用户截图、业务数据或 EXIF；
- 不打印 Base64、API Key、响应正文或 Function 参数；
- 请求只注册一个自定义 Function，不启用 Web Search、File Search、Code
  Interpreter 等内置工具；
- 捕获结果只含安全分类、HTTP status（如有）、Responses status 和事件类型；
- 无论成功或失败都关闭 Stream 和 SDK Client。

这不是 AI-B7B，也不证明生产附件的格式、大小、像素、清理、用户授权和审计策略
已经完成。

## 默认离线验证

默认 CI 和普通本地测试不会访问云端：

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest tests/test_ai_vision_compatibility_live.py -q
.\.venv\Scripts\ruff.exe check tests/test_ai_vision_compatibility_live.py
```

预期结果是离线合同测试通过、一个 Live 测试跳过。离线测试会确认：只有精确设置
`AI_B7A_LIVE=1` 才能解除门控；请求固定为 `stream=True`、`store=False`、
`parallel_tool_calls=False`，并且仅含一个自定义 Function；模型未识别四象限时不能
误判通过。

仅在 B4-B6 回归通过、数据治理允许后运行。测试只有在显式 Live Flag 开启后才
导入应用 Settings；届时使用系统标准配置来源，因此可以使用已经安全保存在被 Git

和操作说明都不读取、显示或复制 Secret。不要把 Key 写进命令、Markdown、截图、

## 判定规则

只有安全分类为 `passed_image_stream_function_call`，Responses status 为
`completed`，事件集合包含 `response.completed`，并且指定自定义 Function Call
同时确认图片可用且识别为 `four_color_quadrants` 时，方案 A 的“技术兼容性”才可
记为 PASS。`other` 或 `unclear` 会安全归类为
`model_did_not_observe_expected_pattern`，不能仅凭接口接受请求判定通过。

下列情况均不得开启 Vision：

- `image_data_url_or_request_rejected`：Data URL 或组合请求被拒绝；
- `authentication_rejected`、`rate_limited`、`timeout`、网络或服务端错误：结果为
  INCONCLUSIVE，修复测试条件后再运行；
- 只有长期公共 URL 才能工作；
- 无法确认 `store=false`；
- 事件流未完成，或没有指定的 Function Call。

若方案 A 失败，只能另立审批评估公司受控、不可枚举、最短 TTL、单对象签名 URL
并在处理后删除的方案 B；本 Spike 不实现该方案。完整 B7A 还需在所选路径上补齐
图片大小、格式、像素和安全错误矩阵，AI-B7B 才能开始。
