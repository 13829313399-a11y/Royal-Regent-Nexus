# 布料仓现用表格分析

现有四份表分别承担放产用料跟踪、采购实际入库、分用途发料和收发存月结。布料仓可以继续复用纸箱模块的页面框架，业务记录围绕需求、收料、发料、库存分别建立，再用来源关联串起来。库存和月报应由实际流水生成。

本分析提供业务设计依据。原工作簿保持原状，没有导入系统或生成库存单据。数量、金额和公式结果来自文件保存时的状态，不代表已盘点、已结账或重新计算后的结果。

## 四类记录的关系

放产需求说明某个产品需要什么、需要多少、何时需要；采购部门负责下达采购；仓库据采购和送货资料记录本次实收，再按领用申请记录本次实发。实际收发形成库存流水，库存流水生成当前结存和月报，收料结果反馈到放产到料进度。

一个需求行可以关联多个采购明细，一条采购明细可以分多次到货，一次到货可以拆成多个缸号、卷支和仓位，一次发料也可能服务多个放产任务。需求归属与实物批次需要分别保存，不能把货号或物料编号当作唯一业务行标识。

### 放产用料跟踪

“总表”A1:AB1包括客名、负责部门、合同、货号、物料编号、PO数、计价单位与数量、仓存、应购数、订单数、采购入库、齐料、欠数、交期、放产编号与日期，以及裁床、辅料跟进备注。

当前公式示例在L2:P2：应购数为计价数量减仓存，订单数向上取整，齐料比较采购入库与应购数，采购欠数为入库减应购数，负数表示欠料。这是现表的计算方式，不应直接升级为全物料的统一规则。尤其要确认“仓存”是当时分配给该需求的数量还是全仓结存，已经领用的料是否仍参与齐料判断，不同单位是否都需要取整。

建议在库存管理的待发料或用料跟进中承接需求，展示需求量、分配量、已到量、实发量和待发量。采购来源仍放收料入库，不增加由仓库下采购单的职责。到货齐料与领用完成分别表达。

### 采购实际入库

“总表”A1:Y1已区分供应商、入库日期、送货单日期、送货单号、采购订单号、合同、放产编号、货号、物料编号与规格、订货量、入库数量、单位、人民币单价与金额、汇率、港币金额、明细备注和月结月份。

同一采购来源确实分批到货。例如CGDD007682、JP3342、物料01-03-06-00031在第13、71、150行，订货量均为11,024码，三次入库分别为1,405、9,562、57码，合计11,024码。订货量不能随每次到货重复累加。

“缸号明细”A1:K8按产品与物料区分1号缸、2号缸等，再逐支记序号与数量。同一缸内第1、2支数量可分别为176、170。它支持设计缸号和逐支数量，不支持“每卷固定长度”的假设；该页未明确标注数量单位，应关联对应入库资料核实。

建议收料单分别保留采购来源、送货单、单据数量、本次实收、差异原因、质量结果、批次缸号、卷支与仓位分配。采购数量、计价数量、库存数量和包装件数各有字段。货币、汇率、价格状态也独立保存。

这份“采购入库表”属于实际入库历史证据。现有系统接收“未回物料”“已回料”的采购来源导入器，并不支持将它直接作为实际收料或期初库存导入，需另定义迁移规则和核对流程。

### 发料与去向

发料表以收料日期或生产批号、位置、货号、编号、物料名称、单位、原库存、发货数、备注为常见明细，同时在每一块标题处记领用部门和日期。

“裁床”I3是该块日期2025年11月26日，A6是明细上的2025年10月20日；M3:M10又注明“做12月份月结”。不能把行内所有日期统一解释为发料日期。系统需区分业务发生日期、来源到货日期和记账期间。跨期记账权限仍需确认。

“裁床”E5写有三个放产单号，C6包含多个产品，E8又有合并发料说明。今后发料需要一个实际发出记录配多个需求分配明细，不能为每个放产任务重复扣同一份实物。

建议发料至少区分生产领用、样板领用、加工发出和跨仓交接。裁床、车间、加工方、厂区分别作为明确去向。“线筒”A1:E4另有发出数、退回数和欠数，属于可回收物往来，不应与普通耗用混算。外加工前后的物料和单位关系，需要在对应任务上保留。

打印页从实际单据生成；历史打印页只保留为附件或核查证据。跨厂交接沿用双方权限边界，发出与接收分别记录。

### 库存与月结

“物料”A3:CQ3除了物料与订单信息，还有旧新编码、供应商、入库日期、位置、备注、暂停、无单、有单、处理、减值等字段。Z:AG是上月结存、本月结存、本月收发与金额，AH:CQ以每天“入”“出”两列展开。

第4行公式将每日入、出分别汇总，再计算“上月结存＋本月入库－本月出库”。这适合作为系统收发存报表的基础关系。退料、移库、更正、盘点差异需要明确记入哪类流水和期间，不能另行覆盖结存。

建议日常界面保留物料、批次缸号、仓位、账面数、质量状态、订单分配和收发明细，月报自动生成与现表相近的收发存结果。暂停、质量冻结、无订单归属、待处理、财务减值分别定义，不能合并为一个“状态”。减值不等于物料已从仓库发走。

## 对现有框架的补充建议

保留当前布料仓七个主栏目和纸箱式页面习惯，在业务接入时补充以下能力。下表均为设计建议，当前单据预览并未实现这些业务。

| 现有位置 | 补充内容 |
| --- | --- |
| 工作看板 | 待收、待发、待匹配来源、收发差异、暂停和待处理提醒，数据取同一组业务记录 |
| 收料入库 | 来源与送货资料分开，本次实收、分批累计、缸号卷支、质量与多仓位分配；保留单据数与实收数 |
| 库存管理 | 待发料承接放产需求；发料单记录去向、业务日期和实际批次；多任务分配；车间退料、加工往来、移库和盘点分别留痕 |
| 异常处理 | 缺编码、缺价、无订单、待匹配、数量差异、暂停物料和补录来源；区分待处理状态与库存事实 |
| 月结对账 | 从流水生成收发存；独立保留记账期间、价格口径、供应商对账和减值处理资料 |
| 基础资料 | 布料、辅料、线分类；物料别名与旧编码；计量与计价单位；批次缸号、卷支、仓位和往来单位 |
| 操作日志 | 来源文件与原单原行、确认操作、变更前后值、更正原因、关联补录；补关联不再入一次库 |

扫码需要能区分实际到货批次。已有逐缸、逐支数量记录，建议标签设计支持卷支追踪，同时允许适合辅料的包或箱。采购单码可用于调出来源，具体贴到订单、送货批次还是单卷，需要现场确认，不能把整单采购量直接当作一次扫描的实收量。

## 接入顺序

1. 确认作为当前依据的库存工作表和截止日，明确仓存、齐料、欠数、实收及记账期间的含义，确定物料编码映射与单位规则。
2. 完成物料、批次仓位、来源关联和收发流水的数据约定。保留原文件、页、行及原始单位作为追溯证据。
3. 先实现一个来源分批收料到多个缸号、卷支和仓位，再实现部分领料、余料保留及车间退料。
4. 让库存和月报从同一份流水生成，核对现场样例。涉及多订单分配、加工转换、跨仓差异的场景分别验证。
5. 盘点确认启用日的期初库存。历史收发仅作查询或明确边界的迁移，不能与期初库存重复计入。完成一个月末及下月结转核验后，再停用相应重复台账。

这一顺序仍是先布料仓、再半成品仓。半成品多轮加工和返修规则继续独立设计，不由这四张布料表推定。

## 核实范围

已逐表检查字段与公式保存值，按定义统计主要明细，对照重复收货记录，独立读取关键单元格并核对分批入库合计、结存差异和透视差异。四个原文件读取前后SHA256一致。

未执行Excel或WPS重新计算，未将扫描到的公式错误修复到原文件，也未据此确认最终库存金额。下一步需要业务人员确认的重点是有效库存版本、启用截止日、需求占用和齐料口径、单位换算与价格来源。
