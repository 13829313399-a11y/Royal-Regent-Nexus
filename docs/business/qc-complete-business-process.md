### 2.3 权威来源顺序

系统应按以下原则确定业务事实：

1. 系统生成的唯一编号、经人工确认的结构化记录和审计版本，是系统内关联与统计的权威来源；
2. 已签发的外部正式报告，是外部报告号、签发状态、签名及外部验货结论的权威原件；
3. 外部报告中的关键字段进入系统统计前，应由解析结果加人工确认形成结构化记录；
4. 原文件名、目录名、旧表备注、OCR 结果和系统猜测只能作为候选提示；
5. 文件夹年份与报告内日期冲突时，采用报告内确认日期，并记录冲突和原始路径；
6. 任何无法从权威字段得到的值必须留空或标记待补录，不得从问题描述、备注或文件名推断。

## 3. 需求范围与分期

### 3.1 P0：现有实现基线

P0 指 V2.0 已进入仓库、但仍需迁移和启动验证的能力：

- 每周生产排期导入、候选匹配、差异预览和逐项确认；
- 有 PO 的临时验货单录入；
- 验货主单结果录入、问题草稿和问题闭环；
- 五类手动 XLSX 报表；
- PDF/JPG/JPEG 显式分组、预览、批量改名和 ZIP 下载；
- 厂区隔离、12 个 QC 权限、审计、并发版本和幂等控制。

P0 已进入仓库不等于已经部署。使用前仍须执行迁移、重启服务、配置权限并完成真实样本验收。

### 3.2 P1：验货业务闭环补齐（本轮核心已实现）

P1 核心主链已进入仓库：

- 验货任务、验货执行事件、PO/货号明细、缺陷、处置和报告包分层；
- 同一任务多次验货和复验历史；
- 一次验货关联多个 PO、货号、数量和报告文件；
- 日报、问题明细、退货汇总、合格率、全年统计、产品质量台账和报告文件索引；
- 退货、返工、AOD、让步接收等结构化处置字段；
- 系统生成的单单验货报告自动形成报告包和文件索引；
- 报表快照保存期间、指标版本、来源修订摘要和文件摘要。

以下仍是后续需求，不能描述为已实现：外部 PDF/图片/DOC/DOCX/XLS/XLSX 原件上传与历史批量迁移、OCR/版面解析、签名页检索、字段级来源单元格血缘、跨报表自动对账以及报告终稿审批流。

### 3.3 P2：相邻质量管理能力

P2 由真实资料识别，但是否纳入“QC 验货运营中心”仍需业务确认：

- 啤机、喷油、装配等部门不合格率分析；
- 产品每日测试记录；
- 各客签办/样板记录；
- QC 培训计划、签到、考核和培训记录；
- 验厂文件准备清单、有效期、责任人和缺口追踪；
- 大体量历史资料结构化迁移。

## 5. 核心业务对象与关系

### 5.1 P0 已有对象

迁移 <code>20260812_0067</code> 定义客户配置、排期导入批次和行、验货主单、验货问题、排期决定、报表快照、改名批次/报告组/源文件、审计事件和幂等记录。迁移 <code>20260824_0082</code> 新增验货事件、PO/货号明细、缺陷、测试、处置、报告包、报告文件，并为报表快照增加期间、指标版本、主单和事件关联。

所有对象必须记录厂区。验货单号、合同号、PO、货号、报告号等标识一律按文本保存，保留前导零、空格、井号、连字符和业务允许的斜杠。

### 5.2 V3.1 已实现对象与后续对象

真实资料要求将“一张主单承载全部结果”扩展为以下关系：

| 对象 | 作用 | 关键关系 |
| --- | --- | --- |
| 验货主单 <code>InspectionOrder</code> | 一项待安排的验货业务，来源于排期或临时单 | 1:N 验货执行事件 |
| 验货执行事件 <code>InspectionEvent</code> | 一次实际执行或复验，保存第几次验货和当次结果 | 1:N 验货明细、缺陷、测试、处置 |
| 验货明细 <code>InspectionLine</code> | 当次报告覆盖的 PO、货号、批次和数量行 | N:M 关联报告包 |
| 缺陷 <code>Defect</code> | 类别、严重度、数量、描述、图片和责任工序 | 归属执行事件或明细 |
| 测试结果 <code>TestResult</code> | 标准、项目、规格、实测值、单位和结论 | 归属执行事件或明细 |
| 处置 <code>Disposition</code> | 退货、返工、AOD、让步接收、关闭验证 | 归属执行事件和问题 |
| 报告包 <code>ReportPackage</code> | 一次验货事件的报告与附件集合 | 归属一个执行事件；通过事件覆盖多条明细 |
| 报告文件 <code>ReportDocument</code> | 原始文件、版本、格式、摘要、签发状态和存储位置 | 归属报告包 |
| 报表快照 <code>GeneratedReportSnapshot</code> | 系统生成报表的范围、口径、修订和文件摘要 | 引用来源快照 |
| 数据血缘 <code>DataLineage</code> | 来源文件、Sheet、行/单元格、解析配置和人工确认 | 后续对象；本轮仅实现来源修订摘要 |

复验必须新建执行事件，不得覆盖首次验货。任务当前状态可显示最新有效事件，但历史报表必须能分别统计首次结果、每次结果和最终结果。

### 5.3 状态必须分层

以下概念不得共用一个状态字段：

| 状态域 | 建议值 |
| --- | --- |
| P0 主单结果 | <code>PENDING / PASS / FAIL / REJECTED / CONDITIONAL_PASS / CANCELLED</code> |
| 外部文档状态 | <code>DRAFT / FINAL / REVISED</code> |
| 处置类型 | <code>RETURN / REWORK / AOD / CONCESSION_ACCEPTED / ON_HOLD / NO_ACTION</code> |
| 问题状态 | <code>DRAFT / OPEN / IN_PROGRESS / RESOLVED / CLOSED / CANCELLED</code> |
| 归档状态 | <code>UPLOADED / INDEXED / VERIFIED / QUARANTINED / ARCHIVED</code> |

FAIL 或 REJECTED 不自动等于退货；CONDITIONAL_PASS 不自动等于 AOD；文件名出现 PASS、REJ 或 draft 也不直接更新系统结果。

## 6. 端到端业务流程

### 6.1 排期导入

1. 业务部提供本周或更新版生产排期；
2. QC 选择厂区、业务周和客户解析配置后上传；
3. 系统读取逻辑数据区域，生成来源行和字段预览；
4. 系统按合同号加客户货号查找候选；
5. 零候选可新建，一候选可比较，多候选必须人工选择或跳过；
6. QC 对每行执行 CREATE、UPDATE、KEEP 或 SKIP；
7. 系统保存导入批次、来源 Sheet/行、决定、版本和审计；
8. 已确认主单进入本周验货排期。

P0 支持 XLS、XLSX 和 XLSM，单文件最大 35 MB，API 入口和导入服务同时校验。真实 BUZZBEE/Disney 工作簿存在被格式撑大到接近 Excel 最大行列数的情况，解析器必须限定候选 Sheet、关键列最后有效业务行和逻辑数据区，不得遍历整个 UsedRange 或盲信 max_row。一个文件还可能同时包含本周、下周和备份 Sheet；导入必须用所选业务周校验 Sheet 内实际日期，不能整本吞入。

### 6.2 临时订单

排期外临时验货单必须填写 PO；无 PO 时服务端拒绝保存。至少录入厂区、周次、客户、合同号、客户货号、PO、产品、数量、出口国/市场、走货期、计划验货日、机构、跟客和备注。来源明确标记为 <code>MANUAL</code>，不得伪装成排期导入。

### 6.3 验货执行

1. QC 在任务下创建或开始一次验货执行事件；
2. 选择验货类型：客验、第三方终检、行验、自检、复验、抽板等；
3. 录入实际日期、检验员、机构、地点、抽样标准、AQL 和样本数；
4. 关联当次涉及的全部 PO、货号、批次和数量；
5. 录入缺陷、测试、图片和当次结论；
6. 上传外部报告或证据包，区分草稿、终稿和修订版；
7. 系统生成问题草稿或进入处置流程；
8. 需要复验时创建下一次事件，保留原事件不变。

V3.1 已将主单详情升级为验货报告工作台：支持创建首验或复验、维护多 PO/货号、缺陷、测试、处置和文档状态，并可“保存并生成验货报告”。主单同步显示最新事件结果，历史事件不覆盖。

### 6.4 问题与处置闭环

P0 的初始 PENDING 不触发问题。提交 FAIL、REJECTED、CONDITIONAL_PASS、CANCELLED，或手动勾选“有问题”，均生成去重的问题草稿；PASS 加手动问题标记也必须生成问题。

问题描述、退货原因、整改措施和处理结果只在问题工作区维护。一张任务允许多条问题。

P1 每条问题还需记录：

- 缺陷分类、严重度、发现位置和数量；
- 第一、第二责任人及责任部门；
- 根因、临时措施、长期措施、期限；
- 退货标记与数量、返工标记与数量；
- AOD/让步接收的批准人、日期和附件；
- 复验要求、验证人、验证日期和关闭结论。

### 6.5 报表、归档和对账

1. 系统按选择的期间和口径冻结来源快照；
2. 生成报表并保存版本、摘要、生成者和筛选条件；
3. 正式报表不得覆盖，修订时产生新版本；
4. 日明细、周明细、客户汇总、厂区汇总和集团汇总逐级对账；
5. 外部正式报告保持原文件不变，通过报告包索引关联执行事件；
6. 批量改名只生成新的 ZIP，不修改原始目录。

### 7.2 排期解析必须兼容的真实差异

真实排期不是单一模板，至少存在客户周排期、BUZZBEE 订单/货号 Sheet、Disney 生产计划等结构。解析需求如下：

- 为不同客户或模板维护可版本化的导入 Profile，不把所有工作簿强制套入一个表头；
- 兼容主合同号、S/C、O/C、Contract No.、华兴 PO 等合同别名，以及客户 PO、内部 PO、SO、生产单号等不同编号域；
- 识别日期型、文本日期和 Excel 序列日期；
- 将 PO、合同号、货号、UPC/EAN 等始终按文本读取；
- 兼容公式、千分位数量、合并表头和多个业务 Sheet，同时保留原始值、公式值和单元格类型；不能因为来源单元格误套日期格式而把数量解释成日期；
- 装箱值可能为 1/24、6P/12、0/6 等文本，数量或箱数也可能出现 3600/2504 等组合值；必须保留原值并拆为子明细，无法无损拆分时阻止确认；
- 保存来源文件摘要、Sheet、行号、单元格、原值、解析值、Profile 版本和人工确认人；
- 将“出口国”和“客户/市场”拆成独立字段。真实资料中的“出口国（客户）”可能实际填写 WMU、WMC 等零售商/市场，不能直接用于文件命名；
- 批量改名所需 <code>export_country_code</code> 必须由受控字段提供，并校验为 2 或 3 位英文代码；
- 只扫描确认的逻辑数据区域，跳过空白、历史说明、图片对象和被格式撑大的无效区域。

### 7.3 外部报告必须抽取但需人工确认的字段

外部报告共同出现的字段包括：

- 报告号、外部验货号、平台 ID、报告版本和 DRAFT/FINAL/REVISED；
- 客户、供应商、工厂、市场、出口国、机构；
- PO、Release、货号、批次、Date code、订单量、验货量、箱数和抽样量；
- 抽样标准、检验水平、AQL、缺陷严重度、实际数和允许数；
- 验货结论、退货/返工/AOD 等处置；
- 包装、外箱尺寸重量、唛头、UPC/EAN；
- 实验室报告号、测试项目、实测结果和附件；
- 检验员、工厂代表、批准人、签名、盖章和日期；
- 产品、包装、缺陷和测试照片。

自动解析只能生成候选值。正式入库前须显示来源页、来源区域和置信度，低置信度或冲突字段必须人工确认。

## 9. 报表字段与原始数据追溯

| 输出字段/指标 | 权威来源 | 禁止做法 |
| --- | --- | --- |
| 日期 | 验货执行事件的实际日期 | 从文件夹年份或文件名推断 |
| 客户、厂区 | 经确认的任务/客户主数据 | 只取目录名 |
| 合同、PO、货号、数量 | 验货明细行 | 把多个值拼成一个无法拆分的文本 |
| 出口国 | 受控出口国代码 | 将 WMU/WMC 等客户/市场直接当国家代码 |
| 验货结果 | 当次执行事件结论 | 从文件名 PASS/REJ 或问题文本猜测 |
| 文档状态 | 报告文件版本 | 与业务验货结果共用一个字段 |
| 报告状态/报告号 | 外部正式报告或内部正式快照 | 用是否上传文件代替报告状态 |
| 验货问题 | 已提交的问题记录 | 从备注拼接或反向改写问题 |
| 第一/第二责任人 | 问题责任字段 | 从问题描述识别人名 |
| 退货次数/数量 | 明确的 RETURN 处置 | 将 FAIL、REJECTED 一律计为退货 |
| 返工 | 明确的 REWORK 处置 | 从“未退货”推断返工 |
| AOD/让步接收 | 有批准人和附件的结构化处置 | 将 CONDITIONAL_PASS 自动计为 AOD |

每个生成报表必须保存：

## 10. 指标和时间口径

真实样表中出现年度累计工作簿、月度每日表和单周快照，P0 当前则按选定周次生成新 XLSX。V3 要求每类报表显式声明时间模式：

- 周快照；
- 月累计；
- 年累计；
- 任意日期范围。

不得仅凭文件名中的“每周”判断工作簿是单周还是全年累计。

### 10.1 待签字的统一指标字典

| 指标 | V3 建议定义 | 上线前需确认 |
| --- | --- | --- |
| 验货次数 | 默认按已执行的验货事件计数，不按文件数、报告包数或 PO 明细数计 | 是否需要同时展示任务数和明细数 |
| 合格次数 | 默认只含 PASS | CONDITIONAL_PASS 是否另列及是否计入合格 |
| 统计分母 | 默认排除 PENDING 和 CANCELLED | ON_HOLD、缺报告事件如何处理 |
| 退货次数 | 只统计有 RETURN 处置的事件 | 一次事件多条退货明细如何计数 |
| 返工次数 | 只统计有 REWORK 处置的事件 | 工厂自行返工是否独立列 |
| AOD/让步 | 只统计有正式批准记录的处置 | AOD 与 concession 是否合并 |
| 首次合格率 | 每个任务第一次已完成事件中的 PASS 数/有效首次事件数 | 是否按客户、PO 或货号拆分 |
| 最终合格率 | 每个任务最新有效完成事件中的 PASS 数/有效任务数 | 跨周复验的期间归属 |
| 不合格品率 | 不合格品数/抽检总数 | 是否另算缺陷数/检验机会数 |
| 周次 | 建议 ISO 周，界面同时显示起止日期和 Asia/Shanghai 时区 | 是否只按周一至周五工作周 |
| 零分母 | 显示空白或“不适用”，导出不产生 #DIV/0! | 最终展示形式 |

以上建议未经业务签字前，P1 新报表不得作为正式经营数据。P0 报表保持现有兼容逻辑，但应在报表元数据中标明口径版本，不能将临时逻辑包装成已确认标准。

真实周聚合样表的客户行曾使用“验货次数减退货次数后除以验货次数”计算合格率，但合计行又错误显示退货合计为 0 和总体 100%。新系统必须从明细重新聚合总计，不能复制旧模板中的合计公式错误。PASS 但有问题仍可计为 PASS，因此合格率与“无问题率”必须分列。

### 10.2 复验和跨期

- 首次验货和复验分别记录为不同执行事件；
- 事件明细按实际验货日期进入日/周明细；
- 首次合格率使用首次有效事件；
- 最终合格率使用统计截止时最新有效事件；
- 跨周复验同时保留原任务周和实际复验周，报表必须显示采用哪一维；
- 取消后重开、报告修订和结果更正必须保留审计，不覆盖旧快照。

## 11. 验货报告与证据包治理

### 11.1 报告包结构

一个报告包至少包含：

- 系统唯一报告包号；
- 厂区、客户、报告类型、机构和外部报告号；
- 一个或多个验货执行事件；
- 一个或多个 PO、货号、批次和数量明细；
- 零个或多个 PDF、JPG、JPEG、PNG、DOC、DOCX、XLS、XLSX 文件；
- 文档状态、签发日期、签名/盖章和版本关系；
- 每个文件的原始名称、原始相对路径、MIME、大小、SHA-256、存储键和上传者；
- 文件间关系，例如主报告、草稿、终稿、修订、DDEI、实验室报告、照片或签字页。

### 11.2 支持的真实组合

完整归档需求必须支持：

- 只有 PDF；
- 只有 JPG/PNG 的正式报告；
- PDF 加图片；
- 多份 PDF 加图片或实验室报告；
- PDF 已内嵌全部照片；
- 历史 DOC/DOCX 报告；
- XLS/XLSX 附件或原始台账。

P0 的“一份 PDF 加至少一张 JPG/JPEG”只适用于当前批量改名功能，不代表完整归档规则。PNG、DOC、DOCX、XLS、XLSX 在 P1 可归档和检索，但默认不参与 P0 改名。

扩展名为 <code>.lnk</code>、异常 <code>.1</code>、MIME 与扩展名不一致、损坏或携带恶意内容的文件应拒绝或隔离，不得进入正式包。

### 11.3 原件、版本和存储

- 原始文件不可变；重命名、转换和缩略图均生成派生产物；
- 同一报告的 DRAFT、FINAL、REVISED 分别保存并建立版本链；
- 重复文件通过内容摘要识别，但不得只因同名而合并；
- 8.06 GiB 历史资料应存入文件/对象存储，数据库保存元数据和关联，不把大文件作为普通数据库 BLOB；
- 历史迁移使用离线、可断点、可重跑的批次，不受在线 250 MB 改名接口约束；
- 每批迁移保存扫描目录、文件数、总量、成功/重复/隔离/失败数和校验摘要；
- 原路径至少在迁移审计中保留，便于回查；
- 保留年限、备份、删除审批和法务冻结规则需由 QC/体系/IT 共同确认。

## 12. PDF/JPG/JPEG 批量改名

### 12.1 P0 已确认命名规则

| 报告类型 | 基础文件名 |
| --- | --- |
| 非彩星 | <code>出口国_客户货号_PO_实际验货日期</code> |
| 彩星 | <code>报告号_客户货号_PO_数量_实际验货日期</code> |

规则如下：

- 分隔符为半角下划线；
- 日期采用实际验货日期，格式 YYYYMMDD；
- 货号采用客户货号；
- 非彩星出口国采用受控的 2 或 3 位英文国家代码并转大写；
- PO 保留业务文本和前导零，只规范化文件系统非法字符；
- 彩星数量只包含数字，不带单位；
- PDF 输出扩展名为 .pdf；
- .jpg 和 .jpeg 输入均校验为 JPEG，输出为 .jpg；
- 单图不加序号，多图按显式顺序追加 _01、_02；
- 非法字符、控制字符和空白转为下划线并折叠连续下划线；
- Windows 保留名、超长名称、格式伪造、损坏文件和目标重名均阻断该组。

示例：

    US_ITEM001_000123_20260812.pdf
    US_ITEM001_000123_20260812.jpg

    RPT009_ITEM001_000123_6000_20260812.pdf
    RPT009_ITEM001_000123_6000_20260812_01.jpg
    RPT009_ITEM001_000123_6000_20260812_02.jpg

### 12.2 P0 显式分组和限制

系统不从文件名猜测配对。当前每组要求：

- 恰好一个有效 PDF；
- 一张或多张有效 JPG/JPEG；
- 彩星标识和同一组命名字段；
- 多图具有不重复且大于等于 1 的显式顺序。

任一必需文件、字段或顺序缺失时，整组不输出。当前限制为：

| 限制 | 数值 |
| --- | ---: |
| 单批报告组 | 39 |
| 每组文件 | 25 |
| 单文件 | 25 MB |
| 批次总量 | 250 MB |

网关请求体上限不得高于 250 MB。报告组是最小原子单位；组内全成功或全不变。一个组失败不阻断其他无关组，发生大小写不敏感目标重名时所有冲突组均停止。执行前重新校验预览指纹，只生成新的 ZIP，绝不原地改名或覆盖源文件。

### 12.3 P1 多 PO/多货号场景

真实报告已存在一个包包含多个 PO、多个货号和多组数量的情况。系统必须先结构化关联多条明细，不能把多个值塞入单一 PO 或货号字段。

用户已确认的单 PO 命名规则继续有效；多 PO/多货号的正式命名顺序、连接符、长度和冲突处理尚未确认。在业务签字前：

- 不自动拼接旧文件名；
- 不截断后冒充完整业务名；
- 可在归档中使用系统报告包号作为稳定存储键；
- 需要改名时将该组标为待人工处理，并保留原因。

## 13. 报表生成、版本和对账

### 13.1 生成原则

- 生成前冻结数据范围、时区、口径和模板版本；
- 草稿可重生成，正式版本只能新增修订；
- 相同来源快照、口径和模板重复生成时内容摘要应一致；
- 来源数据变化后必须生成新修订，不覆盖旧正式文件；
- Excel 公式不得产生 #DIV/0!，空数据报表仍保留表头、口径说明和生成信息；
- 标识字段输出为文本，数量和比例使用真正的数值格式；
- 客户 Sheet 名需清洗非法字符、处理大小写不敏感重名并保留原客户名映射。

### 13.2 对账关系

| 上游 | 下游 | 对账要求 |
| --- | --- | --- |
| 每日验货明细 | 每周验货明细 | 同口径事件数、结果数和问题数一致 |
| 每周客户明细 | 华兴每周聚合 | 客户维度可逐项下钻 |
| 厂区聚合 | 集团汇总 | 每个厂区小计与本厂正式快照一致 |
| 问题明细 | 退货/返工/AOD 汇总 | 仅按结构化处置汇总 |
| 执行事件 | 报告文件索引 | 无报告、草稿、终稿、修订和多文件包均可解释 |
| 首次事件 | 首次合格率 | 每个任务最多贡献一次首次结果 |
| 最新有效事件 | 最终合格率 | 可回查被替代的历史事件 |

对账失败时，报表可生成草稿并列出差异，但不得标为正式版本。

## 14. 数据质量、异常与安全

| 场景 | 处理要求 |
| --- | --- |
| 排期零候选 | 允许人工确认新建 |
| 排期一候选 | 比较差异后人工确认更新或保留 |
| 排期多候选 | 必须人工选择或跳过，不自动覆盖 |
| 临时订单无 PO | 阻止保存 |
| 同一任务复验 | 新建执行事件，不覆盖旧结果 |
| 报告多 PO/货号 | 关联多条明细，不拼入单值字段 |
| 外部报告字段冲突 | 展示来源并人工确认，记录前后值 |
| 日期或客户仅存在于文件名 | 只作候选提示，不直接入正式统计 |
| 并发版本变化 | 拒绝旧版本写入，要求刷新 |
| 相同请求重复 | 返回幂等结果；同请求号不同内容则冲突 |
| 报表生成失败 | 保留业务数据和既有报表，记录失败范围 |
| 零分母 | 输出空白或不适用，不产生公式错误 |
| 改名组错误 | 整组不输出，其他有效组继续 |
| 目标重名 | 冲突组全部停止，不覆盖 |
| 损坏、伪造或恶意文件 | 拒绝或隔离，记录摘要和原因 |
| 跨厂读取/生成 | 后端按权限、部门和显式厂区拒绝越权 |

前端隐藏按钮不构成安全控制。后端必须再次校验权限、厂区、版本、状态、必填字段、文件类型、文件大小和业务范围。外部报告可能含供应商、客户、签名和产品信息，下载、预览、导出和审计均应按最小权限执行。

## 16. 历史资料迁移要求

历史迁移建议分两层：

1. 文件级索引：先为全部文件建立相对路径、格式、大小、摘要、业务目录、候选客户/日期和迁移状态；
2. 结构化提取：按报告族和优先年份逐批抽取报告号、事件、明细、结果、缺陷和签署信息，并由人工确认。

迁移批次必须：

- 只读扫描源目录，不移动或改写原件；
- 支持断点续跑和同批幂等；
- 以 SHA-256 识别内容重复，以原路径保留业务上下文；
- 对 493 组同名文件分别建索引，不因同名合并；
- 记录解析 Profile/模型版本、置信度和人工确认；
- 将无法识别、损坏、快捷方式和异常扩展名列入隔离清单；
- 根目录的历史“每周验货问题统计表”约 299 MB，必须走离线历史迁移与附件抽取，不得使用 35 MB 排期导入接口；
- 先用代表性客户和年份试迁移，再扩大范围；
- 迁移前确定存储容量、备份、保留年限和回滚方案。

## 18. 验收标准

### 18.1 业务与数据

- 每个验货任务有厂区内唯一编号；
- 合同号加客户货号只作候选匹配，多候选绝不静默覆盖；
- 临时订单无 PO 不能保存；
- 同一任务允许多次验货，复验不覆盖首次结果；
- 一个执行事件和报告包可关联多个 PO、货号和数量行；
- PASS 加手动问题标记可生成问题，初始 PENDING 不生成问题；
- 退货、返工、AOD 和让步接收均由独立字段记录，不由结果或文本推断；
- 系统新录入字段可追溯到权威记录、操作人和修订；导入字段到来源文件/行的完整血缘仍待补齐；
- 标识字段保留前导零，出口国与客户/市场分开；
- 零分母无 #DIV/0!。

### 18.2 报表

- P0 五类报表继续按厂区和权限生成 XLSX；
- V3.1 的 8 类新增报表可从规范化事件数据重复生成；跨报表自动对账仍待补齐；
- 首次和最终结果均被保留；分别重算两种合格率仍需业务确认口径后增加；
- 周、月、年和任意日期范围明确标注；
- 正式报表不可覆盖，修订具有版本、摘要和来源快照；
- 空数据仍输出完整表头、口径和生成信息；
- 集团汇总只能由独立跨厂权限生成。

### 18.3 文件与归档

- 外部正式报告原件不变；
- PDF-only、image-only、混合、多 PDF 和历史 DOC/DOCX 均可在完整归档中表达；
- P0 改名继续严格执行 PDF 加 JPG/JPEG 的显式组规则；
- 文件名、目录名和 OCR 不能替代权威业务字段；
- 同名文件不会被错误合并；
- 每个文件保留摘要、原路径、版本、业务关联和审计；
- 损坏、伪造和异常文件进入拒绝或隔离清单；
- 历史迁移可重跑、可核对且不改写源目录。

### 18.4 真实样本测试

每类报表和导入 Profile 至少准备以下测试夹具：

- 正常有数据；
- 空数据；
- 缺字段；
- PASS 但有问题；
- FAIL 后复验 PASS；
- 明确退货、返工、AOD 和让步接收；
- 多 PO、多货号、多数量；
- PDF-only、JPG/PNG-only、多 PDF 和 DOC/DOCX；
- 同名不同内容、同内容不同路径；
- 跨周、跨月和跨年；
- 厂区越权和集团授权。

## 19. 待业务确认事项

以下问题会改变数据模型、指标或输出，开发前必须由 QC 负责人签字：

1. 五类现有报表需要单周快照、年度累计工作簿，还是两者都需要；
2. 验货次数的最小计数单位是任务、执行事件还是 PO/货号明细；
3. CONDITIONAL_PASS 是否计入合格，PENDING/CANCELLED/ON_HOLD 如何进入分母；
4. FAIL、REJECTED、退货、返工、AOD 和让步接收的正式业务关系；
5. 跨周复验在首次、当周和最终合格率中的归属；
6. 多 PO、多货号报告的正式文件命名规则；
7. 只有 PDF、只有 JPG/PNG、多 PDF 或历史 DOC/DOCX 是否需要参与改名，还是只归档；
8. 产品质量汇总、部门不合格率、每日测试、样板、培训和验厂是否属于当前模块；
9. 历史资料迁移多少年，哪些只建文件索引，哪些解析为结构化数据；
10. 历史文件的存储位置、保留年限、备份、删除审批和法务冻结规则；
11. 客户排期采用各自版本化 Profile，还是维护少量统一模板；
12. PDF、CSV、定时生成、共享目录投递和消息通知的优先级。

## 20. 本轮结论
