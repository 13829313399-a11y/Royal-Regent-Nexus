# 华兴 ZURU 统一排期

业务部 → 华兴客户订单中心 → PO与排期导入 → ZURU。
统一排期归属华兴，华康A的统一订单接口拒绝此客户。既有台账不自动改厂区。

支持原生文字 PDF 正单及已经转换核对的 XLSX PO，目标为河源统一
ITEM表、接单表、正单评审表。原周排期仅作字段和产品映射参考，
MA、库存及生产跟进信息不自动作为新订单导入。

## 字段

| 来源 | 统一排期 |
| --- | --- |
| ZURU Inc PO# | 合同号 |
| PO#＋原单 Line | SO#/Reference，不自行续编 |
| 本行 Customer PO | P/O#，保留前导零，不沿用上一行 |
| 完整 SKU-SPEC | 产品编号，保留包装后缀、版本和标点 |
| Name、QTY PCS、Outer、Delivery Date | 英文品名、数量、装箱数、客要求走货期 |
| Price USD、Total USD | 摘要 P/Q 美元单价和金额，保留原单精度 |

新行 N/O 港币字段不继承历史价格或换汇公式；历史价格和手工内容保持。
缺失中文名称可用完整同货号唯一历史值；装箱、标准和包装还需匹配终端客户。
不存在可靠来源的生产单号、验货日期等字段留空。手工更正数量或美元单价后，
金额按更正值重算。

每张表独立在取消区域上方追加，摘要公式直接关联实际 ITEM 行。
生成下载副本，保留原件和历史行。纸箱、拆单来源缺失时安全追加，已有列不重复；
不为 ZURU 增加出货货号。拆单来源是人工记录，不自动扣减原单数量。

## 校验边界

- 原单必须有可靠 PO、原 Line、完整货号及可核对的数量和金额总计。
- 多页订单按表格列及物理行归属读取，客户 PO 不向下填充；不能确认归属的片段拒绝导入。
- 取消、非订单附件和未支持的混装、卡板结构不能作为普通正单。
- 同 PO 修订以原文修订记录为依据，不以文件名或文件顺序猜测版本。
- 相同 SO 和完整货号的重复显示提醒；数量冲突要求核对原件。
- 沿用现有厂区权限、文件处理限制、指纹、导出审计及台账幂等控制。

## 验收

合成测试覆盖厂区拒绝、精确货号及终端客户隔离、三表字段、美元精度、
重复与数量冲突、人工更正、文件不变和台账幂等。真实文件批量结果保存在仓库外，
私有订单与排期不提交 Git。

自动化通过不代表生产部署、真实浏览器交互或原生 Excel 重算已验收。
实际排期的历史内容和原生 Excel 显示需用用户提供的可读取排期副本继续核对。

提供的266份PDF中，246份通过解析及数量、箱数、美元总计校验，20份明确拒绝：
组合/混装/原行号异常13份，跨页身份或货号尾缀证据不足4份，取消单、修订日期无法
识别、非订单箱唛各1份。排除可证明的旧版、副本及一组版本冲突后，得到220个PO、
765行。这是源文件识别结果，不表示已写入真实排期或台账。
