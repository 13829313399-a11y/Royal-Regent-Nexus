# 布料仓与半成品仓框架复用方案

以现有纸箱模块作为界面和操作模板，先建设布料仓，再建设半成品仓。三个模块保持一致的使用习惯，分别管理各自的物料、数量、库存和业务流程。

两仓已沿用纸箱式顶栏、横向导航和单据操作，接通日常业务保存。布料仓保留原采购追货、实际入库与基础资料，并接通领料申请、直接或关联申请出库、退料、调仓及受限冲销；质检回归 QC 模块，仓库仅保留历史记录；半成品接通实收、加工任务、每轮发出、分批回货、加工在外和包装交接。旧文档数据不作为开发前提，不迁移未经核实的历史数量。外部接口后置，模块自身保存与查询已实现。代码接通不等于现场验收。

新日常收发使用独立追加账本，部署前须显式迁移 `20261009_0150` 并配置收发及冲销权限；本地业务 SQLite 已备份并显式升级，本地后台已加载台账接口，线上部署与现场验收仍待完成。采购原始入库记录保持不变，库存从原实收与新增流水共同计算。原预览表单收起为参考，不保存业务。期初、盘点、供应商退货补回、扫码、计价、月结、半成品产品／往来单位／单位资料维护和外部单据自动关联仍未实施。详见[布料仓当前业务说明](fabric-receiving-plan.md)。

两仓的入库、退料入仓及调入必须选择正式启用仓位，后台同时校验厂区和业务域。布料沿用现有仓位资料，半成品新增独立仓位建档及停用；半成品维护需单独授予 `semi_operations:master`，不自动扩大原岗位权限。旧自由文本库存保留数量，须有更正权限的人员明确核实关联后才能出库；不能自动按文字猜配。停用仓位可出不可入，单个仓位不能直接改换所属仓库。

库存台账已提供逐批及勾选批量出库、调仓、仓位维护入口和核实仓位入口。批量整单成功或整单回滚；调仓保留原入库来源及日期，不增加全仓数量。原单不可覆盖，核实和更正分别留痕。半成品仓位目前支持新增和状态维护，整仓更名与批量导入尚未接入。

## 已确定的范围

- 以用户负责的纸箱模块为主要参考，建设顺序为布料仓、半成品仓。
- 先完成可录入、保存、查询和追溯的日常业务，再推进正式切换所需的期初、盘点、计价和月结。
- 页面布局和通用操作沿用纸箱，布料与半成品的资料、数量、状态和流转规则分别定义。
- 重构已有布料仓和半成品仓的展示框架，沿用原入口与来源数据；纸箱业务及数据库保持原状。
- 布料仓接收采购已经下达的资料，办理收发和库存；采购下单责任仍在采购部门。

## 复用方式

建议把“复制纸箱”落实为三层：页面模板、通用交互、独立业务。先让新布料仓使用从纸箱整理出的模板；半成品仓随后复用同一模板。纸箱现有页面暂时继续使用原实现，避免为新模块建设而同时改动已在使用的业务。

| 层次 | 复用内容 | 实施边界 |
| --- | --- | --- |
| 页面模板 | 顶栏、厂区信息、横向主导航、子页切换、表格卡片、弹窗、详情、提示位置 | 对齐当前纸箱布局、密度和全局设计规范 |
| 通用交互 | 日期筛选、排序分页、批量选择、加载与失败提示、导入预览、分仓填写、追溯入口 | 无业务依赖的组件直接用；依赖纸箱类型或接口的部分先适配 |
| 控制机制 | 权限检查、重复提交保护、版本校验、确认后更正、操作留痕 | 沿用机制和验证方法；布料、半成品使用各自权限与业务记录 |
| 独立业务 | 资料字段、库存识别、单位、状态、收发校验、报表和对账口径 | 每个仓库单独实现，复杂业务保留专用页面 |

纸箱的纸质、纸品类型、装箱数、客户合同规则、固定供应商、箱唛流程和计价算法继续属于纸箱。收料和盘点页面的操作方式可以沿用，其业务判断需要重新对照布料和半成品验证。

“通用”应由两种仓库的实际使用验证。第一步只整理必要的页面组件和业务接入位置，不提前建设可以任意配置审批、库存和公式的通用平台，也不把完整纸箱页面复制成两个持续独立维护的大文件。

## 页面框架

页面顺序沿用纸箱的工作习惯：顶栏展示模块、厂区和账号，下面是横向主导航；工作区依次放置标题、子页、筛选、操作、表格和分页。详情集中展示来源、明细、仓位分配及操作记录。教程沿用阅读和检索方式，内容分别编写。

| 主栏目 | 布料仓框架 | 半成品仓框架 |
| --- | --- | --- |
| 工作看板 | 待收料、待发料、收发差异、待补资料 | 待回货、加工在外、待交包装、返修与差异 |
| 订单管理 | 保持现有七区结构，采购来源放在收料入库 | 保留加工交接任务、外购配件、委外加工视图；接收上游任务 |
| 收料入库 | 订单导入、待收料、送货单扫描（待接入）、入库记录、采购接口（待接入） | 待收货、入库记录、加工回收 |
| 库存管理 | 库存台账、出库记录、调仓记录、退料记录、收发流水、领料申请 | 库存台账、出库记录、调仓记录、退料记录、收发流水、领料申请、加工发出与在外、包装交接 |
| 异常处理 | 数量与物料差异、待补来源、待检或暂停物料 | 交接差异、待补资料、返修与暂停加工 |
| 月结对账 | 收发存月报、供应商对账、月结记录 | 收发存月报、加工交接对账、月结记录 |
| 基础资料 | 物料与旧编码、单位、往来单位、仓库仓位 | 产品款式、加工状态、单位、往来单位、仓库仓位 |
| 操作日志 | 来源、收发、变更、更正记录 | 来源、加工循环、交接、返修、变更记录 |

布料仓保持七个主栏目，半成品仓保持八个。复用相同的排布、组件和操作方式，栏目根据职责呈现。半成品“订单管理”不赋予仓库选择加工厂、议价或审批的职责；这些责任仍待业务确认。

当前接通工作看板的录入、收料记录、库存、出库退料、移库、更正及半成品加工交接。未接通栏目保留准确的导航、字段、空态和业务说明。盘点、对账和扫码可以预留入口，但接通前必须显示明确状态。

依据[布料仓现用表格分析](fabric-workbook-analysis.md)，三类布料单据预览已细化为以下分区：

| 预览 | 当前可核对的内容 |
| --- | --- |
| 收料单 | 采购来源、送货与收货日期、记账月份、物料分类、此前累计与本次实收、可增删的批次缸号卷支和仓位明细、质量差异、价格依据 |
| 发料单 | 领用方和用途、发料与来源到货日期、记账月份、申请与本次实发、实际发出明细、多放产任务用料分配、交接差异 |
| 库存详情 | 物料与库存单位、账面数、质量和暂停及订单归属、批次仓位、用料分配、来源期间、期初或更正及价格依据 |

每类预览均可切换填写和详情，通过分区导航快速定位。重复明细可增删，已有内容在移除前会提示；填写只留在当前组件内，关闭或离开清空。零与空白分别保留，原单位不转换，分配不自动合计，价格不生成金额。这里的选项用于核对页面，尚不构成正式审批、质量放行或库存规则。半成品继续保留原有加工任务与交接预览。

### 收料页面的共同操作顺序

1. 选择来源，或打开被推送的待收记录。
2. 展示上游单据与送货资料。
3. 仓管填写本次实际清点数量，记录差异；质检结果按责任分工录入。
4. 分配批次与仓位，核对明细及合计。
5. 由具备权限的人确认，按本仓业务规则形成库存记录。
6. 在详情查看来源、收货结果、流水和后续更正。

当前日常单据保存后生效；更正需独立权限；仓库不办理质检，待检可出库，已有不合格或暂停记录继续限制出库。QC 联动接口尚未接通。单据数量、实收数量、质量数量和可用数量分别表达，不能复用纸箱的有效收料公式直接计算布料或半成品。

## 两个仓库的独立性质

### 布料仓

布料仓主要管理物料的实际到货、领用和结余，同一种物料可能服务多个订单。

| 业务对象 | 推荐保留的信息 | 需要明确的规则 |
| --- | --- | --- |
| 物料 | 稳定编码、旧编码、名称、规格、颜色、材质、库存单位 | 颜色是否已包含在物料编码中；与现有全局原材料主数据的对应关系 |
| 采购来源 | 来源系统、原单号及行标识、供应商、关联放产单、需求量、交期、原始证据 | 上游稳定标识、版本、重复与变更处理 |
| 收料明细 | 送货量、实收量、批次或缸号、质量状态、分仓、来源关联 | 质检和收货的先后关系、超短收处理 |
| 卷支或包装 | 卷号或包号、实际数量、原单位、标签 | 是否逐卷管理，余卷、拆包及补打标签规则 |
| 库存 | 物料、批次、质量状态、仓位、库存单位及数量 | 质量放行、占用、可用量和跨仓移库规则 |
| 发料与退料 | 领用方、用途、原申请、实际批次仓位、实发或实退量 | 分批领料、车间退料与供应商退货分别处理 |

订单归属建议作为库存分配与来源关联保留，不能仅按订单号认定为不同物料。库存由实际流水形成，采购跟踪表中的“已回料”继续只作历史参考。期初库存需要单独盘点和确认。

单位至少区分库存计量与采购计价；米、码、公斤、卷、件不得直接合计。卷数可以是包装信息，不能默认每卷等长。没有确认的换算依据时保留原单位；重量与长度换算不能套用统一固定比例。金额缺价保持待核，不能用零代替。

### 半成品仓

加工任务明确计划产出产品、加工状态、单位、加工方、工序和要求回期。每次加工发出形成独立交接轮次，扣减仓内可出库数量；分批回货关联该轮，人工明确本次产出量及按原发出单位核销的投入量，二者不直接相减、不自动换算。回货新建待检批次，后续再次加工用新任务及新发出单，不覆盖旧轮次。包装实发与仓库代录的接收回执分别记录，回执须留实际接收人，依据备注选填，不再次扣库存。退料当前支持领用及包装退回，加工原物料直接退回尚待补充。

半成品仓在布料仓框架上增加加工任务、加工状态及反复交接。调研中的主要入仓来源是外发车缝、内部车间或手工加工完成后的回货；裁片仓仍是另一个规划对象。

| 增加的性质 | 推荐设计 |
| --- | --- |
| 产品与加工状态 | 同款车缝完成、充棉完成等状态分别识别；工序状态与质量状态分开 |
| 加工任务 | 保存来源生产单、加工方、目标工序、计划数量与交期；仓库办理相关收发 |
| 每轮加工 | 每次发出、分批回收都有独立记录，关联加工任务和前序交接；允许继续发生下一轮 |
| 在外数量 | 与仓内实物分别展示，避免同时计作仓内可用库存；财务归属另行确定 |
| 返修 | 退回、送修、返修回仓分别关联原记录，保留原交货事实和质量处理 |
| 包装交接 | 仓库实发与包装方实收分别记录并处理差异；包装完成后进入成品流程 |

皮料、充棉、下发车间三类进度分别汇总计划、交付与欠数。加工前后可能出现不同产品、状态、数量或单位，应记录真实投入与产出；欠回量和损耗需要明确配比与口径，不能直接把不同单位相减。

补录来源关联不能重复增加库存。真实退料或返修流转应产生对应业务记录；录错单据的更正另行关联原单。跨月返修不能通过覆盖原月单据使历史消失。

## 通用能力的接入边界

| 能力 | 可以共享的部分 | 按仓库定义的部分 |
| --- | --- | --- |
| 导入 | 上传、预览、问题定位、确认结果、原始证据追溯 | 模板解析、主数据匹配、重复身份、业务校验 |
| 来源接入 | 文件、人工登记、上游接口进入同一待办方式 | 来源对象、稳定行标识、变更版本及业务责任 |
| 收发与分仓 | 数量填写、仓位选择、分配合计校验、详情展示 | 可发条件、质量处理、单位换算、库存识别及记账 |
| 盘点 | 盘点单、账面与实盘对照、差异说明、结果核对 | 盘点维度、调整规则、期间限制 |
| 更正与留痕 | 操作人、业务时间、记录时间、原因、原单关联 | 哪些状态允许更正，如何影响库存、进度与结算 |
| 权限 | 使用现有账号、厂区部门范围与服务端鉴权体系 | 布料和半成品的读写动作、主管职责、质检职责 |
| 通知与待办 | 复用工作中心入口和通知阅读机制 | 收货、订单变更等来源事件、责任人及完成条件 |
| 报表与月结 | 筛选、列表、导出及版本展示 | 数量维度、计价、期间更正、对账对象与确认流程 |

纸箱的供应商门户、反馈记录和对账接口带有纸箱范围。新仓库需要这些能力时，应建立相应业务接入，不能直接把新记录写入纸箱接口。通用账号和通知组件可以沿用，但点击已读不能自动完成收货或差异处理。

扫码作为收料或发料的输入方式，进入同一套校验、确认和追溯流程。框架预留扫码入口以及单号查询、人工选择两种替代入口；第一阶段不承诺已实现相机扫码、标签打印或设备兼容。

订单码用于找单；按卷、包、箱累计收货，则需定义实物标签和数量绑定。同一实物标签可以经历多次合法流转，应按业务单据及本次操作防止重复记账，不能简单禁止标签被再次扫描。重打标签、部分领用和拆分包装也需要相应规则。

| 阶段 | 交付内容 | 验收重点 |
| --- | --- | --- |
| 方案设计 | 页面结构、复用范围、领域字段、后续顺序已整理 | 符合纸箱复用方向，明确哪些是已有能力、哪些需要建设 |
| 框架预览 | 已重构两个现有工作区，共用页面外壳及单据预览；布料和半成品各用独立字段 | 页面布局一致，导航可用，字段合理，预览与真实业务状态明确 |
| 布料业务闭环 | 来源接入、期初、收料、分仓、领退料、库存流水、差异和更正 | 一组真实业务从来源追溯到实际库存；重复提交、数量差异能正确处理 |

| 半成品扩展 | 接入加工任务，增加多轮发回、在外、返修和包装交接 | 分批、多轮、跨月返修及包装差异可完整追溯 |

### 框架预览交付标准

- 在现有布料仓和半成品仓入口使用新框架，不再增加重复预览入口；已有路由、采购来源数据及历史链接保持兼容。
- 新框架采用纸箱的顶栏和横向导航，不继续沿用旧仓库框架的侧栏作为视觉模板。
- 页面可切换、浏览详情和预览表单；无实际业务能力的操作明确标为待接入，不能模拟保存成功。
- 推荐默认空数据；如需讲解使用少量演示记录，必须显著标注，并在内存中隔离，不写本地或正式业务台账。
- 表单支持临时填写与详情展示；有内容时关闭或切换页面会确认清空，关闭预览不留下正式单据。表单刷新后不恢复临时内容。
- 原有采购来源导入继续在新布局的收料入库运行，使用相同接口和稳定记录，不重新导入复制一套来源。
- 临时预览不写库存；实际业务层另用独立追加账本和动作权限，不扩大厂区或部门边界。
- 不把纸箱接入新公共框架列为首版前置条件；后续确有维护收益时再单独评估。

### 布料业务闭环的接入要求

正式切换仍要求采购来源能直接对接；本轮按用户要求后置外部接口，先接通两仓人工录入、保存、查询与追溯。当前代码中的来源接口不代表已配置金蝶连接器；没有上游稳定行标识、接口样例和责任方，就不能宣称自动对接完成。

建议先确认库存单位、批次管理和收货质量规则，再确定正式收发契约与数据结构。到业务上线时，物理库存、单据来源、价格和订单分配分别追溯；涉及权限、迁移、数量计算、状态和厂区隔离的实现按仓库工程规则完成测试与独立复核。

现有入口已支持布料来源追货、实际入库和基础资料维护；逾期与数量核对提醒、完整筛选排序和导入候选补齐已接通。来源 ID、原始文件证据、历史链接和权限边界持续保留。新增日常收发与加工交接仍需迁移和现场验收；期初、盘点及期间业务尚待建设。

## 开发组织建议

公共页面外壳与临时单据预览已放在 `src/features/warehouse-foundation/`，当前由 `warehouse-operations/WarehouseShell.vue` 接入；业务栏目与预览字段继续在 `warehouse-operations/` 定义。布料采购来源使用现有专用组件。后续业务复杂后，再分别拆分实际表单、校验、接口及状态，避免提前建立空目录。

通用列表接收列、筛选项、分页结果和操作定义；实际查询由各业务负责。单据外壳提供来源、明细和追溯区域，布料放入批次及卷支信息，半成品放入工序和加工循环。复杂规则写成清楚的业务代码，不放进一个充满仓库类型判断的大配置表。

后端沿用现有 FastAPI、SQLAlchemy 与权限体系。布料、半成品分别拥有业务接口和记录；是否进一步共享持久化结构，等两个领域的实际收发契约稳定后再评估。公共校验或流程工具不直接依赖纸箱数据表，库存及流水始终按明确厂区和仓库范围查询。

## 需要在业务接入前确定的事项

| 事项 | 影响 |
| --- | --- |
| 布料管理范围是否包含全部辅料，哪些需要逐卷或逐包 | 主数据字段、标签与盘点粒度 |
| 每种物料的库存单位、计价单位和换算依据 | 收发数量与金额计算 |
| 谁收货、谁质检、何时允许领用，异常如何处理 | 库存状态、权限和确认流程 |
| 无来源单、缺价、超收、短收的最低登记资料 | 临时业务能否办理与后续待办 |
| 共用物料如何关联订单和占用，谁可以调整 | 可用量、发料及订单追溯 |
| 标签由谁制作，标签代表订单还是实物包装 | 扫码累加、重复保护、补打及拆包 |
| 半成品工序、投入产出配比、返修和跨月处理 | 多轮加工、欠数及对账 |
| 初始厂区、仓库、期初时点和上游来源接口 | 试点范围、迁移与后续切换 |

这些事项不妨碍先做页面框架，但相应业务功能接通前需要形成实例和明确口径。首轮建议选“分批收货、分批领料、退料后再领用”三组布料案例；半成品阶段再增加“多轮加工、跨月返修、包装交接差异”。
