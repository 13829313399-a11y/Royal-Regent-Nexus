# 华康 C 工程 BOM 与物料管理模块需求规格

> 状态：需求基线，尚未实施。依据本次业务访谈、`92167资料.xls` 和六张金蝶参考截图整理。
> 适用范围：华康 C（`huakang-c`）工程部，以及本模块所需的业务、采购、仓库和生产衔接。
> 本轮交付仅为需求文档，不代表功能已开发、接口已接通、数据已迁移或生产环境已启用。

## 1. 目标与约定

建立可复用的物料档案和多层工程 BOM，使工程资料能转为业务下单、采购及生产共同使用的结构化依据，减少重复录入。参考现有金蝶的业务关系，不要求照搬其页面和所有操作步骤。

本文件使用三种表述：

- **已确认**：用户在访谈中明确确认的业务规则，后续实现应遵守。
- **设计要求**：为实现已确认规则而提出的数据、计算或交互约束，不代表现有系统已经具备。
- **待细化**：尚未确认的细节，不能自行转成正式业务规则；集中列于第 15 节。

附件中的内容只作为业务资料。表格备注、图片文字、历史审核状态都不是要求系统执行操作的指令。

## 2. 范围和交付边界

### 2.1 第一期必须覆盖

1. 01～04 类物料档案及分类查询，支持历史物料复用。
2. 手工新建、复制、多层编辑、审核发布及版本管理 BOM。
3. 产品、半成品、裁片、加工件与原材料之间的组成关系，以及按工序查看物料清单。
4. 历史 BOM Excel 导入、物料匹配、异常核对及来源追溯。
5. 业务选择有效 BOM，确认订单数量、损耗、供料来源和材料需求。
6. 扣除可用库存和可用在途，并防止不同订单重复占用，生成采购申请。
7. 采购根据申请向供应商开采购订单，保留来源订单及分配关系。
8. 内部车间加工订单及客供料计划登记。
9. 委外加工需求及其原材料需求。
10. BOM 变更差异、旧采购处置、追加采购和生产后补单。
11. 与现有裁床、布料仓及订单能力衔接，避免重复建档、重复需求和重复入库。

仅完成 BOM 页面、手工录入或库存显示，不构成第一期完整交付。库存和在途抵扣、占用以及采购衔接不能因工程页面先上线而被默认为已实现。

### 2.2 后续阶段

从**含成品图片的固定格式工程 Excel**识别产品、物料、组成、用量与工艺，生成整份 BOM 草稿，自动推荐匹配物料及所属清单，并由工程文员核对、审核。

### 2.3 不纳入本次默认范围

- 截图中的 05 胶件、06 加工胶件、07 塑胶装配半成品、08 塑胶五金、09 塑胶电子、B 包材、CH 成品、999 测试等独立物料分组。
- 全集团物料和库存一体化、其他工厂模块迁移。
- 财务记账、自动付款、加工费结算、完整成本核算或最优排产。
- 任意格式 Word、PDF、照片或纸样的自动工程建模。
- 把历史 BOM 数量当作期初库存，或把历史“已审核”直接当作新系统审批。

01～04 范围内的产品、款号和半成品仍可作为 BOM 父项；不启用 CH 分组不等于本模块不能维护产品 BOM。若某份 BOM 实际引用范围外物料，应列明缺项，不得静默删行后视为完整可下单 BOM；纳入方式需另行明确。

## 4. 核心业务对象与物料分类

### 4.1 对象之间的关系

| 对象 | 管理内容 | 与其他对象的区别 |
| --- | --- | --- |
| 物料档案 | 编码、名称、规格、颜色、单位、属性、负责部门等 | 同一物料可在多个 BOM 或工序出现，不重复建档 |
| 产品／款号 | 货号及颜色、尺寸、规格、客户要求等适用标准 | 判断复用已有 BOM 还是复制新 BOM 的业务依据 |
| BOM | 某个父项的组成与工艺用料 | 有独立标识、版本及适用产品 |
| BOM 版本 | 某次审核生效的结构、用量和工艺 | 不随物料档案或新版 BOM 自动覆盖历史单据 |
| BOM 明细 | 某父项消耗某子项的数量关系和用途 | 同一编码在不同部件或工序的行分别保留 |
| 工序清单 | 裁床、车缝、手工、烫画等使用的明细视图 | 来源于同一 BOM，不能独立维护另一套矛盾用量 |
| 采购需求汇总 | 按可合并条件汇总的外购物料或加工需求 | 必须保留拆回订单、BOM 行和工序的来源关系 |

### 4.2 一期分类

| 一级分类 | 截图示例 | 管理要求 |
| --- | --- | --- |
| 01 布料 | 梭织、针织、网布、毛绒、不织布、其他 | 支持下级分组，保留规格、颜色和计量单位 |
| 02 车衣辅料 | 丝带、棉绳、魔术贴、公仔棉、拉链、线、布标等 | 采用完整物料表建立分类，截图不作为完整字典 |
| 03 外购／客供 | 胶件／假发、牌仔、IC、镀锌线等 | 分类名称不替代每项实际供料方式 |
| 04 生产车间 | 裁片、车缝成品／部位、丝印、绣花、烫画、贴合、捆条、款号、部位／补料、车缝、ZURU 尾扣 | 加工件、半成品可有独立编码和 BOM |

### 4.3 编码、部门、车间及供料定义

**已确认：**

1. 同一物料编码只指定一个负责部门，不等于只能在一个工序消耗。
2. 同色号且为同一物料的车缝线与手工线共用编码，在 BOM 中分别表达用途。
3. `04-01` 裁片默认对应裁床车间；`04-05` 烫画分类可面向不同部门或车间，但每个具体物料编码只指定一个负责部门。
4. 外购是向供应商购买。
5. 本业务的“客供”是其他车间提供材料，本车间完成后续工艺。不能自动解释为外部客户免费提供，也不能据此推断所有权或计价方式。
6. 自制、委外和客供应分别表达加工方式或供料关系，不能只凭分类编号猜测是否需要采购。
7. 物料编码与 BOM 编号允许不同。引用以明确关联和版本为准，不能截取版本号前缀反推物料编码。

**已确认：**保留历史编码，新物料按分类自动续号；物料换负责部门不换编码。工程文员建立并审核物料的编码、名称、规格、颜色和单位，采购维护供应商，仓库维护仓位。

**设计要求：**保存原始编码、旧编码、名称及来源；同名物料不能自动合并。负责部门、默认仓库、实际供料方、领用工序分别建模，不能用一个“车间”字段混写。部门变更保持稳定物料身份、记录变更版本，不改写历史单据；新编码流水位数及历史号段冲突待完整物料表核对。字段维护权不直接等同于现有仓库导入权限。

## 5. BOM 建立、复用和工序清单

### 5.1 新建和复制规则

- 颜色、尺寸、规格、客户要求或包装等标准不同，需要建立相应独立 BOM。
- **货号不同，即使颜色、尺寸、规格等均相同，也需要复制现有 BOM，生成独立 BOM。**不能把两个不同货号直接绑定为同一可编辑 BOM。
- 货号一致且相关标准一致，可以再次下单时复用同一有效 BOM。
- 同一产品修改用量、物料明细或工艺，形成新版本。
- 新货号复制应记录来源 BOM／版本，但复制后独立编辑；不能联动修改来源 BOM。已审核状态不能随复制自动继承。
- 重复订单引用明确的已审核有效版本，不因打开页面或后台出现新版而自动切换。

### 5.2 多层结构和工序视图

支持成品／手工件、车缝件、裁片、贴合件、刺绣件及原材料的父子关系。加工件和半成品可作为父项建立自己的 BOM，并被上层引用。

至少提供以下逻辑视图，具体布局在实施设计阶段确定：

1. **完整 BOM 树**：父子层级、物料、单位、分子／分母、标准用量、工艺及版本。
2. **工序清单**：按裁床、车缝、手工及其他适用工序筛选，显示所需输入、输出或部件关系。
3. **物料汇总**：按相同物料及合法合并条件汇总需求，并可追溯每个组成来源。业务放单时，同编码的自制与委外必须分开汇总；以本次用料行属性为准，保留工程默认属性和业务选择，不回写物料档案。
4. **外购／委外／客供清单**：供业务和采购区分应购买、应加工、由其他车间供给的项目。

工序视图和汇总视图来自同一组 BOM 明细。跨工序的同编码用料可以按合法条件汇总，但不得丢失用途、供料来源或订单分配信息。

### 5.3 审核和有效版本

工程文员负责建立和审核，允许同一人完成两项操作。系统记录建立人、审核人、时间和版本，不强制要求两个不同账号。

建议采用“草稿 → 已审核生效 → 已替代／停用”的版本表达；退回、撤销审核及停用的具体操作边界待实施前细化。无论具体状态名称如何，下列规则必须成立：

- 未审核草稿不能作为正式下单依据。
- 新版本审核生效前，不能用其覆盖当前有效版本。
- 新版本生效后，已替代旧版不再供新订单选择。
- 旧版及其已形成单据的证据仍可追溯；停用不是物理删除历史记录。
- 子 BOM 引用需固定版本，不随其最新编辑内容隐式变化。
- 循环引用、找不到父项、必要单位缺失、分母为零或来源关系不明等问题必须在审核前解决。

## 6. 用量、损耗和计量规则

### 6.1 基础用量

对普通父子用料关系：

```text
每单位父项的子项用量 = 用量分子 ÷ 用量分母
当前路径的子项需求 = 当前路径的父项需求 × 每单位父项的子项用量
```

同一材料出现在不同路径时，先按各自路径计算，再按物料、版本、单位、本次物料属性和供料等适用条件汇总。即使编码相同，自制与委外也不合并；下游采购汇总继续保留此边界。顶层物料本身是展开起点，不把样本顶层 I/J 的 0/0 当作普通消耗关系，也不能忽略真正子项的零分母错误。

用户确认的例子：

```text
每套需要后身裁片 = 2 Pcs
裁片用布分子 = 0.0297 码
裁片用布分母 = 2 Pcs
单片用布 = 0.01485 码
每套该部位用布 = 2 × 0.01485 = 0.0297 码
```

不能将 0.0297 误当成单片用量再乘 2。只用于演示该部位的 1,000 套订单，理论需求为 29.7 码；该例不代表整份 92167 BOM 的布料总需求。

### 6.2 标准用量与实际数量

**已确认：**二者始终相同，不分别人工调整。导入时保存原值并进行一致性检查；如果不同，列为待核对，不能擅自取较大值、较小值或任一列。

“实际数量”是本历史 BOM 字段名称，**不是仓库实发量、现场耗用量或最终采购量**。这些业务事实必须独立记录。

设计要求：用分子／分母及层级重建用量，与来源标准用量核对。本样本可用于验算，但其他模板的根项基数、汇总列和数量显示精度仍需逐模板确认。

### 6.3 订单损耗

**已确认：**整张订单设置一个损耗率，允许部分物料和加工项目不计损耗。工程设置默认免损项，业务确认本单损耗率及例外，业务可以修改。已确认需求修改须保留版本并核对采购影响，不覆盖历史需求或回写 BOM 标准用量。

```text
计损耗项目需求 = 理论需求 × (1 + 订单损耗率)
不计损耗项目需求 = 理论需求
```

示例：100 码按 5% 得到 105 码，不采用 `100 ÷ (1 - 5%)`。上述后身布料 29.7 码按 5% 得到 31.185 码，尚未考虑采购单位进位。

设计要求：

- 每个材料／加工项目能够明确是否参与损耗计算，订单确认时显示例外。
- 损耗计算结果和损耗率随订单需求冻结保存，不回写工程 BOM 的标准用量。
- 多层结构不能在每层机械叠乘同一订单损耗，避免形成 `(1 + 损耗率)` 的多次复利。
- 加工项目与其原料分别按各自理论量及免损标记计算一次损耗。已确认加工 100 件、原料 20 码加 5% 为 105 件、21 码，不再对 21 码重复加成；复杂多层结构仍需真实实例验证。

### 6.4 单位与精度

设计要求：基本单位、库存单位、采购单位分别保留；只有明确换算关系才能抵扣和汇总。码、米、卷、Pcs、套、千克不得直接混算，套与片的关系需由 BOM 组成确定。

**已确认：采购数量有小数一律向上取整数，不保留小数。**例如 31.185→32、31.001→32、31→31、0→0。此规则针对采购数量，不将 BOM 用量、库存事实、单价或金额推定为整数。

计算保留十进制精度：先展开并加损耗、抵扣库存及在途，再换算成采购单位，在允许合并的实际采购行上汇总后统一向上取整，不能逐层或逐订单提前取整后重复放大。保存精确净需求、采购单位换算、整数订量及进位差额。例如精确净采购需求 31.185 码订 32 码，差额 0.815 码不回写为订单消耗、不变成已入库量，也不重复分配给原订单。

计算精度、整卷／整包换算、包装倍数及最小采购量仍需具体档案核对；不能由“700Y/卷”等名称文字直接建立正式换算规则。采购改量使用新的总订量及变更依据，不能对差额再次无依据取整。

## 7. 业务下单、库存抵扣与采购

### 7.1 责任和流程

```text
工程文员建立或导入 BOM → 核对并审核生效
→ 本车间业务录入订单并选择 BOM
→ 业务确认数量、损耗及供料需求
→ 采购分工序填写物料期，供生产编排计划
→ 展开用料并扣除可用库存和可用在途
→ 确认占用并形成采购申请
→ 下单业务自行审核采购申请
→ 采购员开采购订单
→ 采购负责人下发供应商
→ 采购跟踪供应商状态和交期
→ 仓库按实际到料验收入库并按业务指令发料
```

业务负责确认需求。采购申请与供应商采购订单是不同单据，不能合并为一个状态。仓库人员不能开采购订单；仓库身份不能隐含采购权限。

**已确认：**采购申请需要审核；采购员开单后由采购负责人下发供应商。取消、改量由采购员提交给采购负责人审核批准，不能由采购员自行生效。采购申请由下单业务自行审核。内部审核批准和供应商确认取消是不同事实，草稿／待审核采购单不构成有效在途。

采购单需要单价、币种、税率、交期、交货地点和付款条款，价格由采购员填写。含税口径、金额精度和版式随样本核对。库存或未到货采购资料不完整时仅保留草稿，暂不正式下单。第一批只接新订单，暂不迁入在执行旧订单。

### 7.2 抵扣口径

**已确认：**抵扣时排除其他订单已占用、冻结及不合格库存；只使用尚未分配且预计能在需求日期前到货的采购余量。业务确认时占用相应数量，避免多张订单重复抵扣。

金蝶当前没有库存数据。库存基线采用用户另行提供的表格，以表格日期为截止日期，由仓库核实；表格尚未收到不等于库存为零。实际接入时核对截止日前后收发及已有库存记录，不能直接叠加为另一份库存；表格缺日内时点时需核对交易边界。物料档案及未到货采购也由用户提供表格。

待检材料经仓库批准可以抵扣；未批准不计入可抵扣量。批准只确定抵扣资格，不将质量状态改为合格，也不自动授予质量放行或发料权限。设计保存批准人、时间、批次、数量及适用需求范围，并在确认占用时验证。

物料期由采购填写，不同工序分别设置，生产按物料期编排生产计划；业务仍负责需求确认。采购修改物料期时保留依据并重新检查在途抵扣及排产影响。首次填期时点、物料期作为抵扣截止与供应商预计到货日的具体对应，须通过流程实例细化；不能直接用某笔在途自身的预计到货日证明其按期可用，也不由生产倒排或客户走货日自动覆盖采购填期。

对符合采购条件的同一物料及统一单位：

```text
待覆盖需求 = 按损耗规则计算后的需求
库存分配量 ≤ 允许用于本订单且未被其他需求占用的现存量（合格或经仓库批准抵扣的待检量）
在途分配量 ≤ 按期可到、允许用于本订单且未被其他需求占用的采购未收余量
净采购需求 = max(待覆盖需求 - 本次库存分配量 - 本次在途分配量, 0)
```

例：需求 105 码，可分配库存 20 码、按期可用在途 30 码，则新增净采购需求为 55 码。订单仍需保留 105 码总需求及 20／30／55 的覆盖来源。

### 7.3 必须成立的控制

- 同编码不能越过颜色、规格、单位、供料归属、质量和工厂边界直接抵扣。
- 在途只计算有效采购未收部分；采购申请本身不等于已下达采购，也不等于供应商承诺。
- 已收货数量从在途转为实际库存来源后，不能再次作为未收在途计算。
- 未知库存或在途不能默认为零或充足。数据不完整时明确显示，正式下单如何例外放行需另定权限和流程。
- 已为本订单占用的数量应在重算中正确识别，不重复扣减也不重复预留。
- 并发确认要保证同一批可用量不会被两个订单同时占用；界面预览不是占用成功。
- 订单变更、取消、补单及采购变更需重核占用和来源关系，不直接修改库存实物数量。
- 采购可按供应商和采购条件合并需求，但保留原订单逐项分配，防止汇总后无法追溯。
- 迟到在途仍然是有效在途，只是不满足本次按期覆盖条件，不能为简化计算删除其记录。

设计要求：明确显示理论需求、损耗增量、总需求、库存分配、在途分配、净采购需求及计算时点。采购数量与实际领料、耗用数量分别保存。

## 8. 内部车间订单及客供料

### 8.1 已确认流程

其他车间接到客户订单后，下单给本车间完成后续工艺。由**本车间业务人员**根据对方资料录入，不要求对方车间直接进入本模块下单。

内部加工订单需记录供料明细、供料数量和预计到料日期。客供部分不生成向供应商采购的申请；订单中另外需要外购的材料仍按其真实供料方式处理。

### 8.2 建议记录字段

- 内部来源订单号、来源车间、关联客户／货号、要求完成数量和日期。
- 本车间使用的 BOM 及版本。
- 供料明细：物料编码、名称、规格、单位、计划供料数量、预计到料日期。
- 供料方及其来源单据；多批供料分别记录数量和日期。
- 实际收料、欠料及差异通过仓库事实关联展示，不能把计划供料直接计作库存。

同编码客供料可以跨订单共用，不增加逐单批准要求；保留来源和实际使用记录，仍检查未占用量及质量状态。跨厂供料如涉及其他工厂，只记录经授权的来源信息，不自动读取或扣减对方库存。本轮尚未确定材料所有权、计价及超欠料责任规则。

## 9. 委外加工与工艺

**已确认：**委外贴合、刺绣等需要同时生成加工需求和提供给加工商的原材料需求。

设计要求：

1. 委外件作为独立物料／加工输出表达，与加工所需原料建立组成关系。
2. 明确加工数量、单位、工艺、输入材料、输出物料及适用版本。
3. 原材料按各自供料方式处理，不能把委外输出件和其自供原料同时误当作同一层的整件外购，造成重复采购。
4. 工艺变更即使未改变材料数量，也必须在差异中展示，供采购判断加工订单是否受影响。
5. 发给加工商的材料、加工商已收到的材料、加工返回品分别记录事实，不因建立 BOM 自动发生发料或入库。
6. 工艺和供料文件随业务单据关联到明确版本，后续版本不能覆盖已下达的加工依据。

加工和原料各计一次损耗的规则已确认。加工费价格、结算、跨加工商拆单及替代加工路线不在本轮已确认范围内，复杂展开仍需样本验证。

## 10. BOM 变更和历史保留

### 10.1 核心原则

**旧 BOM 不再供新订单选择，历史订单、采购、领料等单据保留当时记录。**“不保存旧版供使用”不等于删除已经发生的业务证据。

每次变更形成新版本，记录变更前后物料、用量、工艺、影响订单、操作者及原因。新版本只在明确生效和选择后影响后续业务。

### 10.2 按本车间订单状态处理

| 本车间订单状态 | 已确认处理方式 | 历史和采购处理 |
| --- | --- | --- |
| 已全部走货 | 工程修改形成新版本，后续新订单使用有效新版 | 已走货订单保留当时记录，不回写历史 |
| 已下单订料、尚未生产 | 形成新版本，可按差异调整后续需求并生成新采购订单 | 先核对旧采购处置、库存和在途分配，不能直接覆盖原单 |
| 已开始生产，包含部分走货 | 另开补单处理变化，不在原生产订单内分段切换 BOM | 原订单保留原依据，补单引用对应版本并关联原订单 |

**已确认：**本车间以生产主管登记实际开工为开始生产节点，保存主管、订单、实际开工时间和登记依据；不以领料、页面打开或缺少报工记录自动判断。

补单分为补料、返工和追加成品。补料／返工不增加客户待交数量；追加成品才增加交付需求。各类补单关联原单、原因、适用 BOM 版本及数量，只形成实际补充部分的需求，不重复原订单已满足的用料／交付记录。补 PO 数量由业务负责；生产不足由生产报数给业务补放，工程补用量由工程建补料单交业务下推采购。生产不足补放仍属补足原交付目标，不增加客户待交总量。

### 10.3 按供应商生产状态处置旧采购

供应商是否已生产是采购处置节点，**不能用是否已到货代替**。

例：原订 A 布 100 码，BOM 改为 B 布 80 码。

| 旧采购对应的供应商状态 | 已确认规则 | 系统设计要求 |
| --- | --- | --- |
| 未开始生产 | 取消原采购单，再采购 B 布 | 由采购核实并记录取消结果；取消生效后更新旧在途和占用，保留原单及取消证据 |
| 已开始生产 | 原采购材料留作库存，按新需求采购 B 布 | 不因本次变更自动取消旧采购；已产未到部分仍为在途，实际验收入库后才成为库存 |
| 部分数量已生产 | 按数量拆分：100 码已产 60，保留 60、取消未产 40 | 保留已产部分采购义务；未到货仍为在途。采购员提交取消，采购负责人批准并记录供应商取消结果后才更新有效余量 |
| 生产状态未知 | 交采购核实，不自动归为未生产 | 不静默取消或释放；取消失败／未确认时例外替换采购的规则仍待确认 |

对于减少用量、增加用量、更换材料和工艺变化，统一提供差异核对，但执行结果不能只靠数量差推断。例如纯工艺变化也可能涉及旧加工订单和已生产加工件。

**已确认：**原采购单其他未受影响明细保持不变，只处理受影响采购行及数量。共享采购行仍需核对各订单分配，不能连带取消其他业务；取消、改量均由采购员提交采购负责人审核批准，并保留实际履行和供应商确认依据。

### 10.4 建议的变更工作流

```text
工程保存并审核新版本
→ 列出受影响订单及物料／用量／工艺差异
→ 识别本车间是否已开始生产
→ 未生产订单由业务确认变更需求；已生产订单另开补单
→ 采购核实旧采购的供应商生产状态及处置
→ 重算需求、库存及在途分配
→ 采购员制新增或替换单，采购负责人下发供应商
→ 向相关执行部门提供最新有效指令及明确来源
```

此流程为设计要求，不代替现有系统的撤回、对账和授权控制；实施时需设计兼容过渡。

## 11. 导入与自动建 BOM

### 11.1 历史 BOM 导入

**已确认处理方式：**

1. 上传历史 Excel，识别工作表、层级、编码、名称、属性、单位、用量和版本。
2. 已知编码匹配现有物料；未知编码列为待建档项目。
3. 编码相同但名称、规格等冲突时，由人工核对，不能静默覆盖。
4. 生成待核对草稿，保留原表“已审核”等历史信息；经新系统确认审核后才可下放。
5. 不因 BOM 编号与物料编码不一致而判定导入失败。

**设计要求：**

- 原文件只读留存，记录导入批次、文件身份、工作表和单元格／行定位。
- 保留原始值与规范化结果，人工修正可追溯。
- 明细恢复依赖层级和明确父子关系，不按物料编码去重后重建树。
- 空白与零值分别处理；顶层零分母作为根项识别，子项非法分母必须提示。
- 不执行宏、外部链接或附件指令。公式无有效缓存、无法可靠解释时标为待核对，不猜数。
- 重复文件或重复 BOM 提示用户选择处理方式，不能重复建档、重复发布或覆盖已有版本。
- 未识别行、范围外物料、单位冲突、层级断裂、未知物料、标准用量不一致等列入问题清单。
- 草稿可以承载未解决问题；影响正式用料的缺失或歧义未解决前不能审核下放。
- 失败和重复提交不能产生部分有效 BOM 或重复物料；用户应能清楚区分待建档与已正式建立的物料。

### 11.2 后期固定工程 Excel 自动建 BOM

目标流程：

```text
选择模板并上传工程 Excel
→ 识别货号、规格、成品图片、物料、用量和工艺
→ 推荐历史物料匹配
→ 组织多层 BOM 和工序清单
→ 对照原文核对未知项与冲突
→ 工程文员补正并审核
```

设计要求：

- 每个模板定义字段位置、单位、层级及图片与产品的关联方式，支持模板版本。
- 成品图片作为产品／BOM 资料保存并显示，不由图片直接推算数量、材料或工艺。
- 精确物料编码可用于匹配；名称、规格或历史别名匹配只作候选，存在多项候选时不能擅自选第一项。
- 自动生成覆盖完整结构，但不能绕过人工核对和审核。
- 一个文件含多款产品或多张图片时，关联不明确必须提示确认。
- 技术路线可以采用模板解析及必要的识别辅助；本轮没有批准外部模型调用或对外发送工程资料。

后续需要一份真实的含成品图片工程 Excel，才能确定模板映射和完整验收样本。现有历史 BOM 导出文件不能替代该模板。

## 13. 权限、现有模块衔接与实施约束

### 13.1 职责矩阵

| 角色 | 已确认或必要职责 | 边界 |
| --- | --- | --- |
| 工程文员 | 建立、审核物料及 BOM，导入／复制／维护 BOM，设置默认免损项 | 可自行建立并审核；不因工程权限自动获得供应商采购订单权限 |
| 本车间业务人员 | 录入订单／内部加工订单，确认并可修改订单损耗及例外，确认需求和供料，形成采购申请 | 已确认需求修改留版本和影响依据；不代采购维护物料期 |
| 采购员 | 维护供应商、分工序填写物料期、制采购单、核实供方生产状态、提交取消／改量并跟进到料 | 不自行下发供应商或批准取消／改量；与仓库授权分开 |
| 采购负责人 | 将采购单下发供应商，审核批准采购员提交的取消／改量 | 内部批准不等于供应商确认取消，不自动推定其为采购申请审核人 |
| 仓库人员 | 维护仓位、核实库存、批准待检量抵扣、按实际业务收发并提供事实 | 不可以开采购订单；批准抵扣不改变质量状态；不以计划到料直接增加库存 |
| 生产执行人员 | 按采购填写的各工序物料期编排计划并执行，提供已开始生产等事实 | 生产后变更另开补单，不改原生产单依据 |

物料档案建审、损耗修改、物料期及采购制单／负责人下发和变更审批职责已确认；采购申请由下单业务自行审核，具体员工授权仍待落实，不能把允许工程自审扩展为所有单据均可自审。

### 13.2 当前项目基线与本需求的区别

依据现有项目文档，裁床已有独立 BOM、明确版本绑定、人工核定需求和采购交期回复等能力；布料仓已有物料及收发数据能力。它们的现状不等于本需求中的净需求、占用、采购单和差额变更已实现。本轮未重新执行代码或运行环境验收。

| 相关能力 | 当前文档约束 | 本次新需求及衔接要求 |
| --- | --- | --- |
| 客户订单中心 | 保存订单事实和下发，不承担详细材料规划 | 业务确认入口可调用需求能力，但不能把全套 BOM／采购算法混入订单事实账 |
| 裁床 BOM | 工程选择明确已发布版本，原订单保留版本依据 | 新工程模块应成为清晰的维护入口，定义现有 BOM 的映射和迁移；新版规则不能偷偷覆盖现有订单 |
| 裁床需求与交期 | 人工核定，回复交期不创建真实采购单 | 新增业务确认、损耗、净需求和采购衔接，不可把现有 ETA 当作有效采购在途 |
| 旧需求变更 | 存在工程撤回和采购对账约束 | 新变更流程应明确兼容和替代边界，不能绕过已形成单据的处置 |
| 布料仓 | 维护实际库存和收发事实 | 工程模块引用权威库存，不能创建平行库存账；占用不等于实物出库 |
| 材料主数据 | 已有全局原料及厂区相关物料引用 | 区分全局身份和华康 C 业务属性，避免复制全局原料主数据或扩大跨厂可见范围 |

原裁床方案中“损耗、抵扣待确认”等文字描述的是其原交付边界；本文件明确了华康 C 新工程模块的目标规则，不代表原实现已同步改变，也不把该口径推广到其他工厂。

### 13.3 安全与一致性设计要求

- 所有读写校验华康 C、部门和动作权限；前端按钮隐藏不能代替服务端授权。
- 物料编码、货号和单据号作为字符串保存，保留前导零。
- 正式计算、占用、版本和单据状态由服务端确认，客户端预览不能作为最终事实。
- 审核发布、业务确认、采购生成和变更应防重复提交和过期版本覆盖。
- 物料、BOM、订单、采购、库存的稳定身份分别保存，不用名称或行号充当长期主键。
- 审核、取消、变更、占用释放及补单均需留痕；历史单据不能因主数据编辑而改变当时内容。
- 失效或已替代版本不供新单选择，但授权人员可查看历史依据。
- 实施数据库、导入、算法、权限及状态流转时，按仓库规定执行严格工程验证。本轮不执行迁移、修改授权或部署。

## 14. 分期实施和验收场景

### 14.1 建议实施顺序

1. **准备**：取得完整物料 Excel，核对 01～04 分类、编码、部门及单位，盘点现有物料／BOM／订单／库存／采购接口和数据质量。
2. **一期 A：工程资料基础**：物料复用、手工建 BOM、复制、工序清单、审核版本、历史导入和来源核对。
3. **一期 B：业务和采购衔接**：订单确认、损耗、客供、委外、库存及在途抵扣、占用、申请与供应商采购单。
4. **一期 C：变更闭环**：旧版本退出新单选择、供应商生产状态、旧采购处置、差额采购、生产后补单及历史追溯。
5. **二期：固定工程 Excel 自动建 BOM**：模板及成品图片识别、自动物料候选、完整结构生成和人工审核。

一期 A～C 是开发顺序，不是允许将 B／C 排除出第一期的范围调整。各段可独立测试，但涉及真实下单的能力必须满足完整的数量、权限和历史要求后才可启用。
