# 客户订单中心后续实施规划

> 文档版本：V2.2
> 当前阶段：BuzzBee 流程01后端基础功能试用
> 当前试点客户：BuzzBee
> 当前状态：真实PO解析、17字段预览确认及客户排期导出已可试用；订单持久化和厂区总排期后端尚未实施
> 重要修正：厂区总排期是系统数据视图，不是Excel合并或导出

## 1. 最终方向

客户订单中心形成两个互相关联、但用途不同的数据层：

1. **订单数据台账**：保存客户PO的17个统一字段、原始文件、来源、版本和确认状态；
2. **厂区总排期**：从有效订单中投影交付需求，按厂区、客户和月份查看待走货PO、临期风险和生产反馈。

流程01仍允许按客户原有格式输出客户排期，但厂区总排期不再输出Excel。

```mermaid
flowchart LR
    A["客户PO与客户排期"] --> B["17字段标准订单"]
    B --> C["订单数据台账"]
    C --> D["厂区总排期数据视图"]
    D --> E["PMC/生产模块读取需求"]
    E --> F["啤机/喷油/装配模块"]
    F --> G["回传完成状态与未完成原因"]
    G --> D
```

## 2. 模块职责

### 2.1 客户订单中心负责

- 导入客户PO和客户排期；
- 映射17个统一字段；
- 保存订单、来源和版本；
- 输出客户格式排期；
- 形成系统厂区总排期；
- 按客户、月份和走货日期汇总PO；
- 识别即将到期、临期和逾期；
- 向下游提供已确认订单需求；
- 只读显示生产模块反馈。

### 2.2 客户订单中心不负责

- 拆解生产工序；
- 安排机台和生产线；
- 计算物料或库存；
- 修改生产任务；
- 修改生产完成数量；
- 代替PMC、仓库、啤机、喷油或装配模块。

## 3. 分步实施计划

### 第0步：BuzzBee流程01真实基础闭环

**状态：已完成**

- 一次选择并上传最多30份普通 AAFES `.xls` 或 WMC 内嵌式 `.xlsx` PO；
- 上传当前指定的 `2026年 BUZZ BEE 生产排期表.xls.xlsx`；
- 解析并预览17个统一字段及来源单元格；
- 阻断缺少必填字段、中文名称、单价或非整箱数量；BuzzBee 普通客允许 P/O# 为空，WM 客 P/O# 必填；中文名称和单价允许跟客明确勾选“跳过并后补”，导出时留空；
- 将重复PO、日期差异作为需人工确认的警告；
- 确认后将本批全部PO合并写入同一份排期的 `接单表`、`正单评审表`及对应的子弹枪/水枪 ITEM 表订单行；存在同货号备料单时，ITEM 在 H 列原公式或数量后直接减去本合同数量，但不自动补 3000，也不新增样板/备料行；
- 浏览器下载新的加密排期，下载文件名保持上传排期原名，服务器不覆盖上传原件，打开密码为 `2026`；
- 印尼排期和 WMU 样本继续排除在当前范围外。

当前实现为无状态文件处理：上传文件只用于本次解析和导出，不写入数据库，也不会形成可查询的订单台账。

### 第1步：定义厂区总排期数据模型

**状态：下一步**

在17个基础字段之外，增加：

- 厂区ID；
- 订单行ID；
- 交付需求ID；
- 订单/需求版本；
- 走货月份和周次；
- 距走货天数；
- 临期/逾期状态；
- 是否允许下游读取；
- 最近订单变更时间。

产出：

- 厂区总排期数据结构；
- 订单台账与总排期边界；
- 活动订单和历史订单范围。

### 第2步：确定交付风险规则

**状态：待业务确认**

需要确认：

1. “即将到期”提前多少天；
2. “临期”提前多少天；
3. 客要求走货期的准确业务节点；
4. 已过期但订单未确认时如何显示；
5. 实际走货后由哪个下游状态关闭提醒；
6. 修改交期后如何保留旧版本风险记录。

暂定前端演示：

- 30天内：即将到期；
- 7天内：临期；
- 日期已过且未关闭：逾期。

这些数值后续应配置，不写死在客户模板中。

### 第3步：设计月度厂区总排期页面

**状态：静态原型已完成第一版**

页面包括：

- 走货月份筛选；
- 客户筛选；
- 生产完成状态筛选；
- 待走货PO数；
- 订单总数量；
- 临期/逾期数量；
- 生产未完成数量；
- 按月PO和客户概览；
- 订单交付排期表；
- 17字段订单详情；
- 生产反馈摘要。

下一轮需要业务确认页面信息密度、默认月份和风险颜色。

### 第4步：确定下游供数合同

**状态：V0.1数据合同草案已完成，不实施接口**

详细字段和候选接口见《[客户订单中心下游数据接口清单](./customer-order-center-downstream-data-interface.md)》。

下游读取时至少返回：

- `order_line_id`；
- `delivery_demand_id`；
- `demand_version`；
- 所属厂区；
- P/O#；
- Contract No.；
- 产品编号和名称；
- 数量、装箱数和箱数；
- 国家标准和包装；
- 行Q、客Q；
- 客要求走货期；
- 走货月份、剩余天数和风险状态。

接口默认只返回：

- 当前有效版本；
- 已确认订单；
- 可供下游读取的交付需求。

生产岗位默认不返回单价HK和金额HK，除非岗位权限明确授权。

### 第5步：确定生产反馈合同

**状态：V0.1数据合同草案已完成，不实施接口**

生产模块回传：

- 订单行ID；
- 交付需求ID；
- 使用的需求版本；
- 生产模块和任务ID；
- 任务状态；
- 需求数量；
- 已完成数量；
- 未完成数量；
- 未完成原因；
- 预计完成日期；
- 最后反馈时间。

客户订单中心：

- 只读展示；
- 不修改生产任务；
- 不修改完成数量；
- 对临期但生产未完成的订单提高风险；
- 对使用旧订单版本的下游显示版本落后。

### 第6步：确认多生产部门汇总规则

**状态：待啤机、喷油和装配模块模型明确**

需要决定：

- 一个订单经过哪些生产部门；
- 总体完成率按数量、工序还是关键节点计算；
- 哪个未完成环节显示为当前阻断部门；
- 某部门完成、下一部门未开始时如何显示；
- 返工、暂停和外发如何汇总；
- 一个订单存在多个生产任务时如何聚合。

### 第7步：完善异常与提醒中心

**状态：静态第一版及V0.1规则草案已完成**

详细规则见《[客户订单中心异常与提醒规则](./customer-order-center-exception-reminder-rules.md)》。

异常分类：

- 订单数据待确认；
- 客要求走货期缺失；
- 未来30天即将到期；
- 未来7天临期；
- 已逾期；
- 生产未下发；
- 生产未完成；
- 生产预计完成时间晚于走货期；
- 下游使用旧订单版本；
- 下游长时间未反馈。

提醒只提示风险，不代替生产部门更改排产。

### 第8步：静态页面业务验收

**状态：待用户评审**

至少验证：

1. 能按月份看到每个客户有哪些PO要走货；
2. 能按客户查看当月PO和数量；
3. 能识别30天内、7天内和逾期订单；
4. 能看到订单是否已确认；
5. 能看到生产未下发、生产中和未完成；
6. 能打开订单查看17字段来源；
7. 能查看未完成部门、原因和反馈时间；
8. 页面不存在“合并总排期Excel”或“导出总排期Excel”；
9. 页面不允许修改生产进度；
10. 生产反馈明确标注为下游权威数据。

### 第9步：实现客户订单数据库

**状态：后续开发阶段**

静态页面确认后，再实现：

- 原始文件；
- 导入批次；
- 标准订单头；
- 标准订单明细；
- 交付需求；
- 字段来源；
- 订单版本；
- 厂区归属；
- 排期派生状态；
- 下游发布记录；
- 生产反馈摘要；
- 审计记录。

数据库完成后，厂区总排期通过查询生成，不复制第二份订单主数据。

### 第10步：实现真实接口

**状态：下游模块具备条件后**

接口分为：

1. 客户订单中心向PMC/生产模块提供订单需求；
2. 下游确认接收的订单版本；
3. 下游回传生产状态；
4. 客户订单中心查询生产摘要；
5. 从总排期跳转到下游任务详情。

所有接口必须使用稳定ID和版本，不使用Excel行号。

## 4. 当前下一步

现在不需要再提供厂区总排期Excel。

下一步应由业务确认以下4项：

1. 即将到期和临期分别提前多少天；
2. 厂区总排期默认打开“本月”还是“未来三个月”；
3. 未确认订单是否进入总排期，还是只进入异常区；
4. 生产总体完成率以后按哪个原则汇总。

在这些规则确认前，前端继续使用明确标注的静态反馈示例，不把演示数据当成真实生产结果。
