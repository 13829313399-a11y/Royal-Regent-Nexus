## 4. 发布候选文件边界

### 4.1 必须纳入候选

- 内部报价与权限相关的 `backend/app/`、`src/` 实现变更。
- 对应的后端/前端回归测试与 L5 真实样表 opt-in 测试代码。
- `PROJECT_MEMORY.md`、内部报价协作文档和本发布清单。
- 四个已跟踪的客户模板 `.bin` 文件必须继续存在且 SHA 不得被无意改写。

### 4.2 不得通过宽泛 `git add .` 带入

- `outputs/` 下的渲染图、验收工作簿和报告不是运行时依赖，应作为本地验收证据单独归档。
- `tools/`、模具样办输出、华兴订单预览及其他模块的未跟踪文件必须逐项确认，不能随内部报价台发布候选提交。
- `public/templates/disney-customer-quote-template.xlsx` 是一个未跟踪、隐藏且仅 165 字节的无效文件，不是客户模板；发布包只能使用已跟踪的 `.bin`。该文件属于现有工作区内容，L6.1 不擅自删除，但 L6.2 必须明确排除。

当前工作分支仍为已经通过 PR 的 `nbbj4`。L6.2 必须从远程最新 `main` 创建新分支，再有选择地纳入本轮 L5/L6 变更；不得直接在旧分支上继续交付。

## 5. 生产环境前置条件

1. 对 PostgreSQL 做可验证恢复的完整备份，并记录备份时间、数据库版本和当前 Alembic revision。
2. 生产 `.env.production` 必须使用强随机 `POSTGRES_PASSWORD`，保持 `SESSION_COOKIE_SECURE=true`、`SEED_DEFAULT_ACCOUNTS=false`，`SEED_ADMIN_PASSWORD` 默认留空。
3. 当前兼容基线为 `AUTHZ_MODE=legacy`、`AUTHZ_WRITES_ENABLED=false`；上线前需确认现有业务/工程/八责任部门角色已执行启动种子补齐，并保留至少一个有效集团超级管理员。
4. 先在与生产一致的 Docker/Compose 环境构建镜像并运行 `docker compose config`、数据库健康检查、API `/health` 和前端首页检查。
5. 发布窗口内禁止同时手工修改生产角色、内部报价表或迁移版本。

## 6. 建议上线顺序

1. 冻结发布分支和 commit SHA，保存 `git status`、测试结果及镜像摘要。
2. 完成数据库备份恢复抽检。
3. 构建前端/后端镜像，确认 `.dockerignore` 排除了 `.env`、`outputs`、本地数据库和测试临时文件。
4. 启动 PostgreSQL，执行 `alembic upgrade head`，确认 revision 为 `20260718_0026`。
5. 启动 API 与 Web，确认 `/health`、登录、业务部模块入口和内部报价台首页正常。
6. 使用生产测试账号依次验证：管理员访问；业务/工程新建与复制；八部门分段权限；双人最终放行；客价转换台接收一个受控 P4 文件。
7. 观察 API 错误、数据库锁/慢查询、文件下载和浏览器控制台；全部正常后再结束发布窗口。

## 7. 回滚边界

- 在尚未写入新内部报价数据时，可以回退应用镜像并恢复发布前数据库备份。
- 一旦生产用户已创建、审批或交接新报价，不应直接运行 `alembic downgrade`：`0023` 的降级会删除最终审核与交接表及相关字段。此时必须先停止写入，导出新增数据，由负责人决定前向修复或完整数据库恢复。
- 客户模板异常可先回退前端镜像；不得用手工覆盖受控 P4 文件或修改已生成 artifact 的 SHA/manifest。
- IAM 异常应保留至少一个超级管理员会话，优先回退应用并恢复角色配置，禁止直接删除最后一个超级管理员绑定。
