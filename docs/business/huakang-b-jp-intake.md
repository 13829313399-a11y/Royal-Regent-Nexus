# 华康B JP问单录入

## 范围

入口为业务部 → 客户订单中心 → 华康B → JP问单录入。该入口移植独立工具的邮件问单流程，不代替其他厂区的正式 PO 导入，不自动保存正式订单、下发生产或修改库存。原独立工具及原件不修改、不上传仓库；仅提交服务端适配和合成测试数据。

## 使用与证据

- 有写权限的业务人员手动上传排期参照、货价表和可选的确认价表（XLSX）。验证通过后按版本更新；并发更新冲突需刷新，失败保留旧参照。确认价可停用，但旧版本和原件保留。不会定时读取个人电脑或共享盘、覆盖别人文件。
- 支持 EML、含 EML 的 ZIP 以及粘贴邮件 HTML。每个文件上限 20 MiB，邮件合计 50 MiB，最多 100 封、250 行；ZIP 展开和工作簿范围另有资源保护。图片 OCR、PDF 和任意其他附件不是此问单入口的输入格式。
- 数量列不明确时由用户选择后重解析。完全相同邮件跳过；同主题不同 PO 保留；同身份修订取新版本，无 PO 的歧义修订要求分开核对。当前回复明确更改交期/包装时，可复用最近引用表并保留引用原值与冲突警告，不能把整个邮件历史都当成新单。
- 客价使用原工具的 HKD 口径；确认价 USD 按原规则乘 7.8。模糊多金额不能直接采信。修改客名或装箱数会清除旧价格，必须明确重新核对价格。匹配回退和缺失信息保持可见，用户仍须逐项确认后导出。
- 生成时服务端重新解析原件、核验指纹/参照版本，统一分配原格式 `01YY-NNNN/NNNNN`。编号不在浏览器计算；并发串行占号，延续参照与历史导出最高流水。重复请求、历史重新下载不占新号；不同账号重复录入相同业务身份也会阻止。超过五位流水上限时拒绝，不循环复用。
- 输出保持 44 列金山问单布局，保留前导零、明确日期/数值类型，邮件文本不执行为 Excel 公式。原始输出、所选行、人工更正、原因、引用原值、参照版本和原邮件均保留于受权限保护的记录中。未选行不占号。导出记录只追加，不能直接删除重用编号。

## 部署与回滚边界

1. 部署前备份数据库，并在还原副本先演练。此功能新增迁移 `20261015_0163`，父版本为 `20261015_0162`，创建五个独立的 `jp_intake_*` 表，引用现有不可修改的 `order_ledger_sources` 原件表；不改变既有正式订单表结构。
2. 在正确的后端环境按仓库 Alembic 部署流程升级。新表不随应用启动自动创建；缺迁移时界面/API 明确提示不可用。不得拿开发测试库覆盖业务库。
3. 更新同版本前后端及 Nginx。仅 JP 文件计算接口采用 55 MiB 请求上限、270 秒等待；普通接口的短超时和维护模式拦截保留。
4. 先用授权华康B业务账号上传参照，复核编号起点及选定邮件，再由业务人员验证实际金山导入。其他厂区不显示此入口，接口也拒绝越厂操作。
5. 回退应用代码可隐藏入口，但必须保留新增表、原件和已分配编号。有任何问单证据或计数时，迁移降级会拒绝删除。不得手动重置计数器或删历史来“恢复编号”。

## 本地验证与未完成的现场验收

自动测试覆盖 SQLite 显式迁移/证据保护、PostgreSQL 离线 DDL、编号并发/幂等/重复身份、权限撤销/厂区隔离、文件安全边界、参照冲突、44 列导出以及前端过期响应/价格复核。真实本地五封邮件与旧纯解析器逐行核对，原始行数为 5/1/3/3/13；新版保留不同 PO 共 25 行，避免旧主题去重漏掉 3 行。原件哈希保持不变。真实排期索引也与原工具作只读比较。

真实邮件联合预览用合成价格表隔离测试，没有据此认定真实业务价格正确。实际 PostgreSQL 升级、真实 Nginx 运行及浏览器全链路、生产发布和实际金山导入均须在相应环境另行验收；GitHub PR 不等于线上已更新，也不能保证所有邮件格式无误。
