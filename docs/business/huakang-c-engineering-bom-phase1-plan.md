## 1. 实施结论

第一期应采用“复用业务事实与执行账，新增工程和需求采购能力”的方式实施：

1. **复用订单中心**的订单行身份、版本、下发和走货记录，新增业务侧 BOM 选用、需求确认及内部订单／补单入口。
2. **扩展现有华康 C 物料档案**，补齐 01～04 分类、负责部门、计量和版本依据，不再建立独立于仓库的同名物料库。
3. **新增多层工程 BOM**及不可变审核版本，通过明确的适配关系供裁床使用；不把裁床现有平铺 BOM 强改为全厂工程模型。
4. **复用仓库的实际收发账**，新增库存和采购在途的占用记录，并将占用保护接入收发、盘点和更正等所有相关写入路径。
5. **新增采购申请及供应商采购订单业务**，扩展采购来源衔接；现有采购来源表和 ETA 回复不能直接冒充采购订单。
6. **保留在执行旧订单的原通道**，新通道按订单明确启用，防止同一订单在裁床旧需求和业务新需求中重复采购。

主要工作量在跨模块一致性、占用、变更和过渡，不只是增加工程页面。第一期只有工程基础、业务采购衔接和变更闭环全部验收，才算完成。

需求权威：[工程 BOM 需求规格](huakang-c-engineering-bom-requirements.md)。本计划中的表名、接口名、路由名是拟定名称；不代表现有接口，也不擅自把需求文档中的待定业务规则改成已确认规则。

### 2.2 特别需要处理的现有差异

- 旧裁床允许明确选择一个历史已发布版本，也允许填写货号不一致的对应依据；新工程通道要求新订单只能选择未被替代的有效版本，货号不同须复制。不能只限制前端下拉框而让旧绑定 API 绕过新规则。
- 旧裁床需求由工程提交，ETA 权限归现有 PMC／仓库部门；新需求由业务确认，采购单只能采购开具。不能简单把旧工程提交接口授权给业务，或把整个仓库岗位提升为采购岗位。
- 仓库当前可用量表达“现场当前可用的批次结余”，不等于“扣完订单占用的可承诺数量”。已确认待检材料经仓库批准可以抵扣，需新增有范围的抵扣批准记录；原库中的待检批次不能批量改成合格以满足新算法。
- 采购来源存在直接结构化入口，但其身份语义固定为金蝶。自建采购必须采用真实的新来源身份，不能伪装成金蝶或通过假 Excel 导入。
- 半成品 `PROCESS_SEND`／`PROCESS_RETURN` 是特定仓库流程，不等于任意布料贴合／刺绣的通用委外订单，应只复用适用的收发证据。

## 3. 复用、扩展、新增能力清单

“直接复用”仍需要权限和回归验证；“扩展”保留现有身份和历史；“新增”指目前没有满足本需求的领域能力。

| 能力 | 处理方式 | 具体实施边界 |
| --- | --- | --- |
| 登录、会话、厂区和部门授权 | 直接复用＋注册新权限 | 沿用后端权威检查、显式拒绝及身份版本；不自动给现有岗位增加采购权 |
| 客户订单身份、版本、下发、走货 | 直接复用 | 使用 `line_id`、版本和 dispatch 身份；不另建同一客户订单台账 |
| 业务 BOM 选用和材料确认 | 新增 | 与订单中心关联的需求工作区；材料规划不塞进客户 PO 解析逻辑 |
| 内部加工订单、补单 | 扩展订单来源＋新增流程 | 明确内部／补单类型、原单关联和人工录入证据，不伪造客户导入来源 |
| 华康 C 材料、供应商、仓位、单位档案 | 扩展 | 保留现有 ID，增加工程分类、负责部门和版本信息；只把适用物料映射为仓库类别 |
| 多层 BOM、工序和分子／分母 | 新增 | 不把现有 `quantity_per_set` 当原始结构；保存完整引用图和来源 |
| 审核、历史、冲突和幂等模式 | 复用模式＋新领域实现 | 使用独立领域身份及命令收据，不直接共用裁床命令记录当工程审计 |
| 裁床部件配套、排期、报工、领料及成本 | 直接复用＋适配 | 不重做排产报工；用工程版本生成固定裁床执行依据；保留旧计划失效和锁月保护 |
| 库存实收、批次、发退调、盘点／更正 | 直接复用＋占用保护 | 原实物账是唯一来源；补齐占用身份随移动、冲销及更正的处理 |
| 净需求计算、库存／在途预留 | 新增 | 独立分配账、需求版本和事务检查；不能把领料申请或发料 allocations 当预留 |
| 采购来源、收料和到料查询 | 扩展 | 建立新采购行到现有来源行映射，实收继续走原仓库；导入历史需去重和资格核验 |
| 采购申请、供应商采购单 | 新增 | 开单、供方、数量、交期、版本、取消、生产状态及打印／导出，不默认包含付款结算 |
| 内部供料计划 | 新增＋复用实收 | 业务录入供应车间、数量和日期；供料不自动入库、不生成外购申请 |
| 委外加工需求 | 新增＋适配收发 | 加工输出和自供原料分别建需求；不迁用裁床结算规则 |
| 历史文件提取 | 有条件复用 | 复用 `.xls`／`.xlsx` 提取及限制机制，新增 BOM 专用解析、核对与批次管理 |
| 固定工程 Excel 整表自动建 BOM／图片 | 二期 | 一期只预留附件和来源关联，不将二期识别工作计入一期验收 |

## 4. 建议的领域边界和数据设计

### 4.1 一份事实由一个模块维护

| 事实 | 权威模块 | 其他模块如何使用 |
| --- | --- | --- |
| 华康 C 物料身份与负责部门 | 扩展后的共享物料服务 | 工程和仓库读取同一记录，维护动作按字段和岗位授权 |
| 工程组成、工艺、有效 BOM | 新工程模块 | 业务选择、裁床适配、采购查看固定版本 |
| 客户／内部订单及补单身份 | 业务订单域 | 工程需求和裁床关联稳定订单行，不重复录入客户事实 |
| 订单用料及损耗、确认结果 | 新需求域，业务确认 | 采购申请、占用和生产供料依据 |
| 供应商采购承诺及生产状态 | 新采购域，采购维护 | 仓库读取可收来源，需求域读取可用在途 |
| 实收、实发、退回和结存 | 现有仓库域 | 需求只计算可分配量，不能直接改结存 |
| 预留、释放、耗用关联 | 新分配域 | 所有影响可用量的写入都检查，不能只在业务下单时检查 |
| 裁床计划、报工、签收及成本 | 现有裁床域 | 工程变更引用其事实判断影响，不改写已执行结果 |

### 4.2 物料方案

优先扩展 `FabricMasterRecord` 的 MATERIAL 身份作为华康 C 本次 01～04 物料的统一入口，配合独立工程扩展／版本结构。保留其现有 ID 和供应商／仓位／单位数据，不批量改名迁表。若准备阶段发现模型约束不足，可新增工程扩展表，但不能再新增另一套不关联的编码主表。

需要补充分类树、负责部门、制造／供料属性、基本／库存／采购单位、适用仓储类型及不可变版本。现有 FABRIC／ACCESSORY／THREAD 是仓储业务类别，应与 01～04 工程分类并存，不能把所有 04 半成品强制归为 FABRIC。

已确认职责为工程文员建立并审核物料、采购维护供应商、仓库维护仓位。保留历史编码，新号按分类自动续号；换负责部门不换编码，保留稳定身份及部门变更版本，历史单据依据不变。新增字段／动作授权不能直接复用整个仓库导入权限包。

对旧 `CuttingMaster(kind='material')` 建立显式版本映射。仅凭同码不能自动认定相同材料，应核对名称、规格、色号、单位；冲突由人工处理。全局 `RawMaterial` 只在确有同一身份时建立关联，不将其 `factory_id='*'` 改为华康 C。

### 4.3 拟新增的逻辑记录

| 记录 | 主要字段和约束 |
| --- | --- |
| 工程 BOM 头／版本 | 独立 BOM ID、货号、适用标准、状态、有效版本指针、复制来源、审核人和时间；发布后不可变 |
| BOM 节点／用料边 | 稳定边 ID、父节点、材料版本、子 BOM 版本、分子、分母、工序、供料属性、来源；环路校验 |
| 工程物料扩展／版本／映射 | 现有 material ID、分类和部门、单位、旧裁床／仓库／全局身份及核对证据 |
| 工程导入批次／问题 | 文件摘要、模板／解析器版本、原位置、原值、候选、修正、提交结果，重复导入可识别 |
| 订单需求版本／明细 | 订单行版本、BOM 快照、损耗率及免损项目、完整展开路径、采购分工序填写的物料期及版本、确认人、规则版本 |
| 采购申请及来源分配 | 需求行、拟采购数量、采购状态和已转换数量；防止申请重复转单 |
| 采购单／行／版本／事件 | 供应商、材料或加工项目、数量单位、必要商务字段、承诺交期、供方生产状态、取消及变更证据 |
| 供给身份及占用／释放事件 | 库存批次或采购行、需求行、数量、单位、版本、状态、释放／实发／转实收关联 |
| 内部供料计划／批次 | 内部订单、来源车间、材料、计划量、预计日期及实际收料链接 |
| 委外加工需求 | 加工输入、输出、工艺版本、需求量及原料分配，不承担本期财务结算 |
| BOM 变更单／影响及补单链接 | 原新版本、用料／用量／工艺差异、订单状态、采购处置、补单和结果 |
| 跨模块映射／应用收据 | 工程版本→裁床版本、采购行→仓库来源行、需求版本→裁床依据；唯一来源键防重复应用 |

上述是概念拆分，不要求每一行一张表。设计审查后确定数据库 Schema；需求路径及版本差异不可只存可变大 JSON 而没有身份、索引和关键唯一约束。

### 4.4 计算合同

- 后端以 Decimal 计算，保存原分子／分母和规则版本；前端只预览，不以浮点结果作为权威值。
- 按固定版本图逐路径展开，再按材料、版本、单位、本次物料属性、供料归属及用途规则汇总，保留回溯到原边的关系。同编码自制／委外分开；业务逐行选择随单冻结，不改工程档案，后续采购合并同样遵守此边界。
- 标准用量与历史“实际数量”一致，不借此记录实发和耗用。
- 订单损耗按 `理论量 × (1 + 订单损耗率)`，免损项目不加；原料和加工分别验算，不能层层重复加成。
- 净需求从含损耗需求扣除本次合法库存／在途分配，零以下显示为零，但不得隐藏超配或重复分配错误。
- 采购、库存和基本单位不一致时，使用已确认且版本固定的换算；无换算关系就列为阻断，不从名称猜测。
- 保留“需求总量、损耗、库存覆盖、在途覆盖、新采购、实际收发”不同字段，不能统一写入一个 quantity。

已确认采购数量有小数一律向上取整数。实现顺序为精确展开／损耗→库存及在途抵扣→采购单位换算→合法采购行汇总→向上取整，保留精确净需求和进位差额；31.185→32、31.001→32、整数及零不增加。不可把此规则扩展到 BOM 用量、库存事实、单价或金额，也不能逐层取整。加工与原料各计一次损耗：100 件／20 码加 5% 为 105 件／21 码。

## 5. 跨模块衔接方案

### 5.1 工程到裁床：固定的执行视图

新增工程到裁床适配服务，选择明确的工程有效版本，生成符合现有 `parts/requirements` 合同的裁床执行版本，并保存双向映射。

适配必须明确每套部件片数、当前裁床必需物料、非当前必需辅料和材料身份。完整 BOM 中无法投影到现有裁床语义的内容不强行填充；必须显示适配问题，工程确认后才能下放。非裁床产品可有工程 BOM，但不能为了发布而伪造“必需裁床材料”。

已映射到新通道的裁床执行版本不再作为独立人工编辑的第二个主 BOM。裁床仍读取自身固定执行依据用于报工和配套核算，历史执行版本保持原样。

业务新需求确认后，通过专用适配动作写入裁床可读取的供料依据，记录真实业务确认人和需求版本。不能冒用工程账号调用旧 `requisition` 接口。需要在裁床侧显式识别 `legacy`／`engineering` 来源模式：

- `legacy`：旧工程手工需求及原撤回核对继续运作。
- `engineering`：新业务确认的需求为唯一来源，旧手工提交入口不能再为同一来源生成采购需求。
- 库存覆盖、客供和在途覆盖分别成为供料证据，不伪装成供应商 ETA；裁床预计齐料计算要能读取这些来源。
- 实际开工／实料依据仍来自现有实际领料和签收，不由采购预计日期自动确认。

### 5.2 业务到需求：引用订单版本

客户订单中心继续保存原 PO 和订单事实；新增关联工作区完成 BOM 选择、损耗、需求日期、内部供料和确认。计算提交前再检查订单版本、BOM 有效性和材料状态。

工程设置默认免损项，业务确认并可修改订单损耗率及例外；已确认后修改形成新需求依据并评估采购影响。物料期由采购分工序填写，生产按物料期编排计划；业务不代替采购维护物料期。日期修改保留版本并重算受影响供给、提示生产调整。首次填期时点及物料期与在途抵扣截止、供应商预计到货日的对应仍需流程实例明确，不能按在途自身交期循环判定其可用。

内部加工订单和补单需要扩展明确的订单来源类型和人工录入 API。优先沿用现有 `OrderLedgerLine` 身份，使裁床外键和下发链可复用，但为其增加合法来源合同，禁止伪造特定客户 PO 导入、伪造走货或复制原订单的已走数量。

补单明确区分补料、返工和追加成品；只有追加成品增加客户待交数量，补料／返工保留原交付基数，仅生成实际补充需求。各类补单关联原单和版本，补 PO 数量由业务负责；生产不足报数给业务补放，工程补用量建补料单经业务下推采购；补足原交付目标不增加客户需求。

订单更改或取消后，需求进入待核对，保持原占用和采购处置证据，不能静默重算并释放正在履行的采购。下发快照只增加经审查的业务关联字段，不把完整 BOM 或内部价格塞进所有部门都能读取的白名单。

### 5.3 采购到仓库：采购行与来源行一对一关联

新增本地采购来源类型（拟名 `NEXUS_PURCHASE`）及采购行稳定身份，扩展受控的来源衔接服务。沿用现有 `FabricProcurementLine` 和原收料 API，避免新采购模块再造收料表。

采购申请由下单业务自行审核；采购员制单，由采购负责人下发供应商。取消／改量由采购员提交采购负责人审核批准。服务端分别控制制单、下发和变更批准；待审采购单不形成有效在途，内部批准不代替供应商取消结果。

- 本地采购行与仓库来源行建立唯一映射，不依靠“采购单号＋物料名称”匹配。
- 一张采购行可分配多个订单，分配表保留需求量；仓库实收仍只记一次。
- 金蝶来源和本地来源有不同身份及更新权限；旧 Excel 导入不能覆盖新系统采购行。
- 已存在的金蝶来源需要明确绑定和核验后才能作为可用在途，不能将新增本地订单和原导入记录重复计数。
- 发出采购单与仓库可收来源应保持可恢复的一致状态；同库优先使用组合事务。现有 `apply()` 内部 commit 不能原封不动嵌入新事务，应拆出事务内核心并保留旧接口行为。
- 仓库收料、更正、冲销和交接单收料都回传同一采购行进度；采购未收量使用实际履行事实，不用来源 Excel 累计值重复扣减。
- 旧源有 `baseline_known=false` 或来源冲突时，先核对真实余量，不擅自按零已收处理。

### 5.4 库存和在途占用：必须覆盖写入端

新增占用服务，由数据库约束和事务防止重复分配。可用量查询统一经过该服务，但原库存结存仍从仓库权威事实读取。

| 事件 | 占用应发生的变化 |
| --- | --- |
| 业务确认需求 | 校验并建立库存／在途分配，剩余量生成申请 |
| 原采购到货 | 将相应在途占用转到真实收料批次；不额外创建一份可自由分配库存 |
| 按本订单发料 | 实物库存扣减，同时将对应预留转为已履行，不能重复扣两次 |
| 其他订单或直接发料 | 只能使用扣除他单占用后的余量，或经过明确授权的重新分配 |
| 调仓、拆批、合批（如支持） | 维持供给身份追溯并迁移占用，不因换批次 ID 释放占用 |
| 退料、发料冲销、实收冲销 | 根据原单依赖恢复或撤销关联；不能无条件释放已经被后续单据消费的量 |
| 盘点减少、质量限制、采购取消／减量 | 检查受影响预留，形成缺料或重新分配处理，不允许剩余供给小于有效占用而静默成功 |
| 订单取消／变更 | 先核对采购和生产状态，再按明确处置释放或重绑 |

现有 `WarehouseDocumentRequest.allocations` 只是按生产号记录本次实发分配，不能用其代替上述预留模型。

实施时绘制完整锁依赖图，保持已有“裁床→源订单→布料”顺序；需求、采购和材料新增锁必须在所有入口采用相同顺序，不能在持有布料锁后反向请求裁床锁。组合服务要显式管理事务边界，禁止嵌套提交破坏原子性。

### 5.5 变更和供应商生产状态

新增独立变更单。工程发布新版只生成影响评估，不自动改原订单及采购。

- 本车间未生产：业务确认新需求；采购核实供应商状态，完成旧单处置后建立新采购。
- 供应商未生产：核实取消原采购，更新对应在途／占用，再采购新料。
- 供应商已生产：保留原采购义务，已产未到仍为在途；实际入库后形成库存，不因改 BOM 自动生成入库。
- 本车间已生产或部分走货：以生产主管登记实际开工为节点，另开补单，原生产单不切换版本。
- 已全部走货：历史记录保持，新订单只能选当前有效版本。
- 部分已生产按数量拆分保留／取消：100 中已产 60 保留、未产 40 取消；只处理受影响行／数量，其他明细不变。采购员提交、负责人批准，供应商取消生效后更新余量与占用。共享行分配、取消失败／未确认及状态未知继续核实，不自动释放。

## 6. 分阶段工作包与依赖

建议按 P0～P8 推进。P1～P7 均属于第一期，不把采购、占用或变更延后为可有可无的“二期”。复杂度为相对工程风险，不是工期承诺。

```mermaid
flowchart LR
  P0[P0 规则和现状基线] --> P1[P1 物料身份和权限]
  P1 --> P2[P2 多层 BOM 和历史导入]
  P1 --> P4[P4 采购订单和仓库来源]
  P2 --> P3[P3 业务需求和裁床适配]
  P3 --> P5[P5 库存与在途占用]
  P4 --> P5
  P3 --> P6[P6 内部供料与委外]
  P4 --> P6
  P5 --> P7[P7 变更与补单]
  P6 --> P7
  P7 --> P8[P8 回归、试点与切换]
```

### P0：规则收口与只读现状基线（高影响）

**输入**：需求文档、完整 01～04 物料表、历史 BOM 样本、当前接口和授权；二期图片模板可后补，不阻塞一期基础设计。

**任务**：

1. 输出现有材料／BOM／订单／采购来源／库存的身份关系和只读核对报告，不修改业务数据。
2. 落实采购数量向上取整数、加工／原料各加一次损耗、主管登记实际开工、供应商按已产／未产拆分且只改受影响行；继续核对单位换算、计算精度和异常取消细则。
3. 采用用户另供库存表及表格日期截止，由仓库核实，落实仓库批准待检抵扣并设计批准范围和证据，不改质量状态；等待表格、核对期间收发，物料／未到货采购也由用户提供表格。
4. 落实工程建审物料、采购管供应商、仓库管仓位、保留旧码／分类续号／换部门不换码；落实申请需审、采购员制单、负责人下发并批准取消／改量，落实业务自行审核申请；采购单含单价、币种、税率、交期、交货地点和付款条款，价格由采购员填。落实采购分工序填物料期、生产据此排计划，并核对日期与抵扣实例。
5. 明确内部订单及补单和现有客户订单账的兼容合同；确定不重复触发真实需求的来源身份。
6. 盘点迁移链、功能开关、现有员工授权及历史数据完整性，仅记录，不迁移或开通。

**交付**：字段合同、决策清单、材料映射候选、库存／在途资格基线、锁序和迁移设计、UI 简报。

**退出条件**：数量、权限和状态变更所依赖的关键业务决定明确；未解决项绑定对应发布门槛。可以继续开发不依赖该决定的部分，但不能把未确认决定当默认值上线。

### P1：统一物料身份、单位和权限基础（高）

**任务**：扩展共享物料服务，增加 01～04 分类和负责部门；建立不可变物料版本和旧身份映射；完善采购／工程／业务分别授权；工程和仓库入口读取同一身份，按字段权责编辑。

**预计触及**：`fabric_master` 模型／Schema／服务，现有材料查询和 `src/api/fabricMaster.ts`，新增工程物料 API，权限目录及显式角色升级流程，追加迁移。

**交付**：物料查询／维护、历史映射核对、单位合同、授权矩阵及迁移脚本。

**退出条件**：同色线跨工序共用编码；同码冲突不能自动合并；旧库存和裁床物料 ID 未被重写；仓库账号不能获得采购开单权限；迁移前后旧记录数量和摘要一致。

新增验收：工程可建立并审核物料；采购仅按授权维护供应商，仓库按授权维护仓位；分类续号并发不重码，换负责部门不换码且历史依据不变。

### P2：多层 BOM、版本、工序视图和历史导入（高）

**任务**：新增工程模型／API／前端；父子图和固定子 BOM 版本；按货号复制、工程自审、旧版退出新单选择；`.xls`／`.xlsx` 专用解析、原文对照、待建档和异常核对；发布阻断环路、缺项、零分母等问题。

**复用点**：版本与幂等模式、材料档案、基础文件提取、共用表格和历史展示。导入解析在受限执行边界内完成，复用提取接口前验证无表头 `.xls`、原单元格及数值精度不会丢失。

**交付**：新工程工作区、BOM 列表／详情／编辑、工序清单、导入工作区、不可变版本和审计。

**退出条件**：92167 样本正确恢复 39 行关系和 28 个唯一编码，保留同料多处用途；0.0297÷2 验算通过；BOM 编号不同于物料编号正常；未审核及已替代版本不能用于新通道下单；复制不修改来源。

### P3：业务需求确认和裁床适配（高）

**任务**：新增 BOM 选用、数量基准、损耗例外、需求日期、展开预览和确认版本；引用现有订单行，新增内部／补单合法来源基础；实现工程→裁床固定视图和需求来源模式；旧新入口互斥。

**预计触及**：业务订单 Schema／API 的限定扩展、业务工作区及新需求工作区、`cutting_orders`／`cutting_planning` 和裁床物料读取适配。现有客户模板解析保持原职责。

**交付**：可重现的理论需求结果、业务确认历史、裁床版本映射、完整来源链。尚未接通 P5 时，只能保存草稿／测试确认，不能对真实订单宣称净采购已完成。

**退出条件**：订单或 BOM 变更后旧预览提交被拒绝；业务身份真实留存；同一订单不能双通道提交；裁床配套数、必需材料、历史签收和已发布计划保护不被破坏。

新增验收：业务可确认／修改损耗及免损项，已确认需求变更不覆盖旧依据；采购分工序填写物料期，生产可读取版本化日期用于排计划，修改日期触发供给与排产影响检查。

### P4：采购申请、供应商订单和来源接入（高）

**任务**：新增申请转采购、供应商及交期、采购版本和打印／导出、供方生产状态、取消及历史；建立 `NEXUS_PURCHASE` 来源及旧金蝶绑定；仓库来源、实收及回传接入；采购开单与仓库操作权限分离。

**预计触及**：新增采购领域；扩展 `fabric_procurement` 来源合同和事务核心、`fabric_receiving`／交接收料关联、采购查询及新采购工作区。不要复制纸箱专有采购、计价和结算规则。

**交付**：有效采购单、仓库唯一可收来源、供应商生产状态证据、采购余量查询、异常恢复。

**退出条件**：申请重复转单、迟到重试不会多开采购；采购和仓库来源要么一致提交，要么保持可恢复失败；部分收货、冲销和旧导入重入不重复增加库存或在途；仓库人员 API 开单被拒绝。

新增验收：申请审核前不能进入正式采购履行；采购员无负责人权限时不能下发或批准取消／改量；采购数量向上取整数，差额可追溯；待审核单不计有效在途。

库存或未到货采购资料不完整时只保留草稿，暂不正式下单。

### P5：净需求、库存／在途预留及履行（最高）

**任务**：实现可用量资格判断、版本化计算、确认时事务占用；加入在途转实收预留、发料履行、释放和重绑；改造全部库存影响入口，覆盖直接／批量发料、交接单、裁床领料、盘点、调仓和更正。

**预计触及**：新需求／占用服务与记录，`warehouse_operations`、`fabric_receiving`、`fabric_inventory_setup`、`fabric_issue_groups`、`material_handover_procurement`、`cutting_materials` 等的受影响写路径。

**交付**：统一可分配量查询、业务确认与采购申请原子提交、预留明细和来源追溯、并发保护及回收处置。

**退出条件**：105−20−30=55；两个订单抢同一供给不能超配；任何发料入口都不能绕过他单占用；收货转换不产生自由量；更正、盘点及限制库存不会留下静默负可用量；PostgreSQL 真实并发验证通过。

新增验收：待检量只在仓库批准范围内抵扣，未经批准或后来冻结／不合格的量不能继续作为有效可分配供给；批准记录不修改质量状态、不产生采购权限，影响已有占用时必须明确处置。

### P6：内部供料和委外需求闭环（高）

**任务**：内部加工订单由本车间业务录入，保存供料计划和分批日期；客供与外购需求分流；委外需求保留工艺输出和供给加工商的原料；关联真实收料／发料证据。

**交付**：内部订单及供料页、委外加工需求和输入材料清单、到料／发料链接、来源及损耗例外。

**退出条件**：客供部分不生成供应商采购；计划到料不变库存；原料与委外输出不重复外购；同编码客供料可跨订单共用并保留来源与占用；仍禁止越权跨厂和重复抵扣。加工费结算不纳入本包。

### P7：BOM 变更、采购处置和补单（最高）

**任务**：新增影响分析和数量／物料／工艺差异；识别本车间开工和供应商开工两个独立节点；采购取消／保留、占用重算、新采购、补单关联；保留旧单证据。

**交付**：变更工作台、受影响单据清单、采购处置状态、补单及下游更新记录。

**退出条件**：未生产可按规则处置；供应商已产未到不自动入库；已生产本车间订单只走补单；已走货历史不变；纯工艺变化可见；部分生产／混单／取消失败按确认规则处理，不静默释放。

### P8：独立审查、回归、试点和切换（发布门槛）

**任务**：完成数据模型、算法、权限、锁序与迁移的独立审查；按第 9 节执行跨模块测试和浏览器验收；使用真实业务样本核对；第一批仅接华康 C 新订单，暂不迁入在执行旧订单。

**交付**：验收报告、差异核对记录、数据备份及迁移演练、权限清单、操作说明、回退手册和启用范围。

**退出条件**：需求规格一期用例 A01～A28、A30～A40 全部有结果，二期 A29 单独排除；库存、在途及采购业务人员签认；无未解释数量差；所有高风险问题解决后才允许正式业务切换。

### 7.1 最小接口合同

| 动作 | 请求须携带 | 返回及校验 |
| --- | --- | --- |
| 保存／复制／审核 BOM | factory、operation_id、expected_version、来源版本 | 新版本、真实审核者、材料有效性、图校验；重试返回原结果 |
| 导入预览／确认 | 文件摘要、解析器版本、预览 token、映射及补正 | 原行定位、阻断问题、草稿身份；过期预览不能覆盖 |
| 需求预览／确认 | 订单行及版本、BOM 版本、数量、日期、损耗例外 | 计算规则及输入摘要、需求版本、占用和采购申请；确认时重查供给 |
| 申请转采购 | 申请行版本、分配量、供应商、商务字段、幂等键 | 采购行及来源映射；累计转单不得超出有效待购量 |

## 8. 数据迁移、新旧并行与回退

### 8.1 迁移原则

1. 追加迁移，不重写已应用版本；实施时检查实际 Alembic head，不能在本计划预定未来迁移编号。
2. 先备份并在副本演练，新增表、字段和唯一约束默认不启用新写入。
3. 对照迁移前后订单、仓库、裁床及历史版本的记录数和内容摘要；禁止用重建库或重导入覆盖真实账。
4. 材料映射保留来源 ID；同码冲突报告出来，不批量猜测匹配。
5. 旧裁床平铺 BOM 不能反推不存在的多层关系。需来源证据补全后作为工程草稿审核，不自动宣布已升级成完整工程 BOM。
6. 历史采购来源只有核实身份、未收量、交期和可分配归属后才进入在途池；对未知量不作有利猜测。
7. 金蝶当前没有库存数据；以用户另供表格及表格日期作库存基线，仓库核实后设计期初接入。核对表格日内边界、期间收发和已有账，避免叠加重复库存；本轮不导入。

### 8.2 并行规则

- 按订单保存来源模式和接管状态，默认既有在执行单走原通道。
- 新通道新单只允许工程有效版本，并关闭对应旧裁床手工采购需求入口。
- 需要接管的旧订单先处理原申请、ETA、采购和预留，再在一个明确切换点建立新需求，不能先新建再慢慢取消旧需求。
- 原有历史版本查看不受新单选版限制；已发料、报工和锁月证据继续可用。
- 全局物料和他厂订单不参与本次自动迁移或数据合并。

### 8.3 回退边界

- 未发生真实下单时，可关闭新确认入口，保留草稿和新表供检查。
- 已存在采购、预留或收发后，回退不是删表、恢复旧数据库或解除所有占用。暂停新增需求／采购，保留读取和完成旧收发、释放／处置的能力。
- 应用回退版本必须能识别新来源并保护现有占用；不能回退到完全不检查占用的老发料接口。
- 失败命令先通过幂等收据核实执行结果，不能因网络超时自动重新开单。
- 发布前明确继续履行与补偿处理脚本，所有补偿保留原始事件和原因。

### 9.1 核心测试矩阵

## 10. 关键风险、门槛与最终交付

| 风险 | 控制措施 | 必须解决的阶段 |
| --- | --- | --- |
| 旧库存和采购未收基线不可信 | 来源资格核对；未知量不参与自动可用池；记录受限范围 | P0、P5 正式确认前 |
| 待检批次未经批准即参与抵扣 | 执行仓库批准抵扣规则，记录范围和批准依据；不改质量状态，不赋予质量放行权限 | P0、P5 |
| 同料三套身份冲突 | 单一材料身份、版本映射和逐项异常核对 | P1、迁移前 |
| 旧裁床平铺结构丢失工程树 | 工程树新增，裁床单向固定投影；原树不足时待补 | P2、P3 |
| 业务新需求与裁床旧需求重复 | 订单来源模式互斥、服务端约束和接管核对 | P3、P8 |
| 原仓库写路径绕过预留 | 全路径写入检查、并发回归及同一锁序 | P5 |
| 源采购与本地采购重复统计 | 稳定来源映射、旧导入不可覆盖本地单、实收同源 | P4、P5 |
| 部分生产／混单取消超范围或提前释放 | 保留已产、取消未产，只处理受影响行；负责人批准及供应商取消结果留痕，异常未定不自动释放 | P0、P7 |
| 名义停用后旧 API 仍选旧版或跨货号 | 新来源模式下后端统一选版及货号检查 | P2、P3 |
| 上线回退导致预留保护失效 | 回退版本保持占用保护与履行能力，不删新记录 | P8 |

第一期最终交付物应包括：功能与接口、追加迁移及演练、材料／版本映射、权限方案、数量验算样本、自动测试及独立审查记录、浏览器证据、员工操作说明、试点及回退方案。

第一期完成必须同时满足：工程资料可复用、业务可确认、需求可重现、库存／在途不重复占用、采购单可履行、仓库只记一次实物、变更和补单有完整历史。二期的含图片固定工程 Excel 自动建整份 BOM 不计入第一期完成条件。

本轮仅完成源码核对和计划文档检查，未宣称任何新增能力已开发或验收。计划采用阶段和依赖管理，待 P0 的数据质量与决策收口后再估算日历工期，避免在关键条件未知时承诺上线日期。
