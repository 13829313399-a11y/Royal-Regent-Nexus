# 注塑排产中枢 V3：实现与使用

依据用户提供的 2026-09-05 V1.0 开发规格和华兴 9.1 工作簿重建。原始工作簿只读，只分析“计划表”。历史迁移保持不变，新模型采用 `injection_v3_` 前缀。

## 已实现的范围

1. A：稀疏读取目标表、字段注册表、原始证据对账、Decimal 数量与日历纯函数。
2. B：共享模具、实物资产、本厂设备、需求和历史持久化；导入、编辑、后台查询。
3. C：交期优先的确定性排程、人工移动、甘特与机台视图。
4. D：开停工、累计班次报工、更正去重、订单分配、后续链回算和变化同步。
5. E：全字段工作台、四厂隔离、现场与交换表导出、往返和浏览器验证。
6. F：隔离数据库迁移演练、回归测试、部署说明与现行项目事实更新。

## 业务边界

四厂为华兴、华登、华康 A、华康 B；全局厂区目录不变。共享模具资料不等于复制实物，单副资产不得重叠。`/api/injection` 仍属啤办；新接口使用 `/api/injection-scheduling`。日常排程一次计算保存，不引入审批或发布流程。

真实历史数量、旧计划快照、正式排期与实际执行分别存储。旧表累计与班次明细不得叠加；未证实的历史物理口径独立保留。未开工不得显示在产。价格、重量等缺项只影响对应估算。

源码交付与生产部署分开核验。当前完成本地开发、隔离数据验证和本地数据库启用，生产部署及生产数据导入未执行。

## 真实工作簿与公式

原件 `华兴啤机日排版表9.1.xlsx` 仅读取“计划表”。SHA256 为 `07b4878ed052598c83a103a1a4abf7cadeb5bfd4839e4a12a2452ee7724b832f`，分析后保持相同。附件 MD、独立提取器及取证 JSON 均只读。

| 核对项 | 结果 |
|---|---:|
| 机台 | 76：旧 39 / 新 37 |
| 需求候选 | 280：机台区 210 / 尾部 70 |
| 数值 L / N 行 | 274 / 273 |
| 原 ΣL / ΣM / 缓存 ΣN | 5,540,233 / 2,253,660 / 3,186,573 |
| 标准 Σ(L−M) / 原 N360 差额 | 3,286,573 / 100,000 |
| 数值班次格 / 合计 | 1,449 / 2,267,721 |
| 班次与 M 差额 | 14,061，挂回 6、118、131、132、134 行 |
| 公式节点 / 缓存 #N/A / 有日期班次列 | 4,739 / 40 / 570 |

原公式、缓存、错误、原行列和快照全部留证。L89/L121 除 2、L220 除 4、L370 除 8 保留来源口径，不统一猜穴数。N360 原空值不改写；标准欠数单独计算。AE 错用 AS、尾部旧日期、AF 周序号差、AT 未解释数值不参与新调度，AW/AX 无日期数不当成今天。共享公式节点与独立提取结果逐项对比。

正式计算使用 Decimal 和语义字段。剩余啤数除以有效速率后穿过真实工作日历计算时长；价格、重量缺失仅影响对应金额/重量。保留可编辑的日目标 24 小时基准、3 天后工序准备和 1% 材料附加建议。维修使用实际时间区间，不使用 WEEKNUM 差。

## 四厂统一模板：填写、导入及保留原机台

四厂使用工作台右上角的“下载统一模板”，格式沿用华兴原表：只有一张“计划表”，保留第 3 行原表头、A:AX 原列顺序、青色机台分组、隐藏辅助列、前三行及前十九列冻结、右侧白班/夜班横向记录。下载窗口显示本厂设备数量，可选择每台预留 5、10 或 20 条空白任务行，默认 10 行，末尾保留待排区。设备台账尚未建立时先维护本厂设备，再下载模板。每次最多导入 5000 条需求；旧华兴表、上一版平铺统一模板及系统标准交换表仍兼容。

1. **先准备常驻资料**：在本厂设备库登记机号，在公共模具库登记模号，并核对实物模具所在厂区和可用状态。统一模板不会新建设备、公共模具或实物模具。
2. **核对表头信息**：F2 由下载厂区带入，I2 为固定排期起点，例如 `2026-09-10 08:00`。从对应厂区下载以取得本厂设备和参数。新下载文件修改 F2 后与模板所属厂区不一致会被拒绝；上传页面的厂区也必须一致。文件名包含厂区，方便分发。
3. **在机台下方填需求**：每行填写工模、单号、货号、订单数、颜色、色粉、用料等原有业务字段。不用再填写需求编号或机内顺序。机台分组内从上到下就是排队顺序，空白任务行会跳过。需要更多任务时插入整行，并复制同组 A:DJ 任务区域及公式，不要复制整行数据覆盖隐藏基础资料；复制新机台组后填写不同的本厂机号。
4. **安排或留待排机**：只在青色机台行的 A 列维护机号，可从本厂设备下拉选择，规格、机械手、状态和备注同步从下载快照查找。B 列作为隐藏辅助列自动继承机号，不再手填第二遍。机号按文本保存；`1`、`01`、`B1` 是不同机号，华康 A 的 `1` 和华康 B 的 `1` 也分别匹配各厂设备。系统统一全半角和字母大小写，不删除前导零或前缀。同一台机器的任务放在一个分组里。没有安排机器的任务放到末尾“待排区”。原行机号与机台分组冲突时预览列出行号及两边机号，先核对再把整行移到正确机台组并复制该组公式。
5. **补全排产参数**：日目标按 24 小时基准填写。机安、日目标等空白时可以取已维护的公共模具值。机械手仍按设备能力核对；自动化状态、可拆卸夹具和吸盘只作为准备参考。用料中的树脂和牌号参与设备限制核对，备注中的暂停、待料、待通知或修模保留为待处理状态，不能直接生成开工队列。未知参数不要猜填 0。
6. **记录产量并检查公式**：AW、AX 记录本期开始前累计已啤数；BA:DJ 按日期记录 31 天白班/夜班产量。M 自动相加汇总，期初和本期产量不可重复填写。N 欠数为 `MAX(0,L订单数−M已啤数)`，AM 啤货天数为 `欠数÷日目标`，V 料重及 X 金额沿用原位置。未知重量、价格或日目标仅让对应计算留空。Excel 计划日期为连续生产参考，系统结合班历和设备占用计算正式计划；原表的周序号差不会再被当作停机天数叠加。右侧日期从 I2 起算，已有班次记录时不要随意改 I2；换期先结转期初并清空本期记录。
7. **上传并核对预览**：在 Excel 重新计算保存后点击“导入 Excel”。预览显示从分组和行位置识别出的机号、顺序及已排机数量。无效机号、相同业务身份重复行、缺少实物模具或适机冲突会指出原行。修正后重新上传，也可明确跳过问题行再应用。
8. **应用后核对队列**：已排机的未完成需求按表中机器和先后顺序生成待开工批次，未排机需求进入待排区。表外已有任务保留在队列前方。导入不会自动换机，也不会替操作员实际开工。

名称、机型/机安、日目标、净重、毛重、单价、机械手及夹具通过本页隐藏区的公共资料快照查找。快照在下载时读取系统基础资料，不含历史订单和产量，也不反向更新公共模具、设备或实物资产。公共资料更新后重新下载，或导入后使用“应用最新公共资料”。现场可以覆盖本单参数，空白参数在导入时仍可由系统公共资料补全。

首次 M 列“已啤数”整体计入期初累计，不伪造系统班次报工。系统按工模、单号、货号、颜色、色粉、用料生成厂区内稳定身份，调整行位置或数量可识别原需求；同一业务身份不要分成多行，拆批在系统内处理。修改这些身份字段应使用系统界面或标准交换表，不能靠修改模板身份字段覆盖旧需求。同一文件重复应用不重复新增，完全无变化重导保留现有操作。有系统独立修改、合并或生产记录时拒绝模板覆盖。表中删行不等于删除系统需求，误导入清空仍使用下文的确认流程。

已有旧华兴或手工需求如果业务身份相同，统一模板会提示重复风险，不另建一份。换用新模板不要求清空当前生产记录；可从新增需求开始使用。模板是普通顺序啤数计划，同啤向量、双色出件或同模多副选择等复杂情况先导入为未排机，再在系统配置后排产。

当前模板版本 `RR_INJECTION_HUAXING_V2` 由 `huaxing_template.py` 定义，原样排版通过 Artifact Tool 构建并随源码打包。`GET /api/injection-scheduling/templates/plan` 需要当前厂区排产权限，按本厂设备展开机台组并写入公共资料查找范围，运行时不依赖 Excel。上一版 `RR_INJECTION_UNIFIED_V1` 仅保留导入兼容。应用复用既有厂区版本检查、共享资源锁、幂等记录和整批事务，选中行有错误则整体回滚。没有数据库迁移。

## 日常流程与业务规则

1. 选厂并导入，检查数量、原表问题和差异。多候选明确选择或跳过；部分成功的冲突仍留在预览中，不静默覆盖。
2. 维护公共模具、实物资产、本厂机台、班制日历和参数。需求本单覆盖与主档来源分开；点击“应用最新公共资料”才应用新的主档字段。
3. 自动排产直接保存，可选仅未排、选定机台/需求、全部未开工。预览不写排程，撤销读取操作记录，无审批/发布流程。
4. 拖排可换机/插队，12A 模不能进 7A 机；明显上放需本次明确确认，仍校验其他约束。详情可固定机台和队列位置。
5. 现场实际点击开工后才显示在产。卡片展示真实累计、本班量、剩余、下一计划。检修会暂停批次；恢复未知显示“等待恢复”，仍保留机台与实物模具占用。
6. 白夜班报工输入本班累计物理啤数，0 为已报零，空白为未填写。默认选业务时区当前班次，凌晨夜班归前一生产日。粘贴先预览、逐行保存反馈；Esc 清除该行物理量/良品/废品全部草稿。

普通组甲欠 60、乙欠 80，报 100 分配甲 60/乙 40，物理累计仍为 100。同啤向量 A 每啤 2/B 每啤 1，欠 A100/B80 时需 80 物理啤次，可填写各产物累计良品与废品；同一产物只填一次。历史 M 与历史班次不叠加，未确认旧双色口径不冒充物理量。

本班 200 改 250 仅加 50，再改 230 回减 20。相同操作 ID 重试不重复，修订过期报冲突。转机建立新执行段承接剩余，旧历史/更正不搬走；结束段不能被重排复活。

排程检查 A/允许上放、卧式/立式/双色、高速硬要求、禁排机号、抽芯/电热等设备能力、机械手、材料牌号、资产位置和日历。更大机器不会自动提高速度。先交期和可行交付，再比较转换/适配，同模同色仍检查材料改变。模具占用包括转换与生产，副模为独立资产；组团保留子单身份与交期，不增加更急任务延误。

**全自动状态不影响排期；夹具、吸盘、夹子等可人工装卸的工具属于生产准备信息，不是排产硬性条件。** 在“基础资料 → 本厂设备 → 编辑”中，这些字段可以按实际情况记录；未填写、全自动填“否”或未登记对应夹具，都不会因此阻止排程。公共模具和需求中的夹具要求仍保留，供开工前准备。原计划导入、自动排产、人工调机和组批使用同一规则，也不会仅因这些填写内容不同而拆开连续生产组。单据原始值和来源不会被改成“全部具备”。

规则修正后，之前被这两项条件拦住的待排需求可再次预览排产；已有计划不会在更新程序时自动改动。其他硬性条件不满足的需求仍会显示对应原因。

## 看板多选和全选开工

1. 进入“排产工作台 → 看板”，确认左上角厂区。只有具备本厂报工权限的账号会显示批量开工入口。
2. 可先按车间、机台搜索缩小范围，或勾选“仅待开工”。点击卡片左上角方框选择多台；点击“全选待开工机台”会选择当前机台筛选范围内的全部待开工机台，包含滚动后才能看到的卡片。没有下一批、正在生产、已暂停或设备停机的机台不可选，卡片会说明原因。
3. 检查“已选 N 台”，点击“批量开工（N）”。窗口按机台列出下一批模号、关联单号、剩余啤数和当前核对结果。此时没有写入开工记录。
4. 有问题的机台会显示具体原因，可以点击对应行“移除”。若两台选择了同一套实物模具，须保留其中一台再核对；不同编号的独立实物模具不按模号一概排斥。
5. 核实现场已经准备好后，点击“确认现在开工（N 台）”。该按钮只提交本次核对为可开工的机台，并以实际提交时间记录开工；每台只开工已保存队列的第一批，不会把后面的所有任务一起开工，也不会自动填入报工数量。
6. 结果窗口逐台显示“已开工”或未成功原因。成功机台更新为在产并取消勾选；未开工机台保留勾选。处理原因后可点击“重新核对未开工机台”，再次核实后提交。

切换厂区、车间、机台搜索或筛选条件会清除选择。勾选后如果“下一批”发生变化，必须取消勾选并重新选择，不会悄悄换成另一批。核对后资料被他人修改时，会保留选择并要求重新核对；网络中断时重试同一操作不会重复开工。自动排产的预览不会成为开工任务，只有已经保存的计划可被勾选。开工沿用实际设备、实物模具占用和停机日历检查；全自动状态和可装卸夹具仍为准备参考信息。

## 导错计划表后清空并重新导入

1. 先确认左上角厂区，进入“排产工作台”，点击右上角“更多 → 清空本厂计划数据”。入口需要本厂排产权限；请先保存或取消正在编辑的内容。
2. 核对预览中的需求、排产任务、班次报工、导入历史产量、导入批次和机台占用数量。**范围是当前厂区的全部计划数据，包含手工新增需求，不受筛选条件、当前页或勾选行影响。** 展开导入批次可以查看文件名。
3. 点击一次“确认清除”即可，不用填写原因、输入确认文字或额外勾选。如果包含已开工、暂停、转机、结束或报工记录，窗口会明确说明这些生产记录也将一并删除；此时账号仍需要本厂报工权限。
4. 成功后计划表、甘特和报工记录同步刷新，选中行、筛选和分页归零。再点“导入 Excel”，选择正确工作簿，检查预览并应用；同一份文件也可以重新导入。

清空会保留公共模具库、本厂设备规格、实物模具、班制日历、排产参数、保存的视图和其他厂区数据。被清理任务的机台占用及当前工艺会重置；故障、维修状态和恢复时间保持不变。“清除筛选”仅恢复显示范围，不删除数据。

关闭窗口或点击“取消”不会删除任何记录。若预览后有人修改了数据，系统会拒绝旧确认；点击“重新预览”核对最新范围后，再点“确认清除”。有生产记录却没有报工权限时，请由同时具备排产和报工权限的本厂人员处理。

删除及清空前审计快照在同一事务中保存，失败会整体回滚，重复提交同一操作不会重复删除。清空不能通过“撤销排产”恢复；重新导入只恢复工作簿中的数据，不会恢复原来在系统里新增的需求、开工或报工记录。
