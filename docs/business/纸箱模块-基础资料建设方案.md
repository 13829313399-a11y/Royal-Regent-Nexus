# 纸箱模块基础资料建设方案

> 状态：第一版已实施。实际落地范围和边界见下方说明；后续章节保留建设设计，不能将其中所有扩展项视为现成功能。  
> 编写日期：2026-09-08。  
> 依据：当前纸箱模块的客户维护、订单录入、交期推算、收料、分仓库存及领用逻辑。

## 第一版落地范围

- 页面分为“基础设置”和“货号与包装”。基础设置集中展示本厂通用交期、客户与规则、可展开的关联合同、车间与仓位及折叠的维护授权；客户继续复用原有客户表，直接在客户行打开资料编辑。
- 自动整理完整正式历史订单和已接受的历史导入，正式确认新订单时同步补充。不把 OCR 预览或未确认普通订单当成基础资料。
- 以工厂、客户、货号及整套包装内容区分配置；纸品类型、材质、规格、尺寸单位、计量单位和每箱产品数一起保留，落单主动选用，多套或不同配置软提醒。
- 高级维护可修改内容、推荐、启停用并留下原因和前后快照。自动整理保留原始、当前和已有来源中的配置关联，不覆盖人工修订，不恢复停用项。
- 编号规则支持前缀、长度、字符范围，可选择不检查、提醒或强制检查；合同关联新货号及其他客户同号单独提醒。停用合同不能新建订单；已保存订单的日期和备注修改不重新套用格式规则。
- 新单采用工厂默认／客户覆盖的采购提前量，未配置时为 3 个自然日，计划交期最早为下单当天。客户交期建议可单独关闭，需要落单时主动采纳；旧订单和追加保留原提前量。
- 仓位采用稳定 ID，可更名、启停用；停用后不能新增入库或调入，仍能清退和受控冲销。普通收发不能借自由文本自动建仓位。可按仓库名称向已有本厂库存权限的负责人授权维护，修改仓库归属同时核对原、目标仓库权限。
- 车间单独维护，单笔／多选出库可指定车间，逐行可覆盖统一车间。流水保存当时的车间名称，后续更名和冲销保留原证据；这只记录领用去向，不是车间实际耗用账。

第一版边界：编号格式可优先按填写样例、否则按正式历史识别，保存后固定且可手动修改；不以历史单价作为基础资料默认价；跨年度同号合同暂不区分批次；没有独立包装版本编号、批量复制版本或日期模拟器。资料与来源目前全量返回，尚未完成大规模历史数据性能验证。完整客户名单、编号规则、车间和授权仓库应由有权限人员按现场实际维护。

## 1. 判断与建议

方案可行，而且能解决现在反复输入、沿用错误历史资料、客户与货号选错、仓位名称随手填写等问题。

建议在纸箱模块增加一个“基础资料”入口，集中维护客户、合同登记、货号与包装资料、车间、仓库仓位和交期规则。日常落单、入库、出库直接引用这些资料，发现差异时提示具体原因。

需要把握四个边界：

1. **格式正确不等于业务正确。** 合同号位数合规，还要检查属于哪个客户、是否允许该货号。
2. **一个货号可以对应多行纸品和不同包装版本。** 不能只保存一组“类型、材质、规格”，否则外箱和滑板纸会互相覆盖。
3. **默认交期只能辅助填单。** 系统算出的建议日期，不能冒充客户实际确认的交期。
4. **资料修改不改历史账。** 已保存订单、入库、出库及采购文件保留当时的信息；仓位调整仍通过调仓完成。

用户已确认：目标是方便落单和防错；允许同货号有不同纸品配置，但出现不同配置必须有软提醒；计量单位和装箱数纳入资料；车间与仓位分开；基础资料修改不影响旧单；必须自动从历史订单加入资料，修改已有资料需要高级别权限。

第一版以“历史自动加入、选择带出、差异软提醒”为主，不要求所有历史资料逐条审批才能使用。格式检查和对应检查分开处理：历史差异和新组合提醒核对，跨厂、越权和无效数量等明确错误仍拦截。

## 2. 当前系统已有基础与需要补建的部分

| 内容 | 当前情况 | 本方案建议 |
| --- | --- | --- |
| 客户 | 已有按工厂隔离的客户资料、启停用和维护权限 | 复用，补充编号格式和交期规则 |
| 合同与货号 | 主要保存在订单中，录入可引用历史货号资料 | 历史正式订单自动加入合同、货号及包装资料，可直接选择使用；冲突并列提醒 |
| 一单多纸品 | 已支持，纸品需求按产品数量和装箱数换算 | 保留，基础资料一次带出多行纸品 |
| 交期 | 客户交期手填；计划交期固定提前 3 个自然日，最早为下单当天 | 改为可配置提前量，保留后端计算和紧急提示 |
| 仓库／仓位 | 已有按工厂隔离的稳定仓位身份、分仓数量及调仓 | 统一维护入口，补充更名、停用及适用范围规则 |
| 车间 | 还没有纸箱模块中的独立车间目录及结构化领用去向 | 增加车间目录；如需出库按车间追溯，须同步接入出库登记 |
| 历史追溯 | 已有订单、收料、库存和操作证据 | 保存资料版本与操作当时的名称，不重算或改写旧单 |

这不是从零重建系统。客户和仓位继续使用现有身份；新增资料负责辅助和约束录入，不取代订单和库存流水。

## 3. 页面安排

“基础资料”保留两个页面：

| 页面 | 内容 | 常用操作 |
| --- | --- | --- |
| 基础设置 | 唯一的本厂通用交期、客户及格式/交期规则、客户关联合同、车间、按仓库分组的仓位、折叠的维护授权 | 新增、修改、启停用，合同和权限按需展开 |
| 货号与包装 | 客户、货号、物品名及多套纸品明细，包含材质、规格、尺寸单位、计量单位和装箱数 | 查找、建档、修改、选择用于落单、启停用 |

客户未设置独立规则也显示在客户列表中；“本厂默认”改为顶部通用交期卡片，不混入客户名单。客户规则和工厂默认入口复用已有记录并锁定适用范围。车间与仓位在同一区域内分别管理；停用保留历史，更名不移动库存。资料与规则通过同行入口打开紧凑编辑框，不再显示独立的“维护客户资料”管理清单。

主页面沿用当前连续表格、筛选和右侧操作布局；行内只有一个操作时直接显示该操作，不再套一层“更多”。

## 4. 资料之间如何关联

### 4.1 客户、合同、货号

推荐关系如下：

```text
工厂
 ├─ 客户
 │   ├─ 合同登记 ── 可关联多个本客户货号
 │   └─ 货号 ── 物品名 ── 包装方案／版本 ── 多行纸品
 ├─ 车间目录
 └─ 仓库 ── 仓位
```

- 同一客户可以有多个合同、多个货号。
- 一个合同可以包含多个货号；一个货号也可以用于这个客户的多个合同。
- 货号按“工厂＋客户＋货号”识别，不能把其他客户恰好同名的货号直接带进来。
- 合同第一版按“工厂＋客户＋合同号”识别。若现场会跨年度重复使用同一合同号，应在上线前确认是否增加年度／合同批次，不能把两份合同悄悄合并。
- 合同登记只表示归属与可用货号，不自动新增订单、不累计采购数量、不生成库存。
- 一张正式订单仍保留当前“客户＋合同＋一个货号＋多行纸品”的结构。一份合同下多个货号，仍按现有订单方式分别落单。
- 相同客户、合同和货号出现新的正式订单时，系统提示已有订单供核对，但不能仅凭这三个字段就合并库存。

### 4.2 新合同不要成为落单障碍

新合同可以从落单页面快速登记，预填当前客户和输入的合同号，再关联本次货号，不要求用户来回跳页。

没有历史资料的新合同可正常录入本次订单，系统提示“首次使用，请核对”；订单完成现有正式确认后自动补充资料和本次合同货号关联，不要求先退出落单去建档。自动补充形成带来源的历史资料，不覆盖主管维护的现有资料。

OCR 识别结果、导入预览及未正式确认的录入草稿不进入基础资料。已通过现有校验并正式入账的历史订单可以自动加入，不额外逐条审批。

### 4.3 历史订单自动加入：首次整理与持续补充

必须同时支持现有历史数据首次整理，以及后续正式订单增量补充。处理完整历史分页，不能只拿列表当前页或最近若干单作为资料全集；同一批数据重复整理不得重复新增。

自动收集本厂已有客户身份、合同号及货号关系、物品名、完整纸品组合、类型、材质、规格、尺寸单位、计量单位和装箱数。历史订单已有客户时复用其现有身份，不以名称相似自动合并客户，也不因旧订单名称不同而覆盖客户现名。价格不是本次自动建档的必填条件。

| 历史情况 | 自动加入方式 |
| --- | --- |
| 同客户同货号，物品名与完整纸品组合完全一致 | 合并为一项资料，累积来源订单、出现次数和最近使用时间 |
| 同客户同货号出现不同物品名、纸品组合、规格、单位或装箱数 | 各组合并列保留，标记“存在不同历史配置”；不拼接不同订单的纸品行生成新组合 |
| 与高级权限人员维护的资料一致 | 补充历史来源，不覆盖人工维护内容 |
| 与人工维护的资料不同 | 新增历史配置并软提醒；不改已有推荐配置或已停用状态 |
| 某项资料已停用或历史错误配置已被标记不再推荐 | 重扫历史不恢复启用，也不创建副本绕过停用 |
| 旧资料缺单位、装箱数等必要信息 | 自动加入并标出缺项；带入订单时补齐，不能编造默认值 |

无冲突的完整历史配置可以直接选择带出，显示“来自历史订单”。有多种配置时展示差异和来源供选择；主管指定的推荐配置优先展示，其余按最近使用时间排列。最近使用不等于已核实正确。

普通录单人使用不同的本单配置，正式确认订单后系统可以新增一项历史配置；这不等于允许其修改、覆盖、停用主管维护的原资料。自动补充也必须使用同样的去重、来源及权限边界，不能成为覆盖主资料的后门。

车间只使用已有结构化记录或由有权限人员维护，不能从备注猜测。仓位复用当前仓位目录；历史订单不含实际分仓数量，不能据此改写现有“待核仓位”或重建实物分布。编号规则和默认交期也不根据历史样本自动发布，只生成建议供高级权限人员设置。

## 5. 编号检查：既查格式，也查归属

### 5.1 客户可以维护哪些格式

合同号和货号分别配置，支持：

- 固定前缀、后缀。
- 总长度或长度范围。
- 允许数字、字母及指定分隔符。
- 是否区分大小写、是否允许中间空格。
- 多种合法格式及明确的历史例外。
- 提示强度：不检查、提示核对、正式确认前必须处理。

页面使用可读选项和示例，不要求仓管填写正则表达式。保存规则前，展示“这些例子能通过、这些不能通过”，并预览现有资料会有多少项不符合。

合同号和货号始终按文字处理，保留前导零、合法连字符和原始输入。系统可提示清除首尾空格；不得擅自删掉连字符、补位或把相似字符改成另一个编号。

示例只能用于讲解：假设某客户合同格式为“10 位数字，可带 -1 这样的批次后缀”，系统就检查长度、字符和后缀。实际规则必须以该客户真实合同样本为准。

### 5.2 哪些提醒，哪些拦截

| 情况 | 建议处理 |
| --- | --- |
| 编号格式不符合、货号与现有货号只差一位 | 标出差异和可能候选，不自动替换；试用期先提醒 |
| 选中的合同记录属于另一客户 | 阻止跨客户带入该记录；仅号码相同而记录不同不判错，提示核对归属 |
| 合同尚未登记 | 提供快速登记／待核对入口，不直接判定合同不存在 |
| 历史合同货号清单中没有本次货号 | 提示“本合同首次使用该货号”，允许核对后正常落单，正式确认后自动补充关联 |
| 已停用客户、货号或包装版本用于新订单 | 阻止新选用，历史单继续可查 |
| 同货号存在多种配置，或本单纸品、单位、装箱数不同 | 显示具体差异的软提醒，允许选择／保留本次配置；不强制主管审批，不改旧配置 |
| 同合同同货号已有未完成订单 | 提示可能重复，让用户核对是新单还是追加，不自动合单 |
| 跨工厂资料或没有权限的仓位 | 后端直接拦截 |

编号格式建议先运行提示模式，确认客户样本和例外齐全后，高级权限人员才可决定是否开启强制检查。纸品配置差异保持软提醒，不因存在多个历史配置而自动升级为阻断。缺少必要字段、装箱数非正数等影响正常计算的错误仍按现有业务校验处理。

同一套规则必须用于手工落单、导入预览及后端正式保存／确认，不能只在网页上检查。

## 6. 货号与包装资料

### 6.1 货号主资料

保存客户、货号、物品名、备注、状态；物品名表示成品名称，纸品类型表示外箱、内箱、滑板纸等，两个字段不要混用。

### 6.2 一个包装方案包含多行纸品

每行建议保存：

| 字段 | 用途 |
| --- | --- |
| 纸品类型 | 外箱、内箱、滑板纸、卡纸等 |
| 材质／纸质 | 沿用当前纸质字段的业务含义，统一称呼，避免再建一个意思重复的字段 |
| 规格与尺寸单位 | 如长×宽×高；明确 mm、cm、inch，非规则尺寸保留说明 |
| 计量单位 | 个、张、套等；与尺寸单位分开 |
| 每箱装产品数 | 接入现有纸品需求计算，禁止缺失后随意套用旧值 |
| 版本及适用说明 | 普通版、出口版、客户改版等，标明当前推荐版本 |

例如同一货号的一个方案同时有外箱 A33、滑板纸 B 材质，两行分别保存规格、单位和换算资料。客户改规格时新建版本；若同一时期有两种合法包装，选择对应方案，不强迫二选一覆盖旧资料。

### 6.3 不同配置的软提醒

选择货号时，若发现不止一套历史配置，在纸品明细上方显示：“此货号有 2 套历史配置，规格／装箱数不同，请核对本次要求。”展示每套的纸品、材质、规格、尺寸单位、计量单位、装箱数以及来源订单和日期。

例如同一货号曾用“外箱 A33，30×20×15 cm，每箱 120 件”，也曾用“外箱 A33，32×22×16 cm，每箱 100 件”，明确突出规格和装箱数差异，不能只提示笼统的“资料不一致”。

用户可以切换已存在的配置，也可以保留本单手工填写的不同配置。提醒不锁死输入、不额外要求高级人员审批本单差异。手工改变数量换算相关字段后，重新计算本单纸品需求并显示结果；已有订单结构修改仍遵守原有锁定与变更权限。

本单差异不会直接保存回原基础资料。高级权限人员才能在基础资料页面编辑、更正、指定推荐或停用配置；后续历史自动补充只新增来源或不同配置，不覆盖原资料。

当前需求公式仍是“产品数量 ÷ 每箱装产品数，向上取整”。若某种纸品要按“每件两张”“每托盘一张”等方式计算，应标明现有公式不适用，另行确认用量规则；本方案不顺带改变数量算法。

第一版不把价格设成货号的固定属性或必填资料。落单时仍可未知价格，入库按送货单填写；错误价格纠正路径仍按此前决定暂不改。

## 7. 车间、仓库、仓位分开管理

### 7.1 三个概念

- **车间：** 领用去向，例如装配一车间。
- **仓库：** 库存存放和管理范围，例如纸箱仓、辅料仓。
- **仓位：** 仓库里的具体位置，例如 A-01。

一个车间可以从多个仓库领料，一个仓库也可以供应多个车间。不要把车间强制绑定成仓库的下一级。

如果现场所谓“车间”其实指车间旁的小仓库，应分别登记“领用车间”和“存放仓库”；只有系统实际管理的存放地点才建立仓位库存。

### 7.2 各仓自行调整资料的边界

各仓获得高级维护权限的负责人可以维护授权范围内的仓位名称、排列和启停状态，普通录单／仓管人员使用已有资料。相同 A-01 可以在不同仓库存在，同一仓库内不能重复。所有仓位继续使用现有稳定身份。

当前权限主要按工厂校验，尚没有完整的“仅管理指定仓库”权限。若要求仓管只能修改自己仓库，需增加后端的仓库授权范围，不能只把其他仓库选项从页面藏起来。工厂主管可查看本厂全部仓库。

纯文字更名保存前后名称；原单据保留操作当时的文字。更名不移动任何库存。实物换位置仍走调仓，产生各仓位数量变化。

停用仓位不删除历史；有库存时提示先调出。停用后禁止新增普通入库，保留必要的清退和经校验的历史冲销处理，避免旧单无法纠正。已经被使用的仓库、仓位和车间原则上停用，不物理删除。

### 7.3 车间必须接入出库才有价值

建议正常领用出库增加“领用车间”，选择本厂有效车间，并保存当时名称；不属于车间领用的客户出货、退货、报损等按真实去向填写，不强制选择虚构车间。

批量出库可以先选统一领用车间，各行存在不同去向时允许分别调整。默认值只是录入辅助，确认时仍核对实际来源仓位和去向。

仓库交给车间表示领用，不代表车间已经消耗。本方案不新增车间在制库存、实际耗用或跨厂调拨。

## 8. 交期默认值怎么设置

### 8.1 两个参数，两个含义

| 参数 | 建议规则 |
| --- | --- |
| 客户交期默认间隔 | 可选的“下单日期＋N 天”建议值；默认关闭。开启后明确标“系统建议，待客户交期核对” |
| 采购安全提前量 | 计划交期比客户交期提前多少天；初始保留现有 3 天，可调整 |

客户已明确给出的交期优先，不用默认值覆盖。新订单正式确认前，录单人应核对客户交期，保留是人工填写还是采纳建议的来源信息；未知客户交期可以先存草稿，不把建议值自动当作客户承诺。

建议优先级：本单已确认的客户交期 ＞ 本客户默认规则 ＞ 本厂默认规则。采购提前量采用客户覆盖值，否则使用本厂默认值。

第一版不按实际入库仓位改变交期。同一订单可能分仓存放，不能因为后来换了仓位就重新计算采购日期。如果现场确实按不同采购仓分别管理交期，应另设订单上的“负责仓库”，在落单时确定并保存，不能取最后一次入库位置。

### 8.2 延续当前计划日期逻辑

```text
建议客户交期 = 下单日期 + 已配置的默认间隔（仅在启用时提供建议）
计划交期 = 较晚者（下单日期，已核对客户交期 - 安全提前量）
```

例如 9 月 8 日下单，核对后的客户交期是 9 月 20 日，提前量为 5 天，则计划交期为 9 月 15 日。若客户交期只有 9 月 10 日，计划交期为 9 月 8 日，同时明确提示不足 5 天缓冲。

第一版继续按自然日计算。工作日、节假日和周末顺延需要工厂日历，并明确向前还是向后顺延后再增加，不能只换一个“工作日”标签。

历史订单缺少客户交期时仍保留原计划日期，不批量补造客户交期。这里配置的是日期间隔，不调整送货日期、实际记账日期或月结期间。

### 8.3 修改默认值后的影响

规则更新只影响后续新建订单。已保存订单保留当时的提前量和来源版本；打开或保存旧单时不能自动套用新默认值。

追加默认沿用原单规则；修改客户交期后，按原单规则重算计划日期。若需要应用新规则，应由有权限人员明确选择，显示旧日期→新日期并留原因，沿用订单变更和采购文件修订流程。

实现时要一起调整前端提示、后端日期推算、订单修改及追加路径，避免网页显示 5 天、后端仍按固定 3 天保存。

## 9. 落单、入库、出库如何联动

| 环节 | 用户操作 | 系统帮助核对 |
| --- | --- | --- |
| 选客户 | 选择本厂有效客户 | 限定本客户合同、货号及默认规则 |
| 填合同 | 选已有合同或快速登记 | 检查格式、归属及合同货号关联 |
| 选货号 | 选择包装方案／版本 | 自动带出物品名和多行纸品；有多个版本时明确选择 |
| 填数量和交期 | 输入本次产品数量、核对客户交期 | 用现有公式计算纸品需求，推算计划日期并提示紧急情况 |
| 确认订单 | 核对差异后确认 | 检查资料状态、版本和明确错误，保存当时的资料快照 |
| 入库 | 选订单，按送货单录数量、单价和实际仓位 | 对照订单当时的纸品资料；不使用最新基础资料覆盖旧订单 |
| 出库 | 选实际库存仓位、数量及用途／去向 | 校验该仓位库存，记录领用车间或其他实际去向 |
| 汇总与追溯 | 查看订单收发、仓位分布及流水 | 沿用原数量和金额逻辑，必要时展示本次领用去向 |

人工登记、Excel 导入和图片识别都执行同一套对应检查。送货单写法与订单不一致时展示差异，允许明确选择匹配；不能因格式相似直接改写订单或将数量入到另一单。

## 10. 补充的必要规则

1. **资料来源和状态。** 区分“历史自动加入”和“高级权限维护”，保留来源；完整历史资料可直接带入，冲突软提醒，缺项明确提示。导入预览和 OCR 草稿不算正式历史。
2. **别名与相似提醒。** 客户简称、旧货号可以帮助搜索，界面明确展示正式名称；一个别名匹配多个结果时由人选择。
3. **版本保护。** 基础资料保存时校验版本，避免两个人同时编辑互相覆盖；确认订单时检查所选版本是否仍可用。
4. **字段与身份分开。** 合同、货号和规格发生实质改变要走订单变更或新版本，不能伪装成基础资料更名而改变已有库存归属。
5. **已有业务优先保留。** 客户／货号停用不自动取消在途订单；停用限制新选用，旧单继续履约须按具体业务状态和权限判断。
6. **修改留痕。** 谁改了格式、装箱数、交期提前量和仓位名称都可查；说明旧值、新值及适用范围。
7. **资料维护不产生库存。** 新增或修改基础资料不触发入库、出库、调仓，也不改变月结金额。

供应商资料已有基础，可以后续纳入这个入口；它不是本次防错联动的前置条件。价格维护及价格纠正流程保持当前边界，不在本方案中扩展。

### 10.1 基础资料维护权限

用户已明确要求修改需要高级别权限。建议映射为纸箱部主管／本厂被授权负责人及系统管理员，并由后端检查专门的基础资料维护权限和工厂／仓库范围，不能仅凭页面角色名称放行。具体账户分配沿用现有权限体系落实。

| 动作 | 普通录单／仓管 | 高级权限人员 | 系统自动处理 |
| --- | --- | --- | --- |
| 查询、选择并带出基础资料 | 可以，在业务授权范围内 | 可以 | — |
| 调整本次未锁定订单的配置 | 按现有订单权限，差异软提醒 | 按现有订单权限 | 不改原基础资料 |
| 历史订单自动加入资料／不同配置 | 无需人工维护权限逐条批准 | 可查看来源和整理结果 | 按正式订单来源去重补充 |
| 修改已有基础资料、指定推荐、启停用 | 不可以 | 可以，限定授权范围并留痕 | 不自动覆盖人工决定 |
| 调整编号强制规则、默认交期 | 不可以 | 可以，显示影响范围并留痕 | 只读取生效规则 |
| 仓位更名、停用及手工建立车间／仓位 | 不可以直接维护 | 可以，限定授权范围 | 不从自由文本猜测生成 |

修改保存时显示关键字段前后差异并记录操作者、时间和原因；对装箱数、计量单位、规格等实质变化保存版本。直接拥有出入库权限不应自动获得基础资料修改权限。前端隐藏编辑按钮，后端仍校验写入，绕过页面直接调用接口也不能修改。

## 11. 建议落地顺序

### 第一阶段：资料可用、规则可试

- 合并客户和仓位维护入口。
- 建立客户货号、多纸品包装方案、单位和装箱数资料。
- 建立合同登记和客户编号规则，先以提示方式试用。
- 配置客户／工厂交期提前量，保留历史订单日期。
- 完整历史订单首次自动加入，后续正式订单持续补充；自动去重、保留不同配置和来源，不要求逐条启用。
- 基础资料手工修改落实高级权限，历史新配置与人工维护内容分开保护。

### 第二阶段：流程联动与仓库自主维护

- 手工、导入和后端确认共同检查资料对应关系。
- 接入车间目录及出库实际去向。
- 增加仓位更名、停用和指定仓库维护权限。
- 对数据已核实的客户逐步开启强制格式／关联校验。

第一阶段即可减少多数录入错误；第二阶段完成后才能宣称“不同仓库各管各的”和“按车间追溯领用”完整落地。

## 12. 验收时重点看什么

| 场景 | 应有结果 |
| --- | --- |
| 两个客户使用相同货号 | 各自引用本客户资料，不串客户 |
| 同合同多个货号，同货号多个合同 | 能正常建单，实际订单库存仍独立 |
| 一个货号同时有外箱和滑板纸 | 两行一并带出，单位与数量分别核对 |
| 包装 V2 改了规格，V1 订单已入库 | 原单、库存和金额仍为 V1；新单可选择相应配置并看到差异软提醒 |
| 首次整理历史订单后再次整理 | 资料自动可用，完全一致的组合不重复新增，来源可查 |
| 同货号历史装箱数 120 和 100 并存 | 两套组合均保留，突出装箱数差异，选定后正确计算本单需求 |
| 普通人员保留与历史不同的本单配置 | 允许按现有订单权限落单，有软提醒；原基础资料不被修改 |
| 高级人员修正资料后重扫旧订单 | 不覆盖修正内容，不恢复已停用配置，不自动更换推荐版本 |
| 普通人员直接调用资料修改接口 | 后端拒绝；有高级权限且在对应工厂／仓库范围内才允许修改 |
| 格式合规但合同归属错误 | 明确指出归属问题，不能因格式通过就放行 |
| 合法新合同尚未建档 | 可以快速登记，不要求编造已有合同 |
| 编号有前导零或合法后缀 | 保存、导入、导出一致，不被转换成数字 |
| 提前量从 3 天改为 5 天 | 新单用新规则，旧单和追加默认保留原规则 |
| 客户交期尚未明确 | 默认值显示建议状态，不能伪装成客户确认日期 |
| 一单在多个仓位存放／后来调仓 | 不改变原订单交期、总量与计价身份 |
| 仓管尝试修改无权限的仓库 | 后端拒绝，页面隐藏不能代替权限检查 |
| 停用仓位仍涉及原单冲销 | 保留历史与受控纠错路径，不删除原仓位证据 |
| 人工和导入输入同样的错资料 | 得到一致的检查结果 |

## 13. 上线前需确认的现场资料

这些不影响讨论整体方案，但实施强制规则前必须拿到：

- 每个客户实际的合同号、货号样例及合法例外；合同号会不会跨年度重用。
- 同货号是否有不同客户市场、不同包装方案或并行版本。
- 一次出库会不会发往多个车间；车间与存放仓位已确认分别管理。
- 各厂仓库清单、仓位命名及哪些人员能维护哪些仓库。
- 客户交期是否确实有稳定的默认间隔；若没有，就只配置采购提前量，继续手填客户交期。
