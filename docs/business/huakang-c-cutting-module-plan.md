### 2.1 可以沿用的能力

1. 当前主线已提供华康C客户映射（INDEX、JAZAWARES／JAZWARES、MAXX、STROTTMAN、JP）。裁床沿用华康C自己的业务订单台账与下发快照；不得整体搬回华康D客户或改写其历史订单。

## 3. 界面：六个业务区，加生产看板与操作日志

### 3.1 参考关系与边界

采用本项目布料仓的顶部导航、页内分类、摘要、筛选和表格组织方式，复用项目通用界面组件。保留裁床独立权限、订单版本、配套、签收、实际耗用与锁月规则；不照搬喷油工资、工序产值或委托方收款。

### 3.2 主界面结构

顶栏为“裁床部／返回生产部／华康 C／使用说明／账号”。厂区标识不是切厂控件。下方横向导航依次为：

| 工作区 | 页内结构与主操作 |
| --- | --- |
| 生产看板（默认入口） | 当日任务、异常任务、历史与计划外实绩；按日期、订单和执行方核对，携带原任务与业务日期进入填数 |
| 生产排期 | 总订单、已排期、未排期摘要；订单台账及现有 BOM、需求、预排和实际核定；领料只提供跳转 |
| 每日填数 | 每日任务、日报记录、裁片配套、外发收回与验收、交接与抽查；保留原填报和更正流程 |
| 物料库存 | 库存台账、订单领用汇总、收发记录、领料申请、耗用与余料、采购交期 |
| 月结 | 月结总览、内部月结、外发对账与结算、付款与核销、冻结报表、历史期初 |
| 基础资料 | 产品与配套 BOM、物料与单位、本厂与外发资源、工作日历；日历仍保存到执行方版本 |
| 物料费用 | 订单费用、耗用与原批次、完工与在制归属、待计价与核对、成本变更历史 |
| 操作日志 | 按授权来源、单据、操作人和依据查询；保留原事件、版本、业务日期及关联记录 |

**统计与追溯口径：**

- 订单数量摘要按有效下发 `line_id` 去重（笔），不等于订单头或套数；总数＝已排期＋未排期。部分排期算已排期；仅草稿、发布已失效算未排期；有效发布后的新草稿不取消既有已排期状态。取消单不计卡片，历史台账仍保留。摘要在基础筛选后、分页前计算，排期状态筛选只改变下方列表。
- 每日看板按订单与任务去重，草稿不计已填报，明确填零仍计已报；合格完成与交接分列。无实际核定依据只提示待核定，不推测缺料；外发报称不计完成。
- 库存余额＝有效签收－仓库生效退仓－正常耗用－损耗；未签收单列、不同单位不相加，不另建库存账。订单领用汇总按订单、冻结任务／执行方／BOM、物料版本及单位归并，仍回到原实发查看。
- 月结状态按当前有效单据计算，冻结历史分别标识当前与失效；付款余额导出使用现有全量有效余额口径，不伪造单笔历史冻结余额。
- 日志聚合已有落账证据，服务端按真实操作时点稳定分页；翻页发现追加记录或权限范围变化要求刷新。成本、结算和付款分别校验权限。外发价格确认作为原事件展开凭据，不冒充月度结算单。未记录的历史岗位和失败尝试不补造。
- 使用说明通过弹窗展示岗位流程、数量口径和权限边界。页内切换保留编辑器及未保存输入，跨页仍执行原离开与未知结果保护。

实施与验证范围见 [界面改版验收记录](../cutting/cutting-workspace-redesign-acceptance.md)。原型中的示例数字不进入正式页面。

### 3.3 统一交互原则

- 使用项目深青绿色主色、浅色底面、细边框和紧凑表格，遵循 `DESIGN.md`。
- 订单总台账固定生产单号、客户／货号等识别列，其他列按订单、物料、计划、实际和月份分组；宽表只在自身容器内滚动。
- 月份按所选期间动态展开，不把7月、8月等写死为固定字段；未知值显示“待确认”，缺报与明确填零分别显示。
- 看板和每日任务按所选业务日期查询，日报详情保留该日期作为统计截至日期；月结、费用页面另有明确的月份选择，避免混淆“当天”和“整月”。
- 当前订单详情在页内展开；从订单进入其他页时保持订单筛选及关联记录定位。订单侧栏与窄屏抽屉作为后续交互优化，不列为本轮已完成项。
- 小于1024px优先列表和单任务填报；窄屏保留日期、任务识别及主要按钮，复杂排期以表单提供等价操作。
- 保存期间阻止重复提交；网络超时保留填写并核对上次操作结果，不能再次生成一笔新业务。
- 切换页面、厂区或账号时处理未保存内容；失效的旧请求不能覆盖新上下文。模块只接受明确的华康C厂区，不回退其他厂。
- 配套、超产、缺料、待计价等状态同时使用文字和颜色；不能仅靠红绿底色表达。
- 首次上线无数据时显示真实空状态和下一步动作，不能沿用喷油演示数字。

## 4. 业务流程与单据链

```mermaid
flowchart TD
    A[华康C业务确认并下发订单] --> B[裁床接单与工程BOM关联]
    B --> C[按订单及BOM提交物料需求]
    C --> D[采购统一采购并回复分批物料交期]
    D --> E[主管预排：本厂或外发裁剪及每日计划套数]
    D --> F[实际收料、质量与前置工序就绪确认]
    F --> G[确认执行条件及首次供数日期]
    E --> G
    G --> H[本厂生产或外发裁剪]
    H --> I[每日配套报数、散片与耗料登记]
    I --> J[交接或外发收回验收]
    I --> K[内部生产、库存、材料费用月结]
    J --> L[外发加工费对账与结算]
    L --> M[付款登记与未付余额]
```

采购预计交期支持预排，不等于物料已经可用。订单下发也不直接生成实际库存、耗料或完成数量。

建议的关联层次为：业务订单明细 → 裁床生产任务 → 本厂／外发执行任务 → 日计划、日报、物料流水、交接／验收、费用及结算。

一张订单可以有多个部件、颜色和执行任务；一张采购单可以供应多个生产任务。所有拆分和合并均保留原订单及数量分配关系。

## 5. 排期业务区

### 5.1 页面分区

- **订单总台账**：参照截图，查看订单、物料、计划、实绩、差额和月度汇总。
- **待排需求池**：显示待接单、待BOM、待采购回复和可排任务，支持筛选及批量关联。
- **日计划表**：按任务／执行方展示每天计划套数，支持日期窗口、批量填数、复制计划和局部调整。
- **计划版本**：查看首次发布计划、当前有效计划、调整内容与原因、操作者及版本影响。

主操作为“接收订单”“拆分任务”“编制日计划”“预览调整”“发布计划”。确认或审批层级见第17节；不得自行增加不必要的逐日审批。

### 5.2 工作日及完成期

- 准备周期默认建议3个工作日，并非强制最低限制。主管可按本厂／外发任务设置0～365个工作日；首次编制、保存及发布计划无需填写原因；已有发布计划后，修改准备周期、日计划或其他任务设置须填写调整原因并保存新草稿。发布修订版时带入已保存的调整原因，可核对修改；旧草稿未保存调整原因时须补填。系统保留原因、操作者、新旧版本及首次基准。由生产日历定义休息日、节假日、调休和加班工作日。
- 已确认不要求所有辅料到齐，可按任务／批次设定当前生产阶段所需物料，部分到齐即可安排生产排期。未列为当前阶段必需的辅料不统一阻止排期，但须继续显示缺料数量、预计到期和后续影响。
- 已确认以该批任务所配置的开工必需物料及贴合／捆条等前置工序就绪为任务准备周期的起算条件；不能以全部辅料最晚到期日作为统一起算日。本厂／外发分别配置每周工作日及休息、调休、加班日期。
- 准备周期大于0时起算当天不计，按所设天数顺延工作日；0天允许就绪当天供数，当天休息则顺延到下一工作日。默认3天示例：周一就绪、周二至周四均为工作日，则周四开始供数；调整为1天则周二、0天则周一开始供数。收到订单、工程确认BOM及需求、采购回复当前必需料交期后即可提前编制每日计划，不必等待实际领料。预排采用预计日期；实际领料后按实际领料及前置工序实际就绪日核定，预计和实际供数日分别展示。未配资源日历两阶段均默认周一至周六工作、周日休息；涉及节假日／调休须配置日历。实际日期须有凭据且不得晚于北京时间当天；仓库接口未接通前保留人工核对依据，不自动生成库存流水。
- 采购回复用于预计首次供数日；实际到料确认后形成执行条件。计划开裁日、首次供数日、计划完成日分别记录。
- 系统按主管填入的有效日计划累计达到任务目标数量的日期计算计划完成期；未排足数量时显示“计划未排完”。
- 建议首次基准计划保留不可覆盖版本，后续调整形成新版本。物料延期提示受影响任务，不静默移动已发布计划或历史日报。
- 允许部分到料形成可生产批次；需要核对当前阶段每种已配置必需物料的实际可用量，并扣除其他任务已占用部分。只满足部分数量时，按可支持数量分批执行；预计后续来料支持预排，不冒充实际库存。
- 界面建议在物料清单增加“当前阶段是否必需”“适用部件／工序”“可支持生产数量”“未到料影响”及责任人字段，由有权限人员配置并保留调整记录。无需逐张订单重复勾选全部物料，可从工程确认模板带入再核对。
- “可开始裁剪”和“可报完整套数”分别判断：部分物料到齐可先安排相关部件裁剪，尚不能形成完整配套时保留散片／在制数量，不能提前计为合格完成套数。
- 不同产品套数不能直接等同于工作负荷。第一版由主管编制每日生产计划；同产品／已确认换算的资源可进行容量提示，标准工时未确认时不宣称自动最优排产。

### 5.3 排期示例

某任务目标6,350套，每个生产日安排1,500套，最后一天安排350套，需5个有效生产日。日期按实际工作日历落位，不能把中间休息日算作有效产出日。

本厂6,000套、外发4,000套组成同一订单10,000套时，应分别形成执行任务和日计划。允许暂时未分配完，明确显示待分配量；累计分配不得无依据超出有效需求。

## 6. 填数、配套及交接

### 6.1 配套口径

工程BOM应定义产品／款式、颜色、规格、部件及每套所需裁片数量。不同版本和不兼容规格不得混配。

对同一可配套范围，设部件i每套需用 `rᵢ` 片，尚未用于配套的合格可用量为 `qᵢ`：

`本次最多可新增配套数 = min(floor(qᵢ / rᵢ))`

例如每套需要前片1片、后片1片、袖片2片；分别有1,000、950、1,800片合格可用裁片，可组成900套，剩余裁片继续保留。缺少一种必需裁片不能按其他部件平均完成量报套数。

### 6.2 推荐两种填报方式

| 方式 | 使用条件 | 控制 |
| --- | --- | --- |
| 直接报合格配套数 | 现场已经完成核套，适合文员日常快速录入 | 记录核套人／依据与任务版本；声明为完整套，不伪造每种裁片实际产量 |
| 按裁片核套 | 现场有可靠裁片明细，需要管理散片及欠片 | 先登记合格裁片，再生成配套记录并扣减可配套散片，不重复生成生产完成量 |

已确认每个任务固定一种记录主口径：直接报完整套数或按裁片核套。直接配套报数和裁片自动核套不能同时增加同一批产量。跨批、跨执行方合并配套需要可追溯的移交和数量分配，不能仅凭相同货号自动合并。

### 6.3 每日报数

文员按生产日期选择任务，登记当日新增合格配套数、未配套裁片、待判／不良／报废及异常原因。已确认文员提交即生效，主管抽查，不设置主管逐日报批。已实现保存草稿、提交、更正、作废及抽查；批量粘贴预览留待后续批次。

日报保留业务日期、录入时间、录入人、执行方、订单／BOM版本及更正关联。漏报与填零不同；超产允许登记真实事实，但应提示、留原因并核实是否纳入任务及结算额度。

日报确认不自动推定领料、耗料、仓库收回、下道交接或客户出货。上述事实分别登记，并由共同任务关联。

### 6.4 本厂与外发的数量状态

- 本厂：实际合格配套完成 → 待交接 → 已交给下道工序。
- 外发：外厂报称完成 → 发回在途 → 实际收回 → 验收合格／待判／不合格 → 交接。
- 外厂报称完成用于预计进度，不直接作为已验收数量或应付依据。
- 外发只含裁剪；后续车缝、手工和包装不重复记为裁床产量。
- 返工关联原任务，不重复计正常订单完成量；修正、退回和重新验收保留原记录。
- 本模块的裁片／配套交接不自动生成现有半成品仓入库，接收方和仓库接口另行确认。

### 6.5 统计口径

已确认将原“累计交货欠产”改名为“累计计划差额”，并单独列出“未完成套数”；两项不得混用。未完成套数的计算已确认采用“订单总数－已完成数”，两者均按同一订单的配套套数统计。P2b 首批已实现按单汇总；订单总套数采用工程确认的订单换算口径，未核定时不以原订单件数或执行任务目标代替。

| 指标 | 口径（已确认项注明，其余为建议） |
| --- | --- |
| 当日计划套数 | 当前有效计划在所选业务日的数量 |
| 累计计划套数 | 截至所选日期的有效日计划合计，详情可对比首次基准计划 |
| 累计合格完成套数 | 确认的合格完成记录净额；外厂自报及验收采用独立列，不混计 |
| 累计计划差额 | 已确认：累计已交接套数－累计计划套数，负数表示落后 |
| 未完成套数 | 已确认：`订单总数－已完成数`，按同一订单的配套套数计算，直接保留相减结果 |
| 完成率 | 累计合格完成÷任务有效目标；目标为零或未知时不计算，真实超产不截成100% |

示例：订单总数153,000套、截至当日计划115,000套、已完成107,500套；若已交接同为107,500套，则计划差额为−7,500套；未完成套数为153,000－107,500＝45,500套，完成率约70.3%。

## 8. 物料库存与采购协同

### 8.1 唯一库存来源

布料仓库、裁床现场和外发厂应围绕同一套物料批次、存放位置及库存流水展示。若仓库模块尚未实施，先确定权威流水所属模块及接口，不能让两个模块各录一次收货。

| 位置 | 主要记录 |
| --- | --- |
| 布料／辅料仓 | 采购实收、质量状态、预留、发料、退回及盘点 |
| 本厂裁床现场 | 领入、可用余料、实际耗用、损耗、退回及调拨 |
| 外发加工厂 | 发出、签收／在途、在外结存、耗用、余料退回及差异 |

发料是位置及保管责任变化，不立即等于生产耗用。外发料在途与厂商确认收到分别记录，合并查看时不能重复算两份库存。

### 8.2 采购需求及到料

- 工程发布生产BOM，并由工程部正式提交物料需求（已确认）。首批由工程明确目标套数、数量依据并逐行核定需求量；损耗、库存抵扣及审批规则未获确认，不自动推算净采购量。采购交期先沿用 PMC／仓库部门、单独授予权限（已确认）。
- 采购可统一采购、分批回复预计日期与数量，保留采购明细到多个生产任务的分配关系。
- 采购承诺、供应商发货、仓库实收、质量可用分别记录；延期通知关联受影响计划。
- 物料用途区分当前裁剪阶段必需料与后续工序用料，支持配置部分到料即可排期；非当前必需辅料继续跟进到期，不一律阻止当前排期。哪些物料属于当前阶段必需、如何触发可调整准备周期的起算及后续工序约束，按任务适用规则明确。
- 上游未接通时允许带来源说明的结构化登记／模板导入；后续正式来源接入采用核对关联，不能重复入库或重复生成需求。
- 裁床不承担采购付款流程。布料供应商采购应付并未在本轮明确纳入裁床月结，需独立确认系统边界。

### 8.3 库存控制

- 物料身份至少包含编码、名称、规格、颜色、基本单位；批次、色缸、幅宽、克重等按物料类型补充。
- 预留影响可用量，不改变实物在库；共享批次不能重复分配给多个任务。
- 整卷、散料、可复用余料和报废分开；不同规格或质量状态不能直接合并。
- 单位换算需明确来源：公斤转米依赖对应物料及条件，不使用全局固定比例。
- 推荐无可用库存时阻止正常出库；特殊短账处理规则、审批及后补流程须先确认，不默认允许负库存。
- 更正通过关联原流水的冲销或调整完成；已被后续使用的物料不能无约束撤销原收货。
- 盘点以截止时点的账面与实际数比较，登记差异原因；期间锁定、并发收发和历史日期的影响必须核对。

## 9. 实际生产物料费用

### 9.1 页面与口径

提供“订单费用”“耗用明细”“标准与实际对比”“在制与待计价”四个页签，可按生产单、执行方、月份、物料及币种筛选。每笔金额可展开到耗料、批次价格和来源凭据。

| 费用 | 依据 |
| --- | --- |
| BOM标准材料费用 | 同一目标／比较产量的标准用量×已确认参考价格 |
| 实际材料费用 | 实际耗用数量×适用库存成本，包含明确归属的调整 |
| 未配套／在制材料费用 | 尚未归属于已完成配套的实际投入，按确认规则结转 |
| 外发加工费 | 外发验收与冻结单价形成，单独列示，不混入材料费用 |

不能将订单总量×BOM用量直接标成实际耗料，也不能用当前采购价重算已经结算的历史耗料。

### 9.2 耗用登记与对账

可直接登记任务实际耗用，并通过盘余核对：

`期初现场结存＋本期领入／调入－退回／调出－期末现场结存＝本期耗用及损耗`

该平衡式用于核对或经确认的盘余计耗方式，不与已经登记的耗用重复相加。正常耗用、报废、非生产损失和盘点差异分别分类；未分配到订单的公共耗料进入待分配池。

### 9.3 成本规则

- 已确认按原实发批次实际成本计价，缺价显示待计价；PMC／仓库采购岗位单独授权确认实际单价、币种与成本凭据，暂不自动分摊税费、运费。采购导入单价不自动成为正式库存成本。
- 退料追溯原领用和成本来源；退回物料与供应商扣款是不同事实。
- 未知价格保留为空并显示待计价；明确的零价需要证据，不能用零掩盖缺失。
- 共用耗料的分摊规则、损耗承担、余料价值、税费和运费计入方式均需版本化确认。
- 不同款式的套数不能不经规则就作为统一费用分摊权重。
- 本批单套正常材料成本＝主管确认归属于对应合格完工的正常材料费用÷对应合格完成套数；外发取验收合格数。套数为零、缺价、物料未归齐或公共耗料待分配时显示待核对。损耗费用单列，暂不摊入；各币种分别显示单套值，保留六位小数，HALF_UP。
- 金额计算推荐后端Decimal，中间保持精度、单据金额按确认规则到分；保存币种和舍入规则。不同币种不直接相加。
- 费用补价形成调整证据，不能覆盖已冻结月结和历史导出；锁期后的补价采用批准的调整或反结流程。
- 材料费用不是订单总利润；人工、设备等成本未纳入时不展示“完整利润”。

## 10. 月结：内部核算与外发结算

### 10.1 内部月结

推荐页签：生产核对、物料收发存、材料费用与在制、锁月记录。

| 核对范围 | 主要内容 |
| --- | --- |
| 生产 | 本月计划／合格配套／交接数量、未填日报、超产、未完成订单、散片及返工 |
| 库存 | 期初、实收、位置转移、实际耗用、退料、损耗、盘点差异、期末及外发在外料 |
| 费用 | 已知材料费用、未计价、待分配、在制结转及订单成本差异 |
| 完整性 | 未确认单据、未解决更正、缺价格／规则、账实不符及结算争议 |

流程建议：生成核对草稿 → 跳转处理异常 → 责任人复核 → 冻结本期快照 → 锁定月份 → 导出。

跨月订单继续沿用原单，本月只归集本期事实。生产、库存和费用完成度分别展示；生产数量核对完成不代表财务已结清。物料缺价等未解决事项必须影响相关费用结清状态。

### 10.2 外发加工厂对账与应付

推荐页签：待结明细、对账单、结算单、付款登记、调整与历史。

- 外发任务保存加工厂、裁剪范围、计价单位、单价版本、币种及价格依据。生产按套统计；按片报价时另存计费数量和确认的转换关系。
- 首批已确认按截至所选月份的验收合格套数计费，允许部分及跨月续结；外厂自报、收回未验收及超出冻结任务额度的数量不自动计费。验收沿用独立 acceptance_write 权限，真实验收员工另行指定。
- 支持部分验收、部分结算和跨月继续结算；同一验收数量不能被两张单重复占用。
- 可结数量来自验收证据扣除已有有效结算分配及退回限制；未结退回释放或减少额度，已结退回形成关联原单的贷项／调整，不能既扣数量又扣款两次。
- 外发超产能否付费须单独确认；实际数量保留不等于超额费用自动获批。
- 我方材料成本与加工费分别归集，不能把我方供料再次算进外发加工费。
- 补料、返工、报废、扣款、补款及其他费用逐项记录来源、责任和确认结果。
- 首批采用单独授权裁床主管确认的每任务含税结算单价、币种及报价凭据，可形成正式含税应付；不自动拆税、汇兑或另加运费、扣补款。CNY／HKD／USD 分别核算，零价也须凭据。已确认结算保留原价，新报价不追改旧单。

对账流程建议：生成草稿 → 核对验收／价格／调整 → 记录与加工厂的核对结果及凭证 → 内部确认 → 冻结结算单 → 登记付款与核销。

系统不自动对外发送信息。加工厂在线登录及消息发送属于后续单独确认范围。

### 10.3 付款及期间保护

- 结算确认与付款分开：已确认有效应付扣除有效付款核销，形成未付余额；退款、冲销和贷项分别关联处理。
- 一笔付款可分配多张结算单，多次付款可核销同一张单；币种、额度及重复登记需核对。
- 仅登记实际付款凭证和核销，不自动操作银行；预付款或超付需要独立规则，不默认为负未付余额。
- 内部月结与外发月结状态分别保存，互相展示未完成影响；外发争议金额未确认时，完整任务成本不能标为已结清。
- 锁月后不得直接编辑当期正式单据。更正采用开放期调整或有权限的反结，并保留原版本、原因、操作者和时间。
- 结算修订不删除已有付款证据；已有核销、后续期间或关联入账时，先检查影响再允许反结。
- 精确结账顺序、审批分工、未开票金额与争议费用处理，由财务确认后实施。

| 价格与费用 | 外发价格版本、计价单位、币种、成本及分摊规则、月结规则 |

优先引用现有权威客户、人员等主资料。历史单据保留当时的名称、规格和价格快照；停用资料不删除历史证据。临时资料须标记待完善，不能用默认值伪造完整资料。

## 13. 订单、BOM及其他异常处理

- **加单／减单**：接收新订单版本，比较已分配、已完成、已交接、已发料及已结算事实。减单低于已执行量进入异常处理，不能直接扣掉历史产量。
- **取消订单**：停止后续安排，保留已生产、在外料、退料、费用及结算处置任务，不删除整单证据。
- **BOM变更**：发布新版本并明确影响范围；已确认领耗料、日报及结算继续引用原版本，剩余任务经确认后切换。
- **采购延期／短料**：标出受影响任务和预计完成期，由主管重排；实际到料不可被采购预计日期覆盖。
- **超产／欠产／缺片**：真实数量保留，原因与处理分开，超产不直接扩大采购、交接或外发付费额度。
- **报数更正**：确认前改草稿，确认后关联原记录更正；检查其对配套、交接、库存和结算的影响。
- **重复点击／网络重试**：同一次业务操作只记账一次；保存结果未知时先查询原操作结果。
- **历史导入**：先预览映射和差异，再确认；只有累计值时作为有截止日期的期初，不能编造每天的实际数量。期初模式与完整历史流水重放不能重复采用。

### P2a 任务拆分与生产预排交付边界

- 在排期订单详情编制本厂／外发完整套数任务。任务目标合计不得超过工程确认的订单目标套数，可保留未分配量；任务日计划不得重复日期或超出目标，未排满不生成完整完成期。
- 执行资源资料内配置日历并保留修订；未配置默认周一至周六工作、周日休息。任务选择“提前预排”或“实际核定”：提前预排按当前必需料及前置工序预计日期计算；实际核定按实际领料及所需前置工序实际日期计算。两种模式均按任务的供数准备工作日计算，默认3天可调整（0～365天）；大于0时不计就绪当天，0天可就绪当天供数、休息日顺延。首次编制、保存及发布无需原因；已有发布计划后的调整保存须填写原因，修订发布带入草稿所保存原因、允许核对修改，缺历史调整原因须补填。系统保留调整原因、操作者、新旧版本及首次基准。日计划可通过调整周期提前或延后，但不得早于所选就绪依据与准备周期推算日或落在休息日；物料及前置条件仍须核对。
- 提前预排无需实际领料：工程需求已提交且当前必需采购料有交期回复后，主管核定该批物料日期与数量支持依据，编制并发布日计划。采购日期带入当前最晚回复日，允许主管按批次调整，但不得早于该物料最早采购回复；不采购行采用人工预计日期及依据。非当前必需辅料不推迟当前阶段，数量可支持范围不自动推定。
- 实际领料后在任务中补填实领日期和凭据、切换实际核定，并按实际最早供数日核对或调整日计划；所需前置工序也必须有实际就绪日期及凭据，不能用预计日期替代。日期不得晚于北京时间当天。前置工序要求独立保留，清空日期不会取消要求；取消原要求须写核对依据。
- 两种供数日期分列，已有实际条件但未切换核定仍提示待核定，不自动改动发布计划；调整后发布新版本，首次基准及旧版仍可追溯。人工实领记录不等于仓库出库、质量放行或可用数量核验，不重复记库存、报产或费用。旧预计领料字段仅作历史，旧计算规则的计划须重新核对。
- 草稿、当前发布及首次基准分别保存，调整生成新版本；订单/BOM/目标或采购交期变更、旧需求待核对、执行资源修订／停用或物料停用均使相应计划待复核。订单重新签收保留原计划。修订待复核计划时保留任务日计划、重新填写预计物料、实际领料及前置条件依据，不自动套用新BOM行。
- 本厂／外发资源可设置默认准备工作日（0～365，默认3），仅带入新任务；原任务保留其设定。更换执行方保留原任务编号、前置要求、数量及日计划，原实际凭据清空并回到预排；后续使用实际凭据时，若执行方相对草稿或发布版发生变化，须填写复核依据。删除有前置要求的原任务须明确取消依据，保存／发布同时检查原发布任务，旧草稿不能通过换编号绕过。取消依据随连续草稿与发布版保留。
- BOM支持编码、名称、货号、款式、颜色及历史修订内容检索，仍由工程明确选择发布版本。BOM历史请求按最新请求和当前对象核对，迟到成功／失败不覆盖新查询。
- 日计划支持日期区间、每日套数、替换／追加和来源任务复制；按当前资源日历跳过休息日，追加跳过已有日期，尾日按剩余目标截数，先预览后确认应用。替换已有日计划再次确认；来源任务、目标、日历或参数变化即令已有预览失效。区间上限730天；物料就绪及数量仍由服务端保存／发布校验，不自动判断产能或可用库存。
- 排期列表支持未排、部分排期、已发布、待实际核定、待复核筛选，与采购办理状态组合，先筛选再分页；状态可重叠。修订保存／发布前展示当前发布版与本次任务、日期、数量、执行方、准备周期及物料／前置依据差异。历史详情展示物料行日期、资源版本、日历例外及取消／复核依据。
- `cutting_ops:plan_write`、`cutting_ops:plan_publish` 独立授予生产部门；主管日历维护沿用 `master_write`。不自动赋权。API 为 `/orders/{line_id}/plan`、`/plan-publish`，沿用原操作恢复端点及工厂事务锁。
- 计划使用现有裁床订单版本JSON存储，无新增数据库表或迁移；P1c所需本地结构已显式迁移并启用，线上生产环境未操作。页面可看当前、基准和历史计划，已有采购／工程操作保持独立。
- P2b 首批已独立实现每日实际填数、直接报套／裁片核套、订单未完成套数、交接及外发收回验收；P2a 预排本身不写实绩。仓库领料申请、实发与签收见 P3a；库存预留、耗用及计价未纳入本批。

### P2b 首批：日报、配套及数量流转

- 文员保存草稿不计产量；提交立即生效，主管独立抽查。提交、更正、作废、抽查须保留说明、操作者及时间。更正草稿不替代原生效数；同一任务同一业务日只能有一张有效日报，明确填零与未报区分。
- 每个任务首次保存固定直接报套或裁片核套。裁片日报逐部件登记合格、不良、报废片数；核套按冻结 BOM 消耗合格散片，取最短缺部件支持量，不重复增加产量。不同 BOM／执行方不得沿用有记录的任务混记；应另建任务。
- 本厂合格报套／核套计完成；外发只计报称，实际收回后登记验收合格／不合格，剩余保留待验，合格验收才计完成。交接独立登记且不得超过合格可交接数。计数不生成采购、库存、耗料、应付或付款。
- 更正和作废保留原记录，按业务日和首次生效顺序重算，若影响后续核套／验收／交接须先处理后续记录。同日先保存下游草稿不影响后来提交的正常业务顺序。
- 新日报须使用最新有效来源及未失效发布计划；未生效草稿首次提交重新校验。来源取消／任务移除后，已有事实仍可更正，既有散片及实收余额可按冻结上下文继续核套、验收或交接，不能借历史任务新增日报产量。未来实际日期拒绝；超产、实际条件未核定或早于核定供数日须说明现场依据，不作为实际开工或结算批准。
- 填数页提供按订单、截止日期的合格完成、交接、未完成、计划差额及月度汇总；排期详情展示独立实绩摘要。实际交数＝交接；未完成＝工程核定的订单总套数−合格完成，不截零。统计按该订单全量事实计算，不汇总当前分页冒充全厂合计。
- 新增显式迁移 `20261010_0155`，在 `0154` 后建立只追加生产事件表及 SQLite／PostgreSQL 不可改删保护；不通过启动自动建表。独立权限 `report_write`、`report_review`、`handover_write`、`return_write`、`acceptance_write` 归生产部门，均须已有裁床读取权；不自动赋权。
- 接口：`GET /api/cutting-operations/orders/{line_id}/reports`；同路径 `POST /{save|post|void|review|discard}`；原操作核对使用 `/orders/{line_id}/report-operations/recover`。沿用工厂事务锁、订单预期版本及本人操作回执；结果未知保留原请求并阻止离页。已保存服务器草稿可重开；未保存内容强制关页仍会丢失。
- 本批不等于 P2b 全部现场验收完成：批量粘贴／导入、外发发回在途单、实物退回与返工专用单据、跨任务裁片移交、历史分页和大数据量性能仍待后续批次；本地开发库已迁移启用并通过 admin 页面验收，测试产量只写隔离副本；真实员工、浏览器多尺寸、PostgreSQL 并发及线上生产启用另行验收。岗位清单与边界见[本地启用与岗位权限清单](huakang-c-cutting-p2b-local-acceptance.md)。

### P3a 首批领料申请与布料仓对接

- **办理方式（已确认）**：裁床按已接收订单：、已发布本厂／外发任务及 BOM 物料行提交申请，直接交布料仓核对发料，不增设主管审批。领料日采用裁床确认收妥的签收日，支持分批；外发仍由裁床人员依据外发收妥回执登记，不开外发门户。
- **物料对应**：明确选择仓库物料版本，核对编码、规格、颜色和原单位并填写对应依据。允许编码不同，但必须同单位、同布料／辅料类别，不自动换算。冻结订单下发、BOM、任务／资源与双方物料身份。发布计划变化后先停止旧申请继续发料；仅日期等非实质调整时，裁床持领料申请权限的人员核对当前发布版本并填写依据，可显式确认续用。必须与原冻结下发、BOM、执行方及其版本、原任务目标套数、仓库物料版本一致；数量或身份实质变化仍须关闭余量后重新申请。原申请不改写，续用逐次留痕；已有实发仍可签收和退仓。
- **唯一库存账**：使用现有 `warehouse_operations_documents`。申请不预占或扣库存；仓库 `ISSUE` 按原申请和实际批次出库，累计不超过申请量。签收只登记证据，不重复加减库存；仓库 `RETURN` 追溯原实发，新增退仓按完整有效签收／退料业务日期时间线校验，允许合法补录，任一日期净可退量不得为负。未签收在途异常不伪记退仓。仓位、批次、缸号／卷号沿用布料仓原始证据。
- **纠错与关闭**：支持分批签收、签收撤销和关闭未发余量，均记录操作者、日期、凭据／原因，保留原记录。签收后不能直接冲销实发；先撤销签收才可按仓库原规则冲销。原实发仍有有效退料时禁止直接撤销签收。录错退料且回仓批次尚无后续使用时，仓库持冲销权限可留因整单冲销，再登记正确退料；冲销只撤回退料入库及已退数量，不重复恢复原出库库存。有后续使用记录时禁止直接冲销，需另行核对关联纠错流程。新增出库冲销日期不得早于相关撤签／退料冲销日期，撤签不得早于退料冲销；旧版已接受的历史日期记录仍可回放。关闭只停后续发料，不回退实发或退料，不重新开放已退数量。
- **排期衔接**：完整历史展示申请、实发、退料、签收、撤签、冲销、关闭及续用的单号、关联单、业务日期、登记时间、经办人和原因，并显示需料日期与当前确认计划版本；签收历史展示实际领料日期与数量；部分签收不等于全部必需料齐备，也不自动推算可生产套数。主管按当前批次必需料和前置条件核对，在 P2a 中引用签收单号、填写实际领料日并发布修订。已有计划的调整仍需原因，首次基准保留。首批不自动改写计划或补报产量。
- **页面**：裁床物料库存工作区选中订单后显示“领料申请与布料仓回传”，统一办理申请、仓库回传与分批签收；排期页仅保留“前往物料库存办理领料”，携带当前订单及已有核对月份，目标页面重新校验权限并读取订单。跳转继续检查未保存填写及结果未明的操作，不自动开单或授予权限；布料仓“库存管理 → 领料申请”核对对应依据、办理分批出库和关闭余量，“退料回仓”处理已签收退料。沿用项目共用面板、按钮、表格和状态样式。无物料资料／批次时必须先按真实资料建档收料，不自动造期初库存。
- **岗位**：裁床申请、关闭及计划续用使用 `cutting_ops:material_request`，分批签收／撤销使用 `cutting_ops:material_receive`，均限定华康C生产部门；查询需 `cutting_ops:read`。布料仓沿用华康C PMC／仓库部门的 `fabric_operations:read`、`operate`，冲销需 `correct`。工程 BOM 权限、采购交期权限不自动获得领料或出库权限；固定岗位不自动扩权。员工账号待明确指定，本地先由 admin 验收。
- **接口**：`GET /api/cutting-operations/warehouse-materials` 只返回物料身份白名单；`GET /api/cutting-operations/orders/{line_id}/materials` 返回本单申请、实发和签收历史；`POST .../materials/{request|receive|void|close|reuse}` 提交对应操作；`POST .../material-operations/recover` 核对原操作并阻止未执行操作晚到。仓库仍从 `/api/warehouse-operations/fabric/documents` 办理实发、退仓及冲销，单据保存结果核对使用同路径 `/recover`。恢复只需本仓读取权，并绑定原操作者及内容；未执行操作以原请求号封存，阻止迟到重试。跨域写入同一事务提交；操作编号绑定操作者及内容，结果不明后即使遇到登录、权限或版本错误仍保留原请求，只能原样重试或核对；确认未执行并停止原操作后才生成新请求。物料查询遇到登录失效可重新登录后保稿恢复。
- **数据库与启用**：本批无新增表和新 Alembic 版本，复用仓库原迁移 `0134/0142/0143/0152` 及裁床原表。根目录本地库已通过备份、隔离演练、原数据保全与完整性检查补齐上述原迁移并重启，保留未登记完整 Alembic 链的现状；现有 admin 验收使用空业务台账，不造测试库存。两端代码需一起发布，否则旧仓库投影无法识别签收／关闭／续用／请求封存记录；存在这些记录后不能直接回退旧仓库代码。缺表时明确返回 503，不以零库存替代未知。正式库仍须核对迁移链、备份并演练，禁止对未登记迁移版本的库盲目 stamp。
- **验收**：隔离数据覆盖部分申请／发料／签收／退仓、撤销依赖、余量关闭、原单位小数、来源及资料变更、幂等重试、并发签收、提交失败原子回滚、越部门拒绝及缺表拒绝；前端覆盖保稿、登录恢复、版本冲突刷新、原请求核对和异步查询过期结果。真实员工、真实订单数量核对及 PostgreSQL 并发验收仍待完成。
- **未交付**：库存预留、自动 BOM 可生产量、现场／外发在外料耗用与盘余、实际材料费用、退料成本、损耗计价、月结及加工费结算；收妥签收不代表 QC 放行。

### P3a 补充：保稿刷新、签收关联和累计核对

- 新建申请遇到版本冲突可保留数量、用途、需料日期及映射依据，刷新当前订单、BOM和发布计划；展示前后版本，重新确认后提交。来源、BOM或执行方身份变化时须重新选择仓库物料，不能静默沿用。结果未知的操作必须先按原请求核对，不能通过刷新生成另一个请求。
- 主管在排期中选择本任务、当前订单/BOM和执行方的有效签收，带入所选最晚签收日；不以部分签收推定全部必需料齐备或自动可生产套数。签收关联和当时退仓状态冻结在计划版本；撤签或退仓变化后动态标记待复核，发布前重新校验。人工实际凭据仍可保留，但调整已发布计划必须填写原因，首次基准不改写。
- 累计领料按冻结来源、BOM、任务、执行方版本和物料行分别展示历史申请、有效申请、实发、未发、签收、退仓及净签收；关闭的未发余量不计有效申请，退仓不重新开放原申请。表内理论量注明原计划及目标套数；新申请用当前任务理论量核对，超量提示说明补领依据，不自动阻止有依据的申请。

### P3b 首批：实际耗用、损耗、盘余核对和原批次成本

本地启用、岗位权限与后续验收见 [P3b 验收清单](huakang-c-cutting-p3b-local-acceptance.md)。

- **已确认的职责**：生产文员按任务及原实发批次登记正常耗用、裁剪损耗／报废和本次盘余核对数，提交即生效，主管独立抽查；PMC／仓库采购岗位单独授权确认原批次实际单价、币种和成本凭据。员工仍待逐人指定，不自动授予权限，本地先用现有 admin 验收。
- **同一物料责任账**：以裁床有效签收为领入，扣除布料仓有效退仓与有效耗用／损耗，计算现场或外发余料；不再向布料仓重复出入库。每原实发、每业务日仅允许一张有效耗用单。本次盘余按所选业务日、登记截止时点的净签收减累计耗用及损耗核对；同日后续签收／退仓另行更新当前余料，不改原盘余，差异不自动补损耗。物料按原单位和批次核对，不自动换算、跨任务调拨或计入完整套数。
- **时序与纠错**：所有业务日不得晚于北京时间当天；耗用不得早于原实发或超过当日可用签收净额。补录、更正、撤签和退仓均回放完整业务日期时间线；有后续盘余依赖时须先处理后续单据。提供关联更正入口，在一次事务内撤销原单并生成替代单，保留原实发、原业务日期、盘余截止流水及双向关联；失败时原单保持生效，后续依赖阻挡提示具体单号和日期。独立撤销仍保留原耗用并可重新登记，相关退仓／撤签／出库冲销日期不得早于解除依赖的耗用撤销日；仅约束新操作，不重写历史。查询按裁床→布料仓锁顺序取得一致的签收和耗用视图。
- **原批次成本**：同一原批次在不同实发任务中共享已确认成本版本。正常费用与损耗费用分别按实际数量×批次成本计算，每个原实发的累计正常耗用及累计损耗分别按 Decimal 四舍五入到分，按币种分别汇总；首批支持 CNY、HKD、USD，币种必须明确选择。缺价保留空值，明确零成本必须有凭据。后续补价／调价追加新证据，保留登记时价格快照及全部确认历史；当前未锁月费用按最新已确认批次版本展示，不改原耗用数量。税费、运费暂不自动分摊，不从导入采购价直接取值。
- **接口与权限**：`GET /api/cutting-operations/orders/{line_id}/usage` 查询物料责任量；`with_costs=true` 另需 `cutting_ops:cost_read`，普通裁床读取不返回价格、金额或成本凭据。`GET .../usage-balance` 按业务日期及原实发提供不含价格的历史余额提示，更正时按原单截止时点查询；`POST .../usage/{post|void|correct}` 需生产 `usage_write`；`review` 需生产 `usage_review`；`price` 需 PMC／仓库 `cost_write` 和独立 `cost_read`。成本读取可授予生产或 PMC／仓库。`POST .../usage-operations/recover` 绑定原人原内容核对或封存原请求，防止迟到重试。未知结果时保留原操作，登录或撤权不允许改请求号绕过。
- **数据库与页面**：显式迁移 `20261014_0156` 在 `0155` 后新增 `cutting_ops_material_events`，含 SQLite／PostgreSQL 不可改删保护，启动不自动建表；无 DDL 合并迁移 `20261015_0162` 将其与远程 `20261014_0161` 连接为单一迁移头，不改写两条原迁移，也不代表本地或生产库已升级到该头。物料区按单登记耗用与余料；实际生产物料费用区按单核对耗用、损耗、待计价、批次成本与历史。无迁移、无授权、无真实业务时分别显示对应提示，不造测试库存。成本历史显示原批次、物料、缸号／卷号、实发单、业务日期、订单／任务、版本及凭据。成本缓存在登录失效或读取被拒绝后隐藏，保留草稿，只有重新成功读取后恢复显示。新耗用保存服务端仓库截止流水，旧格式按原登记时间兼容；本次仅扩展只追加 JSON 证据，无新增迁移，前后端及仓库回放需同步发布，旧回放不能处理新的同日时点与关联替代记录。
- **第二批成本核对汇总**：费用查询在原明细之外返回只读 `cost_summary`。任务按冻结订单下发、BOM及执行方版本分组；物料按仓库物料身份、资料版本及原单位分组，数量不跨单位相加。正常及损耗金额沿用原实发累计金额的分位四舍五入结果后分别求和，不再按汇总数量重新计价，币种分别显示；缺价的实际耗用另列实发笔数与原单位数量，明确零成本仍列为已计价。已冲销实发不纳入当前汇总，原单历史保留。该字段仅在已有成本查询权限下返回，普通物料查询不返回，登录失效或撤权时随费用明细隐藏。不新增表、权限或记账操作，不据此自动分摊在制、计算单套成本或确认结算。
- **第三批在制归集与成本核算**：生产主管需独立 `cutting_ops:allocation_confirm` 和 `cost_read`，通过 `POST .../usage/allocate` 按冻结订单下发／BOM／任务／执行方版本逐笔覆盖全部有效实发，确认累计正常耗用中归属于合格完工的数量，余下正常耗用列在制；不可超过原实发累计正常耗用，合格套数为零时完工归属只能为零。主管明确勾选全部物料已核对完整、是否仍有公共耗料待分配；未确认前归属显示待核对，不默认全部完工或全部在制。归集只追加原 0156 事件表的 `allocate` 证据，不新增库存流水、DDL或自动员工授权。确认、更正保留原因、原确认关联、日期、操作者、合格产量和当时价格快照。
- **归集有效性与核算**：合格套数由 P2b 权威实绩取得，外发仅验收合格计入，交接变化不改分母；历史执行方版本从原发布计划核对，身份不一致不得混算。耗用、实绩或有效实发范围变更使原确认待复核，并暂停单套成本；主管保稿刷新后须重新核对。完工材料金额按原实发到分，正常总费用减完工费用得到在制费用，分位余差保留在在制，保证两者合计等于原正常费用。当前未锁月数随确认批次价格更新，旧快照不改；缺价、公共料未分配、归集未完整或零套数不展示单套数值，损耗另列，币种不混加。当前确认按北京时间当天登记，不倒签历史月结；正式跨月结转及冻结属于 P4。
- **并发边界**：归集、实绩、耗用和相关仓库写入沿用裁床→布料仓事务锁，读数与确认依据保持一致；旧版本冲突保稿核对，结果未知按原操作恢复。新增 SQLite 并发验证及可选 PostgreSQL 同一套测试，后者仅接受专用 `cutting_test` 数据库和随机 schema；未配置连接时显式跳过，不能宣称 PostgreSQL 已验收。工厂全量回放／全厂版本冲突和大历史量性能仍需后续优化。
- **后续批次**：纯盘点差异单、专门期初录入、现场／外发之间调拨、单位换算、公共耗料／损耗分摊、标准费用对比和大数据量优化仍未交付。月度截止、内部月结及锁月见 P4b；外发加工费及应付／付款另行实施，首批材料费用不代表完整利润或已结算金额。

- **防重与并发**：本厂付款凭证号规范化后防重；金额按分精确计算。提交、确认、冲销与结算反结使用同一事务锁；重读余额和冻结结算版本，不能重复核销或超额。不同凭证号下的同一银行付款仍需会计查验凭据。
- **修订与复核完善**：草稿保存校验单据编辑基准，遇到同单并发先比较并明确选择；未生效草稿／退回单可留因跨月纠正日期，历史保留原月份。成功回执恢复定位原保存记录；复核对比上一编制版，付款占用按独立权限提供跨月定位。无需新增迁移或员工授权。
- **界面**：月结区增加付款独立区域，展示当前累计应付、已付、未付和待复核占用；付款月份筛选不代表历史月末快照。数量、加工费、付款查询权限分开，权限撤销清除付款敏感填写。
- **部署**：显式0166迁移，前后端同步；不自动迁移、授权或操作银行，不对付款执行内部材料锁月。见 [P4d验收清单](huakang-c-cutting-p4d-acceptance.md)。
