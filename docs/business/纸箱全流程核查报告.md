## 核查场景

### 历史订单模板与后续数量链

模板下载入口：订单管理 → 下载历史订单模板。文件为 `public/templates/carton-history-order-import-template.xlsx`，含空白主表、附加纸品、填写示例和字段说明。主表前八列是客户、合同号、货号、下单日期、计划交期、外箱需求数量、内箱需求数量、卡纸需求数量，其他资料在右侧选填。示例页不参与导入，合同号和货号按文本保存。

| 填写内容 | 要求及后续影响 |
|---|---|
| 客户名称、合同号、货号、下单日期、计划交期 | 必填，日期包含年份。原表“公司”识别为客户。未知客户须先维护，不能误当成工厂 |
| 外箱／内箱／卡纸需求数量 | 至少一种纸品有正需求；填写明确数量后以其为准，装箱换算不一致只提醒核对 |
| 产品订单数量、每箱个数 | 已知才填，未知留空。不会用外箱 100 × 装箱 12 推断产品数量 1200；也不会把未知装箱数写入标准包装 |
| `0/12` 装箱数 | 旧仓表识别为内箱无、外箱每箱 12 个产品；与正内箱需求同时出现则报错。新版模板用独立内／外箱每箱个数填写 |
| 纸质、规格 | 内外箱及卡纸分别填写。仅在基础资料唯一匹配时补齐，并在预览中说明；无法确定可先保存待下单，确认锁定前必须补齐 |
| 规格单位、纸品单位、币种 | 按实际填写并在预览核对；缺省 cm、内外箱个、卡纸张、CNY。英寸等不能省略后误用默认值 |
| 单价 | 可暂缺，界面标为待核价；缺价不等于免费，供应商月结确认前仍须核实 |
| 客户交期、产品名称、备注 | 可先留空。客户交期与计划交期独立保存，不用客户交期减三天覆盖历史计划 |
| 卡纸及其他卡类／滑板纸等 | 普通卡纸直接在主表填数量即可，无需附表或历史订单号；“卡类／卡”数量按卡纸登记并在预览说明。不同卡类、多种规格或其他纸品仍在附加纸品页逐行填写并关联主表 |
| 历史订单号 | 普通单选填；同客户、合同、货号的独立批次，以及需要附加纸品的订单须填写不同编号，以免混单 |

导入链为“选择文件 → 只读核对预览 → 修正错误／核对警告 → 明确确认 → 待下单”。错误阻断整批；重复、资料缺项逐单展示。文件、客户、供应商、基础资料或既有订单变化会使旧预览失效。旧纵向模板仍兼容，但不能与新横表混装一个工作簿后静默漏读。

后续编辑保留未知产品数量和装箱数、原计划交期以及明确纸品需求。确认锁定后，采购单按纸品需求形成不可变版本；追加和减单按每条纸品调整，保护已收与待确认数量，单条纸品减为零仍保留历史。创建和调整时间线记录逐纸品数量快照。

收料、出库及库存继续按实际纸品数量记账。订单导入不生成收料、期初库存或供应商应结金额，也不恢复历史履约进度。期初库存是独立正调整，不能重复作为本期采购收料；供应商月结依据实际验收入库日期、有效收退货数量和核实价格。

对应源文件：`carton_history_wide.py`、`carton_procurement_history_import.py`、`carton_procurement.py`（API／schema／model／service）、`carton_procurement_export.py`、`carton_master.py`、`carton_order_timeline.py`、`CartonHistoryImportDialog.vue`、`CartonProcurementView.vue`、`src/api/cartonProcurement.ts`、0106 迁移及相应回归测试。

八列简化专项：解析 23 项及三纸品待下单导入 API 1 项通过；不填写产品数量、装箱数及材料仍保持未知，缺材料不能锁定，导入不产生库存。类型检查与构建通过。

此前完整链专项验证：新版解析 12 项，预览／旧身份 API 9 项，旧纵向导入兼容场景通过；显式数量 API 覆盖补齐资料、确认、发行、按纸品追加减单、待确认保护和继续收料。隔离测试中 40 个 × 3.46 元进入供应商来源金额 138.40 元。迁移／数量链／时间线及旧计算数量回归通过，独立复核修复了混合表漏读、供应商预览漂移和时间线缺纸品变化问题。测试组有重叠，不累计为独立用例总数。

本地 0105→0106 先在真实库副本演练，再备份升级；132 张原有表全部原字段值和记录数保持不变，完整性和外键检查通过。未导入测试订单至真实业务库。登录页面只读核对订单加载与模板入口，导入确认及跨厂迟到响应由组件和隔离 API 测试验证。最终前端 3 文件 92 项通过，`typecheck:test`、`build`、`git diff --check` 通过；未配置 lint 命令。

## 仍需完善的业务能力

1. **实际期初切换仍需核实实物及基准日。** 库存管理→期初库存已提供简化模板、批次共同资料、只读预览及确认入账。每批选客户、仓库、完整基准日及尺寸单位，当前简化入口币种为 CNY。主表填写 PO、货号、纸品／纸质、长宽高、仓位、实际结余，单价可空。零结余跳过，缺价保留待核价，原结余金额与数量乘单价不符时阻断。确认时复核预览及库存证据，任一错误整批不入账。相同纸品和仓位的已导期初不会因换行序或来源行号再次增加；不同数量、价格或基准日报冲突。旧完整格式保留兼容，但简化入口不会覆盖现有库存，也不重放原入库、领料历史。
2. **历史履约未自动恢复。** 老订单导入需求不等于还原历史已收／已领／完成进度。需要另行区分未交订单、期初结存和历史已结清订单。
3. **供应商对账首版为手工账单录入。** 已实现数量／价格／金额核对与确认版本；文件导入、额外费用处理、付款记录和实际退货日期补录未实现。规则见《纸箱月结与供应商对账方案》。
4. **错误非零单价更正流程待定。** 当前支持有依据的零价核实；已入库的错误非零价格不能直接覆盖，更正及跨期重算规则需先确认。
5. **普通库存流水列表只加载最新 500 条。** 完整汇总和计价不受此限制，但更早流水的日常查询／纠错入口仍有限。
6. **大数据量和其他数据库环境未完成验收。** 历史核查、估值、仓库删除会扫描同厂历史，持锁时间需用实际规模测量；SQLite 测试不代表生产 PostgreSQL 并发和迁移验收。
7. **金额和数量测试通过不代表供应商实账已对上。** 本轮没有真实账单作为核对输入，也没有实际付款记录；仓库实物仍需盘点确认。

供应商月结使用 0105，显式历史需求使用 0106；本地已备份后升级至 0106 并核验原表值及记录数不变。不删除真实仓库、不做采购单外发、不锁定真实账期，也未执行 Git 提交、推送或 PR 操作。
