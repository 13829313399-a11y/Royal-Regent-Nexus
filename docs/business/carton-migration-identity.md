后续如需对账，先停写并保留完整可恢复备份，在隔离副本核对旧迁移、引用表主键/唯一约束/索引、原件列与检查约束、创建审计的归属证据及裁床历史结构，再设计与验收显式身份衔接。必须比较所有原有业务列、行、文件和审计，确认未丢失才可操作实际库。禁止盲目 `stamp head`、改旧文件冒充已迁移或重放已存在的归属 DDL。此代码交付没有修改任何业务库的版本号、结构或内容。


## 纸品工艺备注

正式迁移从 `20261110_0194` 分出两支，`20261116_0195` 新增打印机遥测表，`20261119_0196` 新增纸品工艺备注列。两支在 `20261119_0197` 合并。旧订单纸品的工艺备注默认为空。当前 `alembic upgrade head` 还会执行[注塑排程退役迁移](../project-memory/production.md#injection)，在副本确认排程表、专属权限的清理范围及其他业务数据后再安排发布。

早期本地 SQLite 使用了 `20261119_0195`，原始脚本保存在 `backend/alembic/legacy/20261119_0195_carton_paper_process_notes.py`。遇到这个版本时先停写并完整备份，将 `DATABASE_URL` 指向独立恢复副本，在 `backend` 下执行以下命令。

```sh
alembic -x reconcile_carton_process=1 upgrade head
```

此入口仅接受该本地单一版本，会验证历史结构、工艺列和遥测表状态。在同一事务内识别等价的工艺迁移并补齐遥测表，保留已有工艺内容。核对原有表、行和工艺备注以及外键完整性后，再安排实际库切换。
