# 公共工具栏：协同填表

在公共工具栏点击「协同填表」。上传人创建任务，指定填写人员或部门及单元格范围，参与者登录后直接填写，最后由上传人下载汇总文件。

## 使用步骤

1. 切换到本人所属厂区，点击「上传表格」，选择 `.xls` 或 `.xlsx` 文件并填写任务名称。上传后为私有草稿。
2. 在「分配填写」中选择工作表、部门或账号，输入范围（例如 `L3:N14`），点击「添加」。部门支持多选，一次为所选部门添加相同范围；重复的分配自动跳过。也可分批添加，为不同对象分配不同范围。
3. 保存分配设置，点击「发布填报」。指定人员登录后可以看到任务；未指定人员看不到。
4. 参与者选中可填写单元格后直接打字，或双击 / F2 编辑原内容。Enter 向下、Tab 向右，Shift 反向；方向键移动，Esc 取消当前输入，Delete 清空。支持从 Excel 粘贴最多 500 格；粘贴范围包含公式、合并区域内部或未授权格时整次拒绝。点击「保存填写」或 Ctrl / ⌘ + S 保存。顶部填写框仍可使用，编号可选择「文字」；直接输入保留前导零，百分比按数值识别。
5. 填好后点击「我已填完」。后续表格或分配发生变动，需要再次确认完成。
6. 上传人可查看完成情况和操作记录，点击「结束填报」停止修改，再点击「下载汇总」。也可以重新开放填报。

多人使用同一份表，已授权人员能看到完整工作簿，修改仅限分配范围。上传人可修改所有已分配范围。公式、合并单元格非左上角位置不允许填写。任务列表自动检查更新；当前表格使用「读取最新」刷新，避免打断正在输入的内容。多人同时保存发生版本冲突时，系统保留本地填写，读取最新后须核对并再次保存，不会直接覆盖他人的新内容。

「填写人员与进度」列出已保存授权覆盖的当前厂区全部有效、已确认账号，包括从未操作的人员；账号和部门重复授权只显示一次。红色为未填写，蓝色为已保存但未确认完成，绿色为已确认当前版本完成，橙色为表格更新后需要重新确认。保存与完成确认是两个不同动作。名单及状态每 15 秒轻量刷新，不替换表格或未保存输入；停用、撤权或调离部门人员会从当前名单移除。选择多个部门时，账号预览合并显示所选部门在当前厂区的匹配账号；分配保存后才生效。

网格内复制单格保留原值及内部数据类型，多行文本不会在内部粘贴时误拆成多格。当前提供常见填写操作，不包含 Excel 的整列拖拽、完整公式编辑或计算引擎。

## Univer 新版编辑器

打开任务后默认使用 Univer 新版编辑器，可直接在画布内选择和填写单元格，支持方向键、复制粘贴、Ctrl / ⌘ + Z 撤销及 Ctrl / ⌘ + Y 重做。手动输入和粘贴使用同一套内容识别，保留编号前导零，百分比按数值处理。需要查看原版图片布局时，点击「使用原版编辑器」即可切换，并继续处理同一份未保存内容；点击「使用新版编辑器」可切回。保存、部门授权、人员进度、版本冲突处理及原格式下载沿用现有流程。

新版采用固定版本 1.0.3 的 Univer OSS 核心，按需加载当前工作表，未接入付费导入导出或实时协同服务。画布只接收已有文件解析结果，填写值仍经过现有范围与类型检查后保存。行列结构、格式和公式不可修改，公式显示原文件缓存结果。

新版画布暂不显示表内图片：选中图片所在单元格后，可在下方查看原图；使用原版编辑器可查看已有图片布局。下载继续通过原文件写回保留图片，不通过 Univer 重建文件。复杂 Excel 格式和打印版式仍以下载文件为准。

新版已设为本地默认编辑器，尚未部署生产。隔离验收使用独立试验账号、数据库和上传副本，不改动用户原文件。两份 XLS 与约 50 MB 的开发记录 XLSX 已通过真实画布填写、保存和原格式下载核对；大表下载保留全部 153 个媒体文件的原始内容。试验资料位于 `outputs/univer-trial-20261009/`，包含业务样表副本和试验数据库，不能提交到 Git。

## 格式与范围

- 原文件只读保存，下载仍为上传时的 XLS 或 XLSX 格式，填写记录写回原表。不会把 XLS 转成 XLSX，也不会把表格重建为普通数据表。
- 浏览器支持常见字体、底色、行高、列宽、合并单元格、数值格式和 WPS 单元格图片。复杂自定义格式及浮动图形不保证完全还原浏览器显示；原有图形保留在下载文件中。
- 浏览器不重新计算公式。填写后下载并使用 Excel/WPS 打开，按原工作簿计算规则重算；手动计算工作簿需手动重算。
- 当前收集的是单元格值，不提供插入行列、修改格式、编辑公式或图片的功能。
- 单文件最多 100 MiB（界面显示为 100 MB，上传请求最长等待 300 秒），解压后最多 160 MiB、最多 5,000 个压缩包文件项，最多 50 张工作表，显示区域累计最多 100,000 格，每表最多 5,000 行、256 列。受保护、加密、带宏、数字签名和不支持的旧版结构会明确拒绝。
- 仅已确认身份的在用账号能在所属厂区参与。部门授权使用当前部门成员关系；调离部门或停用后不继续获得该部门权限。仅上传人能够下载汇总。

## 实施与部署

前端入口为 `src/views/ToolCenterView.vue`，业务界面在 `src/features/collaborative-sheets/`，请求封装为 `src/api/collaborativeSheets.ts`。厂区切换前的草稿保护位于 `src/lib/factoryChangeGuard.ts` 和 `TopBar.vue`。

后端 API、模型、请求结构分别在 `backend/app/{api,models,schemas}/collaborative_sheets.py`；流程和权限在 `services/collaborative_sheets.py`，文件检查与保格式写回在 `services/collaborative_sheet_files.py`。使用已有文档存储，依赖 `document_tools_enabled` 开关。`olefile` 已加入直接依赖。

新增表结构迁移 `20261009_0121` 保留前置版本 `20261005_0120`；合并迁移 `20261009_0148` 将它与主线 `20261008_0147` 接为单一升级终点，不改写已有迁移。**生产网页已更新至 main `e34fc123`，支持部门多选；后端沿用 `60a4fb1f`，数据库版本为 `20261009_0148`。Univer 默认编辑器与 100 MiB 上传支持尚未部署生产；发布这两项改动需要更新前后端，无需数据库迁移。** 部署时先备份数据库，在副本上演练 `alembic upgrade head` 并核对旧数据，再升级正式数据库、前后端和依赖；新后端会拒绝启动尚未升级的既有数据库。部门名单遵循最新身份管理中的当前主厂区、主部门和任职生效时间。

## 两份真实样表试验

使用用户提供的货款汇总及新产品统计 XLS 原文件，在独立本地数据库中创建四个试验账号完成流程。所有填写均为明确标注的测试值，不修改原文件、不写入正式业务库。

试验覆盖部门分配、非授权账号拒绝、跨厂拒绝、填写保存、旧版本保存冲突、确认完成、结束后拒绝修改、上传人下载和参与者下载拒绝。下载后核对工作表名称、尺寸、合并范围及每个单元格格式索引；所有非 Workbook 的 OLE 数据流逐字节一致，包含新产品表的图片资源。原文件前后 SHA-256 相同。

试验输出及结构化结果在 `outputs/collaborative-sheets-20261009/`：

- `货款汇总-协同填写试验.xls`
- `新产品统计-协同填写试验.xls`
- `sample-acceptance.json`
- `excel-open-validation.json`（同一保格式引擎早期测试副本经本机 Excel 只读打开验证）

自动化验证使用 `npm run build`、`npm run typecheck:test`、协同填表/公共工具栏/厂区切换前端测试，以及 `backend/tests/test_collaborative_sheets.py` 和相关反馈、迁移回归。具体执行结果以本次交付说明为准。

验证覆盖原表格式保留、完整部门名单及完成状态、格内编辑与粘贴、版本冲突、厂区和部门隔离、草稿切换保护，以及两个迁移分支接入最新主线。实际 Excel 完整交互与浏览器支持范围的差异见上文。
