# 华康 C 裁床部 P4d 首批：外发加工费付款登记与核销

本批已实现，根目录本地开发库已显式应用0166并启用现有 admin 验收。入口：裁床部 → 月结 →「外发加工费付款登记与核销 · P4d」。真实员工授权、真实财务样例及生产部署仍须另行验收。

## 已确认业务范围

- 只登记已经实际支付、且有凭据的款项，不连接银行或执行转账。
- 每笔对应同一家外厂、同一币种；可分配多张当前已确认的有效结算单，也可分次核销同一张单。
- 实际付款金额须为正数、最多两位小数，与全部分配金额之和完全一致。币种分别核对，不做汇兑。
- 会计单独授权登记并提交，另一名会计独立复核生效。复核人与编制人、提交人均须不同。
- 错误记录由单独授权人员填写原因，整笔冲销登记及所有核销，再关联原记录重新登记。冲销不代表银行退款。
- 本批不包含预付款、超付、未分配款、实际退款、跨期调整单、付款期间锁定或银行流水自动导入。

## 流程及金额口径

1. 读取当前有效应付，填写实际付款日期、付款方式、付款凭证号、凭据／交易流水说明、币种和金额。
2. 逐结算单填写分配金额，预览并保存草稿。草稿不占用额度。
3. 提交复核后占用可核销额度；此时仍未计入已付。
4. 另一会计核对原付款凭据、外厂、币种、冻结结算版本及全部分配，填写依据后复核生效；错误则退回。
5. 生效登记只能整笔冲销；重登保留原凭证、原单关联及完整操作历史。

金额使用 Decimal 精确计算，接口和页面按分展示：

- 未付余额＝当前有效冻结应付－有效已付核销。
- 可继续核销＝未付余额－待复核占用。
- 付款月份用于筛选登记记录；余额始终为全部有效结算的当前累计余额，不是历史月末余额。筛选不删除隐藏的已选分配。

提交和复核均重新核对结算版本、币种、外厂和可用余额。有待复核付款或有效核销的结算单禁止反结，须先退回或整笔冲销相关付款。原内部材料锁月与付款登记分别办理。

付款凭证号在本厂范围按 Unicode NFKC、大小写及首尾空格规范化防重；有效和待复核登记不能重复占用。同一银行交易使用不同凭证号仍需会计人工核查，不声称已自动识别全部重复银行付款。

## 岗位权限

各操作均须 `cutting_ops:read`，以下权限仅允许会计部范围：

| 权限 | 用途 |
| --- | --- |
| `cutting_ops:payment_read` | 查看付款登记、核销分配、当前余额及付款历史 |
| `cutting_ops:payment_prepare` | 登记、修订草稿、提交复核及关联重登；同时须付款查询 |
| `cutting_ops:payment_confirm` | 独立复核生效或退回；同时须付款查询 |
| `cutting_ops:payment_reverse` | 留因整笔冲销登记及核销；同时须付款查询 |

原结算报价／明细另需 `cutting_ops:settlement_read`；材料成本权限不会替代付款权限。未自动授予任何员工或外厂账号权限。

仅 development 环境的现有 `user-admin`、admin 角色且明确开启 `CUTTING_PERIOD_ADMIN_ACCEPTANCE=true` 时允许本地双岗位验收。记录显示验收标识；正式员工仍须不同账号复核。

## 追溯与异常处理

- 付款单固定原冻结结算事件与分配金额，历史展示操作者、原因、日期、版本和当时凭据。
- 已冲销历史不计当前有效核销，明确显示当前状态；原登记和关联重登可双向定位。
- 可从分配明细打开原冻结结算版本，并从已付／占用明细定位对应付款。
- 保存同时校验本付款单版本和全局余额版本。刷新余额保留原单编辑基准；本单被他人修改时展示服务器最新内容与本地填写的差异，明确选择采用哪份内容并填写修订依据后再保存，期间再有修改仍拦截。已失效分配不能静默删掉；父级加载不丢草稿，实际撤权清除金额、凭据及差异缓存。
- 草稿和已退回登记可留因纠正跨月实际付款日期，原事件保持原日期；当前列表按更正后月份归属。待复核须先退回，已生效仍须整笔冲销重登。历史按原业务月份打开，返回当前版本跟随最新月份。
- 复核展示上一编制版本的付款日期、凭证、方式、币种、金额、凭据及逐单分配变化；新增、取消和调整分列，按分精确计算，币种改变不计算跨币种差额。
- 结算详情中的当前付款占用列出月份、凭证、状态及分配金额，可直接打开付款面板并定位；仅另有付款查询授权时返回和显示，目标读取再次检查权限。
- 未知写入结果保留原操作者及原请求内容，只核对原回执；确认已成功后打开原保存月份、单号和事件。读取失败仍保留已保存记录的重读入口，不重复登记；未执行请求封存。旧请求缺少新增编辑基准字段时回执指纹保持兼容。浏览器不持久保存付款业务填写。
- 付款、核销及结算反结共用裁床事务锁，重复相同请求只产生一次事件。证据表禁止直接修改或删除。
