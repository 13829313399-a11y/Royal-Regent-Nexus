# 喷油模块闭环扩展与本地验收

本轮在既有 Vue / Pinia / FastAPI / SQLAlchemy 技术栈内补齐喷油工作区能力。华兴、华康 A、华康 B、华登共用组件，以执行厂区隔离数据；客户厂区不替代执行厂区。改动留在独立工作区，未提交、推送、创建 PR、部署或迁移业务数据库。

## 已实现

| 范围 | 可执行行为 |
| --- | --- |
| 工艺与实体流转 | 任意无环前置依赖、可视工艺图、分支/汇合校验；返工保留其他已完成工序；同一实体数量不会因分支复制。旧串行工艺兼容。 |
| 排产 | 日/周画布、资源/订单视角、跨工作时段拆批；共同检查设备、人员、工装的日历和容量；改排可整体释放旧预留后重新分配，已开工任务不能移动。 |
| 报工与工资 | 生产与非生产活动；按员工、日期、班次汇总多任务，分别保存已赚、保底、有符号差额、补贴和应付；确认后冻结。草稿保存提交标识，刷新后重试不重复报工。 |
| 历史导入 | 列、固定单元格、向下沿用、确认常量及横向日期矩阵；明确表页角色、逐行预览、身份去重、来源关联、显式更正、撤回和跨表差异。原日期、单号、公式、数值精度及坐标可追溯。 |
| 经营与输出 | 实际物耗、送退货净额、月结冻结和后续期间调整；按原币与单位展示历史对账。原文件不变，原格式复刻或将当前记录绑定到原模板单元格输出副本。 |
| 持续操作 | 报工、排产、导入映射草稿及保存视图按账号/厂区持久化，并检查草稿版本。订单、任务、资源时间轴和导入差异使用虚拟列表。 |

后端主要变更位于 `spray_production.py`、`spray_scheduling.py`、`spray_advanced.py`、`spray_history.py`、`spray_imports.py`、`spray_templates.py`，配套模型、API 和 `0109` / `0110` 迁移。前端集中于 `src/features/spray-production/` 和 `src/api/sprayProduction.ts`；未重写其他生产模块。

## 浏览器与规模验证

使用真实浏览器连接本地接口，未用静态数组替换 API。浏览器工具链采用已安装能力可用的 Playwright CLI；当前环境未提供该技能所引用的专用浏览器运行时，因此按技能回退路径操作。

- 拖入 100 件批次只填写草稿，未向生产命令接口写入；建议按两班拆为 60 + 40，保存、刷新恢复、应用和再次刷新均验证通过。
- 同一员工两项任务 3 + 2 小时，已赚 50、保底 75、差额 25、补贴 25，确认应付 75；这里只是明确标记的测试工资策略。
- 上传真实 S04 工作簿，映射 `接单订单` 第 2 行的 2022-07-16 / FD0062；首次新增，重查关联同一业务，不增加当前库存。切换华登后不带出华兴历史事实。S03 缺少必要身份字段的候选显示待核。
- 1920 / 1440 / 1280 / 1024 / 390 宽度报工布局检查；追加 1440 / 390 工艺图及 390 工资、历史映射检查，没有页面横向溢出。最终界面检查无脚本异常。
- 10,000 订单、2,000 任务、50 资源均通过真实接口加载。末次本机开发环境测量：订单首屏 3,509 ms，滚动至末行 22 ms，过滤 21 ms，切换任务列表 203 ms；订单/任务/资源各仅渲染 15 / 13 / 11 行，JS 堆约 67.8 MB。该数据是本机测量，不代表生产网络性能或通用帧率保证。

## 仍需明确的验收边界

这些扩展使主要生产与经营功能能够闭环，具备安排四厂试运行的基础；不能将其描述为四厂已经正式上线。

1. **历史全部确认入账尚未完成。** 70 个表页已读取并形成候选；真实执行厂、实体部件/工序、缺失单号、单位、PO 匹配及来源年份的未决项仍需业务确认。候选、历史事实与当前库存分开，不能用接单累计或历史入库总数推算今天现存。
2. **工资制度与上线期初尚未业务验收。** 历史系数不自动启用，正式策略需要负责人确认。切换日和在制、成品、油漆、容器实物盘点余额不得由测试或旧表缓存代填。
3. **原表输出具有明确计算范围。** OOXML 已覆盖识别的算术与 SUM 公式，未识别的依赖缓存清空并要求表格软件重算；BIFF 保持版式和值，不声称恢复完整公式表达式。扫描 PDF 只保留原件。原模板绑定仍需选择业务字段与目标单元格，不声称所有旧报表自动编排已完成。
4. **建议排程是有限容量建议。** 每次最多处理 200 个候选批次及 200 个任务片段，以当前已放行实物为依据；未满足条件的数量保留待排。它不承诺跨全部未来工序的全局最优解。

本轮修复过程中发现过 Excel ZIP 返回过早、长小数重新预览、文件上传 Content-Type 等问题，均在最终验证前修复。中途失败日志保留作为排查证据，验收以上述最终通过结果为准。
