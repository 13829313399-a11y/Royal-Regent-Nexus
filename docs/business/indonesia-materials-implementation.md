# 送印尼物料实施计划

依据用户确认的 V2.1 业务框架，用户已要求开始执行。原方案中的“仅文档”是上一阶段边界，模块已按用户后续要求接入当前 5173 本地系统，并完成本地库显式新增表迁移；不包含提交、推送或线上部署。

## 实施顺序

1. 新建独立厂区隔离领域、权限目录及显式迁移，复用数据库事务锁和幂等操作凭据。
2. 实现货号／物料资料、合同／客户 PO 需求、需求快照、倒排、供应回复、船务入库、数量分配与未发改绑。
3. 接入统一排期预览／选行确认，保留原文件及行坐标；订单中心稳定标识留在来源字段，不改订单中心流水。
4. 实现客户出货单、包装组、确认与原版模板输出。未确定的混箱输出表现等问题明确保留，不伪装为已经业务定稿。
   用户最新要求删除教程示意图片；保留说明文字、原表格式与实际物料图片，替代此前“教程图片也保留”的要求。
5. 接入三个主工作区、实际空状态和权限提示；移除该入口虚构的样例数量。
6. 针对厂区、数量、备品、日历、幂等、版本冲突、原版输出做测试，完成构建与独立审查。

## 不变量

- 数量采用十进制；正常＋备品占采购数，备品免费但计重量且能覆盖生产需求。
- 生产按周一至周五，运输河源至印尼工厂初始 25 自然日，整理 0 天，采购备料周期必须人工给出。
- 来料仓的供应商回复不入库，船务确认入库后才能实际齐料；正常发出仍保留已履行需求覆盖。
- 每次一客户一接收方；出货确认与下载分离，重试不能重复过账。
- 客人、货号、物料、合同、采购及出货按厂区隔离；七类基础选项全厂共用，读写均走后端授权，不自动扩张既有员工范围。
- 基础资料改动不改写旧合同需求与出货快照；变更经业务显式重算／确认并保留操作历史。

## 存储与接口

采用厂区隔离的类型化业务记录（资料、订单、供应、分配、出货、导入批次），每条保存版本；追加操作凭据保存前后变化与操作者，原文件／导出文件使用独立附件记录。写命令在厂区事务锁内校验版本、关联对象、库存余量及幂等标识。没有任意 JSON 覆盖接口。

- `GET /api/indonesia-materials/workspace?factory_id=`：当前业务记录、服务端计算的看板及操作能力。
- `POST /api/indonesia-materials/commands`：`factory_id, operation_id, action, entity_id?, expected_version, data`。
- `GET /api/indonesia-materials/shared-options`：全厂共用选项、默认项及当前岗位的读写／管理能力，不返回跨厂业务数据。
- `POST /api/indonesia-materials/shared-options/commands`：共用选项专用命令；作用域固定 `shared-options`，沿用原操作编号、版本和审计凭据。
- `POST /api/indonesia-materials/imports/preview`：统一排期文件、厂区、客户、接收方；返回预览及原文件引用。
- `GET /api/indonesia-materials/shipments/{id}/export?factory_id=`：下载已确认出货的不可变模板结果，不再过账。

延期提醒、借料归还、公共备库、实际船期维护及特殊模板表现按业务框架文末遗留清单继续处理。

## 当前实现

### 合同内维护计划与独立草稿

合同明细直接填写日产能、运输自然日及各物料采购周期，自动带入已有默认值。“保存并更新本合同”通过 `order_plan_save` 一次更新默认参数和当前合同日期，无须跳转基础资料或再点重算。其他合同保留原计划；本合同需求量、用量及价格快照、历史分配和已确认出货不变。后端核对合同、货号、完整物料集合及原版本，错误整笔回滚。

合同计划按合同 ID 独立保存草稿。出货确认按单据 ID 和保存版本分别保留核对上下文，回退修改装箱后不会恢复旧版确认。旧草稿身份仍兼容，刷新、重开及网络中断重试保留原操作编号与各条草稿。

### 已实现：回料采购单 → 点选 PO 抵扣 → 出货 Excel

日常流程为“统一排期导入 → 合同看板查看最迟回料期 → 收到回料采购单并导入明细 → 业务点选抵扣客户 PO／合同 → 同批明细生成出货资料 → 补装箱并确认导出 Excel”。顶部为“合同计划”“回料出货”“基础资料库”三个入口；统一排期导入和需求维护收在合同计划内。回料出货采用“导入回料 → 核对并分配 PO → 补装箱 → 确认导出”按单向导，历史记录和手工台账收在次级入口，草稿列表默认折叠。

建单取消交付批次输入，不预估供应商会分几次回料。新需求按客户、接收方、合同、客户 PO、货号识别；改期不产生另一份需求。旧显式批次身份、原件和历史记录保留。新旧格式双向匹配，缺 PO 或多条历史匹配须业务核对，不能重复建单；原无批次记录可带原因补齐一次原来缺失的 PO。实际分配只允许已确认回料；历史预计分配仍可读取，已完成指令原样重放。

“回料出货”默认进入实收导入；确认实收和 PO 后自动进入本单装箱，保存装箱后进入核对，明确确认出货后自动下载 Excel。装箱正常量和备品量分别提示差额，下载失败可重试且不重复记账。向导关联当前实收单与其出货单，保存装箱保留原实收来源，切换单据不会串用另一单的步骤。采购与回料台账保留原手工业务。支持 XLSX／CSV 常见表头，并提供带 UTF-8 BOM 的空白 CSV 模板。一个文件可包含多仓库行；原单无仓库列时可在上传区补充仓库。收料单号、稳定行号、实收日期及有效实收数量须来自原单。无编码时按名称、规格、单位查找；唯一且明确时自动选择，多候选、规格不完整或编码／名称不一致时由业务核对。显式原单厂区与当前厂区不符则阻止该行。

一行实收可由业务点选拆给多个客户 PO／合同，正常量与备品量分别精确合计；不自动跨单位换算、不用计划数量代替实收。即使仅有一个候选 PO，也由业务点选，不自动抵扣。候选显示 PO、合同、货号、交期；来源明确提供的客户 PO 在确认时强制核对。原单“实收合计”包含备品；单列正常量时单独读取。业务选择原采购批次或补齐真实采购单号、行号、日期及采购总量；供应商、单价、币种从原单或基础资料显式带出。选用原批次须核对实收数量及原单明确提供的采购事实，不覆盖原价和换算快照；数量不符先核对／拆分原回料批次，不能重复新建来绕过采购上限。

历史预计分配与实际 PO 不符时，页面展示全部原分配，业务可明确勾选重新指定并填写原因；提交携带旧分配完整编号和版本。后端拒绝过期引用或已用于出货资料的分配，原子保留旧分配归零及原因／原单来源，再建立本次所选 PO 分配；未勾选不得自动覆盖原分配。

有本模块业务维护权限的业务确认原单后，原子生成已确认实收批次、合同分配及一份当前客人／接收方出货草稿，保留原件、仓库、单号、行号及来源坐标；不写仓库模块库存。原手工船务确认入库权限保持。收料身份按厂区＋仓库＋原单号＋行号防重，文件内容或文件名变化不能重新计实收。原导入、物料、采购、合同版本与数量余量均在提交锁内重验，任一错误整笔回滚。可分批选行，已导入行不能再提交。业务格式错误返回已知 4xx，候选过多仅提示并阻止相关行，不影响整个厂区工作区读取。

缺少装箱资料保留为空；完整且唯一的包装组可随单带入。整份来源中同仓库／同单据出现重复包装组标识，即使本次未全选或另一行字段不全，也不自动推算混箱。生成后可直接打开对应出货草稿，补齐箱数、尺寸、纸箱重量及混箱构成，并核对本次发出数量；正式出货仍单独确认，确认前无最终 Excel、不扣发货数。仓库匹配表单按每次导入独立保存本机草稿，未选文件前的客人和仓库也保留，换文件、切换客人和原操作重试沿用现有 CAS／幂等保护。

新增接口：`GET /api/indonesia-materials/warehouse-imports/template`、`POST /api/indonesia-materials/warehouse-imports/preview`，确认通过原命令入口 `warehouse_import_confirm`。记录复用现有 `import` 类型并使用 `import_type=warehouse_receipt`，与统一排期记录分开显示，无数据库结构迁移或历史回填。实现入口为 `indonesia_warehouse_import.py`、`WarehouseImportWorkspace.vue`、`warehouseMatching.ts` 及现有 API／工作区集成。方案、UI 简报与验证证据位于 `D:/royal regent heyuan/outputs/indonesia-warehouse-receipts-20261022/`。真实仓库样表及浏览器交互仍须现场核对，当前会话无 Chrome DevTools MCP。

### 已实现：厂区固定客人层级

用户新增确认的基础资料关系为“厂区 → 固定客人 → 该客人的上印尼货号 → 货号物料与单件用量”。固定客人名单由业务在本模块维护，支持增加；每个厂区分别配置。RRI／RRM保持接收方语义，与成品客户区分。

基础资料库默认进入“固定客人”，支持新增、备注和启停；从客人行进入其货号列表，新建货号预选该客人；左侧为“固定客人”“货号与物料”和“基础选项”。每个货号行可直接“添加物料”，编辑区紧接该货号下方，在同一表单填写物料资料和每件成品用量，也可“选用已有物料”复用同一编码。单件用量上下调整每次增减 1，手工输入仍支持小数。货号与本次新增／编辑的物料在同一个 product_save 事务内保存，任一校验或版本冲突整笔回滚。已有物料编辑携带原 material_version，并提示共用它的货号；配方仍只存 material_id 和 usage，不复制成多份独立物料。“删除货号”只在货号行提供，不再放在嵌套物料表单底部。每张物料卡片单独提供“删除物料资料”，已有物料另保留“移除关联”；后者只移除当前货号用量，不删除物料主档。删除先进入“待删除物料”清单，可撤销并恢复原字段、图片及小数；待删除内容随原货号草稿保存和刷新恢复。未保存的新物料不创建主档；已有物料携带原物料版本，与货号及用量在同一 product_save 事务归档，不删除货号，也不改其他物料。重复删除编号、同时保留与删除、父或子版本过期、其他货号（含已删除货号）引用、合同或采购历史引用均阻止删除，失败整笔回滚。删除后在“已删除物料”恢复原编号资料；编码继续保留，普通保存不能复活，恢复不会自动重新关联货号。原独立物料 API 和历史物料草稿继续兼容，但不再提供分散的物料新增分类入口。嵌套物料及图片随货号自动保存草稿，恢复保留父货号和子物料的原版本。货号可先保存为未配用量的资料，但新建合同、显式重新生成需求或导入确认必须已有该客人、对应货号及非空用量。新合同先选当前厂区的启用客人，再选择其货号，并显示配方预览；更换客人时清空旧货号。RRI／RRM仍单独选择。

“基础选项”全河源厂区共用，涵盖类别、报关单位、数量单位、产品用途、币种、供应商及出口公司；侧栏明确区分“本厂区资料”与“全厂共用资料”。普通业务有本模块业务部查看、维护权限即可新增维护；启停、删除、恢复及换算规则调整由有模块维护权限且任职有效的业务主管／经理或系统管理员处理，不指定个人，不自动扩大员工授权。七类选项支持检索、版本冲突校验及操作审计；名称和分类为关联身份，不能覆盖改名，重复名称按分类及规范化名称拒绝重复。删除仅限未被任何厂区业务及历史快照使用的选项，已使用项提示停用；拒绝信息不泄露其他厂区私有单据。删除保留原编号、状态和规则，可在“已删除选项”恢复。停用／删除后的新选择由服务器再次校验，旧表单不能绕过；既有资料原值可继续维护，原采购及已确认出货快照不重算。共用选项使用独立账号／任职／shared-options 草稿和原操作凭据，切换厂区仍可继续；旧厂区选项草稿保留，只能由用户显式复制为共用新建草稿，核对后提交。旧厂区已落库的选项命令仍按原凭据重放，未落库旧请求拒绝并要求在共用入口重新核对。供应商和出口公司也能在填报时输入关键词搜索或直接填写。初始类别为彩盒/彩卡、利宝说明书、塑胶、半成品、电池，报关单位 KGM／TNE／PCE，数量单位 pcs，产品用途为产品配件，币种 USD／HKD，供应商包含用户指定的八家。停用选项不删除历史记录中的原值。物料字段按原表相对列顺序排列：中文名、英文名、规格、类别、报关单位、数量单位、图片、产品用途、供应商、采购单价及币种、出口公司、物料编码、使用部门、单个净重；取消“单件计费重量”输入，按重量计价直接使用单个净重，无须重复填写；采购备料自然日另放在采购与倒排参数区。出货实填数量、箱数和尺寸仍在相应采购／装箱入口，不在物料主档重复录入。

新资料按报关单位自动确定计费口径，隐藏重复的计费单位和手工系数：KGM 为正常数量×单个净重（kg）×单价；TNE 在上述重量基础上÷1000；PCE 为正常数量×单价。报关重量另按含备品的实物数量和单个净重计算。自定义报关单位须维护按件／按重量及每单位对应的千克数；未知或停用单位不能用于新自动计价。既有自动物料在报关单位及计价模式不变时保留原换算规则，单位停用后仍可维护名称、图片等资料；新建、换单位或由手工转自动仍校验当前启用规则。采购保存当时的单位换算规则快照；既有采购编辑保留原物料快照、计费方式和除数，字典变化不重算旧采购。物料保存时由服务端按净重派生旧计价重量兼容值；新界面的采购请求显式使用净重口径，即使选择尚未重新保存的旧物料，也只按其净重计价。新批次缺失或为零的净重须补全，不能用旧计费重量代替。既有采购编辑保留原单重快照及原口径，旧未决请求不补写新标记，尚未落库的旧请求重试和已落库凭据重放均沿用原规则；旧手工计价与已确认出货文件保持原计算快照。旧物料草稿继续恢复净重，但提交时不再带独立计费重量；原已冻结命令的编号和内容不改写。单箱立方数沿用原公式“长×宽×高÷28316.75×0.0283”，总立方数按实际包装组汇总，混箱共享箱数和体积只计一次；毛重为物料净重加分摊纸箱重量。

固定客人和货号编辑区提供删除按钮，并保留恢复入口。删除是带版本和幂等凭据的可恢复标记，保留原编码、名称、物料与用量；客人仍有关联货号或合同、货号已有合同引用时拒绝删除。历史业务继续使用原快照，已有合同的客人可用停用限制新业务；恢复货号仍须原客人启用。

新增 `customer_save` 命令和厂区隔离的 `indonesia_material_customers` 表，沿用业务写权限、IAM／厂区事务锁、记录版本和幂等操作凭据。迁移 `20261021_0169` 只新增客人表，不重建原记录表、不回填或导入历史业务；startup `create_all` 继续排除本模块表。客人名称与货号所属客人为关联身份，建档后不覆盖改名；停用客人后停止新业务，旧合同仍可查看和按原身份编辑。既有合同快照及已确认出货文件不因维护客人资料而重写。
