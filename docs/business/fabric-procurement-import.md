# 布料仓采购来源导入

布料仓从采购已经下达的订单开始接收来源资料。第一步支持采购日常发送的物料跟踪表，供仓库查询待到物料及后续关联实收；仓库不在此流程替采购下单。

## 本次可用范围

华康 C 布料仓不设独立“订单管理”，不负责采购下单。“收料入库”依次为“订单导入、待收料、送货单扫描、入库记录、采购接口”，日常进入默认显示待收料；扫描和接口明确保留待接入入口。

在“订单导入”上传 `.xlsx`，默认选择“未回物料 + 已有订单变化（推荐）”，读取预览后明确确认保存。该范围新增未回物料，同时从已回料表核对系统已有订单的变化；未关联的已回历史明确计数排除。仍可显式选择仅未回物料、已回料历史或全部。该页的“全部已导入来源（含历史）”和“查看已回料历史参考”查询已保存的采购来源；日常待收料默认只显示未齐料，部分到货仍须跟进。查询和来源详情读取服务端保存的真实记录。旧订单管理查询链接跳转到收料入库的对应查询，原放产用料链接跳转到待收料。

“入库记录”查询仓库实际收料单与批次。待收料支持按来源登记入库，原子保存实收与库存流水；采购文档导入本身不增加库存。原“退货记录”不直接生成待入库；车间退回余料属于库存管理的“退料记录”，两者不能混用。

“未回物料”可以已有部分到货。“已回料”只保存采购历史参考，不生成入库单、库存流水、期初库存或应付账。实际收料按独立稳定的仓库来源明细 ID 关联采购来源，另记实收量、单位、批次、质量和经办人，不能从采购已回参考自动记账。历史状态不代表当前库存或全部验收完成。

## 表头与原始证据

当前适配“物料跟踪表(新版)”的 `未回物料`、`已回料`、`补数未回物料`、`补数已回`，按表头定位，允许前置说明和列重排。默认 TRACKING 新增正常采购及补数未回，已回页仅检查已有来源变化。补数独立分类，保留放产日期、款号、车间组别及补数单号，放产日期不当采购日期，正常采购和补数身份分别识别，包括上游 ID。仅未回/已回/全部范围均覆盖相应采购及补数页。

用户文件 `D:/desk/新建文件夹 (8)/物料跟踪表(新版).xlsx` 的补数未回有 16 条，其中 CGDD014249 订 665、已回参考 628、欠 37 码。`退货记录` 同时包含多送退回、质量退货、内部退回、已补及部分补回；不能全部当待收料。`记录罚款` 含扣费金额/月份，应关联原订单而不重复生成追货数量。两张退货未回/已回辅助表含历史已交、消数、不用交等记录，页名不能证明现行任务。本次这些退货、罚款、留存页不直接导入，补回接口仍需明确来源关系。

保留采购单、供应商、生产 / 放产单、计划跟踪号、物料新旧编码、名称规格、原表单位、订单数量、单价、合同、两次复期、交货明细、送货单、原表入库日期和备注。每次有效新增 / 更新留下文件名、工作表、行号、保存人、业务时区时间、原始单元格及公式文本和变更前后事实。源文件不被修改，且不会放入公共静态目录。缺价不补零，不猜币种或自动解析规格中的单位换算比例。

原表公式不执行。纯数字加法的交货明细可得到采购已回参考数量，并明确标注来源。未回及补数未回表中，已回和交货记录均为空表示未到货，按订单量追；精确 `EVALUATE(本行空交货明细)` 的空缓存或 `#VALUE!` 也适用，包括合法、范围明确的同列共享公式相对行引用。原始表头、公式属性及解释依据一并保存。缺列、交货明细本身为公式、其他公式报错、模糊到货文字或两列冲突仍待核对；已回表与采购接口不默认归零。有效零单价保留零。日期支持 Excel 日期序号和完整年月日；复期中的“等通知”“暂停”等文本保留原文。

文本编号及明确纯零数字格式的前导零保留，原数值和格式另存证据；小数、复杂数字编号格式与 Excel 错误采购明细 ID 阻断。编号按 128 字符、普通字段按 255 字符的契约校验，避免 SQLite 与 PostgreSQL 的长度差异。扫描最多 100,000 行 / 2,500,000 单元格，空行也计入，已处理行从解析树释放。

## 防重复与变更边界

采购单号加物料不能唯一识别明细。没有采购明细 ID 的文档，以订单、供应商、生产单、跟踪号、物料、名称规格、单位和合同组成候选组，数量、价格、工作表和行号均不用于来源身份。首次保存组内多条记录时分别生成稳定仓库来源编号，不合并数量。同组内容完全相同的再次导入或重排保持原编号；单条候选更新须先显示差异。多条候选发生变化时阻断该组，须建立明确明细对应，不能按数量或行号覆盖。

旧解析规则产生的未知到货量可以按上述空明细规则更新。多行候选仅在整份原文件摘要、旧事实及原始行/位置证明唯一对应，且唯一变化是空明细解释时保留原 ID 更新；不把行号当作日常明细身份，不放宽其他多行变更。此前已经登记实收的未知起点继续冻结，不能借重新导入改写历史收料基数。

导入只增加 / 更新明确来源，不把本次文档缺失的行视为取消或删除。分页只限制显示，不截断解析或保存范围。异常组可在确认后排除，确认区明确显示跳过数量。厂区数据库锁和来源版本保证并发导入只有有效预览可以写入；同一请求编号重试取回原结果，不重复新增。相同请求编号不能用于不同文件、范围或账号。

同一自然来源混合带 ID / 不带 ID 的行，或不同编号在同一批指向一个已存仓库明细，整组进入待核对，不能重复新增或连续覆盖。

## 到货筛选与变更提醒

待收料支持全部未齐料、未填到货数量 / 明确未到货、部分到货、采购报到货待核对和订单变更未读五种范围。未齐料要求仍在未回表且已回参考未达到订单数量；已回参考不明时继续保留，欠数显示“待核对”，不把空白当作零。明确数量的采购欠数参考按订单数量减已回参考显示，最低为零，沿用原单位；这不是仓库实收欠数或可用库存。

例如第一次导入订单 100 码、采购已回 20 码，待收料显示采购欠数 80 码。第二次来源变为已回 100 码或移到已回页，进入“采购报到货 · 待核对”，并保留订单变更前后差异。仓库没有登记实收时不会自动生成入库单或库存。标记变更已读仅表示看过。开始追货的已回参考来自未撤销导入证据中首次明确数量，仓库待收量为当前订货量减该参考及本系统实收；首次真实入库自动冻结参考及证据编号，不再手填基数。后续采购已回变满数，仍需核对仓库实收，不能重复扣减已登记入库。空白、参考回退、参考超过订货量或历史先后不明须核对，物料/名称/单位/供应商与起始参考不符也阻止继续入库。系统实收收齐后退出未齐料和到货待核对。最新采购欠数参考与仓库追货待收分别显示。

所有有效 UPDATE 的数量、单价、复期、备注和状态等变化保留来源证据和未读提醒；内容相同不重复提醒。缺少稳定明细 ID 而无法对应的变化继续在导入预览阻断，不能承诺自动识别更换物料/归属后的行。仅选“未回物料”不会检查移入已回料表的订单，推荐保持默认跟进范围。本次表内缺失的旧行仍保留，不推断取消。页面可见且未打开详情时每分钟刷新提醒，也可点“查询 / 刷新”；提醒在本模块内显示，不会发送微信、邮件或系统通知中心消息，文件导入之外没有金蝶自动同步。

## 撤销导入

最近导入记录提供“撤销导入”和每页 20 条的较早/较新记录。只允许撤销最新有效批次；有后续批次时必须逐次撤销，以免覆盖后续订单变化。撤销预览列出移出新增来源条数、恢复原有来源条数，填写原因并确认后才执行。原始证据、操作者、时间和原因永久保留；此入口不是擦除历史。

新增来源使用 WITHDRAWN 状态退出业务列表，更新来源恢复导入前事实；不改变库存。重新预览同一文件可重新导入并复用来源编号。撤销重试不会重复回退；已撤销导入的旧保存请求会拒绝重新报告成功。导入/撤销预览绑定当前厂区版本，导入、标记已读或撤销发生后旧预览须重做。新批次使用单调序号排序，旧批次时间完全相同时不猜测顺序。撤销与标记已读沿用 read + import 厂区/部门权限，明确拒绝优先。

撤销和已读信息保存在批次结果元数据中，原始证据不改写。撤销本身无需新迁移；实际收料增加独立迁移 `20261008_0142`。受影响来源已有实际入库时，撤销预览和执行均阻止回退；收料同样推进共享厂区版本，使旧导入/撤销预览失效。执行过撤销的库不能运行不识别 WITHDRAWN 的旧代码。

## 仓库实际入库

`POST /api/fabric-warehouse/procurement/lines/{id}/receive` 从已存来源读取物料、供应商和原单位，要求当前来源版本、已收次数、UUID 请求编号与明确确认。填写实际收货日期、送货单/手工依据编号、物料分类，以及正数实物明细和仓位；布料每项缸号必填、卷号选填，辅料和线不填布料标识。记账月份由服务端按收货日期生成；旧请求若带独立月份必须与收货日期一致。追货参考由服务器读取导入证据并冻结，客户端不能改写。数量用 Decimal 精确累计，最多六位小数；超出待收数须填超收说明，正常分批/短收不要求说明。同一来源/送货依据只能登记一次，同送货单不同来源可以分别收料。

工人表单参考纸箱收货排版：单据头、来源摘要和待收数量、实收明细表、合计与固定底部操作。默认当天收货与送货单日期，独立记账月份和此前收货问题已移除。分类暂时人工选择，后续通过正式物料类别或工程资料接口带出；不依据名称、供应商、单位或未确认的编码前缀预填。布料缸号和仓位在明细中必填，卷号为单卷编号、选填；送货单日期及备注可展开填写。点击“保存并入库”即提交确认，没有重复确认勾选。只有超收才显示说明并要求填写。

仓库确认后在同一事务生成收料单、实物批次和入库流水；新批次为待检。单据冻结来源事实与版本、价格参考、日期、登记人和批次依据。后续来源变化不会改历史单或库存；物料、名称、单位或供应商变更会阻止沿用旧实收进度继续登记，须核对。网络结果未知时前端锁定已提交内容并使用原请求重试；服务端按账号、来源和完整内容校验幂等。厂区写锁与已收次数防止并发重复。

`GET /receipts` 查询入库单；`GET /stock` 查询实际批次与流水，在既有入库记录、库存台账、库存流水页呈现。库存只包含本系统本次入库，不含历史期初，不转换单位、不推断质检合格、不计金额。供应商送货文件解析、质检放行、实际发料、退货、更正、盘点及锁月仍待接通。记账月份取收货日期所在月，当前没有锁月能力。

## 采购直用数据接口

预留认证接口 `POST /api/fabric-warehouse/procurement/sources/preview` 和 `/sources/apply`，复用文档导入的规范化、核对、锁、版本和证据保存服务。没有配置金蝶云连接、自动拉取或外部系统凭证。后续连接器必须使用已授权身份，不能绕过厂区 / 部门 / 操作权限。

契约定义位于 `backend/app/schemas/fabric_procurement.py`。每个 feed 包含 `factory_id=huakang-c`、`source_system=KINGDEE`、`snapshot_id` 和 `lines`。每行必须有金蝶稳定的 `source_line_id`、来源状态 `PENDING/RETURNED`、采购单、供应商、物料、原始单位和数量字符串；生产单、跟踪号、合同和采购已回参考应尽量齐全。单次最多 5,000 条，连接器可以分批，每批独立预览 / 确认。应用保存另需 `preview_token`、UUID `request_id` 和 `confirmed=true`。

已有文档来源时，直用数据不能自动另建相同来源。第一次关联需要明确 `warehouse_line_id` 和 `expected_line_revision`，并核对订单、物料、单位与归属一致；之后沿用金蝶明细编号更新同一个仓库来源编号。重复上游 ID、重复绑定、版本变化和不一致归属均进入待核对。列表和详情返回稳定仓库来源编号及版本，便于核对接入。首次关联不会增加库存。

## 权限与上线

新域使用规范权限 `fabric_warehouse:read` / `fabric_warehouse:import` / `fabric_warehouse:receive`；导入、实际入库分别需 read+import/read+receive，对华康 C、PMC/仓库部门和操作独立校验，明确拒绝优先。仓库职位模板含三项权限，总经理沿既有授权政策；固定 V2 历史角色版本不会自动扩权，旧仓库账号需按身份流程获得 receive。其他部门/厂区不能因看见页面取得数据。

迁移 `20261005_0134` 增加四张采购来源表；`20261008_0142` 增加三张实际收料/批次/流水表，不迁移历史库存或修改其他仓库数据。已有库不自动建表；缺收料表时返回 503，采购来源仍可查询。已有对应证据禁止降级删表。启用前备份目标库、明确升级并验证实际仓库账号；本地验证不等于现场期初与完整收发/月结验收。
