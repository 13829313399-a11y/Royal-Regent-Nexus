# 布料仓追货、实际入库与基础资料

## 本次范围

仅适用华康 C 布料仓，沿用纸箱的操作习惯，保持七个主栏目。收料入库依次为“订单导入、待收料、送货单扫描、入库记录、采购接口”，待收料是日常默认页。正常采购、补数来源和实际入库已接通；基础资料可实际维护。扫描和采购接口明确显示待接入，尚无 OCR 或金蝶自动同步。原 Excel 不修改，采购历史不作为期初库存。

## 原表分类

- `未回物料`：正常采购追货，含分批到货。
- `补数未回物料`：补数追货，独立来源类别；保留补数单号、款号、放产日期、车间组别。
- `已回料` / `补数已回`：默认只检查已跟进来源的变化，不新增无关联历史。
- `退货记录`：含多送退回、质量退货、内部退回与部分补回；不能直接生成采购来源或库存。退货补回需明确原退货和补回数量后独立接入。
- `记录罚款`：扣款跟进，关联订单，不能再次生成待收料或库存。
- `退货未回物料` / `退货已回物料`：存在历史已交、消数、不用交等混合事实，不能按页名自动认定为现行补回任务。

## 保存与数量

未回与已回工作表按采购明细是否收齐区分，不是把订单拆成可再次相加的两个总量。同一条明细的订单总量 = 已回数量 + 未回数量；同一采购单的不同物料可以分别出现在两个表中，必须分别追货。

待收列表显示“起始待收、本系统已入库、剩余待收”，并在起始量下显示订单总量及此前已回。首次明确且有效的已回参考决定起始待收，例如订货 665 码、已回 628 码，追货从 37 码开始。首次实际收料冻结该参考与来源证据，之后采购更新已回数量不重复扣减系统实收。

未回、补数未回表中，已回数量和交货记录均为空表示尚未到货，以零作为已回参考，按订单全量追货。原表精确 `EVALUATE(本行交货明细)` 对空明细产生的空缓存或 `#VALUE!` 也按此规则，包括有明确范围的同列共享公式相对行引用；不执行 Excel 公式。必须存在已回与交货明细列；有交货明细公式、其他公式/错误、模糊到货文字或冲突时仍待核对。该默认不用于已回表或采购接口。解释依据、原始表头、缓存值及公式属性保留。旧多行同源记录仅在完整原文件摘要、旧事实和原始行/位置逐条唯一对应、唯一变化为空明细解释时可按原 ID 更新；其他多行变化仍须稳定明细 ID。

无法识别的历史数量保持待核对；物料、供应商、原单位及来源身份明确且无冲突时，仍可按本次实物收料。已经实际收料的未知起点继续冻结，后续文件不能自动补出一个新的历史基数。负责人使用现有 read + import 权限核对“本系统首次入库之前的起始待收量”，须填写依据并保留不可覆盖的版本审计。例如本系统已入库 10 码、当前还欠 27 码，应确认起始 37 码；确认后剩余 27 码，库存不变。确认起始为零表示无需继续追货。

明确参考回退、参考超过订货量、历史时序歧义或冻结后的订单数量变更，需核对数量后再继续；物料、名称、单位、供应商身份变化仍须来源协调，不能靠填写起始数量绕过。来源、收料次数和核对版本共同校验，厂区写锁及绑定操作者和内容的请求 UUID 防止并发、过期与重复确认。

库存只增加本次正数实收明细，使用原单位和 Decimal 精确合计，最多六位小数；收料、批次、入库流水原子保存。采购参考、起始核对和基础资料编辑均不改变库存。新批次为待检，不自动质检放行或计价。已知剩余待收量时，超收才要求说明；分批和短收不要求差异原因。未知待收量不虚构超收上限。

## 工人日常填写

日常表单参考纸箱收货界面：顶部单据信息、采购来源摘要、中部实收明细表、底部合计和固定保存栏。收货日期、送货单日期默认 Asia/Shanghai 当天，记账月份由服务器取收货月份，不独立填写。分类默认人工选择，只有已启用物料资料与来源编码、名称、单位一致时才带出已确认分类，工程资料自动接入仍待后续实施。仓位每项必填，已启用仓位可选择；布料每项缸号必填、卷号选填，卷号表示单卷编号；辅料和线不显示缸号、卷号。送货依据必填；备注和送货日期放在补充信息。超收才出现“超收说明”，分批和短收不要求差异原因。

不再询问是否首次收货或手填此前实收。点击“保存并入库”表达提交确认，不再重复要求确认勾选，后端 confirmed 契约、鉴权、数量和幂等规则保留。

待收料沿用纸箱的勾选与已选清单：全选当前页可入库物料，跨分页和筛选保留选择，查看并取消筛选外的已选项，一次最多 50 项。打开“登记所选订单入库”前，重新读取每项来源的版本、收料次数和可入库状态。共用收货日期与送货单号或本批手工收料依据，每项单独填写分类、正数实收、仓位、布料缸号和选填卷号，可拆分仓位或缸号；一次最多 500 项实物明细。待收量不自动填入实收，不将不同物料或单位相加。

批量入库使用一个厂区锁和一个事务，复用单笔数量、资料、权限和来源冲突校验，全部通过才提交；任一项失败则整批回滚。每项来源形成独立收料与批次库存记录。整批 UUID 绑定操作者与完整内容，子请求 UUID 由整批编号及来源 ID 确定，批量与单笔编号互斥；记录的 payload 保存批量编号及内容摘要，无新增数据库迁移。网络结果未知时锁定整批填写内容，以原请求重试。

## 提醒、筛选与排序

提醒包括复期已过、今天到期、待供应商复期、起始数量待核对、采购报到货待仓库核对和订单变更未读。复期取最新回复，最新“等通知”等文字替代旧日期，不从订单日期猜测交期。只有剩余待收数量明确且大于零才计入逾期、今日到期；数量未知但日期已过显示日期提示和数量待核对，不认定供应商仍欠货。

采购单号、生产/放产单、款号、物料编码/名称、供应商及来源文字统一从顶部搜索，输入后自动查询，回车立即查询。筛选栏沿用纸箱的横向紧凑排布和日期范围选择器，支持供应商、采购类型、跟进状态、复期区间及排序；“更多筛选”保留分类、原单位、数量核对状态及导入批次，不重复放置下方文本搜索。排序包括逾期、复期、采购单号、供应商、最近更新、同单位待收数量。后端先筛选、排序全部符合记录，再分页；数量排序必须先选择一个原单位。

## 基础资料

物料、往来单位、仓库仓位、单位与换算独立保存在布料仓。资料有待完善、启用、停用状态，支持版本检查、修改依据和历史记录。查看使用 read 权限，新增、编辑、启用及起始数量核对使用 read + import 权限，不扩大原权限。

导入只提供候选草稿，不自动建档或启用。物料启用需要编码、名称、分类、库存单位；旧编码、规格、颜色、材质可补充。供应商编码需人工确认，可维护联系方式；仓位启用需仓库名称。标准单位编码与名称不得交叉重复。换算配置须有物料、库存与计价单位、正数比例、依据、适用条件和生效日期，目前只保存配置，不参与实收或库存转换。

基础资料沿用纸箱的紧凑设置卡片、顶部统一搜索和仓库分组方式。仓位以按钮显示，可修改名称、状态并查记录。添加仓库须填写首个仓位；添加仓位支持 A01-A20 等同前缀升序范围。空白仓位模板只导入数据页，支持 xlsx/xlsm，最多 5 MB、1000 数据行和 1000 个展开仓位，不接受公式或数字编码。预览后原子保存；同仓已有仓位保持原状态并跳过，跨仓同编码冲突阻止保存。布料仓位编码在本域唯一、不区分大小写，创建后不可改；不能借用导入移动位置或自动启用停用仓位。

整仓更名以同一列表快照派生的完整组版本摘要核对全部仓位，不受单批 1000 个上限影响。新增、导入、更名使用原工厂锁、根/子请求身份与不可变修改证据；未知结果重试原请求，过期预览重新核对。未建立独立空仓或复制纸箱删除/维护授权规则，无新数据库结构。标准单位只填写编码、名称和状态；有依据的物料换算另行填写，不能从物料名称猜测比例。

新收料引用已确认且匹配的资料快照；停用资料不可用于新的匹配收料。历史收料和库存保留当时信息，不随资料编辑覆盖。

匹配仓位时不区分大小写，实收批次使用已确认的正式编码，再检查同卷同仓位重复；小写输入不能绕过停用。旧资料若有多个大小写编码对应，须先核对，不能猜选一个。

## 工程与验证

`20261008_0142` 建立独立收料、批次、流水表；`20261008_0143` 追加数量已知状态以及基础资料、资料变更和起始数量核对表。已有业务库须先备份再明确升级，启动不会静默迁移。旧收料默认保持已知状态；旧结构可查询历史进度，但缺新结构时不允许新保存。迁移回退不得删除已有资料、核对证据或未知起始的实收入库记录。

实际入库使用 read + receive 授权，并明确拒绝和隔离部门、厂区。已有收料或起始核对的来源禁止通过导入撤销。每次收料、核对、导入和撤销均推进共享厂区版本，使旧预览失效。请求编号绑定操作者和内容，同送货依据同来源不重复保存。未明确的网络结果保留原请求重试，含 HTTP 408；关闭已填表单须确认丢弃。

验证包括补数表头/身份/移表更新、分批与多仓位数量、导入参考与库存分离、重复请求/送货依据、并发/过期、权限/缺表/迁移/回退保护、前端保存与未知网络结果重试，运行相关前后端测试、TypeScript 检查与完整构建，并独立审查。实际业务库只在核对备份和迁移状态后升级；不代用户登记测试入库，不提交或部署。

期初、发料、退货补回、收料更正、质检放行、估值和锁月结账仍未实施。当前库存仅代表本系统登记的入库批次，不能与尚未到货数量相加认定为采购总量。PostgreSQL 实库并发和现场切换尚未验证。
