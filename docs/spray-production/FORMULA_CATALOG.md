# 数量与金额口径

后端 Decimal 为权威；存储数量/单价最多 6 位小数，中间计算保持 Decimal，正式金额按 `ROUND_HALF_UP` 到分。Excel 原金额/公式/缓存与新计算分开保存，不能暗改原证据。以下合成规则仅证明算法，不是正式工资或价格批准。

| 类型 | 输入、单位及算法 | 来源/确认/金样 |
|---|---|---|
| 实物报工 | 加工 = 合格投入 + 待判投入 + 报废投入；加工 = 正班 + 加班；每个分摊列分别守恒 | 同单位夹具 100=90+5+5=80+20；60/40 多订单分摊，各列分别校验 |
| 跨单位工序 | 输入按工艺已确认分子/分母变换至输出；不能直接混加件、对、套 | DAG 版本保存单位与倍率；无明确转换不得推断 |
| 部分来料 | 可安排量来自实际可用库存，扣除既有预留；需求本身不是库存 | 50,000 需求仅来 5,000，可安排不超过 5,000 |
| 班组计件 | 正班数×正班价 + 加班数×明确加班价，再按权重分配 | S09；7 人 560 件总产量仍为 560，0.82×560=459.20 |
| 个人计件 | 个人真实产量×价，个人数量和必须等于选定报工数量口径 | 个人数量缺失时拒绝推算；不同加班价缺少个人正加班拆分时拒绝核算 |
| 工时计薪 | 正班小时×正班时薪 + 加班小时×明确加班时薪 | 无产值工时另需明确单价；未知不能回退正班价 |
| 固定工资 | 同员工、同规则每天只计一次固定额 | 同日多工序不得重复计固定额 |
| 保底与补贴 | 当日基础额先汇总；补足=max(0,保底-基础额)；再加有依据的补贴/调整 | 同一天保底一次；冲突保底规则阻断；负调整后总额不得负 |
| 分摊舍入 | 班组总额先到分，各份向下到分，余分按最大余数与稳定 ID 分配 | 1 元分 7 人，份额合计必须为 1 元 |
| 历史时长试算 | 池金额×计薪小时/基准小时，明确汇率方向后再转换 | S09 历史 P≈74.54545、Q≈592.9752；11/12.5 和 0.88 均不设为系统默认 |
| 汇率 | 金额×factor，from_currency→to_currency，规则和日期冻结 | 仅当确认 1HKD=0.88CNY 时 factor=0.88；当前没有预装汇率 |
| 工序产值 | 正常生产合格数量×确认工序价格；返工不重复确认正常产值 | S09 560×2.07=1159.20；与工资、交收收入分开 |
| 材料单位 | SKU 专属确认转换：2 桶×160KG=320KG | 不能用其他 SKU 或未确认规则转换 |
| 批次成本 | 原采购金额÷该批实收基本单位；实际耗用×原单位成本 | 2×1472=2944；耗用 80KG=736，剩余240KG成本2208 |
| 领退耗 | 仓库→车间领用不是成本；退回须关联原领用并保留原批价；仅实际耗用进入成本 | 不按今日新采购价重算旧批次 |
| 节约比较 | (旧价-新价)×比较数量，原表差额保留反向符号 | S12：(1586-1472)×2=228；采购成本2944不得再减228 |
| 验收月结 | 截止月份累计验收，减已结及实物退货限制，选择部分数量×冻结价 | 1000验收→结600→余400；跨月新增验收不得倒计前月 |
| 退货贷项 | 关联原结算行，数量不超过退货及原结算剩余额度，按原冻结价计贷项 | S07 -1800×1.51=-2718 为退货证据，不是负产量 |
| 人工金额差异 | 计算值与手填值并列，人工解释后决定映射事实 | S07 1270×0.26=330.20，手填624，差293.80；不能自动覆盖 |
| 经营结余 | 本币工序产值-本币工资-实际耗用-已确认纳入的费用净额 | 资料/币种不完整时 null；回收冲减；不叠加交收收入与工序产值 |

正式规则建立草稿后须由具备权限的用户确认，保留版本、生效日期、参数、确认人及依据。已确认工资引用日报/工时/规则指纹；源记录改变后旧试算不能确认。新版本不能回写历史冻结结果。期间关闭可以按各原币种冻结；关闭不代表跨币种利润已完成折算。

未知材料成本后续补确认：原耗用事件仍保留 null，新增关联原耗用的成本调整；经营计算只取一次已补成本，旧冻结导出不改写。已知成本不可覆盖，涉及已锁期间时拒绝补确认。费用纳入状态从待确认到纳入/不纳入只允许一次，金额保持原值并追加依据。

日报导出分为生产数量、员工工时与计薪、完整生产日工资核对三张表；无工资权限时不包含工资列和工资汇总表。一个班组的数量只在生产表出现一次，每日保底补贴只在日工资汇总出现一次。

尚待现场确认：计件基数、正加班口径、个人/班组权重、历史参数、保底补贴、工序与交收价、汇率、费用纳入、材料归集完整性和零耗用证明。现有材料覆盖检查能检查“存在已知耗用”，不能证明现场漏报为零，不能把软件检查当财务审计。
