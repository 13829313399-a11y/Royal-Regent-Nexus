## 处理顺序

1. 上传原件，保留字节与 SHA-256；默认上限20MB，解压总量64MB、250,000实值单元格、2,000ZIP成员，拒绝越界输入。
2. 浏览工作表/页码。OOXML 保留坐标、原值、显示值、公式、缓存、错误标志、日期系统、合并单元格及外链信息；从不执行公式或访问外链。BIFF8保留值/格式/缓存，不能声称恢复公式文本。PDF保留原件和页码，人工结构化核对。
3. 选择实际证据格，建立业务单据键，填写或映射类型化字段；前导零按可证明的显示格式保留，不猜失去精度的标识。
4. 逐单说明差异、主事实来源及与其他跟进表如何去重。预览冻结映射值、源坐标、决策和本次工厂修订。
5. 逐单确认；每张业务单据一个事务。成功单据保留，可继续剩余单据；同文件同单及跨文件同业务事实不得重复入账；取消保留证据。

负数只能进入退货等有方向含义的业务或参考，不能直接当负生产。空白与公式错误不能转零。S07实际月份按单据数据决定，不能从文件名“5月”强行推断。到货不能直接增加油漆成本支出，历史摘要不能再生成日报产量。

## 历史衔接

每厂明确 `opening` 或 `replay` 及截止日期，二者互斥。期初按已确认工艺的有效完成集合建立库存，不增加本期收货/生产/产值。截止日及之前的普通实物交易被拦截；已有截止日前交易时不能再补一期初重复叠加。

## 实现边界

已实现签名解析、全部原件结构核验、手工字段映射、证据预览、类型校验及逐单确认；没有实现对70张来源工作表的一键自动业务识别。S04 跟进表与 S06 横向矩阵目前只支持参考/期初，复杂多行/续行/跨表匹配仍需人工逐单核对。没有执行真实历史资料入账；未校准OCR或自动审批历史工资。后续批量自动映射必须逐来源添加金样测试，不能放宽上述保护来提高导入率。
