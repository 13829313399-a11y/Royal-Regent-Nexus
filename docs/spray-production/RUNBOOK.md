# 本地验证、迁移与停用

## 默认状态

`SPRAY_OPS_ENABLED=false` 与 `VITE_SPRAY_OPS_ENABLED=false`。现有业务数据库和服务不因本次开发被迁移/重启，旧喷油表保留。Git交付不代表生产发布。

## 隔离运行

1. 使用明确的临时数据库路径，所有 Python/Alembic 命令显式设置 `DATABASE_URL`，不要让配置回落到业务库。
2. 后端在 `backend` 中使用 `.venv/Scripts/python.exe -X utf8`。空隔离库可由现有启动初始化器建表；迁移验证必须单独运行完整 Alembic 图，不能把 `create_all` 当迁移通过。
3. 测试后端设 `SPRAY_OPS_ENABLED=true`、`AUTHZ_MODE=enforce`；使用合成账号和隔离权限。前端设 `VITE_SPRAY_OPS_ENABLED=true`、`VITE_API_PROXY_TARGET=http://127.0.0.1:8014`、`VITE_API_BASE_URL=/api`，运行 `npm run dev -- --host 127.0.0.1 --port 5184 --strictPort`。
4. 验证 `/health`、`/openapi.json`、登录、合法工厂 `access`；用合成单走通需求→实际来料→准备→排期→报工→交收→工资/月结→下载。

本轮独立 QA 使用5184/8014及临时目录 `rr-spray-qa-20260922`，真实5173/8000未改动。QA库为增量调试库，不替代迁移演练；迁移测试每次生成全新临时库。不要复制 QA 账号、工资参数、测试订单到正式环境。

## 升级与验证

迁移 `20260922_0119` 继承客户报价迁移 `20260922_0118`，新增52张独立表与四厂协调行。旧迁移不改写。已存在的数据库启用模块时检查新表/列，不静默 `create_all` 补齐业务结构。

正式迁移尚未授权和执行。启用前需数据库备份和恢复演练；在副本核对现有head、运行 `alembic upgrade head`，比较旧表DDL/行数、完整性和外键，再验证权限及完整业务场景。PostgreSQL须使用明确隔离库完成并发发布、重复报工、抢结算量与锁月竞争测试。

SQLite迁移测试已验证：升级至前一head→保存旧喷油表DDL/行数→插入历史探针→升级新head→重复升级→核对探针、旧表、四厂、integrity/foreign_key。它不证明生产库数据质量或PostgreSQL行为。

## 停用与回滚

先关前后端开关，验证卡片回到占位、API拒绝业务；保留全部新旧表和冻结证据。此迁移故意禁止自动downgrade，避免删除已经形成的库存/工资/月结证据。需要数据库恢复时，应停止业务写入并按经验证的备份恢复方案处理，不能在线删除新表回退。

## 故障核对

- 超时：保留原operation_id，查询本人回执；未发现时按原完整请求重试。
- 版本冲突：读取最新版比较，不能自动覆盖。预览过期则重新排期/锁月/导出。
- 403：核对本厂具体权限；工资和成本下载独立检查，不能临时绕过。
- 503：检查双开关与schema；不要改成演示数据。
- 导入中断：按已有逐单回执继续，不能删掉成功记录后整本重导。
- 未定价、未知工资/材料：补确认规则或来源，不补零。历史新价重算必须另建依据。
