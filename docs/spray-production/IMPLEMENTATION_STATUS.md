# 喷油部重建实施计划

依据用户提供的 `Royal-Regent-Nexus_Spray_Codex_Pack`，基线 `620ae74`。
原始工作簿和扫描件只读，不纳入 Git。开发只连接隔离测试数据库；现有数据库、历史 `spray_*` 表及迁移不改写。

## 实施顺序

1. **P0 合同与证据**：核验 12 份源文件的 SHA-256、文件签名、关键单元格和扫描表单；记录规则分歧、接口、权限、单位、精度及迁移方案。
2. **P1 工作区**：七个独立工作区、严格工厂与权限上下文、开关、响应式排期/日报/月结视图。真实请求失败不得回退演示数据。
3. **P2 生产闭环**：订单及版本化工艺 DAG、分批来料、准备、有限能力排期、发布/开工、多人多订单报工、质量处置及库存事件。先完成一单，再验证并发和重试。
4. **P3 交收与导入**：送货、验收、退货、返工、周转物、订单修订及 12 个来源解析配置；预览/决策/确认分离，逐业务单据原子落库。
5. **P4 材料**：采购、匹配入库、批次、领用/退回/耗用、未知成本和节约分析。
6. **P5 经营与工资**：版本化规则、班组分摊与舍入、费用、覆盖度；未确认规则仅试算。
7. **P6 月结与验收**：部分结算、退货贷项、锁月、冻结导出，贯通测试、迁移演练、权限与浏览器验证。

## 验证与交付门槛

- 采用临时 SQLite 验证领域/API、迁移、隔离、幂等、版本冲突；PostgreSQL 使用明确的独立测试库，没有环境则明确标记未验证。
- 运行针对性前端测试、`npm run typecheck:test`、`npm run build` 和后端回归。
- 独立检查业务不变量和失败路径，再在隔离服务中完成浏览器操作；记录指定宽度、交互与导出证据。
- 不把源资料中的历史公式当作批准规则；不把构建通过当作现场验收或生产启用。
- 本轮不进行 Git 提交、推送或生产迁移。
