## 已闭合的软件缺口

- 未知节拍可按实体批次填写正数人工估时及依据，不修改任务冻结工艺。已知节拍不能被人工值覆盖。拆批可在独立机台、独立物理治具上并行；同治具不同版本仍互斥。
- 1/3/30 天排程按完整窗口分页，不受最近 100 条快照限制。拖动先预览，取消不写库，确认才提交。已开工批次不可移动，未开工兄弟批次可独立调整；固定计划需说明理由解锁。推荐按分钟对齐且保留完整时长。正在执行时按预计释放时间预留后续计划并提示风险，实际开工仍须前批完工。
- 人工开工/完工记录与设备 Run、核数独立；跨班完工使用当前未关闭班次。未完工、未报产、待检、返工、在制、未签收等缺项进入结班检查，有缺项必须填写交接依据。
- 品质、参与工时、费用、工资、Run 成本池支持有理由冲销，原单不删除、不改写原始金额。工资撤销后可重核，成本池整体撤销关联费用；后续依赖及封账保护继续生效。完整冲销误耗料后，未开工任务可以取消并释放需求。
- 库存源库位和目标库位都检查业务日期顺序；禁止借未来库存或倒填冲销日期改变冻结加权成本。
- 生产导出含品质处置及来源，交接导出含签收/拒收/退回，工资导出含员工分配，冲销依据可追溯。按日期筛选使用各事件自身业务日；关联原单保留真实原日期。日报/月报不能使用含糊的 selected_ids。
- 实时快照每 2 秒推送；当前运行按当前主源游标的持久事件身份、流、绑定版本核对，旧源历史不会冒充当前运行。每个请求重新授权和金额投影。相同授权内容的登录刷新不会重置页面草稿。

## 浏览器合成业务闭环

真实 Chromium + Vite + 隔离 PostgreSQL API，没有替换业务请求的 mock。预览进程仅使用 uv_ops_preview_v4 合成库。

1. 从空资料建立产品、两套独立治具、两台机、未知节拍工艺、生产文件/首件确认、合成单价 0.12 CNY、合成计件工资 0.015。
2. 120 件需求拆为 60+60，分别人工估时并行排程。预览取消不改变计划；原生拖动的预览、取消、确认均核对数据库结果。
3. 两批人工开工/完工；两人参与。第一次核数得到 115 良品、5 待检；先错判转良再撤销，5 件转返工，返工得到 4 良品、1 报废。最终 119 良品、1 报废、125 加工次数。
4. 59+60 件交接全部签收。1000ml/100CNY 入库，耗用 10ml/1CNY。错误 20CNY 费用撤销后登记 2CNY；工资原单撤销重核并保留员工分配。

6. 实际后台生成并下载生产、交接、工资、月报四份 XLSX；生产 3 原核数 + 2 品质处置，交接 2 原单 + 2 签收事件，工资保留 3 原单（1 已撤销）及 5 员工分配（含撤销历史）。月报使用 closed_snapshot，金额为数值，未发现公式单元格。

## 规模、时延与边界

[性能原始摘要](evidence/20260929-benchmark-final.json)：Windows 11 / PostgreSQL 16.15 本机隔离 schema，20 台机、30 天 6000 条计划、100000 条 Run，50 线程，150 次稳态测量。

- 稳态 p50 **299.21ms**，p95 **376.10ms**，max 426.08ms，0 失败；达到建议 500ms 服务查询稳态目标。
- 50 个冷连接同时建立时 p95 **682.47ms**；冷启动尚未达到 500ms。以上包含账本 revision、序列化及用户字段投影，**不包含 HTTP、认证往返或浏览器时间**，不能称为生产 50 用户响应 SLA。
- 数据缓存只共享业务快照，最长 1 秒，提交 revision 变化立即重建；授权不缓存，响应不共享可变对象。SSE 每 2 秒重新授权。
- 浏览器实际加载 30 天 **6000/6000**，12 页全部收齐；22 台显示机中 20 台为容量数据，滚到底部仅渲染 8 个机台行，手机列表也保留完整 6000 条。具体加载时间见 [容量证据](evidence/20260929-browser-capacity-report.json)。短计划按真实时长显示细条，不夸大占用时间；详情通过悬停、键盘或列表访问。
- 5 次合成 snapshot 从发送到浏览器状态变化为 **2401 / 1889 / 2396 / 1869 / 1873ms**，均 <5 秒。这是合成 API→浏览器证据，不包含真实机台→日志采集延迟。
- 1920×1080、1440×1000、390×844、320×760、844×390 视口及键盘焦点检查通过。工程视觉复核已完成；实体触控、屏幕阅读器、业务人员最终评分签认仍属后续验收。
