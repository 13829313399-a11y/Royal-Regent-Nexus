# 启用、监测与恢复

本文件是执行步骤，不代表已经发布。当前业务数据库、现有服务和生产服务器均未为新版 UV 修改。

## 数据库与发布前置

1. 确认实际服务的 DATABASE_URL、版本号、迁移图和备份位置；不依据目录名猜测数据库。备份在隔离副本恢复并校验 integrity/foreign keys 或 PostgreSQL 恢复结果，记录原表内容摘要。
2. 当前本机业务库版本为 `20260917_0117`，但已存在 `0118` 要创建的 customer_price_settings。其副本全链升级在该处失败。必须先核查既有表结构与版本来源，形成单独的历史迁移修复；**不要在真实库盲目 stamp、drop table 或重复 create_all**。
3. 新版 `0121` 在 SQLite 空库及 PostgreSQL 空库链上验证；直接应用到已有 30 张历史 UV 表的副本保留旧表及内容。模型与最终 PostgreSQL 迁移零差异，42 张新表、131 个索引。上述证据不等于已经修好本机旧迁移漂移。
4. 部署后先保持 UV_OPS_ENABLED=false。完成迁移与只读校验，确认无自动新岗位授权；通过平台 IAM 显式建立华康 A / 生产部最小权限。再开启 UV_OPS_ENABLED。旧 UV_PRINTING_ENABLED 不控制新域。
5. 反向代理为 `/api/uv-operations/live` 关闭响应缓冲，超时大于 SSE 5 秒间隔；保留平台 Cookie/HTTPS 保护。同源登录实际验收权限撤销、重连和多 worker。当前已验证开发代理，尚未验证 Nginx 发布链路。

## 现场代理

按 [代理 README](../../edge/uv-printing-agent/README.md) 构建及安装，生产必须 HTTPS。独立 LocalService 服务 SID 仅获配置/状态目录必要权限和明确日志只读权限。配对码单次 15 分钟，DPAPI 状态在请求前落盘；网络丢回执时重试同一码即可。更换身份使用新的状态目录，保留旧 outbox 及凭据用于人工对账。

来源绑定需明确机台、source_id、版本、适配器、日志编码和单位。每机一个主源，每代理/source 只能绑定一机。重新绑定不删除旧证据；新流未绑定时本地保留队列并报告重试性拒绝。需要解绑时在设置中操作并记录依据。

队列为本地 SQLite WAL + synchronous FULL。不要把 outbox 放网络共享盘。在线备份使用 SQLite backup；停服务后才可同时复制数据库/WAL/SHM。不要只拷活动主数据库。升级停服务、备份、替换 exe、保留配置与队列，再启动核对。卸载只移除服务注册，保留证据，撤销服务端身份需独立执行。

## 日常监测

- API 错误率、409/503 原因、查询 p95、数据库连接数；压力基线尚未达 500 ms 建议目标。
- 代理心跳、日志观测时间、积压数/最旧年龄、磁盘余量、隔离条数、采集错误码；代理在线不代表 RIP 有有效证据。
- 持久导入/导出 job 状态、失败码与 10 分钟租约。崩溃后可回收过期 running，不需要内存任务列表。限制大文件/大区间，观察单 worker 串行作业耗时。
- 月末未匹配 Run、未关班次、待检余额、缺失价格/工资/成本、跨币种及封账后迟到差异。

## 回退与恢复

先关闭 UV_OPS_ENABLED，停止本次新代理，保留数据库/队列/上传文件/导出工件/审计。新迁移禁止会删账本的 downgrade；代码回退不删历史或新域表。采用经过复核的前向修复或在独立恢复库对账后切换，不能用“删库重建”解决账本问题。

期内错误用理由充分的冲销或对应事件调整；一旦工资、后道、签收依赖冻结来源，先处理依赖。已封账数据需重开及差异工作流；不能伪造旧日期从未来借用库存、返工或签收余额。

正式放行条件：旧迁移漂移处理完成、实际角色权限验证、现场能力矩阵签认、SCM/锁屏/注销/RDP 试验、反向代理与恢复演练、目标负载性能回归。详见 [现场清单](SITE_READINESS.md)。
