# 给 Codex 的接手审查与后端开发提示词

使用前：DSH前端已经由用户验收、明确提交并合并main；在合并后的main创建UV后端worktree，Codex打开该工作目录。共同文档与已填写的交接文件应在 `docs/uv-printing/`。

---

你接手 Royal Regent Nexus 的“华康A → 生产部 → UV打印管理”模块。DSH已实现前端，我已完成一轮视觉/交互验收。你的职责是审查真实改动、修正业务问题、实现后端并联调，而不是推翻已验收UI重做一套普通表格。

先读取当前AGENTS.md、PROJECT_MEMORY.md相关完整段落、DESIGN.md、UV_PRINT_SHARED_SPEC.md、UV_PRINT_SOURCE_AUDIT.md、DSH交接文件及实际diff。确认当前目录、分支、HEAD、迁移heads、前后端入口、角色权限注册和现有测试命令。最新源码优先于文档基线，差异需记录。

先按严重程度审查DSH改动，给出具体文件与行为证据，重点核对：厂区兜底泄漏、正式预览隔离、敏感数据返回、数量来源重复、质量守恒、单位换算、跨夜班日期、金额精度、零与未填写、商业价与工价混用、库存SKU维度、历史价格快照、分页和错误回落。完成审查后按共同规格阶段继续实现，不只写审查报告就停下。

先打通一条真实垂直链：华康A授权 → 产品/机台/工艺 → 人工报工 → 质量 → 独立工价 → 工资预览 → 同口径经营汇总。再补墨水账本、费用、月分摊、修订/冲销、导入预览/确认、导出、入库核数和B1采集。维护FastAPI/SQLAlchemy/Alembic/PostgreSQL、现有会话和permission_codes，不引入PocketBase、独立.NET、并行账号系统或不必要的中间件。

接口与前端contracts.ts一致；必须改契约时同步共同规格、mock、前端、后端和契约测试，记录原因。用真实transport替换数据源，不重新散布业务计算。正式API与页面绝不能失败回落样例。个人工资/成本权限在后端返回字段、导出和实时通道上都执行，不只隐藏按钮。

遵守关键规则：同源事件幂等而非60秒删重；source job和业务报工分层、来源分配守恒；0不能被默认值覆盖；周日不清零真实生产；上海时区白夜班与跨月归属明确；金额Decimal与最小币种单位分摊准确；商业价/工价独立快照；同色不同供应商/材质墨水分别记账，并发出库事务不得负数；遥测耗墨不重复扣库；历史汇总不能和明细重复计量。

采集器优先只读、出站上传、持久待发队列、稳定事件/作业ID、ACK后删除、断网重放、不确定完成待核。至少一个机型经过真实现场测试后才标实机可用；旧包中五种模式有代码不代表已验收。不要未经授权连接真实打印机、运行旧配置或执行控制指令。

保持DSH已验收版式、颜色、布局和主交互，只修接线、类型、逻辑与必要的交互缺陷。若需要改视觉，写出具体原因与影响，不默默降级。没有必要不触碰其他模块。

在独立PostgreSQL数据库/容器和独立API端口验证，worktree不隔离数据库。新增迁移接当前实际head，不改旧迁移。运行实际存在的前端build、UV测试、测试类型检查、后端测试、权限/路由回归、迁移与并发测试，并按共同规格T01–T45报告结果。无法执行的项目写明未执行与影响，不能声称已通过。

本次“审核”主要是代码和业务正确性审查，不要擅自增加多级审批和通用工作流引擎。日/月关闭等建议采用轻量明确状态即可。根据AGENTS要求安排适当独立复核。未经我明确授权，不commit、push、合并或部署；生产开关只在数据、权限、迁移与验收满足后才启用。
