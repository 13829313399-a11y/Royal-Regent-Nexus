## 1. 产品定位与必须守住的边界

### 1.1 一句话定位

**把“机台正在做什么、今天实际做了多少、哪些记录还没核清、用了多少墨、人员应计多少工资、部门经营结余如何”串成一条可追溯的 UV 生产闭环。**

不是独立站，不是 iframe，不是只看设备在线状态的大屏，也不是把十几张旧表放进 Tabs。首屏必须帮助现场人员立即行动，经营页必须能从汇总追到记录。

### 1.2 厂区与部门

| 项目 | 约定 |
|---|---|
| 业务厂区 | 仅 `huakang-a`，中文华康A |
| 业务部门 | `production`，中文生产部；不是 `three-d-printing` |
| 模块 ID | `uv-printing` |
| 正式路径 | `/modules/production/uv-printing` |

### 1.3 与现有模块的关系

【仓库事实】喷油工作区已有 `capabilities: manual / automatic / pad / uv`。这里的 `uv` 是喷油业务里的工序能力；**不能据此判定独立 UV 打印模块已实现**。此次不删除、不接管、不重算既有喷油工序。

默认两域各自记账。未来需要联动时，以 `source_module + source_entity_id + source_line_id` 建立明确交接：一个域拥有原始产量事实，另一域只引用或接收一次，不双方各加一次。3D 打印域的实时 Hub、设备控制、物料和历史迁移也不复用其业务表。

客户订单中心是原始客户订单的拥有者；UV 只引用客户、货号、单号和已确认需求。没有上游接口时允许手工录入来源编号并标为“外部引用”，不伪造已经联动。人员复用成员/员工体系，不另建登录账号系统。

不引入旧 PocketBase、Vant、独立 .NET API、Redis/MQTT 全套基础设施作为上线前置；不升级宿主依赖、不重写全局主题、不改变已有模块业务。DSH/Codex 是开发工具，不因此在产品里接入 DeepSeek API 或重建已删除的 AI 工作台。

本期不做远程开机、启动打印、修改打印参数、发送作业文件等硬件控制；采集与业务管理分离。也不凭打印完成记录承诺已完成仓库收货、客户交付、财务结算。

## 4. 目标业务闭环与交付范围

### 4.1 主闭环

```text
基础资料/工艺与价格版本
           ↓
选择机台、业务日期、班次和人员
           ↓
人工报工 ← 对应任务证据 → 自动打印记录/补录文件
           ↓

           ↓
确认有效产量 ───→ 入库核数/交接差异（独立记录）
           ↓
按独立工价计算班组金额 → 生成个人工资明细
           ↓
```

## 5. 业务规则与口径字典

### 5.1 三种记录必须分清

**采集作业 `PrintJob`**：设备/软件发生了什么。允许缺产品映射、未知数量单位、结束时间为推断值。保留原始任务名及来源信息，不能直接当客户订单或合格产品。

**业务报工 `ProductionReport`**：车间确认做了多少件，机台、产品、班次、质量和来源是什么。是产量、工资、经营产值的主事实。

**入库核数 `HandoverRecord`**：有人确认接收/交接多少件。可以和报工有差异，但不能覆盖报工原值，也不能未经PMC承接就宣布增加仓库库存。

草稿不计入有效产量、工资或经营产值，也不消耗正式来源分配额度；确认时在同一事务重新校验剩余量、占用有效分配并记账。多个草稿可以引用同一证据，但不能最终重复确认超量。

一份报工可以对应多条采集作业；一条已确认单位的采集作业可以分配到多份报工，但累计分配量不能超出可分配量。人工离线补录后来匹配到自动作业时，**关联已有报工，不新增第二份有效产量**。原始单位尚未确认时允许附作证据，但禁止伪造可分配件数。

### 5.2 数量、尺寸与面积

`product_no`、订单号、任务名、机号全部是字符串，保留前导零。件数为非负整数；每板件数为正整数；秒、ml、平方米、小时是带单位的独立字段，不能都叫 quantity。

- 原始打印次数/板数不是件数；只有适配器已声明是板数、产品工艺每板件数已确认时，才可用“完整板数×每板件数+尾板确认件数”提出建议量。
- 部分打印、取消、不同层多遍打印、混板产品不能套用这个默认公式，进入人工核对。
- 产品尺寸面积 `cm² = 长cm×宽cm`；`1m² = 10000cm²`。是否按包围矩形面积计价属于价规，不等于图案实际墨覆盖面积。
- 分别保存产品计价面积、机器打印面积、计费面积，不能混为一个字段。

质量四分法【新设计】：

```text
reported_qty = good_qty + defective_qty + pending_qty + semi_finished_qty
```

四个桶互斥且非负；“不良”不自动等于“报废”，半成品不自动当合格品。未做质量判定可先保存全部 pending。合格率默认 `good / (good + defective)`，分母为0显示“—”，同时展示待判/半成品比例以免误导。首轮原始报工和返工报工标识分开；B2返工流转必须引用原不良来源，不能再次增加原始投入量。

### 5.3 日期、白夜班与月界

【旧事实】默认白班 07:40–21:00，夜班 21:00–次日07:40。保留为**可版本化班次模板**，不写死在所有页面。

【新设计】业务时间为 `Asia/Shanghai`；事件时间入库为明确UTC时间戳；业务日期是班次开始的当地日期。时间区间左闭右开。

| 上海时间 | 业务日期 | 班次 |
|---|---|---|
| 2026-09-13 07:39:59 | 2026-09-12 | 夜班 |
| 2026-09-13 07:40:00 | 2026-09-13 | 白班 |
| 2026-09-13 20:59:59 | 2026-09-13 | 白班 |
| 2026-09-13 21:00:00 | 2026-09-13 | 夜班 |
| 2026-10-01 01:00:00 | 2026-09-30 | 夜班 |

作业产量默认建议归于完成时所在班次，但以最终报工为准；运行秒数用于利用率时按与班次区间的重叠拆分。**不能因为开始日期和结束日期各命中一次就在两天重复计同一份产量。** 人工跨班拆分必须满足源数量守恒。

生产与工资按班次业务日归属；费用、墨水则保存明确的发生日和归属日，汇总时公开采用哪个字段，不能无说明混合自然日与班次日。不以客户端电脑时区判断；不把上传日当生产日；缺原始时间时显示“时间待确认”。班次时长不是净工作时间，休息与停工需要明确记录，不能直接把白班跨度都计成工人工时。

### 5.4 单价、产值、币种与历史快照

【待确认】旧 `_fen`、`fenToRmb`、页面人民币符号与 `_hkd` 报表并存，代码不能证明所有金额实际使用同一币种。正式启用前确定本模块默认币种；UI样例可用 HKD，但必须标明样例，不把历史数据无条件当港币。

金额统一结构：`currency + Decimal字符串amount`。单价至少允许六位小数、行金额按币种小数位四舍五入；使用 Python Decimal/数据库 Numeric，不以二进制浮点做正式计算。不同币种不能直接相加；未设置换算规则时分币种展示，不自动查汇率改账。

区分：商业执行单价、面积单价、计件工价、定价测算建议价。四者不能互为无声后备。

```text
按件产值 = 可计价数量 × 商业执行单价快照
面积参考产值 = 可计价数量 × 单件计价面积 × 面积费率快照
```

默认【新设计】可计价数量取已确认合格数量；如实际按打印投入件数或板数结算，需改为显式计价基准。两种产值是备选视角，**绝不把二者相加**。没有执行价显示“未定价”，不是0产值。

同一种价规内，精确机台覆盖优先于明确价组覆盖，再到标准价；同优先级的同币种/产品/工艺生效区间不得重叠。回退只能发生在同一种价规内，不能从缺工价回退到商业价，也不能从缺港币价回退到人民币价。

每条有效报工保留产品/工艺版本、数量单位、商业价格版本、计件工价版本、面积费率版本及生效时点。改产品当前单价只影响之后的适用报工；历史更改走更正，不用“全表重算”偷偷改历史。

### 5.5 定价公式

保留旧公式，修正名称。以下所有成本必须是同币种、同一个工作日口径：

```text
理论每日板数 = 每日可用工时 / 每板耗时
理论日产能 = 理论每日板数 × 每板件数
直接日成本 = 日人工成本 + 日油墨成本
直接单位成本 = 直接日成本 / 理论日产能
成本加成报价 = 直接单位成本 × (1 + 加成率)
目标毛利报价 = 直接单位成本 / (1 - 目标毛利率)
```

示例：10小时、每板0.5小时、每板20件、人工200、油墨80 → 20板/天、400件/天、0.70/件成本；成本加成40%=0.98/件，对应毛利率约28.571%；目标毛利率40%=约1.166667/件。

耗时为0、日产能为0时输出不可计算原因，不显示0成本报价。理论板数可以为小数，执行排程需要整板时另列“完整板产能”。损耗、换版/换图/清洗准备时间、维修或折旧等是可选成本项【新设计】，缺失时标注“仅含已填写的人工和油墨”，不可命名“完整成本”。

### 5.6 排班与工资

【旧事实】旧代码存在使用产品价或任务价乘合格/总数量并均分给当班人的路径；这不足以证明商业价就是工价。

【新设计】工资独立配置计件工价、计时工资、补贴；B0先支持计件及明确的手工补贴。无工价、未安排人员、质量未核清时，显示“待核/未定价”，不自动发出0工资结果。

```text
班组计件金额 = 可计薪合格数量 × 计件工价快照
```

默认同机同班、同一工作批次参与人员等分，作为暂行方案；临时换人或跨机兼岗需拆分工作批次或明确份额，不从所有班次名单推测。稳定按员工ID分配最小货币单位余数，例如1.00分给三人=0.34+0.33+0.33，不能变成0.99。先汇总工作批次金额再分配，不每件向下取整。

员工离职后保留历史身份快照；修改当前排班不改变已确认工资。工资预览、确认、调整分别保存；轻量确认不是银行发薪。人工“可回收工资”等报表调整不等同于员工实际扣薪，必须明确独立用途。

### 5.7 墨水账本

SKU至少包含供应商、软/硬/其他材质、颜色；库存位置初期为 UV 仓。颜色保留别名映射（例如白墨/White/W），但映射不能合并不同供应商或材质的库存。

【旧事实】旧表单按一瓶1000ml换算，库存基本单位为ml，单价可精确到分/ml。新包装容量是 SKU 配置，不能把以后500ml/瓶也乘1000。UI保留“瓶↔ml”的双单位提示。

B0事件：期初、采购入库、领用出库、退回、盘点调整、冲销。每条包含 SKU、数量ml、发生日、来源单号/证据、单价和币种、创建人；期初不当本期采购。实际可用量按未被冲销的事件和对应修正计算。

出库在同一数据库事务锁定库存余额/相关行、校验和写入，任一失败整体回滚。允许盘点差异，但需明确方向和原因；不允许普通出库使库存负数。撤销用关联冲销，不删除原流水。

B0经营报表采用可解释的“领用成本”口径：出库成本采用后端移动加权平均的入库价值，缺初值则暂算待核。**领用成本不是精确到作业的实际耗用**。遥测墨量仅用于参考/差异分析，不再次扣减库房库存或重复计费。B2如启用在机墨仓与实际消耗账，必须以单一成本口径替换相应领用成本，不能两份一起扣。

### 5.8 日报、月报与经营结余

分开生产事实、计划标准、经营调整。自动汇总字段只读，调整通过“新增调整项”记录原因、来源、人员和版本，不能用任意单元格直接覆盖底层记录。

保留旧管理口径，命名为“经营结余”，不是法定净利润：

```text
经营结余 = 产值
 - 员工工资 - 管理人员工资 - 设备投资 - 工具费用 - 房租 - 水电
 - 材料 - 杂费 - 维修 - 夜班补贴 - 油墨领用成本 - 无产值工资 - 加工费
 + 可回收工资 + 可回收油漆金额
```

设备采购整笔扣减是旧管理口径，不应被UI标成经营毛利。另提供“排除设备投资的经营贡献”需明示差异，不改动历史模板口径。采购油墨、油墨出库与人工录入“油墨费用”必须按来源去重/选择口径，不能重复计入上述成本。

月度房租、水电、管理工资按独立分摊基数生成日分摊表。旧代码有26/26/21天默认值，新模块不将其当制度：选择月份工作日集合并明确分摊政策；金额舍入余数分配至确定日期，整月分摊合计必须等于配置额。已经结算月份修改参数需修订，不悄悄改历史。

月合格率、工资占比、结余率按**月分子合计/月分母合计**计算，不平均每天百分比。人均产值明确分母是人日还是去重人数；机台开机率、时间利用率分开，不能命名为OEE。班次、机台、未定价、未完成质量、缺成本、数据截止时间都进入报表口径说明。

### 6.1 统一空间与阅读顺序

保留宿主企业深青绿、冷白、浅灰蓝、Slate层次，使用 `src/style.css` 的语义 token 和现有公共组件。新工作区采用独立命名空间 `.uv-workspace`，不写全局 `table/button/input` 覆盖规则。

顶栏只保留“返回华康A生产部、模块名、日期/班次、数据新鲜度、当前角色、主要操作”；二级分段导航固定。每页一个主视图，详情由右侧抽屉或独立子页承接。**厂区是固定业务上下文，不在模块里再造一套厂区选择器。**

默认进入“生产驾驶舱”。不同权限决定可见数据与入口，不复制多套页面。现场人员可一键切“现场模式”，管理人员保留密度更高的表格与经营页。

### 6.4 生产页面：证据与报工并排，而不是来回跳页

主表默认列：业务日期、班次、机台、货号/品名、报工数量、合格/不良/待判/半成品、来源、匹配状态、处理状态。价格和工资只在有相应权限时按需显示，不让现场表横向挤满财务列。

选中一行后，右侧约440–560px抽屉分三段：

1. **我看到了什么**：原任务名、采集器、完成/推断时间、原始次数及单位、打印参数、源记录ID。
2. **我确认什么**：关联产品/工艺、数量换算、业务日/班次、质量桶、工作人员。
3. **会影响什么**：新增还是关联已有报工、剩余可分配量、产量变化；有权限时展示产值/工资的预览和待核原因。

人工报工抽屉默认记住本页最近选择的机台/班次，但不跨账号持久化。扫码或搜索货号后支持Enter确认、Tab连续输入、Ctrl/Cmd+Enter提交；输入法组合期间不触发快捷键。提交后支持“保存并继续”，保持机台和班次，清空产品和数量。失败保留表单内容并可重试。

离线仅支持报工草稿：按当前用户ID+华康A隔离保存到本地草稿存储，保留原operation_id；提示“已存本地，未提交”，不计入正式汇总。不持久化个人工资、凭据或整厂敏感数据。恢复网络并重新确认当前身份/厂区后才提交，服务端ACK前保留草稿；换账号不能自动提交上一账号草稿。库存出库、工资确认、日月关闭必须在线获得服务端结果，不能离线假成功。

原始采集与业务报工在视觉上分别用“设备记录”“人工确认”标签。操作栏是“关联、确认、补质量、更正”，而不是含义模糊的统一“编辑”。更正前后数量差异可见，不覆盖旧记录。

### 6.5 机台页面

行政状态：正常、维修、停用；遥测状态：打印、待机、离线、错误、未知；新鲜度：正常、陈旧、未连接。三个维度不能互相覆盖。

卡片保留机号、名称/型号、软硬墨、当前任务、最近心跳和当班人员；机台详情包括任务列表、当天运行区间、生产与质量、维护费用记录和采集能力清单。能力清单说明该适配器是否支持准确进度、分色耗墨、稳定作业ID、真实开始/完成时间；不支持就显示“设备未提供”。

展示运行时序时按真实时间刻度，不制造连续数据；数据缺口留空并标注。没有排程数据，不把历史运行时序画成“已排未来任务”。维修费用可引用费用记录，不建设新的备件采购系统。

### 6.6 墨水页面

“库存”与“流水”切换保留搜索条件，供应商/软硬材质/颜色支持组合筛选。库存行直接显示“可用ml/折合瓶数/阈值”，用有刻度的小条形辅助比较，低库原因和单位无需悬停才知道。

领用表单先选 SKU 再显示当前库存、包装容量、出库单位和换算结果，最后选机台及用途。未知单价不阻断数量操作，但成本显示待核。冲销必须带原单链接；导出与网页使用同一过滤条件。

### 6.7 人员、定价与经营页面

排班矩阵支持拖放，但必须有点击“分配人员/复制前一班”的等价操作；复制只复制计划，不复制产量/工资。冲突提示同一时间多机安排，不默认禁止熟练员工照看多机；由分配份额与实际工作批次核对。

定价测算台左侧输入工时、每板耗时、每板件数、人工/墨水成本及币种；右侧立即显示板数→产能→单位成本→报价的可解释计算链。滑杆只用于辅助敏感性分析，精确数值仍可键盘输入。每次报价保存输入、公式版本和结果；“采用为执行价”是单独授权动作，不因拖滑杆自动改产品价。

经营页上方先给结论性标题，例如“本月仍有3个班次未定工价，结余暂算”，其下为按日期趋势、费用构成与可核对总表。趋势不对缺失日期补假0；费用对比用排序条形图，产值到经营结余可用简洁瀑布或分项表。所有图提供同口径数据表、单位、期间和缺失说明，不使用3D饼图、无依据双轴或只有tooltip才有信息的图。

### 6.8 响应式、动效与验收标准

- 桌面1440/1920宽：主视图+侧检查器；1366×768仍能看到主任务与关键动作，不被大标题占满。
- 平板1024宽：主表/矩阵优先，检查器覆盖式；横向表仅表容器滚动，页面不整体溢出。
- 手机390宽：概况→待处理→机台列表，筛选折叠；点击进入全屏详情，底部保留一个主要动作，现场报工不依赖横向大表。
- 主要触控目标至少44px，清晰focus，抽屉焦点管理与Esc返回，不靠颜色表达唯一状态。虚拟表保留表头语义与键盘操作；金额等宽数字右对齐。
- 页面过渡约160–240ms；抽屉/胶囊约240–320ms，使用 `cubic-bezier(0.16, 1, 0.3, 1)`作为缓出曲线，不称其为真实物理弹簧。尊重 `prefers-reduced-motion`。
- 微渐变仅用于轻微表面层次，背景不大面积毛玻璃；实时心跳不闪烁、不循环扫光。保持宿主品牌，不引入新字体包。

## 7. 状态机与最小必要审计

### 7.1 不把不同概念塞进一个 status

| 对象/维度 | 状态与含义 |
|---|---|
| 作业执行状态 | observed / running / completed / cancelled / uncertain |
| 作业核对状态 | unmatched / needs_unit / ready / partially_allocated / allocated / ignored |
| 业务报工 | draft / confirmed / corrected / voided |
| 质量完整性 | pending / partial / complete；与报工生命周期分开 |
| 工资 | unpriced / provisional / confirmed / adjusted |
| 导入批次 | uploaded / previewed / applied / reversed / failed |
| 日/月期间 | open / closed；调整以新的修订保留原结算快照 |

报工 `draft→confirmed` 由具有 report 权限的人员完成，不强制另找审批人。已确认数量更正创建修订并反向抵消旧有效量；关闭期间的更正必须产生有原因的调整或受权重开，不能直接改原金额。作废与重复怀疑不同：重复怀疑待核；作废是明确业务决定。

### 7.2 保留什么证据

每个关键命令记录操作者、发生时间、作用域、对象、前后差异、原因、关联原单及 `operation_id`。金额和数量更正不能只留一条“修改成功”。无需搭建全局事件溯源平台，使用模块事务和轻量审计表即可。

草稿可编辑；有效账务/数量通过更正或冲销修订。已确认报工的质量补录同样创建可追溯修订，不能原地覆盖good_qty后让已确认工资无声变化；未关期间更新有效投影，已确认工资/已关期间按调整规则处理。迟到设备事件若改变建议数量，只新增差异待核，不回写已确认报工。新增普通主数据、普通筛选和切换Tab不用反复确认。只在冲销、工资确认、日月关闭、批量应用导入等会影响结果的动作给出清晰影响预览。

## 8. 数据模型蓝图

以下是逻辑模型与约束，不要求一个名词强行对应一张表。Codex应结合当前SQLAlchemy模型风格做合理拆分；禁止为了省事把全部模块塞成一个可任意改写的JSON大文档。

| 模型族 | 核心字段/关联 | 必须维护的约束 |
|---|---|---|
| `UvMachine` | factory_id、code、name、brand/model、ink_material、admin_status、enabled、capabilities | 同厂机号唯一；设备停用不删除历史 |
| `UvProduct` / `UvProcessVersion` | 宿主产品引用可选、客户引用、货号/品名、材料、尺寸、面积基准、每板件数、版本、生效日 | 货号不能按品名模糊覆盖；历史工艺不可无声修改 |
| `UvRateVersion` | 类型commercial/piece_wage/area、产品/工艺、机台或价组覆盖、币种、Decimal单价、生效区间 | 优先级明确、同作用域生效区间不重叠；零价与缺价不同 |
| `UvPrintEvent` / `UvPrintJob` | connector_id、machine_id、source_event_id、source_job_id、seq、observed_at、received_at、原始字段、规范化单位和能力 | 原始事件幂等保留；一个作业多个事件更新投影，不变成多份产量 |
| `UvProductionReport` / 明细 | factory_id、机台/产品/工艺、业务日/班次、数量四桶、来源、状态、版本、价规快照 | 数量守恒；有效修订唯一；来源分配不可重复超量 |
| `UvSourceAllocation` | job_id、report_line_id、piece_qty、有效/冲销标志 | 同一来源分配在事务内核对剩余量 |
| `UvShiftTemplate` / `UvAssignment` | 时间模板版本、业务日、机台、班次、参与人员、份额/工作批次 | 同员工记录不可重复；跨机安排显式表达 |
| `UvWorkerRef` | employee_profile_id可选、内部工号、显示名、在离职、生效信息 | 不存登录密码；现场未开户工人可独立劳动名册映射，不伪造系统账号 |
| `UvPayrollBatch` / `UvPayrollLine` | 班组源报工、员工、工价快照、金额/补贴、分配依据、版本、状态 | 金额分配守恒；确认后修改形成调整 |
| `UvInkSku` / `UvInkMovement` | 供应商、材质、颜色、包装ml、阈值；入出库、成本、位置、来源、冲销关联 | SKU账本一致、并发无负库存、原流水不可消失 |
| `UvExpense` | 类别、发生日、归属期、金额币种、机台可选、凭证、来源、冲销关联 | 不与已计价的同一领料/费用重复扣款 |
| `UvMonthlyPolicy` / 分摊明细 | 月份、固定费用、工作日集合、分摊方法与版本 | 月分摊合计准确；变更不篡改已关期间 |
| `UvDayAdjustment` / `UvPeriodSnapshot` | 明确调整项、原因、源单、计算版本、范围/覆盖、确认人 | 自动值和手工调整可区分；闭期快照可复算 |
| `UvPricingQuote` | 输入参数、币种、加成/毛利模式、假设、公式版本、计算结果 | 建议价不自动生效为执行价 |
| `UvHandoverRecord` | 报工/产品引用、交接日、实际接收件数、接收方、差异 | 仅核数；下游仓库入账须另有已完成集成 |
| `UvImportBatch` / staging | 文件hash、原行号、映射版本、预览结果、应用/冲销记录 | 重复文件可识别，同批应用幂等，无确定映射行不自动过账 |
| `UvAudit` / `UvOperation` | 操作人、对象版本、幂等键、payload摘要、结果引用 | 同键同体返回同结果；同键不同体409 |

所有业务实体带 `factory_id`，B0仅允许华康A。对象引用必须校验厂区与状态，不相信请求中的ID。钱用Numeric/Decimal，数量用明确精度，ID使用宿主惯例。关键索引至少覆盖 `(factory_id,business_date,shift)`、机台作业时间、产品/货号查询、库存SKU时间和事件幂等键。

当前宿主生产库为PostgreSQL，本地SQLite只用于允许的轻量开发。锁、并发、迁移和Numeric行为必须至少在隔离PostgreSQL验证，不能用SQLite测试通过替代。

## 9. 现场连接器：复用适配知识，不照搬旧可靠性

此部分由Codex在B1实现；DSH只做真实能力对应的界面和样例。

旧采集适配器识别五种打印软件模式，其UI、日志路径和字段随现场版本不同。不得从旧配置复制IP、账号、目录或密钥作为新环境默认值。每台机确认“机型/软件版本/适配器/单位/稳定作业ID/完成信号”的能力表再上线。

```text
打印软件/日志 → 只读适配器 → 本地持久待发队列 → UV采集入口
                                                   ↓
                                      原始事件 → 作业投影 → 待核报工
```

连接器使用独立、绑定厂区和机台范围的认证，不借用浏览器员工会话；服务端从凭据校验设备范围。浏览器不接触连接器秘密。优先出站HTTPS批量上报，不要求云端直连工厂内网；凭据放环境/本地配置且不入Git。

要求：稳定 `source_event_id` 持久生成、断电重启不变；队列只有收到服务端持久ACK后才能移除；网络失败保留重试；批量响应逐条给 accepted/duplicate/rejected 和原因。相同ID内容冲突返回明确错误，不能覆盖旧事件。设备重装/日志轮转需要独立generation标识，避免任务号复用碰撞。

`source_job_id` 与 `source_event_id` 不同：同一个作业的开始、进度、结束是不同事件；服务端归并成一个作业。没有天然作业ID时，适配器用本地持久观察状态、文件身份/记录位置和generation生成稳定ID，不能仅用任务名+当前一分钟。

区分 `observed_at` 与 `received_at`；时钟漂移、推断开始时间、UI消失/解析失败、CPU变低等都要标记证据等级。**三次读不到UI不是可靠完工信号。** 不确定完成生成 uncertain 待核，不自动产生合格报工。

心跳只影响在线/陈旧，不创造生产记录。默认可沿用5分钟陈旧阈值，按实际心跳周期配置；迟到历史事件可补历史，但不把当前机台状态回滚到过去。累计墨量和增量墨量必须标识，重放不重复相加。

B0可采用10–15秒可见页面轮询；页面隐藏、登出或换厂时暂停，卸载取消请求。B1确需实时再使用独立UV通道，沿用宿主认证能力而非挪用3D业务Hub。简单模块不为“先进”新增Kafka、Redis或MQTT；现场确有MQTT再通过边缘适配桥接。

## 10. 权限与数据边界

【仓库事实】宿主采用服务端会话、现有 `authStore` 与 `ensure_permission_in_scope`；当前全局页面策略允许部分登录用户只读浏览。UV采用类似单厂专属模块的明确入口权限，但**不修改全局策略**。

以下是【新设计】的权限码，必须由Codex在 `backend/app/services/permission_codes.py` 及相关注册/角色模板中落地后才是真实权限；DSH不得通过给authStore塞字符串来模拟正式授权。

| 权限 | 能做什么 |
|---|---|
| `uv_printing:read` | 查看已授权华康A非敏感生产数据 |
| `uv_printing:report` | 人工报工、匹配来源、提交报工、更正本人/被授权范围报工 |
| `uv_printing:quality` | 质量核对及相应更正 |
| `uv_printing:master_write` | 机台、产品、工艺等基础资料维护 |
| `uv_printing:shift_write` | 排班维护，不等于可看工资 |
| `uv_printing:ink_write` | 墨水数量流水和盘点，不自动包含成本定价权限 |
| `uv_printing:cost_read` / `cost_write` | 查看/维护商业价格、费用、经营成本和分摊 |
| `uv_printing:payroll_read` / `payroll_write` | 查看/维护工价、工资预览、确认及调整 |
| `uv_printing:import` / `export` | 导入/导出；还需对应数据域权限，不是全数据通行证 |
| `uv_printing:close` | 日月关闭或受权重开/调整，仍需对应经营/工资权限 |

工人/班长/仓管/主管/成本人员是业务场景，不直接新增一套平行角色系统。通过宿主已有职位或自定义角色授予上述码。系统管理员、总经理、显式deny遵守原规则；不把“总经理”硬编码成绕过所有检查。

金额保护在服务端序列化时完成。普通机台/生产接口不返回工价、个人工资、成本、利润；导出、下载、搜索结果、错误详情、日志、实时通道和客户端缓存同样不得绕过。DSH的隐藏列不是权限控制。

每次读写校验 `factory_id == huakang-a`、用户在该厂区/production范围的权限、所引用实体也属于该范围；跨厂记录ID即使存在也不得使用。普通调用缺厂区返回422，不回落到华康A；非法厂区返回受控错误，不修改当前厂区。所有关键操作在事务内执行并回滚失败结果。

## 11. 前后端共同契约 v1

### 11.1 契约冻结方式

以 `src/features/uv-printing/contracts.ts` 作为前端消费类型，后端用对应Pydantic schema生成OpenAPI并做契约测试。DSH先按本文创建类型与样例；任何字段/枚举/单位调整必须先更新本文与 `DECISIONS.md`，再同时改mock、页面和后端。不能静默改 `good_qty` 为 `quantity` 让另一个代理猜。

下面是核心类型骨架，**不是现有接口的声明**。未列的实体按第8节和第12节补齐明确类型，不使用 `Record<string, any>` 贯穿全部页面。金额统一字符串，前端数值预览不作为正式入账结果。

```ts
export type UvFactoryId = 'huakang-a'
export type IsoInstant = string  // RFC3339，必须带Z或明确offset
export type BusinessDate = string // YYYY-MM-DD，上海班次业务日期
export type DecimalString = string
export type Id = string
export type ShiftCode = 'day' | 'night'
export interface Money { currency: string; amount: DecimalString }
export interface UvMeta {
  factory_id: UvFactoryId
  as_of: IsoInstant
  data_mode: 'live' | 'sample'
  coverage: 'complete' | 'partial' | 'no_data'
  warnings: Array<{ code: string; message: string }>
}
export interface UvResponse<T> { meta: UvMeta; data: T }
export interface UvPage<T> {
  items: T[]; total: number; page: number; page_size: number
}
export interface UvEntity {
  id: Id; factory_id: UvFactoryId; version: number
  created_at: IsoInstant; updated_at: IsoInstant
}
export interface UvScope {
  factory_id: UvFactoryId
  business_date?: BusinessDate
  date_from?: BusinessDate; date_to?: BusinessDate
  shift?: ShiftCode; machine_id?: Id; product_id?: Id
  q?: string; page?: number; page_size?: number
}
export interface UvQuality {
  reported_qty: number
  good_qty: number
  defective_qty: number
  pending_qty: number
  semi_finished_qty: number
}
export interface UvMachine extends UvEntity {
  code: string; name: string; brand: string; model: string
  ink_material: 'hard' | 'soft' | 'other'
  admin_status: 'normal' | 'maintenance' | 'disabled'
  runtime_status: 'printing' | 'idle' | 'offline' | 'error' | 'unknown'
  freshness: 'fresh' | 'stale' | 'never_seen'
  last_heartbeat_at: IsoInstant | null
  current_task_name: string | null
  progress_pct: number | null
  capabilities: {
    progress: boolean; exact_completion: boolean
    ink_by_color: boolean; stable_job_id: boolean
  }
}
export interface UvPrintJob extends UvEntity {
  machine_id: Id; source_job_id: string; connector_id: string
  raw_task_name: string; raw_product_name: string | null
  product_id: Id | null; process_version_id: Id | null
  state: 'observed' | 'running' | 'completed' | 'cancelled' | 'uncertain'
  reconciliation: 'unmatched' | 'needs_unit' | 'ready'
    | 'partially_allocated' | 'allocated' | 'ignored'
  started_at: IsoInstant | null; completed_at: IsoInstant | null
  time_evidence: 'observed' | 'inferred' | 'unknown'
  raw_count: DecimalString | null
  raw_unit: 'piece' | 'board' | 'cycle' | 'unknown'
  suggested_piece_qty: number | null
  available_piece_qty: number | null
  print_time_seconds: number | null
  print_area_m2: DecimalString | null
  ink_total_ml: DecimalString | null
}
export interface UvReport extends UvEntity, UvQuality {
  business_date: BusinessDate; shift: ShiftCode
  shift_template_version_id: Id
  machine_id: Id; product_id: Id; process_version_id: Id
  source_kind: 'manual' | 'device' | 'import' | 'mixed'
  status: 'draft' | 'confirmed' | 'corrected' | 'voided'
  quality_status: 'pending' | 'partial' | 'complete'
  worker_ids: Id[]; notes: string
  replaces_report_id: Id | null
  // 无相应权限时，服务端完全省略对应字段。
  commercial?: { output_value: Money | null; pricing_state: 'priced' | 'unpriced' }
  payroll?: { amount: Money | null; state: 'unpriced' | 'provisional' | 'confirmed' }
}
export interface UvCommandMeta {
  factory_id: UvFactoryId
  operation_id: string
  expected_version: number // 新建0；更改使用读取到的对象版本
}
export interface CreateUvReport extends UvCommandMeta, UvQuality {
  business_date: BusinessDate; shift: ShiftCode
  shift_template_version_id: Id
  machine_id: Id; product_id: Id; process_version_id: Id
  worker_ids: Id[]; notes: string
  source_allocations: Array<{ job_id: Id; piece_qty: number; job_version: number }>
  evidence_job_ids: Id[] // 仅附证据，不声明已核实件数
}
export interface UvMutationResult<T> {
  entity: T
  operation_id: string
  replayed: boolean
}
export interface UvSummary {
  business_date: BusinessDate; shift: ShiftCode | 'all'
  counts: {
    enabled_machines: number; fresh_connected_machines: number
    good_qty: number; pending_qty: number
    unmatched_jobs: number; needs_unit_jobs: number
    reports_needing_quality: number; low_stock_skus: number
  }
  permissions: string[]
  commercial?: { output_value: Money | null; unpriced_report_count: number }
}
export interface UvTransport {
  summary(scope: UvScope, signal?: AbortSignal): Promise<UvResponse<UvSummary>>
  machines(scope: UvScope, signal?: AbortSignal): Promise<UvResponse<UvPage<UvMachine>>>
  jobs(scope: UvScope, signal?: AbortSignal): Promise<UvResponse<UvPage<UvPrintJob>>>
  reports(scope: UvScope, signal?: AbortSignal): Promise<UvResponse<UvPage<UvReport>>>
  createReport(input: CreateUvReport): Promise<UvResponse<UvMutationResult<UvReport>>>
}
```

请求全天时省略 `shift`，不发送类型外的 `all`；响应summary可用 `all`表示全天。`permissions`采用完整权限码，不混用 `report` 与 `uv_printing:report`。样例和真实接口都按同一字段与分页规则返回。其他操作按同样模式扩展具名方法；不在Vue组件中直接拼接HTTP、读PocketBase或自己维护另一份工资公式。

### 11.2 通用行为

查询使用稳定排序及分页，默认50、最大200；汇总由后端全量过滤后聚合，不求和“当前页”。前端AbortController+请求代次处理快速切换，过时响应不能覆盖新页或其他厂区数据。

写入重试保留同一 `operation_id`；内容改变才产生新操作。服务端按“厂区+操作者/连接器+命令类型+operation_id”唯一并保存payload摘要。同键同体重放返回原结果；同键异体409。`expected_version`不符409并返回可用的刷新提示，不使用最后写入覆盖。

创建/提交报工客户端不提交正式总金额；服务器重算数量、价格选择和金额。非法字段返回具体字段错误，跨域金额越权明确拒绝。网络超时不能直接认定未保存，重试幂等请求或查询操作结果。

错误采用兼容现有FastAPI的 `detail`，UV域可返回结构化 `{code,message,fields?,retryable?}`；前端兼容宿主字符串或验证错误数组，归一成可读提示。常用：401登录过期、403无权、404对象不可见/不存在、409版本或幂等冲突、422字段/数量/单位错误、503服务暂不可用。只改UV边界处理，不重写全应用错误协议。

### 11.3 样例数据与正式数据不得自动混合

【新设计】仅 `import.meta.env.DEV` 且本地显式开启 `VITE_UV_PREVIEW=true` 才注册 `/__preview/uv-printing`。此路由是**独立样例预览**，不是给正式路由加授权后门；沿用现有登录状态要求，但不要求尚未注册的UV业务权限，因为其只读写内存样例、不能访问真实UV接口。

preview使用单独 transport/provider 注入，顶部常驻“样例数据·不写入生产库”；普通真实路由仍严格执行华康A与权限。预览角色切换只改变样例提供的数据，不修改真实authStore、用户角色或后端请求。

生产构建不注册预览路由、不静态引入样例数据。正式UV功能启用前由显式发布开关隐藏入口；前端合并main不意味着正式启用。没有后端、403、500或断网都不得回落mock。正式路由得到 `data_mode: sample` 应视为配置错误并停止操作。

## 19. 待业务确认项与不阻塞设计的默认值

| 问题 | 暂行设计 | 不确认的影响 |
|---|---|---|
| 真实机台数、品牌、软件及连接方式 | 从主数据加载；样例若干台，不植入10/11/12的硬值 | 真实设备需逐台登记/验收 |
| 旧单价是销售价、加工产值价还是工价？ | 新模型分开三者；旧值不自动写入工资 | 无独立工价时工资暂算/未定价 |
| 本模块实际币种及旧金额币种 | 新单显式币种；样例HKD，旧历史不猜 | 混合金额无法统一核算 |
| 按合格件、投入件、板还是面积计价？ | 默认合格件×商业执行价；面积仅独立参考 | 正式价规需选定计价基准 |
| 多人、换人、跨机如何分工资？ | 同工作批次等分；换人拆批或明确份额 | 复杂班组工资不自动确认 |
| 夜班模板、休息时间、加班口径 | 07:40/21:00作可版本化初始模板 | 人员工时与工资不能只凭跨度推算 |
| 1瓶是否都1000ml？ | SKU包装容量可配，旧默认明确标1000 | 新包装须先确认再领料 |
| 入库表是否真的对接PMC仓？ | 只做核数/交接，不修改PMC库存 | 无法声称仓库已收货 |
| 生产标准表“合格/实际/半成品”的含义 | 先映射预览，不拿列标题推断业务结果 | 历史表暂作为档案 |
| 月租/水电/管理工资按哪些天分摊？ | 明确工作日集合+版本，保证总额守恒 | 未配置时经营报表暂算 |
| 设备投资是否整笔计入经营结余？ | 保留旧管理口径，并明确标注非会计净利 | 新旧口径不可无说明比较 |
| 可回收工资/油漆具体代表什么？ | 独立经营调整，需来源与原因，不做员工扣薪 | 不能自动与个人工资抵扣 |
| 哪个现场软件先接？ | 挑选一台可稳定提供完成信号的代表机型 | 不承诺五适配器一次全部打通 |
| 是否迁移历史数据？ | 默认不迁移，只提取规则 | 需要历史时另做映射/预览/对账任务 |

这些问题在代码中表现为可配置项、明确缺失状态或未启用能力，而不是让整个页面停工等待。正式财务/工资确认之前，需要把相关口径固化为版本和测试样例。
