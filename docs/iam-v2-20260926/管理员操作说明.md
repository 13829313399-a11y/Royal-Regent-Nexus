# 人员与权限模块｜管理员操作说明

适用版本：IAM V2。界面核对日期：2026-09-27。

本文供管理员日常使用。以下流程以**线上已部署新版、完成数据库升级并启用任职办理**为前提。本机启用不等于线上启用。

## 1. 先看这张操作速查表

进入 **权限与组织 → 人员与权限中心 → 搜索人员 → 点击姓名 → 办理变更**。

| 想做什么 | 选择什么 | 注意什么 |
|---|---|---|
| 旧用户第一次使用新版任职管理 | 确认正式任职 | 核实原权限来源，保持原权限 |
| 换厂区、换部门、升职或换岗位 | 调厂调岗 | 填新任职，并添加对应权限包 |
| 只改姓名或职位文字 | 更正正式资料 | 权限不变 |
| 保留原工作，增加另一份工作 | 增加兼任 / 支援 | 为新增工作单独选择权限和厂区 |
| 临时去别厂帮忙 | 增加兼任 / 支援 | 类型选“临时支援”，填写结束时间 |
| 结束某一份主职或兼任 | 结束任职 | 选准“来源任职”，避免结束错岗位 |
| 暂时停用账号 | 冻结账号 | 当前登录会失效 |
| 恢复被冻结账号 | 恢复冻结账号 | 员工需要重新登录 |
| 员工离职 | 办理离职 | 停止访问，并检查工作交接 |
| 离职后重新入职 | 重新确认复职 | 重新选任职和权限，旧权限不会整套恢复 |
| 把已有任职的权限包更新到新版本 | 升级权限包 | 核对权限增减；换岗位应选“调厂调岗” |

**通用流程：选人 → 选事项 → 填任职和权限 → 预览 → 确认 → 检查结果。**

页面地址为：你的项目域名后加 `/system/users`。如果没有入口或看不到某人，先让集团管理员核对你的管理范围。

## 2. 先分清三个设置

| 设置 | 表示什么 | 例子 |
|---|---|---|
| 正式组织、部门、职位 | 这个人在哪里、担任什么工作 | 华兴 / PMC仓库 / 仓管员 |
| 权限包 | 允许他使用哪些功能，一组配好的操作权限 | 仓库“仓管”权限包 |
| 业务范围、权限作用部门 | 这些权限可以用在哪些厂区和部门 | 华兴 / PMC仓库 |

**只把职位文字改成“经理”，不会自动获得经理权限。** 新建任职时没有添加权限包，也不会因为填了职位名称就获得操作权限。

## 3. 旧用户：先做一次“确认正式任职”

### 为什么原来有权限，还需要确认？

旧用户已有权限，但系统未必知道每条权限是“因为当前岗位给的”，还是“另外单独批准的”。确认任职就是把这些关系核实清楚。

以后调岗时，系统才能停止旧岗位带来的权限，同时保留应继续有效的独立授权。

- 旧用户只需完成一次首次确认。
- 尚未确认时，已有权限仍按原规则使用。
- 这一步以保持原权限为要求；真正调动另办一张变更。

### 操作步骤

1. 找到显示“来源待核实”的人员，点击 **办理变更**。
2. 办理事项选 **确认正式任职**。
3. 核对原厂区、部门和职位。已确认的正式资料可能锁定，首次确认时保持原值。
4. 在“逐项核实历史授权来源”中，为每条待核实授权选择真实来源：

   | 界面选项 | 什么时候选 |
   |---|---|
   | 属于本次主职 | 这条权限是因为当前主要工作而获得的 |
   | 独立个人能力 | 单独批准给此人的权限，需要与主职分开管理 |
   | 独立外部协作 | 来自另外的外部协作身份 |
   | 独立系统管理 | 账号、权限等系统管理授权 |

5. 如有“个人例外处理”，首次确认时核实并按原范围保留。已撤销的历史记录不用重新授权。
6. 点击 **保存草稿并预览影响**，检查原有权限保持。
7. 勾选 **我已核对组织、权限差异及交接范围**，点击 **确认办理**。如果按钮显示“提交审核”，提交后由有权管理员按第 8 节审核。

例如：员工当前在华兴做啤机文员，“啤机文员”权限确实来自这份工作，就选“属于本次主职”。不要把另外批准的系统管理权限也归到普通岗位。

如果提示“来源映射改变实际权限”，重新核实来源和范围。系统会阻止把权限增减混进首次确认。原资料需要修改的，确认后再办“更正正式资料”或“调厂调岗”；资料缺失的由有权管理员核实补全。

## 4. 换厂区、换职位：以工程师调仓管为例

例子：张三从**华康A工程师**调到**华兴仓管员**。

1. 打开张三的人员详情，点击 **办理变更**。
2. 选择 **调厂调岗**。如果只有首次确认选项，先完成上一节。
3. 按下表填写：

   | 字段 | 本例填写 |
   |---|---|
   | 来源任职 | 原华康A工程师主职 |
   | 正式组织 | 华兴 |
   | 正式部门 | PMC仓库 |
   | 正式职位 | 仓管员 |
   | 任职类型 | 长期任职 |
   | 结束时间 | 长期工作留空 |
   | 权限包 | 仓库对应的“仓管”权限包 |
   | 权限作用部门 | PMC仓库 |
   | 业务范围 | 本任职厂区 |

4. 点击 **添加权限包**，确认它出现在下方列表。只在下拉框选中还不算添加。
5. 如有个人例外，逐项核实要“按原范围保留”还是“明确终止”。
6. 填写办理原因，例如“从华康A工程部调到华兴仓库”。
7. 点击 **保存草稿并预览影响**，确认厂区、职位和权限差异正确，再勾选确认并提交。

**特别注意：修改正式部门后，还要检查“权限作用部门”，不要保留旧部门。**

生效后，原主职结束，新任职开始；原主职带来的权限停止，新权限按选择的范围生效。其他合法兼任和独立授权按预览结果处理，历史单据不会因此搬到新厂区。

### 同厂升职怎么做？

也选 **调厂调岗**，正式组织保留原厂，填写新职位、选择对应权限包。只改职位文字时才用“更正正式资料”。

## 5. 权限怎么选、怎么检查？

### 业务范围怎么选？

| 选项 | 用途 |
|---|---|
| 本任职厂区 | 只需在本次任职的厂区工作 |
| 选择厂区 | 需要跨厂时，勾选实际需要的厂区 |
| 当前全部厂区 | 确实需要覆盖所有现有厂区；以后新增的厂区不会自动加入 |

选择更多厂区只扩大所选权限包的作用范围，不代表获得所有功能。

集团总务属于职能组织。给集团职能人员配置业务权限时，要明确选择业务厂区，不能因为属于集团就默认获得六厂操作权。

### 提交前看哪些内容？

- **新增权限**：新增加了什么操作，作用于哪些厂区和部门。
- **停止权限**：哪些原操作将不能继续使用。
- **保留权限**：哪些能力继续有效。
- **来源变化，能力保留**：同一能力仍然存在，只是授权来源变了。
- **工作责任**：有没有待接管事项、哪些模块需要人工核实。

“保存草稿并预览影响”还没有让变更生效。最后需要点击“确认办理”，或提交给有权管理员审核。

### 单独授予某项特殊权限

人员详情中的 **个人例外与供应商授权**，可办理页面已经提供的特殊项目，例如符合条件人员的“本人报价自审”和“纸箱供应商协同权限”。

选择相应项目 → 预览授予或收回影响 → 按页面要求核对并确认。

这个入口目前不是任意权限的通用勾选器。正式任职人员换岗位、换权限包，使用“办理变更”；不要用旧页面的“历史授权清理”处理新版任职。

“明确禁止”会优先于其他允许。供应商授权可与内职分开保留，但实际订单仍受供应商和业务范围限制。

### 查看权限包或升级版本

- 点击顶部 **权限方案**，查看内置职位包含的权限和范围。内置职位的功能由系统维护，页面不能任意逐项修改。
- 如果系统更新了同一个权限包，需要让某份已有任职采用新版本：选择 **升级权限包 → 来源任职 → 预览 → 确认**。
- “升级权限包”更新原包版本；给某个人改成另一种岗位，使用“调厂调岗”。

## 6. 兼任、临时支援和结束任职

### 保留原工作，再增加一份工作

1. 选择 **增加兼任 / 支援**。
2. 填写新增工作的组织、部门、职位。
3. 任职类型选“兼任”；短期帮忙选“临时支援”，并填写结束时间。
4. 添加该工作的权限包，核对作用部门和厂区。
5. 预览并确认。

原主职继续保留。临时任职到期后，这份任职带来的权限失效；通过其他有效来源获得的相同能力仍可能保留。

### 提前结束

选择 **结束任职**，在“来源任职”中选中要结束的那一份，预览停止权限后确认。结束一份兼任不会自动结束其他任职。

## 7. 冻结、离职和复职

| 操作 | 适用情况 | 办理后的效果 |
|---|---|---|
| 冻结账号 | 暂时停止此人使用系统 | 停止访问，原登录会话失效，任职记录保留 |
| 恢复冻结账号 | 可以恢复使用了 | 按当前仍有效的授权恢复访问，需要重新登录 |
| 办理离职 | 正式离开公司 | 停止访问，结束当前和未来任职，撤销允许来源；检查交接 |
| 重新确认复职 | 离职人员重新回来 | 使用原账号，重新确认组织、职位和权限，不自动恢复旧权限 |

这些事项均从 **人员详情 → 办理变更** 操作，核对预览后确认。冻结、恢复、离职和复职按立即办理，不支持预约。

## 8. 审核、预约、撤回和记录

### 出现“提交审核”

表示这项办理需要覆盖完整范围的管理员确认，不代表已经生效。

审核人进入 **变更办理 → 选择待审记录 → 重新核对并预览 → 勾选“已核对变更影响” → 批准办理**。不通过时填写原因并点击“驳回”。

### 想在将来某天生效

只有线上另外启用预约后，调厂调岗、增加兼任 / 支援、结束任职才会显示 **预约生效时间**。按北京时间填写，留空立即办理。

“已预约”表示计划已确认，尚未到生效时间。页面没有这个字段时，不要把草稿当作预约。

### 撤回或继续草稿

- 草稿、待审核或尚未生效的预约：进入对应记录，填写原因，点击 **撤回变更**。
- 草稿要继续提交：在记录中点击 **重新核对并预览**，核对后确认。
- 预约后又发生其他变更，撤回可能被拒绝，需要重新核实最新情况。
- 已经生效的变更不能直接撤回；需要办理新的更正或反向调动。

### 查看结果

- **人员详情**：看当前任职、兼任和任职时间线。
- **变更与交接记录 / 变更办理**：看草稿、待审核、预约、已生效和接管状态。
- 顶部 **记录**：查看最近 100 条可见审计记录；它不是所有历史记录的完整列表。

## 9. “查看授权依据”和工作交接怎么用？

### 查看授权依据：查询某项权限为什么允许或拒绝

1. 在人员详情展开 **查看授权依据**。
2. 选择“操作权限”“业务厂区”和“作用部门”。
3. 查询时间通常留空，表示现在。
4. 点击 **核对授权**，查看允许或拒绝及原因。

这里只查询，不修改权限。“来源记录已撤销”表示该条来源失效，不代表此人一定没有其他有效来源。

授权检查通过后，具体业务仍可能要求单据可编辑、审核资格或模块已开放。过去时间的查询也不是完整历史账号状态还原；查办理经过应看变更记录。

### 调岗、离职后的工作交接

进入 **变更与交接记录 → 选择变更 → 工作接管**。

有待接管项目时，选择合格接管人，点击 **确认接管**。出现状态变化或交接延迟提示时，点击 **重新评估 / 重试**，核对后再办理。

当前自动接管覆盖内部报价中的可编辑报价负责人。啤办/生产任务、仓库/订单、纸箱/供应商、3D、UV、喷油仍需人工核实；注册与密码找回按当前管理角色队列处理。

**“已识别 0 项责任”不等于所有工作都交接完了。** 历史创建人、已完成事实和单据原厂区保留。

## 10. 新员工、密码找回和地方管理员

### 新员工开通账号

进入右上角 **注册审核与密码找回 → 待审批**：

核实申请人 → 核对姓名、厂区、部门和真实职位 → 选择“内置权限职位” → **通过并开通账号**。

任职办理启用后，审核通过会同步建立正式任职。员工自己填写的职位名称不会自动产生权限。集团职能人员还需明确业务厂区范围。

### 员工忘记密码

进入 **注册审核与密码找回 → 密码重置**：核实申请人与账号本人一致，再批准开放自助改密。员工需要在提交申请的原浏览器设置新密码，管理员不会获得临时密码。

### 限定地方管理员可以给别人授什么权

集团管理员打开目标管理员详情，展开 **地方管理员转授上限**：

**新增范围 → 选择可管理组织和部门 → 选择可授出的权限包 → 勾选最大业务厂区范围 → 填原因 → 保存转授上限。**

已有范围可以选中修改，状态可设为“撤销”。这只规定授权上限；此人还要有对应的用户管理、授权管理权限，才可以办理。把普通人的职位写成“管理员”不会获得管理权。

## 11. 常见问题：遇到后这样处理

| 现象 | 处理方式 |
|---|---|
| “办理变更”灰色，提示尚未启用 | 刷新页面；仍然如此，请上线人员核对任职办理开关和授权模式 |
| 只能看到“确认正式任职”，找不到调岗 | 先按第 3 节完成旧用户首次确认 |
| 人员列表没有某个用户，或提示无权限 | 让集团管理员核对管理范围；跨厂、兼任或独立授权可能需要更大范围 |
| 选了职位，预览却没有新增操作权限 | 检查是否选好权限包并点击“添加权限包”，同时核对作用部门和厂区 |
| 首次确认提示权限发生变化 | 重新核实历史来源和范围，保持原授权后再确认 |
| 提示版本变化、预览失效或 409 冲突 | 关闭办理，刷新人员资料，再重新预览 |
| 提交超时，不知道成功没有 | 先查变更记录；未成功时在原页面重试，避免重新创建重复变更 |
| 调岗后员工页面还显示旧组织 | 刷新页面；若正在填写原厂业务表单，先核对并妥善处理，再离开后重新进入 |
| 恢复账号后，原登录仍不能使用 | 让员工重新登录 |
| 权限显示允许，但具体单据不能操作 | 继续检查单据状态、正式业务资格、模块开关和厂区限制 |
| 接管人列表为空，或接管失败 | 核对接管人有效任职与业务资格，重新评估后再选 |
| 提示不能停用最后有效管理员 | 保留有效管理员，先安排具有相应管理权限的接任人员 |

## 12. 上线交付时，只需确认这几件事

由上线人员完成数据库备份、升级和实际权限对比，按 [迁移与回退说明](migration-runbook.md) 发布。不要仅凭本机正常就断定线上权限完全不变。

交给管理员使用前确认：

1. 线上能打开“人员与权限中心”。
2. 管理员能看到应管理的人员，“办理变更”可用。
3. 原用户登录和代表性业务权限已核对。
4. 已明确预约是否启用、哪些交接还需人工处理。

供上线人员核对：任职办理依赖 `AUTHZ_MODE=enforce`、`AUTHZ_WRITES_ENABLED=true` 和 `IAM_IDENTITY_WRITES_ENABLED=true`。预约由 `IAM_IDENTITY_SCHEDULING_ENABLED` 单独控制；不要为打开按钮而未经权限对比直接切换生产授权模式。

**日常记住：职位说明做什么工作，权限包决定能做什么操作，业务范围决定能在哪些厂区做。每次提交前，先看预览。**
