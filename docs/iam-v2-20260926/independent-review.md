# IAM V2 独立复核

用户明确允许独立审查后，由 `iam_independent_review` 子代理只读检查本次实现和验收证据，并用隔离合成数据库复现关键问题。该复核不访问生产，不代替实际操作人员的上线确认。

## 已修复发现

| 问题 | 修复 | 验证 |
|---|---|---|
| 地方管理员的完整范围只检查任职，遗漏独立角色及 allow/deny，可看到或办理同时涉及其他工厂的人员 | 批量汇总当前/未来且未终止的独立来源范围，统一详情、列表、总数和账号级变更检查 | 独立代理复现后验证三类来源列表/详情 403；N 参数化用例覆盖未来角色、全局 allow、未来 deny 与旧状态接口 |
| 密码重置等旧写入路径可能使用已被撤权的缓存办理人 | 共享锁后重新读取 actor，再核对当前授权和目标范围 | 独立连接停用后，旧 AuthContext 的批准/重开/驳回均 401，队列不变 |
| 自定义含 system 权限角色在注册审核时可能被挂到普通任职 | 按权限内容识别系统管理来源，assignment_id 留空，保存独立 source_type | 独立代理实际注册审核复现并验证；N 自定义系统角色用例通过 |
| 密码找回和审核候选仍可能使用未物化的旧 profile | 改用请求时身份解析；V2 没有有效主职时不以旧注册记录兜底 | worker 停止跨 T，申请范围和返回 DTO 采用新厂区/部门 |
| 首次组织目录 503 后，重试只恢复人员列表；403/503 可能与空态同时显示 | 重试重新获取缺失目录，错误态排除空态 | 前端单测及浏览器注入 503、实际 403、重试后办理入口验证 |

独立复核结束时未报告新的未修复 P1 问题。该结论限于本次审查范围，不声称穷尽所有潜在问题。CodeRabbit CLI 未安装，本次未使用 CodeRabbit 服务。

## 额外收尾

- 补齐预检来源窗口、sidecar、特殊账号及待处理队列；只读测试验证文件内容与修改时间不变、无凭据输出。
- 独立兼容发布包经过逐文件校验和三种授权模式的独立进程测试，保留旧会话撤销与已终止任职的拒绝结果。
- 迁移中断后恢复迁移前副本、重新升级并重跑，旧数据保持。
- 原注册部门回归发现新组织校验提前返回 422；调整校验顺序，保留无效部门原有 400 和提示，4 项注册回归复测通过。
- 浏览器真实 409 冲突后重新预览并办结；历史授权来源同时展示关联任职状态，避免把保留的记录误读为当前可用权限。
