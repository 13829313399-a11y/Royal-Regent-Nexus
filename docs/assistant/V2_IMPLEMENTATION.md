# 曜灵 2.0 架构与启用说明

范围：2026-10-12 交接包的 P0/P1。源码基线 `11873d2f39d81551e77650352b4f633f9cd077e5`。
现有成员目录、头像、协作样式及 test-artifacts 的修改属于其他工作。

## 实施顺序

1. T01–T03：v1 请求摘要兼容；v2 schema、原生联网 adapter、统一正文/证据/动作聚合器与持久化。
2. T04–T06：真实事件驱动 UI、草稿/图片/历史修复；fixture 回归与最小公开联网探针。
3. T07–T08：复用受权只读服务、来源依赖重验、注册导航与页面教学。
4. T09–T10：forward migration、私有文档解析、成果版本、检索收藏与真实导出。
5. T11：公私材料隔离、末尾修订、集成回归、桌面/移动浏览器与独立复审。

## 约束

同一 host/store；不恢复 `/api/ai/*`；不自动重试付费请求；业务写入留在原模块。
v1 请求的冻结字段与 hash 保持旧合同；来源与动作随完整 content_parts 保存。
公开搜索单独构造上下文，不输入内部历史、图片或文件。能力配置与真实组合验证分开。
迁移验证使用隔离库；Git 交付与真实库迁移、环境启用及生产部署分别处理。

## 视觉基线

专注态会话栏约 200，资料栏约 300；1120/900/768 断点依次改抽屉与移动布局。
正文 16px/1.75；图标复用 Lucide；动效遵守 reduced-motion。

## 实现结果

T01–T11 的 P0/P1 源码已实现。旧 v1 的 canonical hash、幂等准入、取消、lease、恢复与聊天协议继续使用；v2 增加每步来源、引用、用量、活动和受控动作，并随完整 `content_parts` 保存。

- 联网：独立 DashScope multimodal 原生接口与组合验证档案，支持关闭/自动/本次联网。原生搜索只收公开检索词；涉及内部历史、文件或业务时要求单独公开词，再由关闭联网的聊天步骤综合。实际检索次数未知保留 null；有来源不等于读取网页全文。
- 业务：本人事项、注塑概览、3D 状态三个只读适配器复用原权限与 DTO。事项保留全授权统计与当前筛选统计的区别；注塑分别返回 held、等待料、预计剩余用料与未知项；3D 复用遥测新鲜度，不写设置或下发命令。
- 权限：读取历史正文时同步捕获其来源依赖；上游调用前、运行中、终态及历史/检索/成果/导出再次校验。撤权或源文件失效后整段派生内容不可读，v1 追问也保留依赖。动作点击时重验并只使用注册路由。
- 文件：私有 TXT/MD/CSV/文本 PDF，真实 queued/parsing/ready/failed 状态；CSV 使用物理行，PDF 使用原页码。解析并发、队列、体积、页数、文本长度有上限，重启或超时解析明确失败。扫描 PDF 提示需要 OCR，未伪装成功。
- 成果：本人及任职周期内的成果、不可变版本、过期 base revision 返回 409；导出选中的版本。MD/TXT 与结构化清单/表格 CSV 为实际文件，CSV 防公式。删除源会话/文件或撤权使全部成果版本停止读取和导出，界面已明确说明。
- 界面：原 host/store 内的侧舱、专注阅读和抽屉，四类任务入口、来源回看、文件行页位置、成果编辑、收藏检索、末尾问题修订与显式重新生成。草稿按身份和会话隔离；首次上传迁移未发送文字；旧图片通过授权 blob 查看。
- 教学：门户、事项与注塑各步骤定位到真实语义目标；集团首页另有说明，明确首页指标为静态示例。定位复用页面 reveal，保留 dirty/busy 约束。选中上下文只传 ID/筛选并由服务端重查。

用户、任职周期、会话和文件归属必须同时匹配。历史文件展示当前名称、解析状态及页/行原文，删除需确认；生成中的文件先停止或等待生成完成。删除后立即丢弃本地缓存回答，再由服务端重查可见性。成果编辑未保存、版本加载尚未完成时禁止导出，旧版本只读，版本冲突保留草稿；表格 CSV 保留转义竖线、空单元格及公式保护。成果不能通过另存为来绕过源权限：所有版本共享原 run 来源依赖，删除源会话/文件或权限撤回后，相关版本不再可读或导出。保留旧版本不等于保留已被撤销的数据访问权。

历史和 snapshot 在短写事务内完成过期结算并捕获一致状态，耗时的来源可见性验证在事务外执行，避免遍历历史时长期占用 SQLite 写锁。业务来源重验使用与原模块相同的纯权限谓词，不在读取或成果写事务中嵌套提交审计。成果创建和版本冲突检查仍在同一写事务内完成。

## 运行边界

文件解析使用当前单 API worker 的有界调度池，每个文件在独立子进程解析；监督线程只负责启动、等待、终止与写入状态。`ASSISTANT_FILE_PARSE_CONCURRENCY` 默认 2（1–4），`ASSISTANT_FILE_PARSE_QUEUE_LIMIT` 默认 16（1–64），`ASSISTANT_FILE_PARSE_TIMEOUT_SECONDS` 默认 60（1–300）。超时、删除与服务退出会终止子进程；父进程管道关闭时子进程自退，另有独立超时看门狗。启动恢复标记遗留 queued/parsing 为失败；状态查询也恢复同进程失去任务登记的状态。文件占用或数据库清理异常不占住队列名额，遗留文件按原归属在下次恢复重试。子进程读取文件前安装硬内存上限：`ASSISTANT_FILE_PARSE_MEMORY_MB` 默认 512 MiB（128–2048）；Windows 限制已提交内存，Linux 使用进程地址空间限制。安装失败即拒绝解析，超限返回 `parse_memory_limit`。本机已验证真实分配拒绝、256 MiB 展开的压缩 PDF 被拒绝，以及失败后唯一队列名额恢复；Linux 路径和生产并发容量尚未验收。这不是文件系统、网络或代码执行沙箱。实现依据 [Windows Job Object 内存限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information) 和 [Python resource](https://docs.python.org/3/library/resource.html)。扫描/OCR、Office、向量检索、多代理研究、任意历史节点分支和业务写入不在 P0/P1 范围内。

历史与成果的分页在 owner/epoch 过滤后按稳定 timestamp/id 游标扫描，直到取得足量授权且匹配关键词的记录。前端把翻页绑定到已提交的检索条件，忽略旧搜索/打开详情的晚到结果；新搜索失败时不会使用旧游标。待解析资料在可见面板中自动刷新，切换身份/会话和卸载使旧响应失效，完成后停止轮询。发送按钮被停止按钮替换后，键盘焦点保留在输入框。

当前源代码、隔离回归、真实公开搜索探针、桌面及窄屏交互和实际 Chromium 标签页 200% 缩放已验证；宽代码/表格局部滚动和超长 URL 未造成全页横向溢出。Chromium 可访问树与 live region 检查确认按钮有名、只播报有限阶段而非每个 token。本次新增文件/成果页面验收的六项检查通过，无页面、控制台或 HTTP 5xx 错误；320/390 宽度无全页横向溢出。原生窗口自动化因安全检查无法可靠识别当前浏览器 URL 而中止，未建立真实后台暂停、NVDA 或 OS 字体缩放结论。用户当前没有可用手机，实机软键盘/旋转/safe-area 待验收；本机无可用 Docker/已安装 WSL 发行版，干净 Linux 安装和生产容量也待验收。生产发布尚未执行。旧版历史设备/无障碍结果不能复用为本版本结果。
