# 曜灵验收场景与闭环测试矩阵

**状态：待实施测试规范；本文件没有把任何新功能标记为已通过。**
**适用项目：Royal-Regent-Nexus；日期：2026-09-29。**

主规格定义产品和接口，本文件定义怎样证明功能可用。所有数字、用户和会话均为合成测试数据，不使用真实员工私聊、密钥或生产订单。

## 0. 测试隔离与证据规则

测试前先读当前后端 fixture、应用初始化和数据库配置，保证环境变量在 import 应用之前已设置为隔离库。不要直接启动指向 `backend/data` 或生产 PostgreSQL 的应用。关闭默认账号播种和非必要的真实设备/网络连接；需要账号时由 fixture 创建。

真实模型测试默认不执行；经授权提供测试配置后才能开启，限制为完成验证所需请求，记录结果而不记录秘密。常规测试用本地模拟 HTTP/SSE provider，不把千问“此时没有 Key”当成所有测试无法执行的理由。

证据建议目录：

```text
test-artifacts/assistant/<唯一 run-id>/
  baseline.md
  test-results.md
  visual/
  protocol/
  review-findings.md
  retest-results.md
```

每项记录 `case_id / 环境 / 合成账号角色 / 操作或命令 / 预期 / 实际 / 状态 / 证据路径`。状态只能为 **未运行、通过、失败、不适用且注明原因**。“模拟通过”和“真实供应商通过”必须分开记录。

以下 A 类能力是 V1 必须验证；带“能力条件”的场景，在对应功能对用户展示可用时必须通过。不能把按钮做成可点，再以“可选”回避验收。

## 3. 流式协议、取消、幂等与并发

### 3.1 模拟上游 SSE 的分片用例

构造一个可按任意 byte offset 分块的模拟 provider，逐一测试：

| ID | 注入方式 | 预期 |
|---|---|---|
| ST-01 | 把“曜”“灵”的 UTF-8 字节切在不同网络 chunk | 不产生乱码或丢字；增量解码正确 |
| ST-02 | 同一个 SSE event 跨三块；一块又包含多个完整 event | 不逐网络 chunk 直接 JSON.parse；事件完整有序 |
| ST-03 | CRLF、LF、空行、注释心跳、多行 data | parser 按协议处理；注释不显示为正文 |
| ST-04 | 末尾 usage 事件 choices 为空，再收到 `[DONE]` | 正确记录用量；不会因 choices[0] 不存在崩溃 |
| ST-05 | 上游异常结束，未收到正常终态 | 保存部分回答、状态 interrupted/failed；不伪装成功 |
| ST-06 | 思考与正文分通道返回 | 不互相覆盖或拼成重复正文；阶段真实 |
| ST-07 | 能力条件：tool-call 参数 JSON 跨多个分片 | 按 call ID 累积再校验；未收全不执行；不重复执行 |
| ST-08 | 重复应用同 seq 的下游事件 | 幂等去重，正文不会重复一段 |
| ST-09 | 模型输出未闭合代码围栏、半张表格后续继续 | 渲染不炸布局，最终补全；每 token 不重播消息进场 |
| ST-10 | 代理前后保持超过普通 30 秒，持续发送心跳 | 按新助手配置保活且逐步显示；原模块代理规则不变 |

### 3.2 运行生命周期与故障注入

| ID | 场景与输入 | 必须观察到的结果 |
|---|---|---|
| RUN-01 | 点击发送后快速双击，使用同 client_request_id | 只保存一条用户消息、一个 run，只调用一次 provider |
| RUN-02 | 相同 request_id，不同正文/附件/模型设置 | 返回 409，不复用错误请求、不第二次收费 |
| RUN-03 | 相同 request_id、相同内容，原 run 已存在 | 返回 reused JSON；前端走状态/快照分支，不错误当 SSE |
| RUN-04 | 服务端接收请求后首包丢失 | 用 lookup 找回原 run，不自动新建请求 |
| RUN-05 | 回答中只收起侧舱，再重新打开 | 请求继续、正文一致；收起不等于 Abort |
| RUN-06 | 用户显式停止 | 保留部分内容，终态为 cancelled，释放上游与并发槽 |
| RUN-07 | 发起 run 的 worker 与接收 cancel 的 worker 不同 | 共享取消状态生效；不能靠本进程内存假实现 |
| RUN-08 | 原连接断开/标签页关闭 | V1 关闭上游并记中断；恢复页面读取已有结果，不宣称后台继续 |
| RUN-09 | 模拟 worker 崩溃，lease 过期 | 遗留 run 可被识别并收敛为 interrupted；不自动重发收费请求 |
| RUN-10 | lease 续期写库失败或进程失去 lease | 停止当前生成，避免槽被回收后原 worker 仍持续输出 |
| RUN-11 | completed 与 cancel 同时到达 | 一次条件终态转换，不出现既完成又取消两条终态 |
| RUN-12 | 两标签页对同会话同时发送不同请求 | 一个活动 run；另一请求收到可理解的忙碌/冲突结果 |
| RUN-13 | 不同用户、多个 worker 同时达到并发起点 | 全局计数与每人计数原子执行；无越限、无跨人误占用 |
| RUN-14 | 上游超时/限流，返回 Retry-After | 明确可重试状态；重试策略不会在已输出后隐形重复收费 |
| RUN-15 | SSE 响应头已发后发生错误 | 通过终态事件结束；不假设可把原 HTTP 200 改成 401/500 |
| RUN-16 | 退出后旧请求 finally 执行 | 只清理自身 run，不把新会话 loading/正文清空 |
| RUN-17 | 缺少末尾 token usage | 用量为 unknown/null，不是零成本 |
| RUN-18 | 长回答持续写入数据库 | 采用短事务与合批写入；不持事务等待模型，不共享 Session 跨并发任务 |

幂等请求哈希必须基于规范化的实际输入，覆盖正文、附件、模型档位、思考/搜索选项和冻结上下文；不受 JSON 对象键顺序影响。全局并发测试需要真实的多 worker 或等价数据库并发测试，而非一个线程中的两个顺序请求。

## 4. 历史、附件、删除与数据边界

| ID | 场景与输入 | 必须观察到的结果 |
|---|---|---|
| DATA-01 | A 直接请求 B 的 session/message/run/attachment/export | 全部拒绝或统一不可见，不能只保护列表页 |
| DATA-02 | A 为管理员，B 为普通用户 | 管理员普通助手接口仍不能读取 B 的私人聊天 |
| DATA-03 | 客户端指定 owner_user_id 或伪造权限/工具结果 | 后端不采信；owner 来自当前认证 |
| DATA-04 | 跨账号或跨 epoch 引用 attachment_id | 拒绝发送，不能让视觉模型间接读取他人文件 |
| DATA-05 | 伪装扩展名、损坏图、解码尺寸异常、超出配置大小 | 校验失败可理解；不遗留不可追踪文件、不影响其他聊天 |
| DATA-06 | provider 需要读取图片，但内部附件 URL 要 Cookie | 不直接给无法认证的内部 URL；使用已实现且受控的字节/上传方式 |
| DATA-07 | 分页历史含 100 条以上，导出完整会话 | 导出全部授权记录，不仅当前 DOM/第一页 |
| DATA-08 | 两标签页同时改会话标题 | revision 冲突返回 409，避免静默覆盖 |
| DATA-09 | 重复创建会话使用同创建幂等 key | 创建一次且 owner/epoch 绑定；不能串到别人的同 key |
| DATA-10 | 生成中删除会话 | 先使会话不可再读写并取消 run；迟到输出不能重新创建被删内容 |
| DATA-11 | 删除时文件清理失败/进程中断 | 明确正在删除，保留可重试清理记录；不提前显示永久删除完成 |
| DATA-12 | 清理后再次查询会话/附件/导出 | 不可读取；没有可绕过的旧附件公开 URL |
| DATA-13 | localStorage、浏览器日志、服务端错误和导出检查 | 不含 Key、Cookie、真实私聊缓存和无关页面内容 |
| DATA-14 | 模型生成 `<script>`、onerror、javascript: 链接 | 作为安全文本或清洗后呈现，不执行 |
| DATA-15 | 模型生成远程图片 Markdown URL | 默认不自动请求该图片；不能通过渲染偷偷外发内容 |
| DATA-16 | 不可信 Origin 向 Cookie 认证写接口提交 | 按部署同源策略拒绝；不放宽 wildcard credentials CORS |
| DATA-17 | 一般聊天携带当前页面 | 请求不自动含整页 DOM、隐藏列、员工联系方式、密钥或真实价格 |

服务器目录清理限定在助手自己的受控 storage 根内。测试路径穿越时使用临时目录，不在真实用户文件上做破坏测试。

这些测试分两层：先确定性验证知识条目/函数映射，再通过模拟或真实模型验证答案不歪曲它。模型文本不宜逐字匹配，采用必要事实和禁止断言。

| HELP-18 | UV `data_mode=synthetic` | 模拟/合成数据，不作为真实实绩 | “今天真实生产了……” |
| HELP-19 | “六个厂是不是都有注塑模块？” | 组织范围与模块实现分开，当前注塑代码列四厂 | 擅自把 C/D 加入 API 和帮助 |
| HELP-20 | 问某版本报价的审批顺序 | 使用该版本当前代码依据；没有依据就说明待核实 | 只看路由名套所有版本的审批流程 |
| HELP-21 | 点击未注册区域要求讲解 | 明确暂无精确说明，允许描述/截图追问 | 凭 DOM 文案臆造官方规则 |

HELP-02–08 的数字仅在测试或用户明确提供输入时运用。V1 没有实时读取订单工具，不能将演示数字当成用户当前单据数据。

## 6. 元素定位与操作引导

| ID | 场景 | 预期 |
|---|---|---|
| GUIDE-01 | 点击“指给我看”，选择已注册字段 | 显示正确 help ID 的即时说明与来源，退出选择态 |
| GUIDE-02 | 仅键盘操作进入、选择、退出 | 有可见焦点、合理顺序，无必须鼠标才能触发的操作 |
| GUIDE-03 | 目标位于未打开页签或折叠区域 | 使用业务组件 reveal 接口进行非破坏性展开后定位 |
| GUIDE-04 | 目标在虚拟列表中尚未挂载 | 先定位真实数据项并让列表挂载，不能盲目 querySelector 失败后仍显示成功 |
| GUIDE-05 | 目标已删除、隐藏或权限变化 | 明确无法定位并停止引导，不高亮邻近错误元素 |
| GUIDE-06 | 模型返回任意 CSS selector、JS 或外部 URL | 不执行；只接受注册 help/action 契约 |
| GUIDE-07 | 要导航的页面存在未保存编辑 | 沿用原路由离开确认；不因助手直接丢草稿 |
| GUIDE-08 | 引导到审批/提交/调机/改价按钮 | 可以解释和高亮，不能替用户自动点击执行业务写入 |
| GUIDE-09 | 现有业务模态窗口打开 | 助手不盖住关键确认、不抢焦点；Esc 不同时关闭多个层 |
| GUIDE-10 | 操作目标经路由 catchall 回到首页 | 不能认为 router.resolve 成功就定位成功；必须校验真实 route name/参数 |

## 10. 独立复审与二次验证

第一轮实现后，至少执行一次与编码过程分离的复审。可使用另一个受控 reviewer；无法启动独立代理时，进行明确分离的审查轮次，不虚构有人审过。

复审重点：

1. 真实权限、身份刷新、跨账号响应污染及 supplier 范围。
2. SSE 分片、幂等收费、跨 worker 取消、短事务与 lease 收敛。
3. 已读/完成、欠数两种口径、未知值和模型虚构动作。
4. 视觉层次、真实全屏页共存、焦点、IME、移动键盘与减少动效。
5. create_all、迁移、Docker 自动升级、配置关闭与回退。

每个问题记录严重度、复现步骤、关联 case ID、修改文件和重测证据。修复后重跑相关场景及必要回归，不能只写“已优化”。
