# 近期订单快照与严格刷新

当前工作树仅给客户订单的非实时工具查询增加进程内近期快照复用。其他七域仍按原策略读取；这不代表全部模块都有缓存，也不改变业务权限、计量口径或数据库表。

普通聊天中的订单工具调用可以复用30秒内、同数据库实例/用户/任职与授权指纹/完整查询参数的快照。筛选、页大小、cursor和资源选择均属于键。模型与客户端不能指定缓存策略、actor或授权指纹，工具参数继续严格拒绝额外字段。选中详情始终回源。

“我的工作”、已冻结选择、关系重问，以及当前、现在、今天、刷新、最新、实时、剩余、比较和历史变化等明确意图绕过软缓存。刷新替换原同范围条目；刷新失败先淘汰旧条目，不会把旧数据标成新结果。缓存不影响付费生成步骤、重连/重放和原请求幂等性。

## 时间与来源

命中保留原 `as_of`、`observed_at`、`business_date`、完整范围指标、行和单位，只更新当前请求/读取时点。`freshness.cache_hit=true`，`cache_created_at`仍是原快照读取时间，`policy_id=orders-recent-v1`；`data_mode`保持已有snapshot枚举。命中不是重新测量或实时原子一致。

每个结果重新绑定本轮run/call/step/source/action标识并通过原ToolResult校验。原响应、历史答案和此前来源不会被改写。结果卡在已登记来源匹配本轮时显示“缓存快照”，保留未知/部分状态，并分别显示原数据时间和缓存创建时间。普通工具结果沿用与确定性预查询相同的指标投影，不计算或拼造数字，也不会重复展示同一结果。

## 私有隔离与资源边界

每次查询先按原生订单权限授权。命中另核对当前授权指纹及来源可见性/记录存在；撤权、换用户、任职/授权范围变化、来源删除或无效时钟不能复用。观察到指纹变化时剔除该用户其他旧范围，订单授权拒绝时清除此用户条目。不可读内容不会通过原单或成果出口恢复。

LRU最多128项、全局序列化载荷8MiB，每个用户16项/1MiB；这是载荷预算，不是Python进程RSS承诺。单调时钟最多允许命中30秒，原数据及缓存创建时间还必须在允许年龄内且不能来自未来。过期项在下一次缓存操作回收；进程重启丢弃全部缓存。深拷贝隔离调用方修改；缓存不保存会话Cookie、token、模型密钥或日志内容。不提供缓存枚举接口，不新增依赖、服务或持久存储。

普通当前查询、原单详情和按既有策略读取的成果仍重新授权。缓存只影响读取成本，不授予额外数据范围。分页快照仍各有时点，不能将不同页假称为同一原子数据库快照。
