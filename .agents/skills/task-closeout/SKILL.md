# Task Closeout

Read [AGENTS.md](../../../AGENTS.md) and [task lifecycle](../../../docs/agent-routing/task-lifecycle.md). The CLI is a mechanical gate, not a substitute for evidence or independent judgment.

1. At task start, select the applicable profile and open a local task workspace. Keep the current plan, reference, implementation report, review, cross-review and test evidence under that task ID. Do not place one-time plans in active knowledge directories.
2. Extract only verified durable changes. Update the relevant existing memory, contract or reusable design asset in place and retain actual regression tests. If nothing durable changed, record why. Do not promote temporary visual constants or unresolved decisions as rules.
3. Compare the declared candidate scope with the actual diff (including new/deleted files and pre-existing edits). Seal the final candidate, execute required checks and record actual evidence. UI work needs real browser and independent design review. Use independent actors for review and external cross-review. On a material defect, record FAIL/BLOCKED, fix within scope, reseal and revalidate. Never fabricate PASS, downgrade a profile or claim self-review is independent.
4. Only after external cross-review and necessary fixes, run the close dry run. Inspect candidate, inventory, blockers and archive destination. Apply its exact digest when ready and authorized by the task. No staged changes, commits, pushes, production actions, source moves or blanket cleanup.
5. Report the outcome and archive path. If blocked, keep the open task and evidence. Share only expressly approved sanitized historical summaries; raw evidence stays local. Recovery verifies and copies the archive without overwriting an active task.

Small direct fixes do not require a full workspace. Existing QC, security, Git, release and user scope rules take precedence.
