# 任务分级与协作约定

## 先按语义分级

- L0：文案、确定的局部样式、重复字段映射、既定断言下补充样例。rrn_easy；只定位不改代码用 rrn_scout。
- L1：沿用既有业务契约的普通组件、API 接线、表单交互、已定位的局部错误、运行既定检查。主线程或 rrn_worker。
- L2：新业务闭环、跨模块契约、复杂状态、权限或厂区作用域、金额和库存计算、排产规则、导入/迁移、难复现缺陷、高要求整体 UI 设计。需要时 rrn_architect 定案；复杂实现必须由 rrn_core 或实际已选用 Astra 的主线程承担。

文件位置和数量只是提示。修改权限服务中的注释未必是 L2；前端改一行金额或厂区条件也可能是 L2。
前端“有设计感、层次、工作流”的开放问题不能当成便宜模型的纯 CSS 小修。

## 派发最小工作包

目标与完成条件；真实入口/证据；需要保持的业务语义；可写文件；不应修改的共享文件；依赖的接口契约；相关测试。
不复制整份 PROJECT_MEMORY.md、整仓文件树或所有日志到每个子线程。
必要时只共享相关记忆段落、稳定的任务事实与具体路径；子代理可按需再读原始证据。

## 升级规则

发现未知业务规则、影响范围扩大、共享契约变化或高影响语义时，在继续修改前由主线程重新分配。
同一个问题连续两次有效修复仍不通过，提交已尝试的方法、失败证据和当前 diff，交 rrn_core。
环境、依赖或工具不可用先定位环境问题，不用连续换模型代替环境诊断。
rrn_easy 的不确定任务通常先交 rrn_worker；命中 L2 直接交 rrn_core，不必逐级试错。

## 并行与集成

全部子代理由主线程调度；同时开启数量是上限，不是必须凑满的目标。
独立文件、已确定契约的任务才并行。同一文件一次只分配一个写入者。
对 src/router/index.ts、src/style.css、package.json/锁文件、backend/app/main.py、共享模型和 Alembic 修订链，指定单一负责者。
Alembic 修改由负责者协调 revision/down_revision；主线程验证最终迁移链，不让并行工作者各自猜测当前 head。
多个独立开发任务可使用不同 worktree，但不假定每个子代理自动拥有独立 worktree。
不回退用户或其他代理已有改动。不自行运行 commit、push 或创建 PR。

## 验证与审查

检查与改变的行为相匹配。优先复用真实存在的脚本，不为配置任务安装新测试框架。
普通变更做相关检查；语义改变需验证其行为。高影响变更请独立 rrn_reviewer 审查最终 diff 与证据。
独立只读审查者不负责运行会写缓存或数据库的测试；测试由主线程或 rrn_worker 执行。
测试已有基线失败、无法运行或尚未覆盖时如实报告，不能用“已分析”代替“已验证”。
小变更不因多个代理加入而各自重复执行全套构建；集成负责人安排必要的最终检查。

## 成本与真实能力

主线程读取、思考、接收交接也消耗用量。少开无价值的子线程，关闭已完成线程。
同模型同档位也不代表固定任务成本。比较实际用量、耗时、返工与缺陷，而不是预设节省百分比。
角色模型写死不代表账户必然可用。大模型不可用时报告；没有运行时证据时把模型字段写成“配置目标，尚未验证”。
“不再派生”“只改这些文件”和重试次数是协作指令，不能声称它们是硬性沙箱或精确费用控制。
