# RR-Nexus 模型分配

本仓库采用质量优先方案 A：Astra/high 主线程负责业务判断、复杂实现与集成。普通独立实现交 Terra，窄范围事实或机械任务交 Luna。主线程已经掌握上下文时直接处理，不为拆分而增加交接。Astra/xhigh 设计者和实现者仅供独立难题按需使用，不是每次开发的必经阶段。

主线程根据任务的业务影响、不确定性和依赖关系决定执行者，而不是按代码行数分级。
先读取适用的 AGENTS.md，检索相关 PROJECT_MEMORY.md，核实本地当前实现。

| 执行者 | 用途 |
|---|---|
| rrn_scout | 窄范围只读定位和提取事实 |
| rrn_easy | 已完全明确、低影响的机械性改动 |
| rrn_worker | 明确契约下的普通实现与实际测试 |
| rrn_architect | 复杂设计、架构、业务闭环或高要求 UI 方案 |
| rrn_core | 复杂语义代码、关键算法与疑难问题的实际实现 |
| rrn_reviewer | 高影响变更或批次最终差异的独立只读审查 |

复杂业务的设计、实现、关键审查分别需要时再调用，禁止每次任务机械地启动全部角色。
一个很小的任务可由合适的主线程直接完成，或只交给一个便宜角色。
所有子任务由主线程派发，子代理不再自行派生。

需要详细分级与升级规则时读取 `references/task-routing.md`。
需要仓库入口与现有验证命令时读取 `references/repo-map.md`。
给每个子任务明确目标、必要上下文、可写文件、验收条件和依赖；同一文件一次只分给一个写入者。
默认不继承完整对话；若当前运行时完整继承会锁定父模型，指定其他模型时必须采用支持的最小上下文调用方式。配置角色存在、调用成功、实际模型/档位吻合是三个不同结论。
子代理返回精简结果与代码/测试证据，主线程检查最终组合结果，不重复全文扫描。

角色配置固定模型，但任务分配规则是指令，不是费用上限或文件权限的运行时强制执行器。
无法调用目标角色/模型时，报告实际错误；不得把其他模型的结果标成目标模型已完成。
