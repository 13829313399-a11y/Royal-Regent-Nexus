`20261009_0149_molding_quote_target.py` 曾在本地 SQLite 执行，仅增加报价目标列。
同步远程 main 时，已发布的裁床合并迁移也使用了 `20261009_0149`。

这里保留原脚本内容，不加入 Alembic 的 `versions` 扫描目录。已发布的裁床迁移保持原样，新的 `20261009_0150` 统一两种已有状态：

- 正常的已发布 0149：增加可空报价目标列，旧行保持空值。
- 本地旧 0149：仅当 SQLite 已有报价目标列、三个裁床表全部缺失时，执行原裁床建表脚本；已有报价目标值及业务数据不变。
- 裁床表部分缺失或其他无法识别的状态：中止升级，先核对历史。

`20261009_0150_warehouse_operations.py` 曾在另一本地 SQLite 执行，增加仓库日常收发账本；远程已发布的报价目标也使用了 `20261009_0150`。原仓库脚本同样原样归档，发布链保持报价 `0150` → 裁床订单 `0151` → 仓库 `0152`。

- 正常已发布 `0151`：`0152` 新建仓库账本，不改原有表和记录。
- 旧仓库 `0150`：升级前只读核对仓库账本及三个裁床基础表的完整结构、约束、索引、外键和触发器，确认无提前出现的裁床订单表；随后执行已发布 `0151`，由 `0152` 补齐缺失的报价目标列，保留仓库原记录。
- 结构漂移、无法识别的中间状态或非 SQLite 旧仓库碰撞：停止升级，不重建原表，不重标迁移版本。

两个归档脚本都必须随部署包保留。部署或本地重启前按既有流程停 API、完整备份、在副本验证，再执行 `alembic upgrade head`。当前本地仓库数据库仍是旧仓库 `0150`，此合并只提交兼容升级路径，不代表实际环境已经升级。
