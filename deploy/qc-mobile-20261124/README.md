## 提前准备候选（不启动服务）

服务器的 API 镜像包含按批次更新过的代码，不能仅按镜像标签推断文件内容。[清单](manifest.json)固定了已核对的基础镜像 ID、7 个变更文件和 5 个保留文件的摘要。七个文件为手机 API、共享配置中的一个 QC 开关、桌面扫码入口 JS，以及手机 HTML、CSS、应用 JS 和同步 JS。包内没有迁移、生产配置、业务数据或证书。

在有完整 Git 历史的开发或构建机器，从仓库根目录执行（Python 3，无需服务器权限）：

```sh
python3 deploy/qc-mobile-20261124/prepare.py qc-mobile-545aa59d.tar.gz
```

脚本只读取固定的 Git 对象，生成独立 Docker 构建上下文；输出文件必须不存在。保存打印的 SHA-256，在传输后复核。本批次的七份候选文件均与隔离传数演练使用的文件逐字节相同。不要将压缩包解到正在运行的程序或数据目录。

在**公司受管的隔离构建机**使用与现网相同架构、已载入与清单相同 ID 的原 API 镜像。本批次的构建示例：

## 正式服务器就绪后

1. **容量与回退。** 扩容后核实文件系统实际可用空间，计入备份、构建或载入镜像、回退镜像及照片增长。上次测得根盘已低于 2 GiB 发布预留，仅数据库增量约 1.8 GB；这是当时的测量，不是建议扩容大小。按照[已有生产环境发布流程](../../docs/aliyun-docker-deploy.md#更新已有生产环境)，安排维护时间，验证数据库及 QC 照片、附件和其他持久资产的同一冻结点备份能在隔离副本恢复。保留原 Compose 组合、卷、镜像和配置。
2. **核对切换范围。** 复核运行容器的镜像 ID、挂载与组合，并在隔离副本确认候选启动不会迁移或改动现有业务数据。旧镜像启动路径可能执行 Alembic；单看本包没有迁移文件并不足够。只在已核准的完整组合里更新正式 API 的候选镜像和 QC 参数，保持单正式 API，不重建数据库或其他部门服务。与基线不符或需要迁移时，保持旧版本。
3. **接通 HTTPS。** 给电脑和手机选择同一固定 HTTPS 地址，配置匹配且可自动续期、重新加载的受信任证书。使用公网 IPv4 时，证书须包含 IP SAN，并作为无域名 SNI 时的证书。保留正式 Host、Origin、Cookie 和 Set-Cookie，通过原 Web 转发到原 API；旧系统仅对正式 API 配置 `QC_MOBILE_PUBLIC_ORIGIN=https://实际固定地址`、`QC_MOBILE_REQUIRE_HTTPS=true`，不用改变全站 `APP_ENV`。详见[代理、证书和来源要求](../../docs/aliyun-docker-deploy.md#移动验货上线验收)。
4. **先探测，再实扫。** 从投入使用的厂区网络执行下面的命令。只有退出码为零，且健康、六项手机资源、匿名访问保护（401）和无效票据（422）全部符合预期，才进入真机验收。探测不需要账号，不签发配对票据，也不写业务单。

   ```sh
   python3 deploy/check_qc_mobile.py --url https://实际固定地址
   ```

5. **现场签收。** 在公司指定的隔离测试环境用岗位账号、测试单和 iPhone Safari / Android Chrome 完成实扫：核对厂区与单号 → 拍一张照片、填结果和备注 → 断网暂存 → 复连刷新 → 电脑看到同一笔和一张照片 → 电脑提交进入待审核。另验过期码提示重新扫码。正式入口验收使用只读探测和公司安排的正常业务观察；不要拿真实订单试写。在上线回执中记录候选镜像 ID、正式入口、探测结果和现场签收人。

**回退：** 切换或探测失败，保持维护状态，恢复上一批 API 镜像与配置并复验原系统。已经开放写入后，不得整库回滚覆盖其他部门的新数据。
